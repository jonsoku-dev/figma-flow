# SaaS 캐러셀을 편집 가능한 Figma 프로토타입으로 변환하기

Figma Flow 0.33.0은 브라우저에서 중앙에 스냅되는 카드 목록을 측정해 Figma Design의 상태 프레임과 프로토타입 연결을 만든다. 디자이너는 카드의 레이어를 편집하고, 기획자는 동일한 시작점에서 흐름을 재생하며, 개발자는 그래프의 카드 ID와 전이 목적지를 확인할 수 있다. [사용 안내](../../docs/guide.md) · [관찰 입력 형식](../../docs/web-carousel-input.md).

## 실행과 인수 경로

1. 사용자가 설치한 Chromium을 로컬 Node 명령으로 연다. CLI는 격리 프로필에서 브라우저가 실제 표시한 네 상태와 PNG, 소스 이미지와 터치·자동재생 기록을 얻고 Python 컴파일러를 호출한다. Computer Use, hook, 공식 Figma MCP, API 토큰 없이 사용할 수 있다.
2. 소스 그래프는 순서, 상태별 화면·터치 영역, 초기 상태, 5,000 ms 타이머, 수동 및 시간 경계 규칙, 입력별 목적지와 관측 근거 해시를 소유한다. 준비된 작업은 선택한 Figma 파일·페이지와 그래프 해시를 고정한다. 일반 정적 가져오기는 기존 화면 계약을 사용한다.
3. 자체 플러그인이 상태별 최상위 프레임을 만들고 Figma의 실제 텍스트, 이미지, 벡터와 프레임을 배치한다. 드래그는 측정된 레일의 오른쪽 절반에서 시작해 왼쪽으로, 왼쪽 절반에서 시작해 오른쪽으로 민다. 해당 레일 밖의 페이지를 드래그해 페이지를 바꾸지는 않는다.
4. 프레임에는 자동재생 시간을, 드래그 영역에는 인접 목적지와 방향을 설정한다. 실물 레일의 처음·끝에서 같은 상태에 머무는 그래프 엣지는 목적지 이동을 생략한다. 재적용 시 기존 상태, 편집된 상호작용 및 흐름 시작점을 비교한다.
5. 기존 파일의 해당 작업을 다시 읽고 패널에서 시작 프레임과 네이티브 연결을 확인한다. 프레젠테이션에서 실제 입력과 다음 카드가 표시된 시각은 별도로 측정한다.

## 실제 SaaS 템플릿에서 관찰한 결과

| 입력 | 브라우저 | Figma Design 프레젠테이션 |
| --- | --- | --- |
| 첫 카드에서 왼쪽으로 밀기 | 카드 1 → 카드 2 | 같은 두 카드로 이동 |
| 두 번째 카드에서 오른쪽으로 밀기 | 카드 2 → 카드 1 | 첫 카드로 복귀 |
| 마지막 카드에서 왼쪽으로 밀기 | 카드 4 유지 | 동일 프레임 유지 |
| 입력 없이 기다리기 | 순서대로 자동재생, 마지막 카드 다음은 첫 카드 | 카드 3 → 카드 4 → 카드 1 |

브라우저는 모바일 터치 에뮬레이션(390 × 844 CSS px, DPR 1), Figma는 별도의 로그인된 Chrome 프레젠테이션 플레이어에서 마우스 드래그로 검사했다. 5,000 ms 타이머를 적용한 표본에서 세 번째 카드가 나타난 뒤 네 번째 카드까지 5.03초, 다시 첫 카드까지 누적 9.96초를 관측했다. 이 수치는 해당 재생 실행의 측정값이다. 웹의 동적 진행 막대와 네이티브 스크롤 관성은 같은 시간·궤적으로 복원되지 않는다. Design에서 재생하는 대상은 측정한 상태, 순서, 두 방향의 입력과 경계 동작이다.
