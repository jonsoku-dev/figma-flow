# Figma Design 전용 설계

[제품 헌법](../../CONSTITUTION.md)의 편집기 범위를 구현하는 계약이다. 모든 신규 기능은 요구사항 → Design 사용 장면 → 구현 → 인수 근거 경로를 가져야 한다. [정본 그래프](graph.json)

| 대상 | 제품 안에서 하는 일 | 완료 근거 |
|---|---|---|
| 디자이너 | main·instance, 타이포그래피, 벡터, 마스크, 오토 레이아웃과 변수를 편집한다. | 실제 Design 노드 유형과 속성, 인스턴스 연결, 수동 수정 보존 및 재실행을 확인한다. |
| 기획자 | 같은 Design 페이지에서 상태·동선·요구사항과 인수 조건을 검토한다. | 선택한 ID와 관계가 검토 보드 및 프로토타입에서 유지된다. |
| 개발자 | 브라우저 입력과 디자인 토큰, 네이티브 결과와 구현을 대조한다. | 원본 해시, 실제 게터, 렌더링 차이, 확인한 파일·페이지 범위를 연결한다. |

## 구현 경계

- 레시피 카탈로그는 Design/default만 허용한다. 등록된 작업공간, SDK, 위젯과 별도 검증 도구가 생성하는 manifest에서 같은 편집기 대상을 검사한다.
- 실제 쓰기 앞에서 파일·페이지·수신 객체와 소유 여부를 검증한다. 에디터가 다르거나 적합한 수신 객체가 없는 선언은 근거에 그 상태를 기록한다.
- 원본의 입력·레이어·클라우드 읽기와 대체 렌더링 결과는 구분해서 보관한다. 공식 선언 수집이나 컴파일 통과를 실측으로 승격하지 않는다.
- 다른 제품만을 위한 생성·발표·게시 흐름은 구현 대상에서 제외한다. 공유 기능을 확장할 때에는 Design에서 그 자체로 완결되는 사용 장면을 먼저 제시한다.

## 인수 검사

`python3 -B -m unittest tests.test_design_specialization`은 계약 그래프, 등록된 레시피와 기능 라우트, SDK의 편집기 선택, 생성된 SDK·위젯 manifest를 대조한다. 원격 CI의 기본 테스트 검색에 포함된다. 소스 검사를 통과한 후 해당 기능을 실제 Design 파일에서 재실행해 그래프에 근거를 연결한다.
