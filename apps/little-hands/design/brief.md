# 작은손 커피공방

## 실제 사용자 요청 원문

최종테스트는 새로운앱개발을위한 아이디어 기반으로 시작하여 직접 피그마도 조작하면서 전체테스트가 진행되어야해

좀더복잡하게해서 모든내용을 제대로 테스트할숭맀도록

테스트를위한 앱이 아닌 정말 실제 프로덕션레벨의 앱으로

## 제품 해석과 권위

에이전트가 제안한 제품은 작은손 커피공방이다. 회원이 실제 수업을 신청·대기·변경·취소하고 운영자가 같은 PostgreSQL 데이터를 관리하는 Django 서비스다. 한국어, 커피 수업, 현장 결제, 로컬 Hahmlet, 종이색과 적갈색은 에이전트의 제품·시각 제안이며 사용자가 개별 선택한 아트 방향으로 기록하지 않는다. 온라인 결제, 외부 메시지 발송, 실도메인 배포·게시 권한은 포함하지 않는다.

이전 가상 예약 프로토타입은 현재 구현의 정본이 아니다. 현재 사실은 ../ARCHITECTURE.md, ../booking/models.py, ../booking/services.py, ../booking/views.py, 실제 templates/static, 격리된 staging DB와 실제 브라우저 관측에서 읽는다. graph.json 하나가 관계를 소유한다. 생성된 화면 명세와 gallery는 graph의 투영이다.

## 요구사항 열 가지

1. REQ-001. 수업·회차·공간·정원·가격을 실제 DB에서 발견하고 확인한다.
2. REQ-002. Django 인증·회원가입·세션과 소유자/운영자 권한으로 데이터를 보호한다.
3. REQ-003. 인원·현장 결제 총액을 검토하고 서버 트랜잭션으로 신청한다.
4. REQ-004. 정원이 부족하면 명시적 동의로 대기하며 엄격한 FIFO 승급을 지킨다.
5. REQ-005. 예약 당시 단가·현재 상태·예약 번호를 자기 예약에서 다시 조회한다.
6. REQ-006. 정책 기한을 확인하고 명시적으로 취소하며 좌석·대기열·기록을 함께 갱신한다.
7. REQ-007. 같은 강좌의 다른 회차로 원자적으로 변경하며 실패하면 기존 예약을 보존한다.
8. REQ-008. revision·멱등 키·DB 제약으로 중복·경합을 막고 충돌에서 최신 화면으로 복구한다.
9. REQ-009. 운영자가 회차·명단·정원·실제 집계를 관리하고 회원은 자기 알림을 읽는다. 감사 기록은 불변이다.
10. REQ-010. 실제 한국어 반응형·키보드·오류·복구 화면과 편집 가능한 Figma를 같은 의미 ID로 전달한다.

## 화면과 실행 경계

공개 홈, 로그인, 회원가입, 회원 홈, 신청 가능한 회차, 신청 검토, 확정, 대기, 나의 예약, 취소 확인, 취소 완료, 회차 변경, 충돌, 알림, 운영 현황, 운영 일정, 회차 등록, 신청 명단, 회차 편집, 감사 기록,403,404를 포함한다. 기본 브라우저 뷰포트는1200×900과390×960이다. 캡처는 전체 페이지의 실제 콘텐츠 높이를 보존한다.

웹은 Django 인증·CSRF·폼·POST·SQL 트랜잭션을 실행한다. Figma는 관측한 화면·입력 예시·상태를 편집 가능한 레이어로 표시하고 연결된 시각 상태로 이동한다. Figma에서 로그인·비밀번호·좌석 확보·취소·SQL·알림 발송이 실행된다고 설명하지 않는다. 현재 메뉴·본문 앵커·입력 컨트롤 등 이동 대상이 없는 요소는 실제 컴포넌트와 주석을 유지하며 reaction이 없는 정적 조작으로 전달한다.

## 인수 근거

소스 구조·단위/DB 테스트·실제 브라우저 행동·시각 비평·Figma getter·Figma 직접 조작은 서로 다른 근거다. 측정 JSON과 JPEG는 부모가 실제 화면에서 수집한다. source.py는 없는 성공 상태나 geometry를 만들지 않으며 누락을 pending으로 출력한다. 실제 사용자 이벤트, 승인, Figma ID, 영수증을 생성하지 않는다. 실제 검증 전 graph의 acceptance/test를 verified로 올리지 않는다.
