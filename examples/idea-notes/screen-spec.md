# 모음 — 로컬 실행 화면 명세

최초 요구사항은 `brief.md`다. 이 묶음은 로컬 코드 예제이며 Figma 설계·파일·프로토타입을 만들거나 검증했다고 주장하지 않는다.

## SCR-001 목록

- 헤더, 소개, 저장된 카드의 제목/내용/날짜, 총 개수, 검색 필드, 추가 버튼.
- STATE-001: 검색어가 없고 저장된 레코드도 없으면 첫 기록 안내.
- STATE-002: 저장된 카드. 제목/내용을 `textContent`로 출력한다.
- STATE-003: 검색어가 있고 결과가 없으면 검색 결과 없음. 저장소가 비어 있어도 동일하다.
- STATE-007: 읽기 실패. 오류와 `다시 불러오기` 버튼으로 회복하며 성공으로 표시하지 않는다.
- ACT-001 추가 → SCR-002 / STATE-004. 제목에 포커스.
- ACT-005 검색 입력 → 목록을 대소문자 구분 없이 제목/내용으로 필터링.
- ACT-006 다시 불러오기 → 저장소 재조회. 다른 탭 저장 알림과 창 포커스에도 재조회.

## SCR-002 작성

- 제목 필수 60자, 내용 선택 500자. HTML `maxlength`와 저장 경계 검사 모두 사용한다. 문자 수는 브라우저 입력과 같은 UTF-16 코드 단위이며 이 예제의 명시적 해석이다.
- STATE-004 기본 입력. ACT-002 취소/목록으로 → SCR-001, 입력 초기화, 추가 버튼 포커스.
- STATE-005 제목 공백/초과 또는 내용 초과 → 해당 오류와 `aria-invalid`, 입력 포커스. 기본 설명은 영구적인 길이 힌트이며 활성 오류만 `aria-describedby`에 추가한다. 유효하게 고치거나 폼을 초기화하면 오류 연결을 제거한다.
- ACT-003 저장 → IndexedDB 트랜잭션 완료 후 SCR-001. 저장 중 입력과 버튼 비활성화, 완료 후 다시 활성화한 다음 포커스를 이동한다.
- STATE-006 저장 실패 → 작성 화면과 입력 유지. 같은 저장 버튼으로 재시도.
- 탭별 저장은 `add` 트랜잭션이므로 기존 목록의 복사본으로 덮어쓰지 않는다. BroadcastChannel은 목록만 갱신하며 열린 초안을 지우지 않는다. 지원하지 않으면 창 포커스 시 재조회한다. 기기 동기화는 없다.

## 검증의 범위

`tests/app.test.cjs`는 Node 기본 테스트 도구와 명시적인 DOM/IndexedDB 테스트 대역으로 실행한다. 저장 실패·재시도, 포커스 호출, 입력 한계, 검색, 재실행 시 데이터, 탭 알림의 앱 계약을 검증한다. HTML/CSS 검사는 레이블·오류 관계·기본 컨트롤·반응형 규칙의 존재를 확인한다.

테스트 대역은 실제 브라우저 저장소, 물리 키보드 이벤트, 화면 레이아웃, 접근성 트리, 다중 탭의 실제 브라우저 경쟁 상황을 증명하지 않는다. `graph.json`의 verified acceptance는 제목에 적힌 로컬 계약 범위다. 원 기획서 검수 6은 별도 `evidence/browser.json`에 기록된 실제 Chromium 1440×900 / 375×812 및 키보드 진입·오류 포커스 관찰로 보완한다. 브라우저 기록은 저장·새로고침, 검색, 취소, 쓰기 오류 주입·재시도, 두 탭 저장·실시간 갱신도 포함한다. 전체 키보드 순회·스크린 리더·다른 브라우저는 검증하지 않았다. 날짜 정렬은 IndexedDB 자동 증가 키 역순이다.
