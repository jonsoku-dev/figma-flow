# Review a selected graph in Slides

The Slides graph review recipe turns a selected Figma Flow graph into a navigable presentation. It creates a cover and one slide per selected node. Each node slide shows the source type, status, detail, and every incoming or outgoing relationship for that node. The cover and slide metadata preserve the graph ID and the SHA-256 of the canonical graph file.

The recipe creates native slide rows and arranges the generated slides in groups of three. It names each row and slide with graph or node IDs, then opens the cover in single-slide view. The recipe leaves other slides in their existing order.

## Create and build the plugin

Select one to 24 existing node IDs from a valid graph. The projection includes relationships whose endpoints are both selected, up to 48 relationships. The recipe rejects duplicate node IDs, missing relationship endpoints, invalid type or status values, and invalid graph hashes before creating Slides content.

Create a new Slides development plugin in Figma and copy the numeric plugin ID issued by Figma. From the repository root, initialize a local SDK project with the selected graph:

```sh
python3 tools/figma_sdk_project.py init .figma-flow/slides-review-plugin \
  --editor slides \
  --plugin-id FIGMA_ISSUED_ID \
  --recipe slides-flow-review \
  --review-graph path/to/graph.json \
  --node REQUIREMENT_ID \
  --node SCREEN_ID
```

Replace each uppercase value with the value from your Figma project. Add one `--node` option for each graph node to include. The recipe consumes the projection generated by the SDK project tool. It does not define its own review nodes or relationships.

Install the pinned TypeScript compiler and build the project:

```sh
cd .figma-flow/slides-review-plugin
npm install --ignore-scripts --no-audit --no-fund
npm run build
```

Import the generated `manifest.json` through Figma's development plugin menu for Slides, then run the plugin in the selected file. The build command only checks TypeScript against the repository's pinned Figma API declarations. It does not execute the plugin in Figma.

## Reruns and recovery

The recipe stores private plugin data on generated rows and slides. If the graph ID, graph hash, selected node IDs, and slide stamps match, a rerun selects the existing cover without creating another deck. If the selected graph changes, the recipe creates and verifies a replacement grid before removing old rows that carry its private marker.

Before grid verification, a failure removes only the new rows and their descendants, then restores the prior slide grid, selection, focus, and view. If Figma refuses to remove an older generated row after the replacement grid succeeds, the recipe keeps the new deck and reports the remaining row IDs. You can remove those named rows after reviewing them.

## API and runtime limits

The recipe calls `figma.createSlideRow`, `figma.createSlide`, `figma.getCanvasGrid`, and `figma.setCanvasGrid`. The pinned API declares the canvas-grid methods for Slides and Buzz. It marks `getSlideGrid` and `setSlideGrid` deprecated, so the recipe uses the current canvas-grid methods to read, arrange, and verify slides.

The local SDK build and regression harness verify declarations, graph-derived content, row and grid calls, same-input reruns, and rollback against a fake Figma API. A separate Figma Slides run used a selected canonical Magic UI graph with 20 nodes and 16 relationships. Figma created 21 slides across seven native rows, with 42 text nodes. The rerun selected the existing deck and kept those counts unchanged.

The editor run verifies this selected graph and file only. It does not verify other documents, graphs, or Figma editor versions. The harness remains simulated runtime evidence. It does not replace the editor run.
