# RD-05 기능서 · 입력 사진·글꼴·CSS 자산 목록

상태는 제안이다. 우선순위는 보통이다. 기준과 공통 실행 계약은 [계획](../README.md), [현재 상태](../CURRENT_STATE.md), [Cursor 전달서](../CURSOR_HANDOFF.md)에 있다.

## 사용자 문제

화면이 비거나 서체가 달라졌을 때 어떤 파일이 빠졌는지, 외부 주소라 확인하지 못했는지 알기 어렵다. 준비 결과를 읽기 위해 원시 JSON을 찾아야 한다.

## 현재 구현

`input_effect.html_channel`은 중첩 CSS와 import, 이미지·글꼴·script 참조와 present/404/rejected/external-unverified 상태를 수집한다. `project`와 `freshness`가 입력을 고정한다. 현재 패널에는 이 결과를 전달하는 전용 소비 경로가 확인되지 않았다. ImportPanel의 선택 파일 목록은 이 의존성 목록과 다르다.

## 첫 구현 범위

현재 input-effect 결과의 읽기 전용 요약을 해당 prepared task의 상세에 표시한다. 첫 단위는 결과 전달 경로를 확정하고 하나의 HTML 입력 task에 연결한다.

원격 자산 자동 fetch, 파일 업로드·변환·수정, CSS cascade 전체 계산, 브라우저 시각 로딩 판정, 임의 HTML importer, 원본 경로를 집계 서버로 전송하는 기능은 제외한다.

## 기능 요구사항

- **RD-05-REQ-01** — 각 자산에 상대 참조·종류·상태·유입 CSS/HTML의 출처와 현재 freshness를 표시한다.
- **RD-05-REQ-02** — 같은 원본 파일은 한 항목으로 묶되 이를 참조한 출처 목록을 보존한다.
- **RD-05-REQ-03** — missing·unsafe·external-unverified를 서로 다른 문구와 복구 안내로 표시한다.
- **RD-05-REQ-04** — 원본 hash가 바뀌면 과거 목록을 최신처럼 보여주지 않고 재준비가 필요함을 알린다.
- **RD-05-REQ-05** — 외부 주소는 확인되지 않았다는 상태를 유지한다. 목록 열기만으로 네트워크 요청을 하지 않는다.

## 인수 조건

- **RD-05-AC-01** — 중첩 CSS 두 개에서 같은 글꼴을 참조하면 목록은 한 자산과 두 출처를 보여준다.
- **RD-05-AC-02** — 없는 로컬 사진은 404와 해당 상대 경로를 보여주고, 위험한 경로는 rejected로 보인다.
- **RD-05-AC-03** — 외부 글꼴 URL은 external-unverified이며 패널을 열어도 fetch되지 않는다.
- **RD-05-AC-04** — 파일 추가·삭제·byte 변경 후 목록은 stale로 바뀌고 새 input record가 준비돼야 갱신된다.
- **RD-05-AC-05** — 큰 목록을 검색·종류·상태로 좁힐 수 있고 키보드와 텍스트만으로 상태를 구분한다.

인수 조건은 [설계서](design.md)의 경계를 보존하면서 [작업서](tasks.md)에서 구현한다. 현재 이 문서의 조건은 통과로 기록되지 않았다.
