# RD-09 기능서 · 진단 기록 내보내기

상태는0.27 첫 구현 범위의 기능 계약이다. 조건별 fixture·실제 관측과 미지원 확장은 [최종 인수 현황](../FINAL_ACCEPTANCE.md)을 따른다. 우선순위는 높음이다. 기준과 공통 실행 계약은 [계획](../README.md), [현재 상태](../CURRENT_STATE.md), [Cursor 전달서](../CURSOR_HANDOFF.md)에 있다.

## 사용자 문제

실패를 고치려면 플러그인 버전, 파일·페이지, 작업 키, 리비전, 작업 식별자, 페어링과 신선도, 실행 단계의 오류, 쓰기 차단 이유, 입력 요약, 의존성 신선도, 네이티브 읽기 범위가 한곳에 있어야 한다. 그 기록이 흩어져 있으면 진단 기록을 에이전트에 넘겨도 고칠 근거가 빠진다.

## 현재 구현

제어 journal, 입력 요약, 네이티브 읽기는 각각 따로 저장된다. 그래프 패널은 읽기 결과 JSON을 저장할 수 있지만, 비밀값을 가리고 관찰하지 않은 검사를 남기는 진단 기록은 없다.

## 첫 구현 범위

로컬에서 텍스트·JSON·마크다운으로 복사하거나 저장하는 읽기 전용 내보내기를 만든다. 사람이 읽는 본문은 마크다운이고, 같은 사실을 담은 JSON을 그 안에 둔다. 첫 표면은 그래프 패널이다.

새 프레임워크, 차트 의존성, LLM 서버, 임의 Figma JavaScript 실행기는 넣지 않는다. 내보내기는 문서를 바꾸거나 네이티브 쓰기를 보내거나 페어링을 바꾸지 않는다.

## 기능 요구사항

- **RD-09-REQ-01** — 기록에 스키마 이름, 플러그인 버전, 파일 키, 페이지 ID와 이름, 작업 키, 리비전, 작업 식별자를 남긴다.
- **RD-09-REQ-02** — 페어링 상태와 신선도, 런타임 신선도, 실행 단계의 상태와 오류 문장, 불확실 쓰기 차단과 이유를 남긴다.
- **RD-09-REQ-03** — 안전한 입력 요약 행, 의존성 신선도 표시, 요약 또는 전체 읽기가 있을 때의 프로파일·노드 ID·필드·빠뜨린 닫힘·완료 표시를 남긴다.
- **RD-09-REQ-04** — 이번 내보내기에서 보지 않은 검사는 빠뜨리지 않고 목록으로 남긴다.
- **RD-09-REQ-05** — bearer 토큰, 로컬 동기화 토큰, 채팅 토큰, 홈 디렉터리 절대 경로, 자격 증명 쿼리를 가린다. 노드 ID, 리비전, 오류 문장, 작업 식별자는 짧게 만들려다 지우지 않는다.

## 인수 조건

- **RD-09-AC-01** — 마크다운 본문과 그 안의 JSON이 같은 진단 사실이다. 텍스트 복사는 그 마크다운이다.
- **RD-09-AC-02** — 비밀값은 기록에 남지 않고, 노드 ID·리비전·오류·작업 식별자는 남는다.
- **RD-09-AC-03** — 요약 읽기와 전체 읽기의 범위가 구분되고, 읽기가 없으면 그 검사가 관찰되지 않았다고 적힌다.
- **RD-09-AC-04** — 그래프 패널의 복사·저장은 문서를 바꾸지 않고 네이티브 쓰기를 보내지 않으며 페어링을 바꾸지 않는다.
- **RD-09-AC-05** — 실제 Figma 패널에서 내보내기를 확인하기 전에는 그 관찰을 통과로 기록하지 않는다.

인수 조건은 [설계서](design.md)의 경계를 보존하면서 [작업서](tasks.md)에서 구현한다. 현재 조건별 판정과 실제 관측·fixture의 구분, 후속 확장과 출시·설치 근거는 [최종 인수 현황](../FINAL_ACCEPTANCE.md)과 패치 Wiki에서 확인한다.
