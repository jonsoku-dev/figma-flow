# 패치 지식 시스템의 검증 기록

이 기록의 소스 기준은 `0bd817701f3df66673e314007f768a6de404fd78`이다. 실행 환경은 Python3.13.3과 Git2.50.1이다. 도구·기록의 통합 전 검증이며 아직 새 제품 커밋·태그·설치의 성공을 뜻하지 않는다.

## 기록 범위

canonical 조상43개와 태그10개, 당시 CHANGELOG 버전16개를 대조했다. 현재0.26.1 후보는 별도로 표시한다. 삭제 전 bundle의 별도 조상39개와 보존 head19개도 전부 조사했다. canonical 밖 head는10개다. 총82개 고유 커밋을 상세 기록과 연결한다.

원래 bundle 파일의 SHA-256을 다시 계산해 기록된 값과 일치를 확인했다. 보존0.18.1 head와 canonical 첫 구현 반입의 전체 tree 해시는 모두 `ce61009f41c024b1c03586582c6db3aae6d45ba7`이며 파일별 차이는0개다. 옛 패치가 다른 계보의 동일 최종 상태로 반입됐다는 근거다. 개인 bundle 경로는 배포하지 않는다.

## 독립 검수와 수정

별도 읽기 전용 검수자가 Git diff와 기록을 대조해 누락된90f9195, 과소 설명한 aa3acdd·61c0b1e, e30b9a4 부모 순서와 출처 없는 인계 집계를 지적했다. 누락을 추가하고 큰 제품 경로·인터페이스와 실제 부모 순서를 보완했으며 출처 없는 집계는 제거했다.

코드 독립 검수는 임시 파일 symlink, 최초 sync 본문 보존 누락, 허위 실패 문구, 작업 소스 신선도, 남는 하위 프로세스를 지적했다. 실제 fixture로 고정하고 수정했다. 후속 검수에서 stdout/stderr에 가짜 AssertionError 라벨을 출력하는 경우도 재현해 마지막 실제 traceback의 assertion으로 판정을 좁혔다.

## 실행 검사

- `python3 -B -m unittest discover -s tests -p 'test_patch_knowledge*.py'`에서41개 테스트가 통과했다. 실제 임시 Git 저장소의 fork 원격·같은 버전의 다른 커밋·merge·반복 갱신·기존 본문·누락·오래된 근거·허위 통과·범위·소스 변경·링크·시간 초과·남은 프로세스·경로 공격과 검사 기준 약화를 검사했다.
- 독립 코드 검수자의 추가3개 검사도 통과했다. 검사 기준 변경을 거절하고 동일한 기준으로 제품만 수정한 정상 경로와 실행 모드 변경을 대조했다. 기본 검사에서 미커밋 제품 변경을 거절하는 조건과 명시적인 역사 감사 경로를 구분한다.
- canonical 카탈로그는 지정 소스의43개 커밋·10개 태그·당시 버전16개와 대조한다. 현재0.26.1 후보의 CHANGELOG 링크도 검사한다. 역사 감사는 `verify --ref 0bd817701f3df66673e314007f768a6de404fd78 --committed-only`로 명시한다. 통합 전의 작업 중 소스 완료를 인증하지 않는다.
- 보존 계보39개는 `patch_knowledge_legacy.py verify --wiki docs/llm-wiki/legacy --source-git <임시-bare-저장소>`로 실제 Git 객체와 대조해 통과했다. 기본 fork 경로의 structural-only 검사와 구분한다.
- 세 CLI의 도움말 실행, `git diff --check`, 배포 대상의 개인 홈/토큰 형태 검사도 통과했다. 원본 main과 현재 체크아웃을 바꾸지 않았으며 커밋·게시·설치를 수행하지 않았다.

부모가 제시한 반례도 별도의 임시 Git에서 직접 재현했다. 제품을 고치지 않고 check.py의 실패 assertion을 print로 바꾼 경우는 종료1로 거절됐다. check.py의 blob을 그대로 유지하고 product.py만 고친 경우는 기준 실행 종료1, 대상 실행 종료0으로 통과했다. 검사 파일 blob·모드 고정이 조건 ID·문구의 동일성보다 강한 실제 제약임을 확인했다. 실제82개 상세 문서의 반복 sync/capture 후에도 기존 바이트가 모두 같았다.

이 문장이나 저장된 성공 결과는 게이트 입력으로 사용하지 않는다. 각 도구는 현재 기록 또는 실제 명령을 다시 검사한다.

## 남은 범위

이 작업은 기록·CLI·회귀 fixture를 검증한다. 전체 제품 테스트, 실제 Figma·브라우저·실기기·사용자 첨부·새 설치·원격 CI를 새로 실행하지 않는다. 부모 작업의 관찰과 별도로 보고한다. 원래 bundle이 없는 fork는 옛 기록의 구조·해시만 검사하며 당시 Git 객체 대조를 통과로 표시하지 않는다. 기록 설명의 진실성과 검사 조건의 충분함은 코드 검사만으로 증명되지 않는다.

문서 검수자가 범위 정정 전에 기존 `tests/test_native_layer_vocabulary.py`를 별도 Python 환경에서 실행한 부수 결과는9개 중7개 통과·2개 오류였다. 두 오류는 `PIL` 미설치로 예제를 import하지 못한 것이며 설치나 제품 코드는 변경하지 않았다. 이는 정식 전체 제품 검사도 과거 패치의 성공 증거도 아니고, 위41개 기록 도구 검사와도 별개다.
