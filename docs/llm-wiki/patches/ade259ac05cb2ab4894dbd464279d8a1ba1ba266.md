# 예약 앱의 정책·스타일·배포 소유권과 실제 실행 증거

## 문제와 계기

예약의 업무 값, 웹 스타일, 생성 입력과 배포 설정을 앱 그래프 및 역할별 검증에 연결해야 했다.

## 결과 동작

`ade259ac05cb2ab4894dbd464279d8a1ba1ba266`에서 예약 한도, 화면 토큰, SSR 서비스 문구, 수집 계획, 배포 포트 및 앱 역할을 각각 단일 원본에서 공급한다.

## 변경 파일과 인터페이스

`apps/little-hands/booking/policy.json`, `apps/little-hands/design/stylesheet.json`과 `apps/little-hands/config/deployment.json`이 실제 소비 경로에 연결된다. 앱 영역 파일과 사례의 연결은 `release/reviews/application.json`에서 확인한다.

## 설계 이유와 출처

이전 버전의 사용자 편집 그래프, 캡처 이미지 및 마이그레이션을 보존했다. 과거 원본 파일 키의 공개용 해시 변환은 원래 Git 바이트와 별도로 확인했다.

## 호환성·이관·복구

기본 한도와 외형을 유지한다. 설치된 기본 앱 CSS의 바이트가 이전과 일치하며 변경한 그래프로 다시 빌드하면 실제 브라우저와 서비스의 값이 바뀐다.

## 검증과 미검증

Django·Gunicorn과 일회성 PostgreSQL 인스턴스에서 서비스 테스트, 마이그레이션, 계정 역할, 권한 및 SSR 내보내기를 실행했다. Chromium에서 색·간격·화면 폭·입력 피드백을 관찰했다.

## 한계와 후속 개선

실제 배포 서버나 사용자 DB에는 쓰지 않았다. 이 장비의 PostgreSQL 16 실행과 Compose 설정 해석은 배포 이미지를 띄운 결과와 구분한다.
