# feat: keep the control journal when the result post never arrives

## 문제와 계기

기준 5dfc365a6ab9b7e27fed8a8b9d03e2cce9990225는 HTTP 재시작 확인 함수가 없어 `restart must keep the journal when result delivery fails`로 실패했다.

## 결과 동작

restart_delivery_report는 로컬 HTTP 제어 서버로 claim과 native-started를 보낸 뒤 결과 POST를 하지 않고 그 workspace의 runtime 메모리만 지운다. 디스크의 같은 operation은 uncertain으로 남고 단계는 queued, claimed, native-started, uncertain이다. operation id는 그대로다. 같은 mutation enqueue는 차단되고, 다른 세션의 poll은 operation을 다시 넘기지 않는다. 요청 파일은 하나다.

## 변경 파일과 인터페이스

tools/figma_control.py에 restart_delivery_report를 추가했다. docs/development-roadmap/RD-08-operation-lifecycle/tasks.md에 확인 범위를 적었다. tests/test_rd08_restart_delivery.py blob은 기준과 같다. 요청 스키마는 바꾸지 않았다.

## 설계 이유와 출처

RD-08은 서버 재시작과 결과 전달 실패 뒤에도 기록된 단계와 미확정 쓰기 차단이 유지되어야 한다. 그 근거는 프로세스 메모리가 아니라 기존 요청 파일이다. 전달되지 않은 결과를 성공으로 바꾸거나 같은 mutation을 자동 재실행하지 않는다.

## 호환성·이관·복구

기존 poll, native-started, uncertainty blocking은 유지된다. 이 함수는 호출자가 준비한 workspace에서 임시 서버를 열고 닫는다. 제품 serve 루프의 포트 설정은 테스트 workspace 안에서만 임시 포트로 바뀐다.

## 검증과 미검증

종료 게이트가 기준 5dfc365a6ab9b7e27fed8a8b9d03e2cce9990225의 종료 코드 1과 대상 4eab91b666eaeead1fe04395f248f936cdb51b7d의 종료 코드 0을 다시 실행했다. 같은 구현에서 제어 관련 unittest도 통과했다. 로컬 HTTP 서버는 실행했다. Figma Desktop을 열거나 플러그인을 Figma 안에서 다시 불러오지는 않았다.

## 한계와 후속 개선

이 확인은 로컬 제어 서버와 디스크 journal이다. Figma 프로세스 안의 플러그인 재실행은 아직 관찰하지 않았다. RD-03의 identity 분리는 다음 단위다.
