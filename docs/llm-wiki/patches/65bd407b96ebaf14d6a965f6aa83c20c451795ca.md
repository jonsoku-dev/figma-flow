# test: pin declared product button parents

## 문제와 계기

실제 R6 audit은 올바르게 선언한 Frame/Group/Auto Layout 안의 product button도 direct screen child가 아니라는 이유로 180개 실패로 분류했다. 정상 container 부모와 선언 부모를 건너뛰는 오배치를 구분할 oracle이 필요했다.

## 결과 동작

기존 direct-screen 부모와 선언대로의 nested frame/group/auto-layout은 허용한다. 즉시 부모 건너뜀, 같은 화면 sibling, foreign screen 아래 배치, type·Auto Layout 방향 차이는 invalid-real-product-button으로 계속 거절한다. 제품 audit 구현은 이 커밋에 없다.

## 변경 파일과 인터페이스

[finalize_product_button_parents.py](../../../tests/finalize_product_button_parents.py)를 추가했다. 기존 fixture로 합성 container ancestry를 만들고 실제 draft_foundation_audit.audit_draft_foundations에 전달한다. 실제 Figma capture 원본이 아니라 최소 node/semantic/parent 계약을 모델링한 입력이다.

## 설계 이유와 출처

소유 screen 직하만 정답으로 보지 않고 선언 즉시 부모와 screen까지의 조상을 엄격히 대조해야 한다. container 허용은 임의 조상이나 같은 screen 내 모든 배치를 허용하는 완화가 아니다. 올바른 main component/component set, 가시성, reactions도 독립 조건으로 유지한다.

## 호환성·이관·복구

11개 test method는 legacy direct 부모, 3종 정상 nested 부모와 negative subcase를 다룬다. wrong main, source main의 set형 차이, instance/ancestor hidden, reactions의 누락·비list·비empty를 거절한다. 기존 direct-screen 배치를 강제 이관하지 않는다.

## 검증과 미검증

Git diff에서 선언 즉시 부모와 foreign/sibling/type/방향 반례, main/set/visibility/reactions guards를 확인했다. 상위 세션의 미커밋 제품 audit 수정 후 R6는 부모 오탐 180개가 제거되고 실제 binding 부족 22개만 남았다. 이를 새 R7 native 성공이나 기준 커밋의 제품 통과로 바꾸지 않는다. 이번에는 실행하지 않았다.

## 한계와 후속 개선

합성 fixture의 audit은 실제 화면의 시각 품질이나 Figma 생성을 증명하지 않는다. 남은22 binding과 R7 native 실행은 별도이며 모든 실패가 false positive였다고 주장하지 않는다. 실제 ID나 raw readback은 싣지 않는다.
