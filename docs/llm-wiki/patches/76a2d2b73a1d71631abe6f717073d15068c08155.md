# test: give appended layout variants their declared properties

## 문제와 계기

Layout main을 component set에 추가할 때 mock이 이름에서 variantProperties를 만들지 않으면, 재실행 검사가 Visual drift로 실패한다. 그건 너비 공유 실패가 아니다.

## 결과 동작

oracle의 component set append가 `Visual=Primary` 같은 이름을 variantProperties로 읽는다. 제품 코드는 여전히 root 너비마다 main을 나누므로 `supported width uses must share one main`으로 실패한다. 이 커밋이 종료 게이트의 기준이다.

## 변경 파일과 인터페이스

바뀐 파일은 tests/semantic_component_reuse_oracle.cjs다. 부모는 f838d46167cc8078e755c579bc3340c85968f8aa다. `figma-bridge/semantic_components.js`는 포함하지 않는다.

## 설계 이유와 출처

Figma는 set에 들어간 variant 이름에서 variantProperties를 만든다. 검사 더블은 그 읽기만 맞추고, 공유 여부는 제품 코드가 결정하게 둔다.

## 호환성·이관·복구

기존 검사와 런타임 계약은 유지한다. 이 변경은 테스트 더블의 append 동작뿐이다.

## 검증과 미검증

게이트가 이 커밋의 oracle을 다시 실행해 AssertionError `supported width uses must share one main`, 종료 코드 1을 확인했다. 실제 Figma variantProperties getter는 관찰하지 않았다.
