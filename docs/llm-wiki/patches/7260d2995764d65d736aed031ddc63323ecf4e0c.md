# test: pin shared import labels before text properties

## 문제와 계기

일반 가져오기는 같은 버튼 문구를 하위 TEXT에 직접 썼다. 구현 전에 세 instance가 한 main을 공유하면서도 TEXT 속성 참조가 없는 상태를 검사로 고정해야 이후 diff가 기준을 바꿀 수 없다.

## 결과 동작

`tests/test_figma_bridge.py`가 화면 문구 `저장`·`취소`·`보내기`를 한 main에 두고, main label의 `componentPropertyReferences.characters`가 문자열이 아니면 실패한다. 같은 패킷 재실행의 ID·사용자 수정 보존과, 속성 API가 없을 때의 직접 쓰기도 같은 파일에 있다. 이 커밋의 제품 코드는 속성을 만들지 않는다.

## 변경 파일과 인터페이스

바뀐 파일은 `tests/test_figma_bridge.py` 하나다. 부모 3a3d68e64d178d1ca37c3ff275d97d41bc92274d 대비 147줄 추가·2줄 제거다. mock Plugin API에 `addComponentProperty`와 `setProperties`를 더했지만 `figma-bridge/code.js`는 호출하지 않는다.

## 설계 이유와 출처

종료 게이트는 검사 파일의 blob과 모드가 구현 전후에 같아야 한다. 그래서 실패하는 재현을 7260d2995764d65d736aed031ddc63323ecf4e0c에 먼저 두고, 가져오기 구현은 다음 커밋으로 나눴다. 표시 이름에서 key를 추측하지 않는 조건은 이 검사가 반환된 key의 부재로 실패하게 한다.

## 호환성·이관·복구

이 커밋은 플러그인 동작, 기존 페이지, node ID, pairing을 바꾸지 않는다. 이후 구현이 속성 API 부재 시 직접 쓰기로 돌아가도록 그 분기도 검사에 넣었다.

## 검증과 미검증

이 커밋만 실행하면 `tests.test_figma_bridge` 25개 중 해당 검사 하나가 `TEXT property reference missing`으로 실패한다. 종료 게이트가 그 AssertionError를 기준 종료 코드 1로 다시 실행했다. 실제 Figma는 이 커밋의 검증 범위가 아니다.

## 한계와 후속 개선

실패 재현은 mock Plugin API다. 너비 분류, variant 축, 실제 속성 패널은 이 기준에 없다. 구현은 1f80e5d9896e85afb865919aad7dad3572be932e에서 검사 파일을 유지한 채 이어진다.
