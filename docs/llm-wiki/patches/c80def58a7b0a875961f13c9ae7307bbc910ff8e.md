# test: preserve preflight and scoped selection contracts

## 문제와 계기

fixture의 새 auto-layout 부모, host 소유 선택 manifest, 게시 전 중복 task 거절과 기존 테스트 전제가 어긋났다.

## 결과 동작

컨테이너 fixture는 actions-parent를 포함한 5개를 기대한다. 선택 apply는 UI component_fields 직접 전달 대신 manifest/selected_ids를 요구하며 중복 registry key는 publish 시 ValueError와 current 불변성으로 검사한다.

## 변경 파일과 인터페이스

rd07 helper VM에 타이머를 제공하고 RD02 fixture, RD04 component/selective, workspace chat 테스트를 수정했다. graphSyncPlanForMessage가 graphTokenSync보다 앞선다는 검사도 유지한다.

변경 경로: [tests/helpers/rd07_bundle_kinds.cjs](../../../tests/helpers/rd07_bundle_kinds.cjs), [tests/test_rd02_layer_fixtures.py](../../../tests/test_rd02_layer_fixtures.py), [tests/test_rd04_component_fields.py](../../../tests/test_rd04_component_fields.py), [tests/test_rd04_selective_apply.py](../../../tests/test_rd04_selective_apply.py), [tests/test_workspace_chat.py](../../../tests/test_workspace_chat.py).

## 설계 이유와 출처

잘못된 catalogue를 게시한 뒤 send에서 막는 것보다 publication preflight에서 거절하고 기존 workspace를 보존하는 것이 경계다. 선택 신뢰의 원천은 host여야 하며 메시지에서 component field를 직접 commit해서는 안 된다.

## 호환성·이관·복구

제품 메시지나 게시 구현은 이 커밋에서 변경하지 않는다. rotated capability의 409 및 subprocess 미실행 검사도 남긴다. 후속 fbf83b3가 실제 상수명 GRAPH_SELECTION_MANIFEST로 기준 문자열을 정정한다.

## 검증과 미검증

Git diff에서 duplicate publication 전후 current 비교와 source-order assertion을 확인했다. 이는 oracle 정합성 작업이며 실제 admission·동기화 통과는 후속 제품 검증에서 확인해야 한다.

## 한계와 후속 개선

소스 문자열 검사는 악성 선택의 모든 경우나 실제 UI 상태를 검증하지 않는다. export bundle→실제 handler를 구동하는 통합 oracle과 함께 해석한다.
