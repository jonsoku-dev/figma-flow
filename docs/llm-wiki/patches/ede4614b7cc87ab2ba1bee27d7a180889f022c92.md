# docs: explain reproducible inspection of native Design value paths

## 문제와 계기

native value-path runner는 정확한 Design 문서·페이지와 service receipt를 받아야 한다. 절차가 문서에 없으면 호출자는 임시 값이나 잘못된 출력 경로를 추측할 수 있다.
## 결과 동작

Design 런타임 기록에 `native_value_paths.py prepare`와 `normalize` 절차를 추가했다. 준비된 plan은 exact file, page, plugin ID와 입력 service receipt를 고정하고, 정규화 결과는 API priority graph에 receipt evidence로 합친다.
## 변경 파일과 인터페이스

`docs/design-runtime-verification.md`에 CLI 예시, private output 폴더 규칙, manifest 등록, receipt 검토, 새 output 경로 사용 방법을 추가했다.
## 설계 이유와 출처

사용자가 지정한 scope와 앞선 service receipt에서만 route를 만들고, 공개 graph는 비식별 요약만 보존한다. API priority merge는 member ID로 중복 관측을 걸러낸다.
## 호환성·이관·복구

문서는 현재 로컬 작업공간에 새로운 private 출력 경로를 쓰도록 안내한다. Figma 실행이나 공개 게시를 자동화하지 않는다.
## 검증과 미검증

CLI 옵션과 `values.json` route contract를 대조했다. 문서 변경 자체는 별도 Figma 실행을 하지 않는다.
## 한계와 후속 개선

출력 결과의 실제 값은 사용자가 선택한 문서, 페이지, 현재 plugin API version과 receipt에 따라 달라진다. 안내 예시는 값을 고정된 런타임 사실로 만들지 않는다.
