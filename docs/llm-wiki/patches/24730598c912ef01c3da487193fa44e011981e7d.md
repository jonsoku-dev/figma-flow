# feat: record native start only from the claimed runtime

## 문제와 계기

기준 0664a3113792752d37096d12ee02aae08a488b2b는 명시적 native-started 전달이 없어 `native-started must be an explicit authenticated runtime event`로 실패했다.

## 결과 동작

note_native_started는 현재 claim의 id, claim, session, file, page, revision과 서버가 본 runtime이 모두 같을 때만 native-started를 한 번 덧붙인다. 상태는 claimed로 남고 성공으로 바뀌지 않는다. 다른 runtime, claim, client operation ID는 거절한다. lifecycle 필드가 없는 요청은 단계를 만들지 않는다. 플러그인은 runtime이 있을 때 실행 전에 /control/native-started로만 전달한다.

## 변경 파일과 인터페이스

tools/figma_control.py에 note_native_started와 /control/native-started를 추가했다. figma-bridge/workspace_control.js가 실행 전에 그 경로를 호출한다. docs/development-roadmap/RD-08-operation-lifecycle/tasks.md에 범위를 적었다. tests/test_rd08_native_started.py blob은 기준과 같다.

## 설계 이유와 출처

RD-08은 native-started를 인증된 runtime의 명시적 사건으로만 기록한다. claim이나 timeout으로 추정하지 않는다. 이 사건 자체는 완료 증거가 아니며 기존 result 검증은 그 뒤에 유지된다.

## 호환성·이관·복구

runtime이 없는 poll은 native-started를 보내지 않고 기존 실행으로 계속한다. 거절된 전달은 단계를 추가하지 않는다. 결과 payload와 readback 한도는 바꾸지 않았다.

## 검증과 미검증

종료 게이트가 기준 0664a3113792752d37096d12ee02aae08a488b2b의 종료 코드 1과 대상 24730598c912ef01c3da487193fa44e011981e7d의 종료 코드 0을 다시 실행했다. 같은 구현에서 journal, 전이 fixture, 기존 제어 검사 33개와 runtime poll 검사 2개도 통과했다. 실제 Figma 실행, 서버 재시작, 플러그인 재실행, 화면 단계 표시는 관찰하지 않았다.

## 한계와 후속 개선

이력 화면의 journal 조회와 legacy/unknown 구분은 아직이다. AC의 실제 표시는 통과로 기록하지 않는다.
