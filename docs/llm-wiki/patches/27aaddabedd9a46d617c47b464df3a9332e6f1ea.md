# 메이저 패키지를 위한 그래프 소유권과 하드코딩 검증

## 문제와 계기

주요 버전을 배포하려면 기능 그래프에 빠진 관계가 없고 제품 정책·화면 값이 독립된 상수로 복제되지 않았다는 근거가 있어야 한다.

## 결과 동작

`27aaddabedd9a46d617c47b464df3a9332e6f1ea`에서 ZIP에 들어가는 Git 파일을 소유 영역에 연결하고 검토 누락·불일치가 있으면 메이저 ZIP 생성을 막도록 했다. Codex 매니페스트와 등록 뷰·패널 토큰을 지정 원본에서 파생한다.

## 변경 파일과 인터페이스

`tools/major_release.py`와 `release/authority.json`이 후보 Git 배포 파일 및 증거를 대조한다. 기능 graph, 등록된 화면, 호스트 정책과 패널 시각 값은 각각 정본을 검증하고 패널을 깨끗한 트리에서 다시 빌드한다.

## 설계 이유와 출처

원본이 빠지면 권한표를 대체 값으로 만들지 않는다. 이전 버전 규약의 관계 표현은 실제 역할과 확인 가능한 근거에 따라 차단 또는 참고로 표시한다.

## 호환성·이관·복구

기존 작업·화면과 SSOT 식별자를 유지한다. 현재 제품 버전은 그대로 두고 미래 메이저 후보를 별도 검사한다. 자료·의존성 관련 기존 배포 검사도 유지한다.

## 검증과 미검증

저장소 테스트와 배포 후보 시뮬레이션에서 누락된 검토가 메이저 ZIP 생성을 차단하는지 확인한다. 독립 회귀 검사는 정책 부재와 실제 진입 거절을 대조한다. 구체적인 범위는 버전 대조표에 기록했다.

## 한계와 후속 개선

구조·경로 검사와 특정 파생본이 통과해도 미검토 영역의 하드코딩 부재를 보증할 수 없다. 해당 영역의 현재 소스와 실제 검증 결과가 있어야 메이저 자격을 다시 계산한다.
