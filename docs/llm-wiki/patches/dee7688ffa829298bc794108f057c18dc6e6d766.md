# feat: keep only the public runtime boundary symbols

## 문제와 계기

기준 b05f2c444105fa3cf261eabb6f79db5e2ec89675는 public_runtime_symbols가 없어 `runtime boundary must keep only its public symbols`로 실패했다. load_runtime_boundary_trace 설명은 전송이 아직 제자리라고 적혀 있었다.

## 결과 동작

public_runtime_symbols는 assemble_shared_runtime, bundle_task_kinds, controlExecute, controlRequest, load_runtime_boundary_trace, runtime_module_names, trusted_sources, workspaceControlTick을 반환한다. async function controlRequest는 figma-bridge/workspace_transport.js에만 있다. controlExecute와 workspaceControlTick은 figma-bridge/workspace_control.js에 남는다. tools/figma_workspace.py에는 예전 read_text 이어 붙이기와 Transport stays in place 문구가 없다.

## 변경 파일과 인터페이스

tools/figma_workspace.py에 public_runtime_symbols를 추가하고 load_runtime_boundary_trace 설명에서 옛 위치 문장을 뺐다. tests/test_rd07_public_symbols.py blob은 기준과 같다.

## 설계 이유와 출처

RD-07 작업 5는 구 경로를 지우고 필요한 공개 심볼만 남긴다. 전송 정의는 하나다. 도메인 검사는 control 모듈에 둔다.

## 호환성·이관·복구

함수 동작과 wire format은 바꾸지 않는다. 플러그인 버전은 0.26.3이다. 이중 runtime은 남기지 않는다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd07_public_symbols`를 기준 b05f2c444105fa3cf261eabb6f79db5e2ec89675에서 종료 코드 1, 대상 dee7688ffa829298bc794108f057c18dc6e6d766에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 assertion은 `runtime boundary must keep only its public symbols`다. 조건은 RD-07-REQ-04다. 같은 구현에서 assembly, trace, bundle kind 검사도 종료 코드 0이었다. 실제 Figma 플러그인 재로드는 하지 않았다.

## 한계와 후속 개선

이름 목록은 라이브 플러그인이 그 심볼만 노출한다는 관찰이 아니다. 고정 plugin을 다시 열어 runtime identity를 확인하는 일은 남아 있다.
