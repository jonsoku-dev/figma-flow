# feat: build editable native screens from measured web graphs and pinned assets

## 문제와 계기

Browser observations needed a bounded handoff into the existing native-edit plan. Free-form DOM or raster input would not preserve source hashes, screen selection, asset bytes, or a safe write boundary.

## 결과 동작

`tools/web_design_source.py` binds captured screen graphs and explicit local image files. `tools/web_design.py` validates supported geometry, SVG, colors and assets, pins the selected screen graph, and writes a new native-edit plan. `figma-bridge/web_design.js` creates editable frames and verifies actual readback.

## 변경 파일과 인터페이스

The feature extends `tools/native_edit.py` with `web-design` and connects the panel/plugin runtime. The output plan records graph ID, graph SHA, selected screens and viewport; optional previews are size-limited.

## 설계 이유와 출처

The pipeline separates browser observation, human-reviewed graph and native import. It embeds only local hash-pinned raster bytes, uses explicit supported nodes and preserves existing page content through owned-frame markers and rollback checks.

## 호환성·이관·복구

No existing graph plan is overwritten. Plans use new paths; image source paths must remain below the graph directory and match their SHA and format signature. Unsupported content remains reported rather than fetched.

## 검증과 미검증

The commit adds Python and Node checks for planning, supported input, images, actual native scene verification, component reuse and rollback. Later final readbacks confirm 1102 editable nodes across four templates, excluding VECTOR descendants; the four counts and visual limits are in [verification](../../editable-web-verification.md#native-imports).

## 한계와 후속 개선

Only tested element kinds, CSS properties, local raster formats and bounded frame geometry are supported. Pixel parity and arbitrary website conversion are not claimed.
