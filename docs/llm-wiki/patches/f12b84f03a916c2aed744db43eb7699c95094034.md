# feat: pin an HTML task input record and keep its summary safe

## 문제와 계기

기준 904175b5b8ed48f6c2a3bd5f8c23ed0066dfb3c2는 summarize_input_record가 없어 `html task input record must keep its hash and a safe summary`로 실패했다.

## 결과 동작

summarize_input_record는 schema가 figma-flow-input-effect-result-v3인 record의 canonical 바이트 sha256을 돌려준다. 요약 행은 ref, kind, status, source, 12자 digest다. 외부 주소는 query와 fragment를 빼고, 절대 경로와 /Users/는 파일 이름만 남긴다. 404, rejected, external-unverified는 present로 바뀌지 않는다. prepare에 input_record를 넘기면 그 바이트가 task artifact의 input-record.json이 되고 catalogue에는 artifact 이름과 sha256, input_summary가 붙는다. 요청 hash에 sha256이 들어가 같은 discover 인자라도 revision이 달라진다. input_record가 없으면 필드를 만들지 않고 기존 revision 계산을 유지한다.

## 변경 파일과 인터페이스

tools/input_effect.py에 summarize_input_record와 _safe_ref를 추가했다. tools/figma_workspace.py의 prepare가 선택적 input_record를 받아 private artifact로 복사한다. docs/development-roadmap/RD-05-asset-inventory/tasks.md에 범위를 적었다. tests/test_rd05_html_input_record.py blob은 기준과 같다. 새 CLI flag는 없다.

## 설계 이유와 출처

RD-05는 원시 record를 private artifact에 두고 UI 요약에는 상대 참조와 상태만 둔다. 목록을 연다고 외부 주소를 확인하지 않는다. hash가 바뀌면 다른 revision이 된다.

## 호환성·이관·복구

record가 없는 기존 prepare와 replay는 같은 인자를 유지한다. 잘못된 schema나 상태 값은 Invalid input record로 거절하고 기존 task를 쓰지 않는다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd05_html_input_record`를 기준 904175b5b8ed48f6c2a3bd5f8c23ed0066dfb3c2에서 종료 코드 1, 대상 f12b84f03a916c2aed744db43eb7699c95094034에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 마지막 assertion은 `html task input record must keep its hash and a safe summary`다. 조건은 RD-05-REQ-05다. 같은 구현에서 경로 검사와 figma workspace 23개 검사도 종료 코드 0이었다. 브라우저에서 사진과 서체가 로드되는지는 관찰하지 않았다.

## 한계와 후속 개선

요약은 catalogue에 있을 뿐 작업 목록 화면은 아직 그리지 않는다. freshness가 바뀐 뒤의 stale 표시는 다음 단위다. AC의 화면 관찰은 통과로 기록하지 않는다.
