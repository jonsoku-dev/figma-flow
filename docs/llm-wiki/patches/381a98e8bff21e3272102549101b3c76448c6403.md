# 다중 파일 작업 인덱스의 고정 재현

커밋 `381a98e8bff21e3272102549101b3c76448c6403`

## 문제와 계기

정상 파일 키 64개를 기록한 뒤 크기 제한으로 읽기가 실패했다. 가벼운 관측에서는 앞선 파일이 끝나면 뒤의 진행 작업도 idle로 보고할 수 있었다.

## 결과 동작

제품 writer로 만든 기록을 새 CLI 프로세스에서 읽고, 용량 제한에서 거절·교체·영수증·불확실한 쓰기의 처리 결과를 확인한다.

## 변경 파일과 인터페이스

tests/test_active_file_index.py는 실제 파일별 포인터, 요청과 영수증을 임시 개인 작업공간에 만든다. 포화 거절은 정상 CLI로 제출한다.

## 설계 이유와 출처

파일 수만 세지 않고 저장 바이트와 작업 ID, 옵션, 기한 및 종료 코드까지 대조한다. 현재 프로세스의 메모리를 공유하지 않는 재조회가 포함된다.

## 호환성·이관·복구

기존 단일 ID 포인터에서 새 파일 요청을 접수해도 원래 파일의 진행 작업을 조회할 수 있어야 한다.

## 검증과 미검증

수정 전 후보에서 큰 포인터 읽기, 65번째 전부 진행 중인 경우, 종료 기록 뒤의 진행 상태 보고에 대한 독립 재현이 실패했다.

## 한계와 후속 개선

cross-process 재조회는 로컬 제어 진입점의 계약을 검증한다. 실제 플러그인 연결은 동결된 후보로 따로 검사한다.
