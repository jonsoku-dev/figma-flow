# fix: keep callable-valued declarations out of automatic Design getter dispatch

## 문제와 계기

일부 SDK property signature는 값 대신 함수를 반환한다. 자동 property getter queue는 `UIAPI.onmessage`와 `CodegenAPI.refresh`를 일반 읽기 후보로 볼 수 있어 호출·직렬화로 잘못 처리될 위험이 있었다.
## 결과 동작

priority inventory는 function-valued property를 별도 feasibility로 분류한다. `--feasible-only` queue는 이 속성을 제외하고, probe는 해당 property를 실행 가능한 getter로 등록하지 않는다.
## 변경 파일과 인터페이스

`tools/api_priority.py`에 exact `FUNCTION_VALUED_PROPERTIES` map과 `function-valued-property` 분류를 추가했다. `tests/test_api_priority.py`는 두 멤버의 분류와 feasible queue 제외를 확인한다. `docs/api-priority.md`에는 경계를 설명한다.
## 설계 이유와 출처

함수 property는 단순한 값 getter와 의미가 다르다. 이름만으로 callback을 호출하지 않고, 함수 객체도 영수증에 저장하지 않는다. 분류는 exact owner/member에 한정한다.
## 호환성·이관·복구

Pinned Plugin API declaration은 그대로 두고, 실행 후보 정책에서만 해당 두 property를 제외한다. 다른 property의 readable/owned-write 분류와 API audit 분모는 유지한다.
## 검증과 미검증

`test_function_valued_properties_are_not_method_or_getter_candidates`는 `UIAPI.onmessage`와 `CodegenAPI.refresh`를 function-valued property로 분류하고, feasible queue에서 제외함을 검사한다. 이 변경은 함수의 호출 동작을 테스트하지 않는다.
## 한계와 후속 개선

정적 선언만으로 function property를 호출 가능한 기능으로 보증하지 않는다. 이번 map은 catalog에 알려진 두 함수값 property에 한정한다. 다른 함수 반환 property는 별도 검토가 필요하다.
