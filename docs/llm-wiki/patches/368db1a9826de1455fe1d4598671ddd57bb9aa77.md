# ci: add paths-only reference distribution guard workflow

## 문제와 계기

PR과 `main` 푸시마다 가드 단위 테스트, 외부 스킬 의존성 핀 검사, 추적 트리 및 `git archive` 배포 ZIP의 금지 경로 점검을 자동으로 재실행할 CI 워크플로가 필요했다.

## 결과 동작

`.github/workflows/reference-guard.yml`이 `push(main)`과 `pull_request`에서 Python 3.13으로 `tests.test_reference_distribution_guard`, `tools/skill_dependencies.py --check`, `tools/reference_distribution_guard.py --ref HEAD --format text`, `git archive` ZIP 대상 `--target-zip` 검사를 순차 실행한다.

## 변경 파일과 인터페이스

`.github/workflows/reference-guard.yml`을 신규 추가했으며 최소 읽기 권한(`contents: read`)과 커밋 고정된 `actions/checkout`, `actions/setup-python` 액션을 사용한다.

## 설계 이유와 출처

공개 GitHub Actions 환경에는 비공개 참고 ZIP이나 리터럴 목록을 올릴 수 없으므로, CI 스텝 이름에 `paths-only; no local reference lists`를 명시해 로컬 오프라인 참고 대조와 범위를 혼동하지 않도록 했다.

## 호환성·이관·복구

기존 워크플로(`patch-knowledge.yml` 등)를 변경하지 않으며 읽기 전용 검사만 수행한다. 실패 시 해당 PR 또는 브랜치의 금지 경로·임시 증거·의존성 핀 불일치를 정리해 복구한다.

## 검증과 미검증

로컬 합성 단위 테스트 12건과 `HEAD`/ZIP 스캔은 선행 커밋 통합 시 확인되었다. 그러나 GitHub Actions Linux 러너 최초 실행에서는 `tests.test_reference_distribution_guard`가 Git 기본 브랜치 명명 차이로 1건 실패해 이 커밋 시점의 원격 CI는 미통과(실패 관측)로 기록하며, 수정 후 통과는 `b9495234cdbc4547f083f5ee21cbd623c67a381f`에서 확인됐다.

## 한계와 후속 개선

CI 워크플로는 `paths-only` 검사만 수행하므로 실제 릴리스 ZIP 배포 전에는 관리자가 오프라인에서 `--reference-zip`과 `--reference-literals`를 함께 실행해야 한다.
