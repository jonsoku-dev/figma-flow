# feat: add SSoT scanner, setup continuity, and optional metrics

커밋 `375988904b40854a90adf8ef9c654beb4e6faa5c`

## 문제와 계기

여러 도구 스크립트에 호스트·포트·timeout·스키마 ID·한도·파일 권한(`0600`) 처리가 흩어져 있어 정본 일관성을 자동으로 감시할 필요가 있었고, 이미 연결을 마친 작업공간과 플러그인을 새 세션마다 다시 설정해야 하는 불편과 선택형 외부 관측·진단 경로 부재도 함께 해결해야 했다.

## 결과 동작

1. **SSoT 하드코딩 스캐너 및 정본 통합**: `tools/ssot_scan.py`가 Python·JS 전역의 호스트·포트·timeout·경로·한도·스키마 ID·`mirrors` 불일치를 검사하고, `tools/ssot-baseline.json` 기준선 `entries: {}`(0건)로 `tools/maintenance.py check`와 연동된다. 로컬 엔드포인트·스키마 ID·실행 한도·비공개 I/O는 각각 `tools/local_endpoint.py`, `tools/schema_ids.py`, `tools/runtime_limits.py`, `tools/private_io.py`에서 일원화한다.
2. **설정 연속성(Setup Continuity)**: `tools/workspace_registry.py`가 로컬 레지스트리(`~/.config/figma-flow/workspaces.json`, `0600`)에 작업공간 등록 상태를 보존하고, `tools/figma_control.py setup-status`로 한 번에 상태를 조회할 수 있다. `enable --refresh`는 동일 설정의 중복 refresh를 피하며 `tools/plugin_startup.py`와 `figma-bridge/workspace_control.js`는 실행 중 서버 확인 및 파일 전환·초기화 시 프로필 재로드를 보완한다.
3. **선택형 양방향 메트릭**: `tools/metrics/`와 `library/metrics/schema.json`이 기본 비활성(`NullRecorder`) 상태에서 PC별 설정에 따라 `http-json`, `otlp-http`, `jsonl-file`, `statsd-udp` 어댑터와 `pull-json`/`pull-prometheus` 엔드포인트, `figma_control.py metrics` CLI(`list-adapters`, `init`, `add-sink`, `test`, `snapshot`, `flush`, `doctor`, `watch`)를 제공한다.

## 설계 이유와 출처

정본 값을 `library/`와 단일 모듈로 모으고 스캐너 `mirrors` 검사로 JS·패널 사본 드리프트를 하드 실패로 막아 수동 동기화 누락을 차단했다. 메트릭은 기본 완전 비활성 및 장애 격리 원칙으로 설계해 외부 수집기가 꺼져 있거나 실패해도 Figma 제어 흐름을 방해하지 않는다.

## 호환성·이관·복구

기존 작업공간 `.figma-flow/` 설정과 `plugin.json` ID·포트 계약과 호환되며, `~/.config/figma-flow/workspaces.json` 레지스트리는 부재 시 자동 생성되고 메트릭 설정 역시 선택적 opt-in이므로 미설정 환경에서 기존 동작을 그대로 유지한다.

## 검증과 미검증
