# test: keep task identity apart from a control operation id

## 문제와 계기

준비된 task revision과 서버 operation id가 같은 권한인지 확인하지 않으면 이후 dependency가 실행 식별을 대체할 수 있다. 이 커밋 d2de8c2b7c390e259c0535a7ca32d6fea7e83661의 검사는 task_operation_boundary가 없어 `task identity must stay independent of the operation id`로 실패한다.

## 결과 동작

tests/test_rd03_identity_boundary.py는 함수가 없으면 위 문구로 끝난다. 함수가 있으면 task key는 discovery이고 revision 길이는 64, operation id 길이는 32이며 둘은 다르다. operation은 task key를 가리키지만 catalogue에 operation id가 task로 없고, status 조회 뒤 revision은 그대로다. dependency는 생기지 않고 요청 파일은 하나다.

## 변경 파일과 인터페이스

tests/test_rd03_identity_boundary.py만 추가했다. tools/figma_control.py는 이 커밋에서 바꾸지 않았다. 검사는 python3 -B -m unittest tests.test_rd03_identity_boundary로 실행한다.

## 설계 이유와 출처

RD-03 작업 1은 task·artifact identity와 RD-08 operation ID의 권한 경계가 독립적임을 확인한다. UI 통합은 그 다음이다.

## 호환성·이관·복구

이 커밋은 검사를 고정할 뿐 catalogue 스키마를 바꾸지 않는다. 기존 enqueue와 prepare는 그대로다.

## 검증과 미검증

로컬 unittest는 종료 코드 1이고 stderr의 마지막 assertion은 `task identity must stay independent of the operation id`다. 작업 목록 UI는 관찰하지 않았다.

## 한계와 후속 개선

실패 기준은 로컬 workspace다. 구현은 별도 커밋 9c2cec203451ff81f6a0e3f83787d28c2154efca에서 검사 blob을 유지한 채 추가한다. 명시적 edge는 아직 없다.
