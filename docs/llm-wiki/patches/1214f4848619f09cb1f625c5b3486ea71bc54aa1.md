# docs(roadmap): align P2 wave 1 contract with independent review

## 문제와 계기

다른 모델의 독립 계약 검토가 [b2c998d](b2c998d6f58d8deb59803db42069824d663ceb34.md)의 계약에서 세 문제를 찾았다. P0 baseline manifest schema에는 파일별 digest가 없어 그대로 쓰면 입력 digest 인수가 실패한다. baseline 회차에 ledger getter 수를 넣으면 진단 읽기가 시간 샘플에 섞이고 첫 읽기 속성 수가 호출 수로 오해된다. writer별 파일 소유와 법률 검토 비주장이 없었다.

## 결과 동작

커밋 `1214f4848619f09cb1f625c5b3486ea71bc54aa1`는 계약에 파일 소유 표(fixture: `examples/owned-production-workspace/**`, `tests/test_owned_production_workspace.py`, `tools/owned_production_workspace.py`; baseline: `tools/native_read_benchmark.py`와 전용 검사, NF-02 측정 부록; records: 그래프·검토서·README·계약·로드맵 검사·CHANGELOG·Wiki)와 비주장 목록을 추가했다. fixture는 새 manifest schema ID, 파일별 `path`·`layer`·`ownership`·`sharing_scope`·`retention`·`sha256`, 열기 전 거절 조건(A1–A8)을 정한다. baseline은 `readNativeSemantics-full`과 `readNativeSemantics-summary-default` 두 워크로드, 샘플 필드, 시간 샘플의 `getter_count: null`, 워크로드당 `content_sha256`이 같은 5건 이상, median·최소·최대 보고(B1–B9)를 정한다.

## 변경 파일과 인터페이스

`docs/next-roadmap/p2-wave1-acceptance.md`와 `docs/next-roadmap/capability-review.md`의 계약 링크 문장만 바꿨다. 그래프와 검사는 바뀌지 않았다.

## 설계 이유와 출처

근거는 `examples/owned-design-baseline/manifest.json`의 `files` 형태, `figma-bridge/native_semantic_read.js`의 `nativeReadGetterLedger`(첫 읽기 Proxy 기록)·`compareNativeReadProfiles`(네 번 읽기, 경과 필드 없음)·`requireFullNativeRead`, 그리고 fixture writer의 소유 경로 계획이다. 독립 검토 원문은 비공개 증거로 Git 밖에 있다.

## 호환성·이관·복구

문서만 바뀌었다. 두 노드 상태는 `in-progress`로 같다.
