# test: pin 0.33 carousel plugin-data keys and tabs readback wiring

## 문제와 계기

독립 검수에서 0.33 캐러셀 플러그인 데이터 키를 바꿔도 테스트 31개가 모두 통과하는 것을 확인했다. 홈이 tabs 읽기 결과를 저장하는 연결을 빼도 실패하는 테스트가 없었다.

## 결과 동작

캐러셀 테스트가 `figmaFlowCarouselKey`, `figmaFlowCarouselState`, `figma-flow-carousel-hotspot`, `figma-flow-carousel-side`의 실제 문자열을 확인한다. 홈 테스트는 `workspaceObserve`에 tabs 읽기 결과를 보내 실행 이력에 요약이 저장되는지 확인한다.

## 변경 파일과 인터페이스

`tests/test_web_design.cjs`와 `tests/test_workspace_host.cjs`를 바꿨다. 제품 코드는 그대로다.

## 설계 이유와 출처

상수끼리 비교하는 테스트는 이름 변경을 잡지 못한다. 그래서 이미 적용된 0.33 프레임의 문자열을 직접 고정했다.

## 호환성·이관·복구

테스트만 추가했다. 기존 테스트의 기대값은 바꾸지 않았다.

## 검증과 미검증

임시로 `groupKey`를 다른 이름으로 바꾸면 Node 테스트 하나가 실패했고, `workspaceObserve`의 tabs 분기를 지워도 하나가 실패했다. 원래 소스에서는 31개와 26개가 모두 통과했다.

## 한계와 후속 개선

자동 테스트는 실제 0.33 파일을 읽지 않는다. 별도로 0.33 캐러셀 작업을 현재 브리지로 다시 준비해 실제 Figma 파일을 읽었고, 네 상태 프레임과 상태별 드래그 영역 두 개, 타이머, 흐름 시작점이 모두 `current`였다.
