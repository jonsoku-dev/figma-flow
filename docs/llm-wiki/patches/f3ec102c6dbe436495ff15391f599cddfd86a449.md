# fix: track local CSS asset dependencies

## 문제와 계기

`ab1c820`의 고정된 기준은 HTML에서 직접 연결한 CSS 아래의 `@import`, `url()` 사진과 서체 변경을 freshness가 놓치는 문제를 재현했다. 기존 정규식 기반 HTML 참조 수집은 주석·스크립트 문자열과 실제 마크업을 구별하지 못했고 CSS 문법의 import·함수·인코딩도 추적하지 못했다. 근거는 첫 부모 `ab1c8200cd77e2c24a3e322ddde643d80b179239` 대비 9개 경로의 실제 diff다.
## 결과 동작

HTML 파서가 실제 `link`·`script`·`img`, inline style, `<style>` 내용을 분리한다. `tinycss2`가 선언된 CSS `url()`과 `@import` 참조를 읽고, 명시적 입력 root 안의 로컬 CSS import 및 CSS 자산을 재귀적으로 수집해 해시 소스에 포함한다. 존재하지 않는 참조도 `sha256: null` 소스로 남아 나중 생성 시 stale이 된다. 경로 탈출·절대 로컬 경로·percent 디코딩 뒤의 root 탈출·NUL·백슬래시·심볼릭 링크는 거부한다. 직접 연결된 stylesheet만 기존 레이아웃 fact 추출에도 사용하고, 입력 결과 스키마는 v3이 됐다.
## 변경 파일과 인터페이스

`tools/input_effect.py`의 `_HTMLAssets`, `_css_parser`, `_css_references`, `_relative_asset`, `html_channel`, `project`와 `freshness`가 수집·경로 판정·결과 생성을 담당한다. 선택 의존성 `tinycss2>=1.5.1,<2`를 `requirements-optional.txt`에 추가했다. `tests/test_input_effect_css_parser.py`는 HTML/CSS 파싱·중첩 import·인코딩·잘못된 경로·누락/생성/삭제·의존성 누락을 다룬다. `tests/test_regression_program_inputs.py`는 root 탈출 및 v1·v2 재생성 거절을 확인한다. 회귀 예제의 `html/css-assets/`는 기존 공유 사진·폰트를 CSS 경로로 연결하며, 폴더 README와 회귀 프로그램 README가 실행 위치와 한계를 설명한다.
## 설계 이유와 출처

브라우저 실행 없이 정적 입력의 파일 freshness를 기록해야 하므로 HTML 표면에는 표준 `HTMLParser`, CSS에는 선택 의존성 `tinycss2`를 사용한다. URL 탐색은 explicit root 밖으로 나가지 않으며 외부 origin은 `external-unverified`로 남긴다. 순환 import는 상대 경로와 상속된 encoding을 포함한 방문 집합으로 끝내고 중복 자산은 canonical 표현으로 합친다. 읽을 수 없는 CSS 의존성이 생기는 경우 tinycss2 설치 안내를 오류로 제공하되 HTML 입력이 없는 brief-only 투영은 계속 가능하다. 근거는 이전 oracle과 현재 함수 구현 및 해당 테스트다.
## 호환성·이관·복구

투영 결과 스키마가 v2에서 v3으로 바뀌므로 기존 v1·v2 기록은 `freshness()`에서 명확히 거절되며 투영을 다시 생성해야 한다. 기존 입력 경로와 `project()`/`freshness()` 호출 형식은 유지된다. CSS를 쓰는 환경에는 `requirements-optional.txt`의 선택 의존성을 설치한다. 공유 자산을 쓰는 예제는 `examples/regression-program`을 root로 지정해야 상대 경로가 root 안에서 해석된다. 오래된 결과 파일을 자동 변환하거나 덮어쓰지 않는다.
## 검증과 미검증

수정 당시 35개 focused CSS/입력 검사가 통과했고, 별도로 고정된 32개 회귀 입력 검사의 독립 subset도 통과했다. 개선 게이트는 변경하지 않은 `ab1c820` oracle로 baseline exit 1과 target 조건 2개 통과를 재실행했다. 별도 작업 기록에는 5개 독립 파일 변경과 10개 입력 소스의 stale 확인, 실제 회귀 페이지 4개 화면과 Figma 실제 getter 77개 노드·사진 4개·노트 8개 읽기 및 데스크톱/모바일 왕복이 남아 있다. 이들은 정적 검사와 별개인 당시 브라우저·Figma 관찰이며 이 커밋만으로 재현 가능한 공개 산출물은 아니다. 전체 테스트 스위트·원격 CI·새 설치를 이 CSS 수정이 통과했다고 주장하지 않는다.
## 한계와 후속 개선

추적은 정적으로 발견되는 같은 root의 로컬 HTML/CSS 의존성에 한정된다. CSS cascade 전체를 계산하지 않고, imported stylesheet는 신선도에는 포함하지만 직접 stylesheet 레이아웃 fact에 합치지 않는다. 외부 URL 내용, JavaScript가 만든 참조, 임의 HTML importer, 브라우저 렌더링 성공, Figma 웹 글꼴 바이너리 업로드는 검증하거나 제공하지 않는다. `tinycss2`는 CSS를 파싱하지만 브라우저 동작을 보증하지 않는다. 더 넓은 CSS 의미 분석은 별도 인수 기준과 독립 검증이 필요하다.
