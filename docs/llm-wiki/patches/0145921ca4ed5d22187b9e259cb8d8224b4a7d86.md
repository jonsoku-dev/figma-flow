# test: cover missing assets and fresh native reads

## 문제와 계기

정상 producer가 누락된 asset을 sha256:null로 명시해도 prepare가 이를 잘못된 hash로 거절했다. 알려진 부재와 위조 pin을 구분하는 admission 기준 및 요청마다 fresh native getter를 읽는 보조 회귀 근거가 필요했다.

## 결과 동작

누락 asset의 명시적 sha256:null과 계속된 부재는 current로 인정하고 public summary에는404를 유지하도록 요구한다. 파일이 생기면 stale, record를 다시 만들면 current여야 한다. 별도 reader matrix는14개 full/summary 쌍에서 변경된 tree/text/style/variable/raster/page/file을 새로 읽도록 검사한다.

## 변경 파일과 인터페이스

[missing-asset oracle](../../../tests/finalize_missing_asset_admission.py)의2개 테스트와 [freshness matrix](../../../tests/finalize_reader_freshness_matrix.cjs)를 추가했다. 실제 project→prepare→task_input_freshness 경로와 직접 readNativeSemantics 호출 경로를 각각 사용한다. 제품 구현을 수정하는 커밋은 아니다.

## 설계 이유와 출처

명시적 None은 알려진 부재이며 sha256 key 누락이나 존재 파일의 None과 같지 않다. reader matrix는 heavy/dependency API를 summary가 호출하지 않고 fields/omitted/complete=false를 정확히 보존하며, 모든 과거 snapshot이 그대로이고 nativeReadSessionSnapshot이null인지 확인한다.

## 호환성·이관·복구

잘못된 hash형·길이·hex, sha256 누락, root 밖 상대/절대경로, 누락 pin 경로의 symlink는 계속 거절한다. source bytes 변경도 admission을 막는다. reader의 scope는 caller가 제공하며 이 fixture가 fileKey 검증이나 현재 page 자동 발견을 대신하지 않는다.

## 검증과 미검증

상위 세션 최초 missing admission은2개 중1개가 기존 prepare hash 거절로 실패했다. 후속 제품 수정의50개 focused pass와 실제 canonical215 asset/215 UI 관측은 별도 근거다. matrix의14개 쌍 변경 검사는 fixture 통과이며 실제 Figma event/cache 통합 검증이 아니다. 이번 문서 작업은 Git diff만 대조했다.

## 한계와 후속 개선

동일 image hash의 byte 교체와 파일 간 동일 native ID 재사용은 합성 반례로 요청별 getter 읽기를 증명한다. 실제 이벤트 전달·캐시 무효화·유효 font bytes·브라우저 asset 사용이나 전체 native 생성을 증명하지 않는다. R8 실제 결과는 아직 미확정이다.
