# docs(nf02): define fresh-read baseline measurement contract

## 문제와 계기

`p2-read-performance-baseline`을 구현하기 전에 측정 workload, 시계, getter 정의, 기록 형태와 인수 조건을 NF-02에 고정해야 했다.

## 결과 동작

커밋 `8e3bb31a9f77a4dac72124f2556c532345c6188d`는 `docs/next-roadmap/NF-02-incremental-native-read.md`에 fresh-read 기준선 측정 부록을 추가했다. 측정은 선택 flag로만 동작하고, 기본 discovery 출력과 reader는 바뀌지 않는다고 정했다.

## 변경 파일과 인터페이스

`docs/next-roadmap/NF-02-incremental-native-read.md`만 바꿨다. 코드 인터페이스 변경은 없다.

## 설계 이유와 출처

[P2 1차 실행 계약](../../next-roadmap/p2-wave1-acceptance.md)의 B절과 [검토서 기준선 절](../../next-roadmap/capability-review.md#p2-performance-baseline)을 따른다. 구현보다 측정 정의를 먼저 고정해 수치가 다른 일을 재지 않게 했다.

## 호환성·이관·복구

NF-02 문서에 부록만 추가했다. 기존 NF-02 캐시 계약 문단과 코드 경로는 바뀌지 않는다.

## 검증과 미검증

문서 커밋이며 실행 근거는 없다. 부록 문장은 이후 러너 구현에 맞춰 [5d068b0](5d068b010d5fb53147a15913efbd458737eb8281.md)와 [a5e4a09](a5e4a098726872e9953e92da36065f4789f22811.md)에서 고쳤다.

## 한계와 후속 개선

부록은 측정 계약이며 측정 결과가 아니다.
