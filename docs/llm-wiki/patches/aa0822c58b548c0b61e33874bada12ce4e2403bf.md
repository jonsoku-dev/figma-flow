# test: require a server operation journal before lifecycle phases are shown

## 문제와 계기

서버가 발급한 operation ID와 단계 journal이 기존 요청 기록에 없었다. 이 커밋 aa0822c58b548c0b61e33874bada12ce4e2403bf의 검사는 lifecycle_version이 없어 `server lifecycle journal must be stored with the operation`으로 실패한다.

## 결과 동작

tests/test_rd08_operation_journal.py는 필드가 없으면 위 문구로 끝난다. 필드가 있으면 operation_id는 요청 id와 같고, 단계는 queued에서 claimed, result-received로 쌓인다. claim 전 timeout은 queued만 남고, claim 후 timeout은 uncertain을 더한다. 클라이언트가 보낸 operation ID는 거절된다. lifecycle 필드가 없는 요청은 단계를 만들지 않고, 깨진 lifecycle_version은 claim하지 않는다. 같은 scope discovery는 recovery_of로 원래 id를 가리키며 원래 영수증은 바꾸지 않는다. native-started는 없다.

## 변경 파일과 인터페이스

tests/test_rd08_operation_journal.py만 추가했다. tools/figma_control.py는 이 커밋에서 바꾸지 않았다. 검사는 python3 -B -m unittest tests.test_rd08_operation_journal로 실행한다.

## 설계 이유와 출처

RD-08 작업 2는 서버 operation ID와 additive phase journal을 기존 상태 저장에 통합한다. UI가 보낸 ID를 권한으로 믿지 않고, 저장된 사실 이상을 기존 요청에 추정하지 않는다.

## 호환성·이관·복구

이 커밋은 검사를 고정할 뿐 요청 스키마를 바꾸지 않는다. 기존 uncertainty blocking과 recovery_read 판정은 그대로다.

## 검증과 미검증

로컬 unittest는 종료 코드 1이고 stderr의 마지막 assertion은 `server lifecycle journal must be stored with the operation`이다. 실제 Figma 읽기와 화면 단계 표시는 관찰하지 않았다.

## 한계와 후속 개선

실패 기준은 합성 plugin 응답이다. 구현은 별도 커밋 4f451eec0b49366519297f878867b05aff0ff197에서 검사 blob을 유지한 채 추가한다. native-started 전달과 AC의 화면 표시는 통과로 기록하지 않는다.
