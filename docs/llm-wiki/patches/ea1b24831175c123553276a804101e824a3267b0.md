# feat: capture clicked tab panels through a local Chromium pipe

## 문제와 계기

관찰 JSON을 만들 사용자 명령이 없었다. 캐러셀 CLI는 Chromium 파이프 연결 코드를 혼자 갖고 있었다.

## 결과 동작

`tools/web_tabs_capture.mjs`는 `--click`을 순서대로 누르며 탭 중앙 hit test, 패널 변화, 스크롤 고정을 확인하고 상태별 화면과 PNG, 클릭 영수증을 남긴 뒤 `web-tabs`까지 실행한다. 진입 애니메이션이 끝날 때까지 기다린다. 캐러셀 CLI는 같은 `tools/chromium_pipe.mjs`를 쓴다.

## 변경 파일과 인터페이스

새 파일 `tools/chromium_pipe.mjs`(`chromiumBinary`, `withChromiumPage`, `until`)와 `tools/web_tabs_capture.mjs`를 추가했다. `tools/web_carousel_capture.mjs`에서 중복 연결·실행 코드를 지웠다.

## 설계 이유와 출처

첫 실측에서 상태 A가 히어로 진입 애니메이션 도중에 기록돼 로고 줄이 비었다. 그래서 유한 Web Animation이 끝날 때까지 기다리고 `--settle-ms`(기본 1500)를 둔다. 무한 반복 애니메이션은 기다리지 않는다.

## 호환성·이관·복구

캐러셀 CLI의 인자와 출력은 바뀌지 않았다. 실제 SaaS 페이지 재실행에서 상태 4개, 전이 12개가 같은 방식으로 나왔다.

## 검증과 미검증

실제 Devtool 홈(1440×900)에서 A→B→A 캡처가 성공했고 두 클릭 모두 hit test가 참이었다. 이전 SaaS 캐러셀 명령을 이관 후 다시 실행해 그래프 생성까지 확인했다.

## 한계와 후속 개선

로고 띠처럼 탭과 무관하게 계속 바뀌는 영역은 캡처 순간의 모습으로 남는다. 픽셀 동일성은 상태 판정에 쓰지 않는다.
