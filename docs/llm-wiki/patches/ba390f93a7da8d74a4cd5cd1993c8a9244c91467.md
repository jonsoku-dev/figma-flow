# test: pin native inline text allocation rounding

## 문제와 계기

실제 앱의 남은 TEXT–TEXT box overlap 두 건에서, 원본 할당은 서로 닿기만 하지만 native 단일 줄 너비·높이 ceil로 박스가 약 5.47% 겹치는 유형이 관찰되었다. 이 분류는 native box의 교차이며 실제 glyph ink가 겹쳤다는 판정과 구분한다.

## 결과 동작

새 정상 사례는 Hahmlet Bold의 45와 앞 공백이 있는 명을 사용한다. 원본 첫 너비 38.125가 native 39, 두 번째 너비 15.453125가 16, 높이 19.5가 20이 되더라도 원본은 첫 x=884.75의 오른쪽 922.875와 두 번째 x=922.875에서 정확히 닿는다. 정상 양자화만 허용하고 raw native 좌표·크기는 그대로 보존해야 한다는 oracle이다.

## 변경 파일과 인터페이스

[JS linebox oracle](../../../tests/finalize_linebox_rounding.cjs)에 textPairFixture와 두 테스트를, [Python linebox oracle](../../../tests/finalize_linebox_rounding.py)에 text_pair_fixture와 TextPairAllocationRoundingTests를 추가했다. JS는 기존 실제 validateDraftGeometry를 desktop/mobile API fixture에서 호출하고 Python은 native_screen_findings 및 authored design_quality.evaluate를 호출한다. 제품 소스는 변경하지 않았다.

## 설계 이유와 출처

단일 text/control의 높이 ceil에 이어 서로 다른 크기의 inline text 두 할당에도 같은 좁은 구분이 필요하다. source h=leading과 명시적 max_lines=1, 정확한 원본 x/y, native의 정확한 ceil 크기를 요구하는 기준이다. 넓은 overlap percentage 허용이나 일반 subpixel tolerance로 실제 충돌을 숨기려는 변경이 아니다.

## 호환성·이관·복구

기존 높이 정상 사례와 11개 negative guard는 수정하지 않고 뒤에 pair 사례를 추가했다. 새 16개 반례는 각각 첫/둘째 x·y drift, authored overlap, wrapped height, 첫/둘째 non-ceil width·height, h/leading 불일치, multiline 및 max_lines 부재를 거절하도록 요구한다. 제품 schema·폰트 자산·source layout은 이 커밋에서 바꾸지 않는다.

## 검증과 미검증

Git diff로 추가만 이루어졌음을 확인했다. 양 언어의 정상 pair는 raw geometry 불변성을 검사하고 16개 결함은 JS의 unexpected native overlap 또는 Python text-overlap으로 실패해야 한다. Python authored-quality는 원본이 닿는 정상 사례를 허용하지만 둘째 x를 1 옮겨 실제 source가 겹치면 거절한다. 상위 세션이 보고한 새 pair 정상 사례의 초기 실행은 의도한 red이며 이번 기록 작업은 정적 대조만 수행했다.

## 한계와 후속 개선

후속 pair 제품 수정은 아직 미커밋이고 실제 Figma runtime replay는 남아 있다. fixture의 박스 ceil은 glyph outline·폰트별 시각적 충돌·모든 텍스트 배치의 타당성을 증명하지 않는다. 기존 native 실패 전체가 false positive이거나 최종 native 생성·GUI 인수가 통과했다고 해석하지 않는다.
