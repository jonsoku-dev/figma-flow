# 8f2d51b · 연결된 다중 페이지 네이티브 검토

## 문제와 계기
여러 regression 앱은 준비됐지만 다중 페이지 간 연결을 포함한 native review 및 round-trip 계약이 부족했다.

## 결과 동작
Regression apps와 design system runtime/build가 확장되고 `lib/paint.js`가 공통 표시 처리를 보강한다. `figma_draft.py`와 `direction_review.js`는 다중 페이지 계약을 반영하고 graph contract 및 readable spec을 갱신한다.

## 변경 파일과 인터페이스
39개 파일: regression apps/design system, `figma-bridge/direction_review.js`, `tools/figma_draft.py`, graph contract 및 multipage/rendering/app 테스트. 새 `entry.js`/build/runtime가 fixture 실행 경로에 들어간다.

## 설계 이유와 출처
근거: 전체 커밋 `8f2d51b5a65d01a5e161a6158e4766934fc28ad0`; `test_multipage_native_contract.cjs`, `.py`, regression rendering tests, `examples/regression-program/lib/paint.js`. 페이지 간 연결을 별도 계약으로 다룬다.

## 호환성·이관·복구
예제 실행자는 신규 build/runtime 경로를 사용해야 한다. 실제 사용자 graph나 Figma 문서는 자동 변환하지 않는다.

## 검증과 미검증
multipage native, app, rendering 테스트가 추가/수정됐으나 실행 로그는 없다. 실제 Figma round-trip도 미검증이다.

## 한계와 후속 개선
커밋 제목의 “complete”는 검증 완료를 증명하지 않는다. fixture 범위 밖의 앱·상태는 별도 acceptance가 필요하다.
