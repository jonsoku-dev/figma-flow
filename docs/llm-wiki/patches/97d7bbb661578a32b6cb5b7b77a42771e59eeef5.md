# 첫 실행의 사용자 메타데이터와 기능 정책 그래프

## 문제와 계기

여러 팀에서 일하는 사용자가 한 기기에서 Design 제작과 개발자 인계에 쓸 환경을 파일별로 정할 수 있어야 했다. 일반 Plugin API로는 좌석이나 청구 권한을 자동 확인할 수 없다.

## 결과 동작

`97d7bbb661578a32b6cb5b7b77a42771e59eeef5`은 최초 실행에서 Figma가 관측한 정보와 사용자가 지정할 플랜·좌석을 나눠 보여준다. 모름으로 계속할 수 있으며 재실행과 설정 변경에 같은 로컬 기록을 사용한다.

## 변경 파일과 인터페이스

`library/figma-profile/policy.json`이 원천 필드·조건·기능·작업을 정의한다. `figma-bridge/profile_policy.js`와 `figma-bridge/workspace_profile.js`가 판정과 저장을 맡고, 호스트와 React 패널이 그 결과를 소비한다.

## 설계 이유와 출처

좌석 선언은 제작 요청을 제한하거나 인계를 안내하는 용도로만 사용한다. 실제 dev/inspect 맥락과 기존 파일·페이지·작업 검사는 선언과 별도로 확인한다. 고객의 디자인 그래프에는 사용자 프로필을 넣지 않는다.

## 호환성·이관·복구

발행된 Design manifest에 currentuser 권한을 추가한다. 동일한 개발 플러그인을 다시 열면 처음 한 번 설정한다. 이전 작업 목록·이력은 별도 저장 구조를 유지하며, 식별자나 로컬 저장소가 없는 환경에서는 세션 범위로 동작한다.

## 검증과 미검증

자동 검사는 계정·파일 격리, 저장소 실패, 플랜·좌석 조합, 동시 창의 작성 제한, 서명된 작업의 수동·자동 진입을 대조한다. 브라우저·Figma 앱의 검증 범위는 사용 가이드의 연결 문서에 기록한다.

## 한계와 후속 개선

로컬 선언은 관리자 권한이나 실시간 구독 확인 수단이 아니다. 제조번호·인증키·프로필 사진은 저장하지 않는다. 다른 ID의 파일럿에서 유료 좌석으로 실제 Inspect를 실행하는 검사는 별도다.
