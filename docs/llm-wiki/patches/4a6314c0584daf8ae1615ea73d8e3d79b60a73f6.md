# 4a6314c · 그래프 토큰을 Figma·웹 동기화 정본으로

이 기록은 원본 커밋 `4a6314c0584daf8ae1615ea73d8e3d79b60a73f6`의 실제 diff와 파일 경로를 기준으로 작성했다.

## 문제와 계기

디자인 시스템 값을 Figma와 웹에 각각 따로 유지하면 같은 컴포넌트 스타일이 어긋날 수 있었다. 기능 요구는 그래프의 design_system.tokens를 단일 정본으로 삼고, 제한된 컴포넌트 집합만 동기화하는 것이었다.

## 결과 동작

tools/graph_sync.py와 tools/graph_design_system.py, figma-bridge/graph_token_sync.js를 새로 추가해 그래프→Figma 쓰기/읽기 검증 및 웹 스타일 동기화 경로를 제공한다. examples/graph-ssot/README.md와 skills/graph-ssot/SKILL.md가 운영·복구 흐름을 안내한다.

## 변경 파일과 인터페이스

Graph sync CLI/함수는 graph schema의 design_system.tokens와 컴포넌트 참조를 입력으로 사용한다. 네이티브 브리지의 scoped sync와 tools의 apply/verify/import 작업이 경계다. 테스트 코드는 graph sync, design system, JS bridge 각각에 추가됐다.

## 설계 이유와 출처

토큰을 정본으로 두고 디자이너 직접 편집은 역수입 또는 충돌 검토를 거치게 하여 양방향 덮어쓰기 위험을 제한하려는 구조다. 실제 좁은 범위와 충돌 절차는 새 스킬/예제가 계약을 설명한다.

## 호환성·이관·복구

신규 graph-sync 절차는 기존 Figma 파일의 무조건 전체 변환을 뜻하지 않는다. 예제의 최초 이관·백업·실측 검증 단계를 따르고, 충돌 시 사용자가 고른 값만 정본으로 반영해야 한다.

## 검증과 미검증

세 테스트 파일 추가는 정적 커버리지이며 실행 성공 기록이 아니다. 실제 Figma·웹 프로젝트에 적용한 결과는 미검증이다.

## 한계와 후속 개선

구현 규모가 크며 현재 diff에서 확인되는 범위 밖 컴포넌트·스타일은 자동 동기화되지 않는다. 실제 Figma 문서 변경은 런타임과 사용자 승인에 달렸다.
