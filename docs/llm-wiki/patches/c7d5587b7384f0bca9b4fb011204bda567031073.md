# fix: verify previously imported typography against its canonical screen on read and reuse

## 문제와 계기

같은 그래프를 재적용할 때 오래된 importer가 처음부터 잘못 만든 스타일도 당시 scene fingerprint와 일치할 수 있었다. 이런 경우 정확한 원본과 비교하는 실제 getter가 필요했다.

## 결과 동작

자체 플러그인은 같은 그래프를 읽거나 재사용하기 전에 각 소유 레이블의 실제 폰트·크기·줄 높이·색·정렬을 정본과 대조한다. 잘못된 프레임은 그대로 보존하고 어떤 요소가 다른지 알려 준다.

## 변경 파일과 인터페이스

`figma-bridge/web_design.js`에서 글꼴 선택과 읽기 검증을 공유한다. `tests/test_web_design.cjs`에서 이전 버전 fingerprint와 원본 스타일 차이, 올바른 별칭·대체 글꼴을 검증했다. 정적 API 기준도 다시 생성했다.

## 설계 이유와 출처

같은 텍스트 스타일이라도 머신에 설치된 실제 글꼴 표기가 다를 수 있다. 새 프레임에서는 적용된 글꼴을 기록한다. 그 기록이 없는 프레임은 필요할 때 현재 가용 글꼴과 원래 선택 규칙으로 확인한다.

## 호환성·이관·복구

이전 fingerprint는 동일한 과거 형식으로 확인할 수 있다. 맞는 프레임은 재사용하고 이전 버전이 잘못 만든 프레임은 명시적 새 graph ID로 별도 생성할 수 있다. 기존 레이어를 대체하거나 삭제할 필요가 없다.

## 검증과 미검증

동일 파일·동일 프레임·동일 원본 그래프로 확인했다. 수정 전 가운데 버튼은 실제 20px, 원본은 24px였다. 읽기는 요소별 줄 높이 불일치를 보고하고 적용은 거절했다. 20/24/20px가 일치하는 이전 정상 프레임은 같은 ID 그대로 재사용했다. Node 웹 검증 9건이 통과했다.

## 한계와 후속 개선

이 동작은 명시한 화면의 지원 텍스트 필드와 컴포넌트 레이블에 적용된다. 외부 미디어나 CSS 마스크의 픽셀 동일성을 추정하지 않는다.
