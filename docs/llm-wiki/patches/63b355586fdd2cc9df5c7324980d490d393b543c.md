# fix(provision): prevent duplicate wrapper rollback and classify partial or unknown apply failures conservatively

## 문제와 계기

NF-01 첫 실기 적용이 중복 표시명 충돌로 실패했을 때, `figma-bridge/native_provision.js` wrapper가 core(`ensureSemanticComponents`)의 내부 롤백 뒤에 다시 보상 삭제를 시도해 중복 `.remove()` 진단을 남겼고 실패 결과를 지나치게 낙관적으로 분류할 위험이 있었다.

## 결과 동작

커밋 `63b355586fdd2cc9df5c7324980d490d393b543c`는 wrapper의 중복 보상 삭제를 없애고 `nativeFamilyReservedKeys`, `nativeFamilyObservePostFailure`, `nativeFamilyAttachFailureReceipt`를 추가했다. 실패 뒤 범위 내 페이지 상태를 관찰해 잔여 소유 노드나 root drift가 보이면 `partial`(`partial-owned-nodes-retained`), 확인할 수 없거나 core가 내부 롤백 미완을 보고하면 `unknown`으로 보수적으로 분류하고, 남은 노드는 손대지 않는다.

## 변경 파일과 인터페이스

`figma-bridge/native_provision.js`, `tests/test_family_provision_runtime.cjs`를 수정했다. 실패 오류 객체의 `readback.status`·`readback.mutation_state`·`rollback_conflicts` 분류가 바뀌었다.

## 설계 이유와 출처

롤백 책임을 core 한 곳에 두어 이중 삭제로 사용자 노드를 건드리는 위험을 막고, 관찰하지 못한 상태를 성공(rolled-back)으로 보고하지 않기 위함이다.

## 호환성·이관·복구

정상 적용 경로는 바뀌지 않는다. 실패 시 이전보다 `partial`/`unknown` 분류가 늘 수 있으며, 남은 노드는 사람이 확인 후 처리한다.

## 검증과 미검증

추가 테스트 `skips duplicate wrapper compensation on apply failure and conservatively classifies rolled-back, partial, and unknown outcomes`가 wrapper `remove()` 0회와 각 분류를 검사하며, P1 Node 집중 suite와 `e6f4fd8` CI에 포함돼 통과했다. 비공개 개선 gate(`437aa048` → `3e3f4e42`)의 base/target 묶음에 포함된 수정이며, 공개 재현 대응은 [974b5de 기록](974b5de74bc99d645926afd5595f21f155356203.md)에 정리했다.

## 한계와 후속 개선
