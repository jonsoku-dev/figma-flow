# test: pin scroll rail clipping for editable web frames

## 문제와 계기

실제 캡처로 만든 Design 프레임에서 scroll-snap 레일 밖의 인접 카드가 잘리지 않고 보였다. 브라우저 레일은 overflow-x: auto 같은 스크롤 값으로 내용을 자르는데, 캡처기는 hidden과 clip만 clipping으로 인정했다. 수정 전 실측 graph에서는 네 상태 모두 레일 프레임의 clipsContent가 false였다.

## 결과 동작

tests/test_web_design_capture_clipping.cjs를 추가했다. 이 테스트는 공개 캡처 스크립트 web_design_capture.js를 수정 없이 vm 문맥에서 실행하고, 레일 밖 인접 카드를 자식으로 가진 ul 레일을 검사한다. auto/hidden, scroll/auto, clip/hidden, hidden/clip이면 clipsContent가 true이고 인접 카드가 레일 자식으로 남아야 한다. visible/clip, clip/visible, visible/visible이면 false여야 한다. 이 커밋은 테스트만 추가하므로 커밋 시점의 트리에서는 실패하는 것이 정상이다.

## 변경 파일과 인터페이스

변경 경로는 `tests/test_web_design_capture_clipping.cjs`이다. 전체 경로와 diff 해시는 이 페이지의 Git 기록에 있다.

## 설계 이유와 출처

패치 기록 계약의 실패 기반 개선 절차에 따라 수정보다 실패하는 회귀를 먼저 커밋했다. 그래서 개선 전 실패와 개선 후 통과를 같은 검사로 다시 실행할 수 있다. 실제 계산 스타일을 판정하는 공개 경로를 그대로 부르므로 내부 구현이 바뀌어도 동작 기준은 유지된다. 인접 카드가 레일 자식으로 남는지도 확인해, clipping 수정이 요소를 버리는 회귀로 바뀌는 것을 막는다.

## 호환성·이관·복구

포크는 이 커밋과 부모의 변경 경로를 대조해 적용할 수 있다. 캐러셀 CMS나 외부 계정 연결은 필요하지 않다. 원본 화면과 사설 영수증은 로컬에 보존한다.

## 검증과 미검증

실측 영수증(clipping-red.log)에서 이 테스트는 'auto/hidden clips both axes' 단언의 false !== true로 실패했다. 2078ea9 이후 같은 테스트가 통과했고, 독립 gate가 이를 다시 실행했다. 자세한 내용은 2078ea9 항목에 있다. 브라우저 DOM이 아닌 최소 모의 객체 위의 테스트라서 실제 레이아웃 계산은 확인하지 못한다. 실제 결과는 별도 캡처와 Figma 화면으로 확인했다.

## 한계와 후속 개선

여기서 확인한 결과는 해당 입력과 검증 범위에 해당한다. 브라우저의 연속 스크롤 관성이나 물리 모바일 기기의 동작은 별도의 관찰이 필요하다.
