# test: set explicit initial branch and restore previous branch in guard test

## 문제와 계기

`976a966c1b497890aae12dd1a63b1dd6b05ee763`의 합성 단위 테스트가 `git init -q`의 호스트 기본 브랜치 이름에 의존해 `main`을 전제로 체크아웃하면서, 기본 브랜치가 `master`인 GitHub Actions Linux 러너에서 `reference-guard.yml` 워크플로가 실패했다.

## 결과 동작

합성 저장소 초기화 시 `git init -q -b main`으로 초기 브랜치를 `main`으로 명시하고, 임시 브랜치(`bad-manifest`) 검증 후 이전 브랜치 복귀를 `git checkout -q -`로 바꿨다.

## 변경 파일과 인터페이스

`tests/test_reference_distribution_guard.py`의 `ReferenceDistributionGuardTests.setUp` 및 `test_corrupt_pins_or_spoofed_acorn_provenance_fail_closed` 2개 줄을 수정했다. `tools/reference_distribution_guard.py` 구현이나 CLI 인터페이스는 변경하지 않았다.

## 설계 이유와 출처

호스트의 `init.defaultBranch` 설정에 무관하게 Linux CI와 macOS 로컬 환경 모두에서 동일한 브랜치 이름으로 결정적으로 테스트가 실행되도록 하기 위함이다.

## 호환성·이관·복구

테스트 픽스처 생성 방식만 수정하므로 기존 제품 동작·가드 규칙·`v0.35.0` 배포본에 영향이 없다.

## 검증과 미검증

이 수정 커밋(`b9495234cdbc4547f083f5ee21cbd623c67a381f`) 기준 원격 GitHub Actions `Reference distribution guard` 워크플로가 Linux 러너에서 통과(`success`)로 확인됐으며, 로컬 `tests.test_reference_distribution_guard` 12개 테스트도 통과를 직접 재확인했다. 선행 커밋 `368db1a9826de1455fe1d4598671ddd57bb9aa77` 시점의 실패는 과거 실패 기록으로 구분 유지한다. 브라우저·Figma 네이티브 실행은 범위 밖이다.

## 한계와 후속 개선

원격 워크플로는 여전히 `paths-only` 모드만 실행하므로 릴리스 배포 시 로컬 오프라인 `--reference-zip`·`--reference-literals` 검사를 별도로 수행해야 한다.
