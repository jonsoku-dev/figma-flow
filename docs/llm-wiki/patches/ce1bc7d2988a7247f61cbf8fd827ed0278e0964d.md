# Relay scoped read-only history details and preserve the direction of recorded relations

## 문제와 계기

컨트롤 서버가 정확한 범위 기반 상세 DTO를 제공하더라도 Figma 플러그인 브리지·호스트·전송 계층이 범위를 핀 고정해 중계하고 선후 관계 방향을 보존해야 패널에서 안전한 상세 조회와 뒤로가기 이동이 가능했다.

## 결과 동작

커밋 `ce1bc7d2988a7247f61cbf8fd827ed0278e0964d`는 `figma-bridge/workspace_control.js`, `figma-bridge/workspace_host.js`, `figma-bridge/workspace_transport.js`에 범위 고정 읽기 전용 `history-detail` 중계를 추가하고 기록된 선후 관계(predecessor/successor) 방향이 반전되지 않도록 보전하며 `tests/nf03_history_detail.cjs`를 추가했다.

## 변경 파일과 인터페이스

`figma-bridge/workspace_control.js`, `figma-bridge/workspace_host.js`, `figma-bridge/workspace_transport.js`, `tests/nf03_history_detail.cjs`(신규)를 수정·추가했다.

## 설계 이유와 출처

페이지 전환·태스크 변경 시 잘못된 범위의 상세가 잔존하지 않도록 전송 계층에서 범위 토큰을 대조하고, 역방향 관계 병합으로 인한 인과 왜곡을 막기 위해 방향성을 명시 보존했다.

## 호환성·이관·복구

기존 브리지 작업공간 제어 메시지와 하위 호환되며 상세 조회가 미지원인 오래된 호스트에서는 안전하게 거절 응답을 전파한다.

## 검증과 미검증

`node --test tests/nf03_history_detail.cjs`가 `7/7` 통과(및 `e6f4fd8` CI Run `43599181267` 포함)했으며, 실기 Figma Desktop 연동에서도 선행 artifact 링크 탐색과 페이지 변경 시 스테일 무효화 동작을 확인했다.

## 한계와 후속 개선

브리지 중계 자체의 검증이며 React 패널 렌더링과 키보드 복귀 경로는 후속 `016a777e` 커밋이 담당한다.
