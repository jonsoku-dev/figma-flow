# feat: measure full and summary native reads on one fixture

## 문제와 계기

기준 954a00c7cd0a0d7a61b7cc6cd63bfa66d83e0411는 compareNativeReadProfiles가 없어 `native read comparison must report measured bytes`로 실패했다. 같은 mock에서 요청 필드, getter, JSON 크기가 따로 적혀 있지 않았다.

## 결과 동작

compareNativeReadProfiles는 schema figma-flow-native-read-comparison-v1을 반환한다. 요청 필드는 일치한다. 이 mock fixture에서 summary getter는 8개로 page.id, page.loadAsync, page.findAll, rect.id, rect.parent, rect.type, rect.name, rect.width다. full getter는 19개이고 rect.fills를 포함한다. summary는 rect.fills를 포함하지 않는다. UTF-8 JSON은 full 13362바이트, summary 297바이트다. invalidation은 unmeasured다. wallClockMs는 없다.

## 변경 파일과 인터페이스

figma-bridge/native_semantic_read.js에 compareNativeReadProfiles와 utf8JsonBytes를 추가하고 module.exports에 넣었다. tests/rd06_read_comparison.cjs blob은 기준과 같다.

## 설계 이유와 출처

RD-06-AC-02는 getter 수가 요청 필드 범위만큼 줄어드는 것을 적고, 측정 전 wall-clock 개선율은 표시하지 않는다. 0.26.2의 9.16MB에서 0.68MB 사진 결과는 이 비교에 쓰지 않는다.

## 호환성·이관·복구

비교는 읽기 전용이다. 기존 full 호출과 summary profile은 유지한다. 플러그인 버전은 0.26.3이다.

## 검증과 미검증

종료 게이트는 `node tests/rd06_read_comparison.cjs`를 기준 954a00c7cd0a0d7a61b7cc6cd63bfa66d83e0411에서 종료 코드 1, 대상 b3285c42f1189f69ea52d1f7b65ccf71d594a842에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 assertion은 `native read comparison must report measured bytes`다. 조건은 RD-06-AC-02다. 같은 트리에서 fresh read와 summary coverage 검사도 종료 코드 0이었다. 바이트와 getter 수는 위 mock을 이 구현에서 읽어 적었다. 실제 Figma 문서의 지연과 전송 크기는 측정하지 않았다.

## 한계와 후속 개선

변경 무효화는 cache가 없어 unmeasured다. 이 13362바이트와 297바이트는 노드 하나의 mock이며 라이브 문서의 크기가 아니다.
