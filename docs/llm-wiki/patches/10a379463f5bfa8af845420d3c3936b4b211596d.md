# 10a3794 · 실제 Figma 텍스트 기하와 디자인 시스템 보존

이 기록은 원본 커밋 `10a379463f5bfa8af845420d3c3936b4b211596d`의 실제 diff와 파일 경로를 기준으로 작성했다.

## 문제와 계기

검토 초안에서 텍스트의 측정값과 실제 Figma 렌더링이 일치하는지, 가져오기·수정 과정이 기존 시스템 통제를 유지하는지 확인할 근거가 부족했다.

## 결과 동작

figma-bridge/direction_review.js에 대규모 네이티브 렌더링/기하 검증 경로를 추가하고 native_semantic_read.js 및 tools/draft_token_plan.py·draft_foundation_audit.py·design_quality.py를 보완했다. tests/test_native_render_geometry.py 등 정적 테스트 코드와 수동 Figma 비교 이미지도 추가됐다.

## 변경 파일과 인터페이스

검증 인터페이스는 direction_review의 렌더 geometry 흐름, draft_token_plan의 명시 토큰·바인딩, draft_foundation_audit의 foundation 점검, design_quality.py 및 관련 Python/Node 테스트다.

## 설계 이유와 출처

작성한 수치만으로 품질을 판단하지 않고 네이티브 Figma 읽기 결과와 비교하려는 방향이 변경 구조에 드러난다. 세부 설계 배경은 CHANGELOG·테스트 설명 이상의 것은 미상이다.

## 호환성·이관·복구

기존 워크플로·JSON 스키마 변화는 개별 검사 함수에 따라 다르며, 해당 diff만으로 전체 구버전 패키지 마이그레이션이 보장된다고 볼 수 없다.

## 검증과 미검증

테스트 파일은 입력/기대값에 대한 정적 커버리지의 증거일 뿐 실행 성공 증거가 아니다. 실제 Figma 문서 수정·렌더 확인은 미검증이며 이미지도 당시 캡처의 출처/실행 절차까지 확정하지 못한다.

## 한계와 후속 개선

대규모 추가로 실제 렌더와 추정 기하 간 오차·환경별 글꼴 차이가 한계다. 사용자 승인 없이 네이티브 문서 변경을 적용하지 않는 기존 단계는 유지해야 한다.
