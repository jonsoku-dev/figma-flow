# feat: let execution history read the server journal

## 문제와 계기

기준 c71aabb35f06b4ce860b36837be44d17b8bd2d6c는 이력이 서버 journal을 읽지 않아 `execution history must read the server journal`로 실패했다.

## 결과 동작

journal_history는 요청 파일의 phase와 time만 돌려주고 status의 journal 필드에 붙인다. 기록된 마지막 단계가 phase다. lifecycle이 없으면 classification은 legacy이고 phase는 unknown이다. 깨진 lifecycle은 classification unknown, operation_id 없음, phase unknown이다. error와 readback 경로는 포함하지 않는다. workspaceRecord는 journal이 전달된 경우에만 classification과 phase를 이력 항목에 넣는다.

## 변경 파일과 인터페이스

tools/figma_control.py에 journal_history를 추가하고 status가 그 결과를 journal로 돌려준다. figma-bridge/workspace_host.js의 workspaceJournalHistory와 workspaceRecord가 그 뷰를 이력에 붙인다. docs/development-roadmap/RD-08-operation-lifecycle/tasks.md에 범위를 적었다. tests/test_rd08_journal_history.py blob은 기준과 같다.

## 설계 이유와 출처

RD-08은 journal을 canonical로 두고 clientStorage를 표시 cache로 둔다. 없는 단계는 unknown이고, lifecycle 필드가 없는 요청은 legacy다. native-started는 저장된 사건이 있을 때만 이력에 나온다.

## 호환성·이관·복구

journal 인자가 없는 기존 workspaceRecord 호출은 이력 키를 바꾸지 않는다. status의 state와 uncertain_operations는 유지된다. 원문 readback은 이력 뷰에 복사하지 않는다.

## 검증과 미검증

종료 게이트가 기준 c71aabb35f06b4ce860b36837be44d17b8bd2d6c의 종료 코드 1과 대상 da3c7c51c4bc20733a5bf27278f9b459de1773ff의 종료 코드 0을 다시 실행했다. 같은 구현에서 제어 관련 unittest 34개와 workspace host, runtime poll 검사도 통과했다. 실제 화면 단계 표시, Figma 실행, 서버 재시작, 플러그인 재실행은 관찰하지 않았다.

## 한계와 후속 개선

이력 화면이 이 조회 결과를 사용자에게 보여주는 실제 관찰은 없다. 충돌 상세와 재실행 버튼 금지는 다음 단위다. AC의 화면 표시는 통과로 기록하지 않는다.
