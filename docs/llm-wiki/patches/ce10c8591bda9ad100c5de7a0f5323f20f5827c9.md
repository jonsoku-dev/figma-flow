# test: pin raster and interrupted review oracles

## 문제와 계기

네이티브 사진을 여러 노드에서 반복 읽으면 실제 이미지 바이트가 노드마다 복제되어 전송 크기 제한을 넘길 수 있었다. 검토 시안 생성이 중간에 실패한 뒤 같은 패킷을 재시도하면 기존 부분 페이지를 지나쳐 중복 페이지를 만들 위험도 있었다. 구현 전에 두 실패를 독립 오라클로 고정했다. 출처는 첫 부모 `f3ec102c6dbe436495ff15391f599cddfd86a449` 대비 테스트 두 파일의 실제 diff다.
## 결과 동작

첫 오라클은 표시된 동일 이미지의 반복 읽기를 1회로 하고, 행별 중복 대신 실제 이미지 해시를 키로 한 최상위 raster 테이블과 행 참조를 요구한다. 불필요한 이미지 노출 금지와 기존 동기화 바이트 한도도 확인한다. 두 번째 오라클은 같은 검토 패킷으로 이미 부분 생성된 페이지가 있으면 새 페이지 생성 전에 기존 페이지 ID가 포함된 복구 안내로 중단하고, 기존 페이지를 바꾸지 않아야 한다고 고정한다. 이 커밋은 테스트만 추가하며 두 실패가 실제 Node 실행에서 기준선으로 재현된다.
## 변경 파일과 인터페이스

`tests/native_raster_dedup_oracle.cjs`는 `readNativeSemantics()`를 실제 모듈에서 불러 14·56개의 표시 노드에서 실제 JPEG 바이트, `imageHash` 참조, 단일 읽기, 미표시 이미지 비노출, 2,000,000바이트 경계를 검사한다. `tests/partial_review_oracle.cjs`는 준비 도구가 만든 명세 prelude와 실제 `direction_review.js`를 VM에서 실행해 부분 페이지 충돌과 `createPage()` 미호출을 검사한다. 제품 코드·함수 서명·설정은 변경하지 않았다.
## 설계 이유와 출처

기능 변경을 기준 테스트와 분리해 개선 전 실패를 보존한다. 사진 검사는 저장소의 실제 JPEG를 사용하고 단순 모형의 바이트 길이를 실제 원본이라고 가정하지 않는다. 검토 복구 검사는 기존 semantic key와 소유 노트 보드가 있는 페이지를 사용해 재시도 동작을 관찰한다. 기록 근거는 두 테스트 코드 및 개선 게이트의 baseline 실행이다.
## 호환성·이관·복구

테스트 추가만으로 기존 플러그인이나 결과 데이터 형식은 바뀌지 않는다. 기준 상태에서는 두 오라클의 실패가 의도된 결과이므로 이 커밋만 단독으로 녹색 테스트 세트로 볼 수 없다. 후속 구현은 중복 생성 금지, 기존 페이지 ID 알림, 원본 이미지의 정확한 보존을 만족해야 한다. 기존 페이지나 사진을 삭제·정리하는 동작은 이 패치에 없다.
## 검증과 미검증

기준 커밋에서 이미지 중복 읽기/전송 단언과 부분 검토 중복 생성 단언이 각각 실제 Node 실행에서 실패했다. 이는 실패 기반 개선의 고정 입력이다. 이 테스트 전용 커밋 자체에서 기능 수정 후의 성공은 아직 검증되지 않았다. Figma Desktop, 원격 CI, 전체 제품 인수 결과도 이 커밋의 근거가 아니다.
## 한계와 후속 개선

두 오라클은 특정 네이티브 이미지 반복과 같은 패킷의 한 부분 생성 사례를 다룬다. 다중 페이지 그래프 탐색이 생성된 플러그인 코드에서 테이블을 전달하는지, 완료 메타데이터의 유효성, 실제 바이트와 전체 시안 복구는 다루지 않는다. 후속 개선과 추가 회귀 경로는 [0.26.2 변경](bd511d743a228b0a71ea4a0fc5e2a92e8c0920ff.md), [생성 탐색 기준](3932393cfd5cdb40edf38f0ecbc8f997cf7a9bbf.md), [생성 탐색 수정](e179df281a870086582ad25cf649931af5a8eaa2.md)에 있다.
