# 개발 변경 리포트의 역추적·오프라인 경계 보강

커밋 `f219eba38aab407a4c8da21695748db62cc8e17c`

## 문제와 계기

테스트 경로 변경에서 기존 증거가 가리키는 제품 경로를 추적하지 못했다. 정본·증거가 사라져도 성공 코드를 반환하는 경우가 있었고, 부분 클론에서는 Git 읽기가 객체 가져오기를 실행했다. 인덱스 및 리비전별 후보 표시에서도 예외를 재현했다.

## 결과 동작

기존 출시 검토 근거를 양방향으로 조회한다. 테스트 바이트가 달라졌거나 누락되면 영향을 받는 정확한 파일과 함께 검토 필요를 표시한다. 현재 증거가 깨졌을 때는 앞선 확인 가능한 리비전의 연결을 분석 후보로 남긴다. 객체가 로컬에 없으면 원격을 사용하지 않고 종료한다.

## 변경 파일과 인터페이스

`tools/development_changes.py`, `tools/development_witnesses.py`, `tools/graph_impact.py`와 개발 검증 문서를 갱신했다. 명령 옵션은 그대로 실행할 수 있으며 JSON의 `witnessDependents`와 `findings`가 새 근거를 제공한다. `tools/graph_governance.py`는 같은 로컬 Git 읽기 입구를 사용한다.

## 설계 이유와 출처

이미 등록된 파일별 검증 기록과 실제 테스트 해시를 읽는다. 충돌하거나 확인할 수 없는 증거가 현재의 판단으로 승격되지 않도록 한다. 기준·인덱스·작업 트리의 근거를 그 리비전 안에서만 읽고, 비교 전후의 인벤토리와 실제 사용한 작업 트리 바이트를 다시 대조한다.

## 호환성·이관·복구

추가 예정 인덱스 항목은 `intentToAdd`로 표시하고, 실제 스테이징한 빈 파일에는 기존 지문 형식이 남는다. 기존 읽기 명령과 Graph 정본은 계속 사용할 수 있다. 실제 Figma 플러그인 동기화는 같은 제품 경로에서 관리한다.

## 검증과 미검증

Astra Ultra가 임시 저장소에서 이전 실패 사례를 동일한 입력으로 다시 확인했고 관련 테스트 54개가 통과했다. 부분 클론의 자동 fetch와 팩 변경이 사라졌다. 손상된 증거, 정본 누락, 파일을 저장한 뒤 복원한 경우, Git 가시성 플래그 변경을 확인했다. 실제 리포트에서 패널 도구와 9단계 패널 집계를 통과했고, 기록된 테스트 경로 160개를 역조회했다. 기존 참고 자료 검출 3건은 기준과 후보에서 동일했으며 신규 검출은 없었다.

## 한계와 후속 개선

해시 일치는 테스트 바이트의 근거이며 실제 테스트 실행 결과는 따로 확인한다. 전체 기록에 없는 연결은 추론하지 않는다. 부분 클론에 로컬 객체가 없으면 외부 획득은 별도 승인된 작업에서 처리한다.
