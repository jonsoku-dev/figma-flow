# feat: record the getters used by one full native read

## 문제와 계기

기준 f943bc9f1f316f0f7c6624087e1bba2c1b6f45eb는 nativeReadGetterLedger가 없어 `full native read must record the getters it uses`로 실패했다.

## 결과 동작

nativeReadGetterLedger는 페이지와 자식을 Proxy로 감싼 뒤 기존 readNativeSemantics를 호출한다. 반환 schema는 figma-flow-native-read-ledger-v1이다. full은 그 reader의 전체 snapshot이고 getters는 처음 읽은 id.getter 이름이다. mock rect의 width와 fills가 기록되고 exportAsync는 없다. 같은 fixture의 두 번째 호출은 같은 목록을 낸다. readNativeSemantics(figma, page)는 그대로 full을 반환한다.

## 변경 파일과 인터페이스

figma-bridge/native_semantic_read.js에 nativeReadGetterLedger를 추가하고 module.exports에 넣었다. docs/development-roadmap/RD-06-native-read/tasks.md에 범위를 적었다. tests/rd06_full_getter_ledger.cjs blob은 기준과 같다.

## 설계 이유와 출처

RD-06은 요약과 full verifier를 다른 reader로 복제하지 않는다. 요약 전에 현재 full 호출이 만지는 getter를 같은 함수 위에서 기록한다.

## 호환성·이관·복구

기존 호출은 옵션 없이 full이다. ledger는 입력을 바꾸지 않고 결과만 감싼다. 기존 snapshot 필드는 유지한다.

## 검증과 미검증

종료 게이트는 `node tests/rd06_full_getter_ledger.cjs`를 기준 f943bc9f1f316f0f7c6624087e1bba2c1b6f45eb에서 종료 코드 1, 대상 9c9d5575eea6d883620407e591972c7e92cc244f에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 assertion은 `full native read must record the getters it uses`다. 조건은 RD-06-REQ-01이다. 같은 구현에서 raster·명세 native mock 검사도 종료 코드 0이었다. 실제 Figma 문서의 getter 수와 지연은 측정하지 않았다.

## 한계와 후속 개선

ledger는 mock 속성 접근이다. 요약 profile과 coverage는 아직이다. AC의 실측 속도는 통과로 기록하지 않는다.
