# Document the dependency graph and evidence requirements for the Design roadmap

## 문제와 계기

기존 `docs/next-roadmap/README.md`와 별도 제안 문서 사이에 중복 우선순위 표가 남아 있었고, `p0-reference-safety` 및 API 후보 분류의 선행 조건·수용 기준·포터블 링크 불변조건을 기계 판독 가능한 정본 그래프로 고정할 필요가 있었다.

## 결과 동작

`docs/next-roadmap/backlog.graph.json`(`schema: figma-flow-capability-backlog-v1`)을 단일 의존성·상태 정본으로 추가하고, `docs/next-roadmap/capability-review.md`의 각 절 앵커와 1:1로 연결했다. `docs/next-roadmap/README.md`는 `backlog.graph.json`과 `capability-review.md`를 유일한 시작점으로 가리키고 `next-ready` 판정(`status == "proposed"`이면서 모든 `depends-on` 선행 노드가 `accepted` 또는 `verified`)을 명시하며, `p0-api-queue-validation`은 `1,382`행/`825` 미관찰/`12` Design 후보(`design-api` 8, `design-node` 4)를 CLI 측정 근거로만 두고 제품 지원으로 승격하지 않는다.

## 변경 파일과 인터페이스

`docs/next-roadmap/README.md`, `docs/next-roadmap/backlog.graph.json`, `docs/next-roadmap/capability-review.md`, `tests/test_next_roadmap_backlog.py`를 추가·갱신했다. `tests/test_next_roadmap_backlog.py`는 스키마·비순환 DAG·`next-ready` 판정·부정 불변조건 5종(미충족 선행 의존성, 누락된 proof 경로, 공개 증거 없는 `verified`, `proposed` 노드의 `verified` 주장, 순환 의존성) 및 링크·앵커·포터블 금지 문자열 검사를 수행한다.

## 설계 이유와 출처

기능 제안과 실행 권한·런타임 인수를 분리하고, 중복된 우선순위 목록 대신 단일 그래프와 검증기로 상태 과장 및 깨진 참조를 사전에 차단하기 위해 작성했다.

## 호환성·이관·복구

기존 `NF-01`~`NF-09` 설계 문서와 `v0.35.0` 이전 역사 기록은 보존한다. 이 변경은 계획·검증 계약만 다루므로 기존 제품 코드나 Figma 플러그인 동작을 바꾸지 않는다.

## 검증과 미검증

로드맵+불변조건 검사 묶음이 통합됐으며 `tools/api_priority.py` CLI 수치(`1,382`행/`502` observed-graph/`825` 미관찰/`12` Design 후보, SHA-256 `4e5480245bf3779a7d39668698be65fd5d0974bee71b5ce9316eea0918c551a5`)와 일치함을 확인했다. 당시 시점에는 후속 `fixture`(`examples/owned-design-baseline/`)가 아직 통합되기 전이므로 `p0-reference-safety`는 `proposed` 상태로 유지됐다.

## 한계와 후속 개선

이 커밋 시점의 `p0-reference-safety` 노드는 `status=proposed`, `evidence_status=pending-independent-proof`였으며, `d98860037b4082b744a3ecd9fd7aae9ae2d729bf` 통합 후 `6c9c6e454d826347971d4f7e612abcd43b8a306b`에서 공개 인수 영수증과 함께 `verified`로 갱신됐다. P1·P2 항목은 제안 상태이며 구현·브라우저·Figma 런타임 인수를 포함하지 않는다.
