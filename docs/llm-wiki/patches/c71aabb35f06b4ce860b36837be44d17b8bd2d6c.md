# test: require execution history to read the server journal

## 문제와 계기

실행 이력이 서버 journal을 읽지 않으면 lifecycle이 없는 요청과 깨진 요청을 기록된 단계로 볼 수 있다. 이 커밋 c71aabb35f06b4ce860b36837be44d17b8bd2d6c의 검사는 journal_history가 없어 `execution history must read the server journal`로 실패한다.

## 결과 동작

tests/test_rd08_journal_history.py는 함수가 없으면 위 문구로 끝난다. 함수가 있으면 claim 뒤 이력은 queued와 claimed만 보여 주고, readback과 오류 문장은 빠진다. lifecycle 필드가 없으면 classification은 legacy이고 phase는 unknown이다. lifecycle_version이 1이 아니면 classification은 unknown이고 operation_id는 비운다. native-started는 추정하지 않는다.

## 변경 파일과 인터페이스

tests/test_rd08_journal_history.py만 추가했다. tools/figma_control.py와 figma-bridge/workspace_host.js는 이 커밋에서 바꾸지 않았다. 검사는 python3 -B -m unittest tests.test_rd08_journal_history로 실행한다.

## 설계 이유와 출처

RD-08 작업 4는 실행 이력에 서버 journal 조회를 연결하고 legacy와 unknown을 구분한다. clientStorage는 표시 cache이며 단계의 근거가 아니다.

## 호환성·이관·복구

이 커밋은 검사를 고정할 뿐 이력 키를 바꾸지 않는다. 기존 status 상태 값은 그대로다.

## 검증과 미검증

로컬 unittest는 종료 코드 1이고 stderr의 마지막 assertion은 `execution history must read the server journal`이다. 실제 화면 단계 표시는 관찰하지 않았다.

## 한계와 후속 개선

실패 기준은 합성 요청이다. 구현은 별도 커밋 da3c7c51c4bc20733a5bf27278f9b459de1773ff에서 검사 blob을 유지한 채 추가한다. 화면 표시는 통과로 기록하지 않는다.
