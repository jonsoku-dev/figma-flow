# feat: compile measured carousel states into pinned Design plans

## 문제와 계기

0.32.2까지 웹 가져오기는 한 시점의 화면만 정본 graph로 만들었다. 스와이프와 자동재생을 가진 캐러셀은 여러 상태와 전이로 이루어진다. 그런데 브라우저에서 관찰한 상태 순서, 첫·끝 경계 동작, 자동재생 간격, 증거 스크린샷을 담을 정본 형식이 없었다. 그래서 Design 프로토타입으로 옮길 근거가 남지 않았다. CSS 클래스나 라이브러리 이름으로 동작을 추정하면 실제 브라우저와 다른 전이를 만들 위험도 있었다.

## 결과 동작

`native_edit.py web-carousel`이 추가되었다. 이 명령은 기존 WEB 화면 graph와 관찰 JSON(schemaVersion 1, source·carousel·states·transitions)을 결합해 `carousel` 필드가 있는 새 정본 graph를 쓰고 `compiled-not-applied` 영수증을 낸다. 검증기가 확인하는 조건은 상태 2~16개, 상태·입력별 결정적 간선 하나, 수동·자동재생 wrap의 별도 선언, 1000~60000 ms 간격, 각 화면 viewport 안의 레일 경계다. 증거 PNG는 SHA-256, 개별·합계 8 MB 한도, 상대 경로, 심볼릭 링크 금지를 확인한다. `web-design` 서명 계획은 carousel을 그대로 고정하고 모든 상태 화면을 포함해야 하며, 계획 검증 때 증거 핀을 다시 확인한다. 입력 형식은 docs/web-carousel-input.md에, 1×1 자리표시자를 쓴 합성 fixture는 tests/fixtures/web_carousel_synthetic에 있다.

## 변경 파일과 인터페이스

변경 경로는 `docs/web-carousel-input.md`, `tests/fixtures/web_carousel_synthetic/README.md`, `tests/fixtures/web_carousel_synthetic/capture.png`, `tests/fixtures/web_carousel_synthetic/observations.json`, `tests/fixtures/web_carousel_synthetic/screens.json`, `tests/fixtures/web_carousel_synthetic/transition.png`, `tests/test_web_design.py`이다. 전체 경로와 diff 해시는 이 페이지의 Git 기록에 있다.

## 설계 이유와 출처

graph에는 브라우저에서 관찰한 사실만 넣고 빠진 관찰을 채우지 않는다. 그래서 관찰 간선(`observed: true`, 스크린샷 필수)과 유도 간선(증거 금지)을 구분했다. 출력은 덮어쓰지 않고 관찰 디렉터리 안에만 써서 상대 증거 경로가 계속 유효하다. 계획 서명은 graph 해시와 carousel 내용을 함께 묶어, 계획 단계에서 간선을 바꾸거나 상태 화면을 빼는 변경을 막는다. 두 명령 모두 표준 라이브러리만 쓰고 브라우저나 Figma를 호출하지 않으므로 컴파일과 Figma 쓰기 권한이 분리된다. 입력은 하이픈·밑줄 입력 이름과 `wrap` 객체·`manualWrap`/`wrapAutoplay` 평면 필드를 모두 받아, 문서 형식과 캡처 도구 출력을 함께 수용한다.

## 호환성·이관·복구

포크는 이 커밋과 부모의 변경 경로를 대조해 적용할 수 있다. 캐러셀 CMS나 외부 계정 연결은 필요하지 않다. 원본 화면과 사설 영수증은 로컬에 보존한다.

## 검증과 미검증

커밋이 추가한 Python 테스트 8개는 정확한 계획 고정, 4개 화면 결합, fixture로 두 공개 명령 실행, 잘못된 타입·중복 상태·심볼릭 링크 거부를 확인한다. 증거 교체 탐지와 출력 불변, 모호하거나 모순된 전이 거부, 서명 계획의 간선 변경·상태 누락 거부도 다룬다. 실측 영수증에서 커밋 시점 web_design Python 테스트 16개가 통과했다. Chrome 157(390×844, DPR 1)로 캡처한 4개 상태 입력은 여러 차례 컴파일되어 매번 상태 4개·전이 12개의 `compiled-not-applied` 결과를 냈다. 합성 fixture는 형식 예시일 뿐 실제 브라우저 동작의 증거가 아니다. 현재 검증기는 상태가 순서대로 이어지는 단일 레일만 받는다.

## 한계와 후속 개선

여기서 확인한 결과는 해당 입력과 검증 범위에 해당한다. 브라우저의 연속 스크롤 관성이나 물리 모바일 기기의 동작은 별도의 관찰이 필요하다.
