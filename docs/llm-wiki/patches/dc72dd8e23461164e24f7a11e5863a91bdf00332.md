# test: pin component reference readback before extending the bridge

## 문제와 계기

네이티브 의미 읽기는 component property definitions와 child component property references 같은 getter-backed 자료를 보존해야 한다. summary/profile 요청은 기본적으로 범위를 줄이지만 해당 필드를 무심히 생략하거나 mutable getter 결과를 공유하면 다음 bridge 작업의 readback 기준이 약해진다. 이 커밋은 기존 계약을 고정하는 독립 Node 테스트를 추가한다.

## 결과 동작

테스트는 full read에서 definitions와 references 값이 관찰되고 summary가 이 두 getter를 실행하지 않는지 확인한다. unsupported node와 getter 예외는 각 node 및 receipt의 `unavailable_fields`/`unavailableFields`로 분류한다. 같은 getter의 후속 읽기는 최신 값을 반환하며 앞선 receipt는 이전 복사본을 유지한다. summary에서 component property getter를 명시 요청하면 full read fallback을 사용한다.

## 변경 파일과 인터페이스

첫 부모 `068eb35374c2ec5f6f86efad6cefe7c316fa0740` 대비 `tests/test_native_component_properties.cjs`만 추가됐다. 검증 대상은 `figma-bridge/native_semantic_read.js`의 `readNativeSemantics`와 `nativeReadGetterLedger`; 제품 API나 실행 경로는 변경하지 않는다.

## 설계 이유와 출처

가짜 Figma node는 property maps를 API getter로 제공하고 getter 호출 수를 기록한다. 이는 값의 presence뿐 아니라 profile이 getter를 실제로 생략했는지, snapshot이 mutable native map을 분리했는지도 확인한다. summary의 component property 요청이 full fallback으로 가는 기존 정책을 명시적으로 지킨다.

## 호환성·이관·복구

추가된 파일은 테스트 전용이며 데이터·플러그인 설정 변경이 없다. 테스트를 되돌려도 제품 behavior는 바뀌지 않지만 다음 native read 확장 전 이 기준을 다시 마련해야 한다.

## 검증과 미검증

현재 checkout에서 `node --test tests/test_native_component_properties.cjs` 실행 결과는 1 test pass다. 이 테스트는 mocked API getters에서 실제 호출·복사·fallback behavior를 검증한다. 실제 Figma file, account permission, native runtime readback은 수행하거나 보장하지 않는다.

## 한계와 후속 개선

fixture는 지원되지 않는 getter와 동시 변경을 결정적으로 흉내 낸다. 모든 node type별 실제 Figma property availability나 native API 버전 차이를 증명하지 않는다. 제품 bridge를 확장할 때 실제 API 계약과 이 fixture를 함께 검토한다.
