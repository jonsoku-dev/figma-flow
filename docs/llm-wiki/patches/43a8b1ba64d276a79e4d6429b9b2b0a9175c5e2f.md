# fix: require disclosure states to be reachable from initialState

## 문제와 계기

이 커밋은 disclosure 상태마다 초기 상태에서 실제 경로가 있는지 Python 컴파일러와 Figma 브리지 양쪽에서 검사한다.

## 결과 동작

각 전이의 출발 상태에서 목적 상태로 가는 목록을 만들고, 초기 상태에서 연결된 간선을 따라 방문한다.

## 변경 파일과 인터페이스

방문한 상태 수가 선언된 상태 수와 다르면 disclosure 계약을 거부한다. 서로 연결된 cycle만 있고 초기 상태에서 닿지 않는 상태는 통과할 수 없다. 관련 변경: `figma-bridge/web_design.js`, `library/figma-api/coverage-baseline.json`, `tools/web_design.py`.

## 설계 이유와 출처

수정은 사용자가 관측한 `open`, `close`, `switch` 간선의 의미와 hotspot 배치를 바꾸지 않는다. 모든 간선은 여전히 관측된 클릭이어야 한다.

## 호환성·이관·복구

기존에 관측된 유효 그래프와 Figma 계획은 그대로다. 시작 상태에서 갈 수 없는 상태가 있는 입력만 두 진입점에서 거절한다.

## 검증과 미검증

고정 검사 066830a의 기대 실패와 이 구현의 성공을 같은 파일로 재실행했다. Python 24건과 플러그인·호스트 Node 62건이 통과했다. Node 최초 실행은 격리 폴더에 esbuild가 없어 한 건 실패했고, 같은 의존성을 제공해 다시 검사했다.

## 한계와 후속 개선

로컬 재생 보고서는 수정 후보의 관측 그래프와 계획이 네이티브 인수 기준과 같음을 기록한다. 실제 FAQ 캡처의 범위는 세 상태, 여섯 전이, 다섯 질문 중 두 질문으로 제한된다.
