# fix: retain raster tables in generated discovery

## 문제와 계기

`3932393`의 실제 생성 번들 oracle은 직접 readback에 추가했던 해시별 raster table이 Python이 생성한 graph discovery 코드에서는 전파되지 않는다는 것을 고정했다. discovery 결과는 여러 허용 페이지의 노드를 모으지만 사진 원본 바이트를 잃으면 이후 native handoff가 검증 불가능하다. 이 커밋은 생성기 양쪽에서 공용 병합 동작을 재사용해 경로 차이를 없앤다. 근거는 첫 부모 `3932393cfd5cdb40edf38f0ecbc8f997cf7a9bbf` 대비 4개 파일의 실제 diff다.
## 결과 동작

공유 `mergeNativeRasterImages()`가 페이지별 raster table을 합치고, 같은 hash가 다른 encoded bytes를 가리키면 중단한다. 직접 multi-page readback과 생성된 graph discovery가 같은 병합 규칙을 쓴다. Python discovery bundle은 결과에 최상위 `rasterImages`를 만들고 실제 native read에서 받은 테이블을 누적한다. table의 원본 바이트를 두 경로 모두 보존하며 row 단위 inline 복제를 만들지 않는다.
## 변경 파일과 인터페이스

`figma-bridge/native_semantic_read.js`에 `mergeNativeRasterImages(target, source)`를 추가해 Node 모듈 export와 플러그인 컨텍스트에서 공유한다. `figma-bridge/code.js`의 multi-page `readback()`은 helper를 호출한다. `tools/graph_sync.py`가 생성하는 `discoverGraphNative()`도 결과 table을 초기화하고 page read마다 helper로 병합한다. `tests/test_native_raster_table.cjs`는 직접 경로의 동일/충돌 table과 Python으로 실제 생성한 discovery 코드를 실행해 동일 해시 중복과 충돌을 검증한다.
## 설계 이유와 출처

한 번 구현된 byte merge 규칙을 두 consumer에 공유해 한 경로에서만 충돌 보호가 빠지는 일을 막는다. 검증은 source 템플릿이 아닌 실제 `discovery_bundle()` 출력 JS를 실행하고 여러 페이지의 같은 hash와 의도적 바이트 불일치를 함께 검사한다. 근거는 고정 discovery oracle 및 현재 helper/export, bundle generator, 실행 테스트다.
## 호환성·이관·복구

기존 readback의 inline `rasterImageBytes`를 직접 다시 받는 호환 경로는 유지되며, 이전 행 결과도 Python 검증기가 계속 지원한다. 새로운 table/reference는 실제 `IMAGE` paint와 원본 자산 hash를 대조한 뒤 기존 검증으로 전달된다. 생성된 discovery의 결과 형식만 table을 보존하도록 확장되며, 기존 Figma 원본 노드나 사용자 수정은 쓰지 않는다. 서로 다른 바이트가 같은 image hash 아래 나오면 데이터를 합치지 않고 오류로 중단한다.
## 검증과 미검증

현재 source 기준 Python 1,072개 중 1,070개 통과·2개 skip, Node 224개 중 223개 통과·1개 skip, demo 2개 통과가 기록됐다. 관련 generated-discovery 개선 gate는 base `3932393`에서 동일 oracle의 실패를 확인하고 target `e179`에서 통과를 확인했다. 실제 byte 저장량 비교(1/6/14 반복 이미지 참조에서 raw JSON 0.94705→0.484869MB, 4.105712→0.560531MB, 9.157631→0.679650MB)는 각각 약 48.8%, 86.35%, 92.58% 감소했으며 각 trial의 노드·table SHA가 맞고 이미지 항목은 photo 1개와 참조 2개였다. 실행 순서가 교차되지 않아 시간 개선은 주장하지 않는다.

별도 실제 native 자료는 3페이지, 노드 75·95·127개, 사진 4·24·56개와 페이지당 노트 8개를 보존하고 desktop/mobile 정상 handoff를 확인했다. wire format을 제외한 기존 native 값은 유지됐다. 14개 사진 작업은 불확실한 중단 상태와 빠진 주석 8개를 발견해 기존 native edit로 그 8개 명세만 복구했고 사진 56개의 node ID와 바이트를 보존했다. 이전 receipt는 수정하지 않았으며 최종 page ownership/flow completion metadata도 복원하지 않았다. 해당 14개 사양 검증 기록과 관찰은 실제 파일을 바꾸는 커밋 테스트나 전체 현재 verifier를 대신하지 않는다.
## 한계와 후속 개선

여러 이미지 반복 수는 전송 크기 비교이지 wall-clock 속도 보증이 아니다. hash table은 bytes를 실제로 대조하고 동일 hash의 불일치는 막지만 Figma 상태 전체의 출처 인증은 아니다. 부분 생성 예약은 commit-marker 안전 장치다. 정확한 current wrappers와 노트 보드 전체는 정상 verifier가 확인해야 하며, 누락 annotation 복구가 최종 ownership/flow metadata나 오래된 receipt를 복원하지 않는다. 자동 재개·cleanup·delete는 없다. 0.26.2 후보 네이티브 실행 기록은 있지만 공개 게시·전역 설치는 완료되지 않았고 global install은 0.26.1이다. fresh normal 0.26.2 smoke와 최신 guard run은 상위 통합에서 확인해야 한다.
