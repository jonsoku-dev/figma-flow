# test: pin bounded production readback capacity

## 문제와 계기

실제 R6 full readback은 compact JSON 29,991,516 bytes, escaped request envelope 33,417,636 bytes여서 옛 request 상한으로 정상 근거를 보낼 수 없었다. 무제한으로 풀지 않고 raw32 MiB/request40 MiB를 정확히 검사할 기준이 필요했다.

## 결과 동작

JS transport 7개와 실제 private HTTP server 5개 oracle을 추가했다. 사례 크기의 JSON, raw 정확히32 MiB, envelope 정확히40 MiB는 수용하고 UTF-8 초과는 fetch/저장 전에 거절한다. response16 MiB와 15초 timeout은 유지한다. 제품 소스는 바꾸지 않았다.

## 변경 파일과 인터페이스

[JS capacity oracle](../../../tests/finalize_control_capacity.cjs)은 실제 workspace_transport를 VM에서 호출한다. [Python HTTP oracle](../../../tests/finalize_control_capacity.py)은 실제 ThreadingHTTPServer/Handler와 private workspace에서 enqueue→poll claim→result→readback 저장을 통과한다. 합성 JSON의 byte 길이와 저장 SHA를 검사한다.

## 설계 이유와 출처

raw JSON과 JSON string으로 escape된 envelope의 용량은 다르다. 다중 byte 한글/emoji fixture로 문자 수만 검사하지 못하게 하고 32/40 경계를 각각 고정한다. 저장 byte/SHA와 status=ok도 확인하여 전송 성공만으로 완료하지 않는다.

## 호환성·이관·복구

초과 raw의 workspace snapshot 불변, Content-Length 초과의 body 읽기 전 413, exact claim/session/file/page/revision, Bearer/Origin/Host/route 거절을 유지한다. response16 MiB, readiness64 KiB, 15초 timeout 계약은 확장 대상이 아니다. Python은 POSIX private workspace를 전제한다.

## 검증과 미검증

상위 세션 기준 실행은 최초 Python5개/JS7개가 red였고 미커밋 제품 수정 후 pass였다. 수동 UI에서 얻은 R6 full getter 근거와 이후 실제 discovery 18,723,263 bytes/10.8초 수용은 별도 관측이며 합성 JSON 기준 결과로 대체하지 않는다. 이번 작업은 Git diff 정적 대조만 했다.

## 한계와 후속 개선

API fetch와 로컬 HTTP는 live Figma 전체 성공이 아니다. request의 제한된 용량을 검사하는 기준이며 모든 환경의 대용량 성능이나 R7 native 인수는 미검증이다. 실제 ID·token·원본 JSON은 Wiki에 싣지 않는다.
