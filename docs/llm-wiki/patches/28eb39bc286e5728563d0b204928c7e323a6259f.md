# docs: publish the verified typography setup and current API totals

## 문제와 계기

The typography recipe had an actual editor result, but the guide still presented rank positions and generator details rather than the steps needed to run it and the current observed API totals.

## 결과 동작

The documentation now explains how to generate a private typography graph, initialize and build a scoped SDK plugin, run it in the chosen Design file, and check the native result. The guide records 150 observed and 1232 remaining API members for 0.30.0.

## 변경 파일과 인터페이스

This docs-only commit updates `docs/design-type-review.md` and the API evidence paragraph in `docs/guide.md`. The recipe code, graph template, manifest, and generated bundle do not change.

## 설계 이유와 출처

Keep exact source IDs and member records in local graph inputs, then use the existing SDK project workflow to build the scoped plugin. The public guide exposes outcomes and commands without exposing private file or node identifiers.

## 호환성·이관·복구

Users select their own destination file and page. Existing recipe entries remain registered as before. The generated local graph and project stay under user-chosen private output paths.

## 검증과 미검증

The editor result reported one reusable main component with four editable text layers, actual typography style readback, and stable main/child identity on repeat. The selection graph contains 19 exact member IDs; 10 are net new, bringing the observed set to 150 of 1382. The stable-clone full suite passed 1215 Python, 323 Node, 75 finalize, 18 design, and 2 demo tests with zero skips.

## 한계와 후속 개선

The typography specimen is a bounded Design lab, not evidence that all API members or every font family work. GeistSans alias requests resolved to Geist styles and receipts retain the family rename notice. Private file and node identifiers remain omitted.
