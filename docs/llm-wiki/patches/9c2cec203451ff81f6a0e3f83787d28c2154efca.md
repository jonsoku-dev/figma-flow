# feat: keep prepared task identity apart from control operation ids

## 문제와 계기

기준 d2de8c2b7c390e259c0535a7ca32d6fea7e83661는 task identity와 operation id의 경계를 확인하는 함수가 없어 `task identity must stay independent of the operation id`로 실패했다.

## 결과 동작

task_operation_boundary는 discovery task를 enqueue한 뒤 catalogue와 journal을 다시 읽는다. revision은 64자이고 operation id는 32자이며 서로 다르다. operation의 key는 task key다. catalogue에는 operation id가 task로 없고 revision은 바뀌지 않는다. depends_on은 생기지 않는다. 요청 파일은 하나다.

## 변경 파일과 인터페이스

tools/figma_control.py에 task_operation_boundary를 추가했다. docs/development-roadmap/RD-03-task-dependencies/tasks.md에 확인 범위를 적었다. tests/test_rd03_identity_boundary.py blob은 기준과 같다. dependency 필드와 UI는 추가하지 않았다.

## 설계 이유와 출처

RD-03 설계서는 영속 operation ID와 task dependency key를 별개로 둔다. 실행의 request와 제작 산출물의 uses-output은 다른 관계다. 이 단위는 그 경계를 실행으로 고정한다.

## 호환성·이관·복구

기존 prepare와 enqueue는 유지된다. status 조회는 task revision을 바꾸지 않는다. 새 edge는 아직 저장하지 않는다.

## 검증과 미검증

종료 게이트가 기준 d2de8c2b7c390e259c0535a7ca32d6fea7e83661의 종료 코드 1과 대상 9c2cec203451ff81f6a0e3f83787d28c2154efca의 종료 코드 0을 다시 실행했다. 같은 구현에서 제어 관련 unittest도 통과했다. 작업 목록 UI와 Figma 패널은 관찰하지 않았다.

## 한계와 후속 개선

선택적 dependency 입력과 DAG 검사는 아직이다. AC의 화면 표시는 통과로 기록하지 않는다.
