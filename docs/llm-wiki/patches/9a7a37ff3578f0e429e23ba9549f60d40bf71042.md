# 9a7a37f · 기존 검토 페이지를 로드한 뒤 탐색

## 문제와 계기
Figma 페이지는 lazy-load될 수 있어 기존 검토 페이지를 찾은 직후 하위 노드 geometry를 검사하면 미로드 상태의 결과를 볼 수 있었다.

## 결과 동작
`figma-bridge/direction_review.js`의 `makeDraft()`가 소유 태그로 기존 페이지를 찾으면 `await page.loadAsync()` 후 geometry 검사와 현재 페이지 전환을 수행한다. 새 페이지 생성 경로는 유지된다.

## 변경 파일과 인터페이스
`direction_review.js`와 `tests/test_direction_native_limits.cjs`. packet 형식이나 명령 인터페이스는 바뀌지 않는다.

## 설계 이유와 출처
근거: 전체 커밋 `9a7a37ff3578f0e429e23ba9549f60d40bf71042`; `makeDraft`, `validateDraftGeometry`, native limits 테스트. 검사 전에 대상 페이지를 로드하는 순서 보정이다.

## 호환성·이관·복구
기존 draft 재사용 시 비동기 load 단계만 추가된다. 로드 실패는 생성 진행 대신 오류로 종료된다. 이관 작업 없음.

## 검증과 미검증
native limits 테스트가 37줄 확장됐다. 실행 결과와 실제 Figma lazy-load 확인은 미검증이다.

## 한계와 후속 개선
정적 테스트는 Figma의 실제 페이지 로딩과 geometry를 증명하지 않는다.
