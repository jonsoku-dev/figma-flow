# 실제 HTTP 수신과 펼침 조작을 검사 기준에 고정

## 문제와 계기

클라이언트의 경로 선택과 정적인 HTML만으로는 호스트 저장 결과와 사용자가 내용을 펼칠 수 있는지 확인할 수 없었다.

## 결과 동작

기준 커밋 `5a1c20bd56951111194253efa143f5df5765f396`에서 읽기 결과의 수신·저장·재전달, 쓰기 결과 거절, 브라우저의 펼침과 실제 표시 순서를 검사한다.

## 변경 파일과 인터페이스

`tests/test_booking_relay_regression.py`는 임시 로컬 작업공간에서 서명한 요청을 보낸다. `tests/test_booking_handoff_regressions.py`는 summary 클릭 전후의 너비와 내용 순서를 읽는다.

## 설계 이유와 출처

서버 메서드의 구현 이름에 의존하지 않고 실제 HTTP 응답과 저장한 바이트, 화면에 남은 텍스트를 검증한다.

## 호환성·이관·복구

이 단계의 파일은 구현 diff에서 보존한 검사 기준이다. 릴레이 및 생성기 수정은 별도의 후속 커밋에 들어간다.

## 검증과 미검증

초기 소스와 동일한 제품 코드에서 세 실패를 재현하고 후속 소스와 같은 검사 파일을 사용하도록 Git에 고정했다.

## 한계와 후속 개선

서버 검사의 입력은 실제 페이지와 비슷한 크기의 생성 자료다. 유료 계정이나 Dev Mode 실행의 근거는 아니다.
