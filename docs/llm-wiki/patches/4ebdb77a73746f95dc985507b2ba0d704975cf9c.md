# feat: refresh declared hug, fill, and fixed sizing after text growth

## 문제와 계기

기준 c7a4dfffb39aaa26eca0f6571a3bf0af97762822는 긴 한글 문구와 부모 resize 뒤 hug, fill, fixed를 다시 계산하는 함수가 없어 `declared hug fill and fixed sizing must follow text and parent resize`로 실패했다.

## 결과 동작

refreshDeclaredContainerSizing은 hug 축을 자식의 현재 상자 끝으로 다시 맞춘다. fixed 축은 배치 때 containerFixedWidth 또는 containerFixedHeight로 기록한 값을 유지한다. fill 축은 부모 Frame의 현재 크기를 따른다. 긴 한글 문구와 instance의 type, main id는 바꾸지 않는다. 화면 Frame의 ID와 clip도 유지된다.

## 변경 파일과 인터페이스

figma-bridge/direction_review.js의 배치 경로가 fixed 크기를 plugin data에 기록하고 refreshDeclaredContainerSizing을 추가했다. docs/development-roadmap/RD-02-layer-structure/tasks.md에 지원 범위를 적었다. tests/rd02_container_sizing_oracle.cjs blob은 기준과 같다.

## 설계 이유와 출처

RD-02는 선형 컨테이너의 hug, fill, fixed만 먼저 다룬다. 새 글꼴 측정 엔진은 넣지 않는다. Auto Layout 자식은 화면 기준 좌표를 지키려고 absolute로 남아 있고, 이 함수가 그 상자로 컨테이너 크기만 갱신한다.

## 호환성·이관·복구

containers가 없으면 이 함수를 호출하지 않는다. 갱신은 컨테이너 크기와 sizing mode만 바꾸고 leaf 좌표와 instance main id는 건드리지 않는다.

## 검증과 미검증

종료 게이트가 기준 c7a4dfffb39aaa26eca0f6571a3bf0af97762822의 종료 코드 1과 대상 4ebdb77a73746f95dc985507b2ba0d704975cf9c의 종료 코드 0을 다시 실행했다. 실제 글꼴 측정, Figma auto-layout reflow, prototype 왕복은 관찰하지 않았다.

## 한계와 후속 개선

mock은 호출자가 준 상자를 사용한다. 실제 글리프 너비와 Figma가 absolute 자식을 hug에서 제외하는 동작은 확인하지 않았다. AC-03은 통과로 기록하지 않는다.
