# feat: reject a partial native read as full evidence

## 문제와 계기

기준 ab8b1fe594b960fb2b22936dff34e3b7e711ff21는 requireFullNativeRead가 없어 `full consumers must reject a partial native read`로 실패했다. 요약 profile이 전체 근거로 저장될 수 있었다.

## 결과 동작

requireFullNativeRead는 schema figma-flow-native-read-summary-v1이거나 coverage.complete가 false이면 `partial native read cannot be stored as full evidence`로 거절한다. 인자 없는 full snapshot은 그대로 반환한다. figma-bridge/code.js의 readback, figma-bridge/native_edit.js, figma-bridge/direction_review.js의 컨테이너 읽기와 readDraft, tools/graph_sync.py의 discovery가 그 함수를 통과한 읽기만 저장한다. 요약 버튼은 partial을 패널에 그대로 보낸다.

## 변경 파일과 인터페이스

figma-bridge/native_semantic_read.js에 requireFullNativeRead를 추가하고 module.exports에 넣었다. 위 네 소비자가 호출한다. tests/test_direction_native_limits.cjs, tests/test_native_edit.cjs, tests/test_native_raster_table.cjs는 분리 실행 샌드박스에 그 함수를 넣었다. tests/rd06_reject_partial.cjs blob은 기준과 같다.

## 설계 이유와 출처

RD-06은 partial을 full schema로 조용히 줄여 전달하지 않고, 쓰기 전 근거는 full read를 유지한다. 요약 UI는 별도 결과로 남긴다.

## 호환성·이관·복구

기존 full 호출의 인자는 그대로다. summary가 아닌 기존 stub은 schema와 complete false가 없으면 통과한다. 플러그인 버전은 0.26.3이다.

## 검증과 미검증

종료 게이트는 `node tests/rd06_reject_partial.cjs`를 기준 ab8b1fe594b960fb2b22936dff34e3b7e711ff21에서 종료 코드 1, 대상 af2a027d7bebe176de697878f3b36d191ef35fe9에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 assertion은 `full consumers must reject a partial native read`다. 조건은 RD-06-REQ-05다. 그 실행은 같은 두 커밋의 깨끗한 clone에서 했다. 당시 작업 트리는 진단 기록 파일로 더럽혀 있었다. 구현 직전에 summary, ledger, native edit, direction limits, container readback, bridge UI, specification update, raster table 검사는 종료 코드 0이었다. 실제 Figma 문서에서 거절되는 화면은 보지 않았다.

## 한계와 후속 개선

session cache는 실제 문서 변경 이벤트를 확인하기 전에는 넣지 않는다. wall-clock 개선율은 통과로 기록하지 않는다.
