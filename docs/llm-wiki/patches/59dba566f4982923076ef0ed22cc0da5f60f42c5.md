# test: preserve the clipping assertion for archive replay

## 문제와 계기

Node 테스트의 실패 출력만으로는 실패 원인이 clipping 회귀인지, node 부재 같은 다른 오류인지 구분되지 않았다. 그래서 patch_knowledge_check gate의 `failure_contains` 조건으로 개선 전 실패를 특정 회귀로 고정할 수 없었다.

## 결과 동작

tests/web_carousel_clipping_gate.py를 추가했다. 이 스크립트는 Node clipping 테스트를 실행하고, 실패 출력에 'false !== true'가 있으면 'Browser scroll rail leaked an offscreen card' AssertionError를 낸다. 그 밖의 실패는 원래 반환 코드로 보고한다. gate 계약의 기준 ID CAROUSEL-CLIP과 재현 명령이 이 파일을 가리킨다.

## 변경 파일과 인터페이스

변경 경로는 `tests/web_carousel_clipping_gate.py`이다. 전체 경로와 diff 해시는 이 페이지의 Git 기록에 있다.

## 설계 이유와 출처

gate는 기준 커밋(59dba56)과 대상 커밋(2078ea9)에서 같은 검사 파일을 실행한다. 검사 파일을 구현 diff보다 먼저 별도 커밋으로 고정했으므로, 구현 diff가 검사 blob을 바꿔 완료 기준을 낮출 수 없다. 특정 실패 문자열을 요구하므로 무관한 환경 실패는 개선 전 재현으로 세지 않는다.

## 호환성·이관·복구

포크는 이 커밋과 부모의 변경 경로를 대조해 적용할 수 있다. 캐러셀 CMS나 외부 계정 연결은 필요하지 않다. 원본 화면과 사설 영수증은 로컬에 보존한다.

## 검증과 미검증

독립 gate 결과(별도 로컬 복제에서 `patch_knowledge_check.py gate --execute` 실행)에서 기준 59dba56 트리의 실행은 반환 코드 1과 위 AssertionError로 실패했다. 대상 2078ea9에서는 반환 코드 0으로 통과했고, 구현 범위는 tools/web_design_capture.js 한 파일이었다. 'false !== true'는 clipsContent가 true여야 하는 단언의 실패를 가리키지만, 같은 테스트 안에서 그 형태로 실패하는 다른 단언과 문자열만으로는 구분되지 않는다.

## 한계와 후속 개선

여기서 확인한 결과는 해당 입력과 검증 범위에 해당한다. 브라우저의 연속 스크롤 관성이나 물리 모바일 기기의 동작은 별도의 관찰이 필요하다.
