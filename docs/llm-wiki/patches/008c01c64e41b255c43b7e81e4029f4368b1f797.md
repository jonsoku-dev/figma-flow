# test: pin declared variant axes before creating combinations

## 문제와 계기

회귀 디자인 시스템의 axes.json은 button size·state와 field state를 선언하지만, 컴파일 결과는 그 축을 기존 variant에 연결하지 않는다. 독립 축을 조합으로 늘리면 선언되지 않은 정의가 생긴다.

## 결과 동작

tests/test_variant_axes.py는 examples/regression-program/design-system/design.json과 axes.json을 읽어 button.variant_axes가 size sm·md, state disabled·loading·error이 아니면 `declared axes must be preserved without new combinations`으로 실패한다. 이 커밋의 컴파일러는 아직 축을 붙이지 않는다.

## 변경 파일과 인터페이스

새 파일은 tests/test_variant_axes.py와 tests/variant_axes_oracle.cjs다. 부모는 c7327603e61a28342f6ebb1338e6758360f75251이다. 제품 런타임은 바꾸지 않는다.

## 설계 이유와 출처

종료 게이트는 검사 파일 blob이 구현 전후에 같아야 한다. 실제 axes.json을 입력으로 두고, 없는 sm/disabled 조합을 기대하지 않는다.

## 호환성·이관·복구

기존 design.json variant 스타일과 단일 Variant 축 패킷은 이 커밋에서 바뀌지 않는다.

## 검증과 미검증

이 커밋의 unittest는 종료 코드 1이다. oracle은 첫 assertion 이후에만 실행되므로 이 실패의 원인이 아니다. 실제 Figma는 관찰하지 않았다.

## 한계와 후속 개선

구현은 0ff91654bd6867c816292a9fbac8561d474644d8에서 검사 파일을 유지한 채 이어진다. 사용 설명과 swap은 입력에 없을 때 만들지 않는 조건을 oracle에 둔다.
