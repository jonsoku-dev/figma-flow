# feat: share one runtime module list for publish and trust

## 문제와 계기

기준 5fb446a3ea368317de9b56df62f93597a25a6251는 runtime_module_names가 없어 `publisher assembly and trusted sources must share one module list`로 실패했다. 발행 문자열과 신뢰 해시가 모듈 목록을 따로 알고 있었다.

## 결과 동작

runtime_module_names는 workspace_chat.js, workspace_transport.js, workspace_control.js, workspace_host.js를 반환한다. assemble_shared_runtime은 그 파일을 줄바꿈으로 잇는다. publish는 그 함수를 호출하고 예전 read_text 이어 붙이기를 쓰지 않는다. trusted_sources는 같은 목록의 figma-bridge 경로가 해시에 들어갔는지 확인한 뒤 64자 해시를 반환한다. 해시 입력의 경로와 바이트 순서는 유지한다.

## 변경 파일과 인터페이스

tools/figma_workspace.py에 runtime_module_names와 assemble_shared_runtime을 추가하고 trusted_sources와 publish가 그 목록을 쓰게 했다. tests/test_rd07_runtime_assembly.py blob은 기준과 같다.

## 설계 이유와 출처

RD-07-REQ-03은 생성된 runtime 소스가 trusted_sources와 runtime identity에 포함되게 한다. 전송 파일을 발행에만 넣고 신뢰 검사에서 빠뜨리지 않는다.

## 호환성·이관·복구

task closure와 wire format은 그대로다. 플러그인 버전은 0.26.3이다. 빠진 모듈이 있으면 `runtime module missing from trusted sources`로 거절한다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd07_runtime_assembly`를 기준 5fb446a3ea368317de9b56df62f93597a25a6251에서 종료 코드 1, 대상 d26df89c9f8b0ec5ca704c02acc07c23222e6047에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 assertion은 `publisher assembly and trusted sources must share one module list`다. 조건은 RD-07-REQ-03이다. 같은 구현에서 trace와 transport move 검사도 종료 코드 0이었다. 생성된 bundle의 모든 task kind와 실제 Figma 플러그인 재로드는 하지 않았다.

## 한계와 후속 개선

오류와 uncertainty를 포함한 task kind 실행은 다음 단위다. 구 조립 문자열은 publish에서 뺐다.
