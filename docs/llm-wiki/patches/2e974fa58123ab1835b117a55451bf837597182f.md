# test: preserve historical diagnostics across version bumps

## 문제와 계기

진단 회귀 검사가 현재 두 manifest의 버전까지 0.26.3에 고정하여 정상적인 다음 버전 변경을 실패로 취급했다.

## 결과 동작

현재 manifest는 숫자 세 부분의 버전 형식이며 서로 같아야 한다. 과거 입력에서 내보낸 record.plugin_version은 계속 0.26.3이어야 한다.

## 변경 파일과 인터페이스

tests/rd09_audit_log.cjs의 manifest assertions만 수정했다. renderAuditExport의 역사 입력 → 진단 record 검증 경로는 그대로 유지된다.

변경 경로: [tests/rd09_audit_log.cjs](../../../tests/rd09_audit_log.cjs).

## 설계 이유와 출처

설치 버전과 보존된 과거 사건의 버전은 서로 다른 값이다. manifest를 동적으로 읽되 역사 fixture를 현재 버전으로 덮어쓰지 않는 것이 검사 의도다.

## 호환성·이관·복구

진단 schema·제품 버전·export API는 변경하지 않는다. 미래 버전 변경은 두 manifest 동기화 조건을 계속 만족해야 하며 오래된 진단 버전도 보존해야 한다.

## 검증과 미검증

Git diff에서 manifestVersion 정규식 및 두 manifest의 일치 검사를 확인했다. record.plugin_version의 0.26.3 assertion이 제거되지 않았음을 확인했다. 제품 실행 통과를 이 커밋에 귀속하지 않는다.

## 한계와 후속 개선

숫자 버전 형식 검사는 배포·설치 성공이나 runtime 버전 일치의 증명이 아니다. 실제 설치와 getter 관찰은 별도 증거다.
