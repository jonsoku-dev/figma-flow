# 개발 중 저장소 변경의 Graph 소유권과 검사 후보 확인

커밋 `6efda0fe6fb092f0f0672817101610194d90f400`

## 문제와 계기

설치된 Biome·Oxlint·Knip은 개발 중 패널을 검사한다. 저장소의 다른 변경도 같은 대화에서 소유 범위와 필요한 검사를 파악하려면, 릴리스 소유 Graph와 개발 시점의 Git 차이를 연결해야 했다.

## 결과 동작

기준 커밋·스테이징·작업 트리의 변경, 파일별 소유 영역, 등록된 소비 영역과 검사 후보를 읽기 전용으로 출력한다. 지문이 바뀌거나 매핑할 수 없는 변경은 별도 상태로 드러난다. 옵션 실행에서 실제 패널 정적 검사를 호출한다.

## 변경 파일과 인터페이스

`tools/development_changes.py --base HEAD [--inventory] [--panel-tools] [--json]`과 [개발 변경 절차](../../development-changes.md)를 추가했다. `tools/release_ownership.py`의 공통 소유 판정과 JSON 경로 해석을 메이저 검사도 사용한다. `tools/graph_impact.py`의 Git 차이 읽기는 인덱스 갱신을 호출 단위로 끈다.

## 설계 이유와 출처

소유권을 새 목록으로 재작성하지 않고 `release/authority.json`과 연결된 하위 Graph를 사용한다. 경로가 같은 상태의 소유 변경도 보고한다. 영역 전체에 선언된 검사와 파일별 과거 테스트는 검토 후보로 표시한다. 최장 경로가 중첩 산출물 영역을 소유하는 기존 규칙을 공유한다.

## 호환성·이관·복구

기존 릴리스 검증과 패널 검증 인터페이스를 유지했다. 개발 분석에는 선택 실행 외의 npm 동작이 없으며 Figma Desktop, 라이브 싱크와 Graph 반영 경로를 수정하지 않았다. 되돌릴 때 공유 소유권 판정기와 두 소비자를 같은 변경으로 복구한다.

## 검증과 미검증

관련 Python 27개 및 패널 Graph 집계 9단계가 통과했다. 실제 체크아웃에서 16개 소유 영역과 미매핑 0건을 확인했고, Node 26.13.0에서 Biome 2.6.8·Oxlint 1.94.0·Knip 6.48.0을 선택 실행했다. Astra Ultra의 독립 검수에서 인덱스 stat 갱신, 링크 아래 외부 파일, 이전 Gitlink, 분석 중 저장 및 중첩 저장소 누락을 재현했다. 교정 후 관련 독립 테스트 29개가 통과했다. 배포 참고 자료의 기존 검출 3건은 기준과 후보에서 같았으며 신규 검출은 없었다.

## 한계와 후속 개선

소유권 판정 결과는 동작 통과 근거와 구분한다. 패널 외에서는 기존 Graph가 제공하는 검사 후보를 표시한다. Git에서 무시한 파일은 인벤토리의 범위 밖이며 서브모듈과 중첩 저장소는 별도 상태로 표시한다.
