# test: align native fixtures and integration harnesses

## 문제와 계기

최종 통합 검사가 실제 게시 런타임의 비동기 admission, 타이머, 선택 manifest와 native Auto Layout 전제를 충분히 모델링하지 못했다.

## 결과 동작

전용 실행 인자가 필요한 lifecycle/selective helper를 helpers 아래로 옮기고 호출자를 갱신한다. actions의 fill 너비는 명시적인 auto-layout 부모에 종속되며, readback과 토큰 변경의 추가 identity 필드를 검사한다.

## 변경 파일과 인터페이스

14개 테스트·fixture 경로를 바꿨다. fixture에 actions-parent를 추가하고 normalization/placement/sizing 기대를 맞췄다. VM에 타이머와 journal refresh를 제공하고, native-started는 preflight→beforeDispatch→재확인→handler 순서로 검사한다.

## 설계 이유와 출처

지원하지 않는 부모에서 fill을 기대하거나 단순 객체 동일성으로 확장된 변경 항목을 거절하면 제품 결함과 하네스 결함을 구별할 수 없다. CSS 대비는 caller가 제공한 관찰을 사용하고 관찰 없는 호출은 거절하도록 기준을 맞췄다.

## 호환성·이관·복구

제품 소스와 공개 프로토콜은 변경하지 않는다. helper 이동을 Python 호출자가 따라가며, 후속 2ae6c2a가 남은 React require 깊이를 수정한다. native control readback은 기존 단일 문자열 대신 필요한 필드 전체를 확인한다.

## 검증과 미검증

실제 diff에서 actions-parent의 fixed/hug·padding, token의 root/identity/group, scope/deadline 재확인 순서를 확인했다. CSS 테스트의 provided-observation은 브라우저를 실행했다는 증거가 아니다.

## 한계와 후속 개선

API fixture는 Figma의 실제 resize·텍스트 측정을 보증하지 않는다. 이 커밋의 기준 정합성 보정과 후속 미커밋 제품 수정의 실행 결과를 분리해야 한다.
