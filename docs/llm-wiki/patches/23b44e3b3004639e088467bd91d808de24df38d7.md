# test: pin startup package byte preservation

## 문제와 계기

startup CLI는 검증 대상 패키지의 Python 모듈을 import한다. 보통의 Python 실행에서 import가 `__pycache__` 파일을 쓰면, 패키지 바이트를 검증하면서 같은 패키지 내용을 변경할 수 있다. 이 커밋은 이를 재현하는 frozen baseline 테스트 하나를 추가해 이후 수정이 일반 `python` 실행에서도 파일 바이트를 보존하는지 고정한다.
## 결과 동작

격리된 임시 패키지 복사본에서 `tools/plugin_startup.py --help`를 일반 Python으로 두 번 실행하고, 실행 전·후 모든 파일의 SHA-256 맵이 같은지 검사한다. 이 commit 시점의 base `e0aeed2...`에서는 fixture에 `library/`를 포함시킨 뒤 실제 assertion `startup CLI must preserve verified package bytes without requiring -B`가 실패해 byte-preservation 회귀를 입증했다. 그 실패는 의도된 baseline 증거다. 이후 별도 제품 커밋 [startup 수정](25b6f754a4798119defc65c5146d59e0d3f23467.md)이 `__main__` 실행 시 `sys.dont_write_bytecode = True`를 설정해 해결했다. 이 테스트 커밋 자체가 baseline 실패를 통과로 바꾸지는 않는다.
## 변경 파일과 인터페이스

변경은 `tests/finalize_startup_self_cache.py` 39줄 추가뿐이다. `StartupPackageBytes.test_plain_python_help_preserves_package_bytes_on_repeated_runs`는 `tools/`, `library/`, `plugin.json`, `.codex-plugin/plugin.json`을 임시 디렉터리로 복사하고, startup CLI의 `--help`를 호출한 뒤 모든 파일의 SHA-256 스냅샷을 비교한다. 새 제품 API나 설정은 없다.
## 설계 이유와 출처

검사는 제품이 확인하는 패키지 바이트를 같은 startup 실행이 바꾸는지 직접 관찰한다. fixture에는 import가 필요한 `library/`도 복사해야 하며, 이를 빼면 의도한 byte-preservation assertion에 도달하기 전에 import 오류로 끝난다. 환경에서 `PYTHONDONTWRITEBYTECODE`와 `PYTHONPYCACHEPREFIX`를 제거해 우연한 호스트 설정에 기대지 않고, `-B`를 CLI에 추가하지 않아 보통 실행 조건을 고정한다. 출처는 첫 부모 `e0aeed2...` 대비 이 파일의 실제 diff와 base에서 확인한 assertion 실패다.
## 호환성·이관·복구

테스트는 표준 `unittest`, `tempfile`, `hashlib`, `shutil`, `subprocess`를 사용하고 실제 저장소 파일을 수정하지 않고 임시 복사본을 검사한다. 데이터나 사용자 파일을 이관·복구하지 않는다. 환경의 cache 관련 Python 변수를 의도적으로 제거하지만, 별도 사용자별 실행환경이나 설치 후 동작을 검증하지는 않는다.
## 검증과 미검증

base에서 fixture 보완 후 실행해 byte snapshot assertion의 실제 실패를 확인하고 그 검사를 커밋에 고정했다. 원격 release index가 별도로 기록할 실제 배포·설치 관찰은 이 페이지 범위 밖이다. 이후 제품 수정의 성공을 이 테스트 추가 시점의 통과로 소급하지 않는다. 테스트 코드의 핵심 oracle은 두 번의 plain-Python `--help` 실행 전후 파일 전체 SHA-256 비교다.
## 한계와 후속 개선

이 테스트는 startup CLI의 `--help` 두 회와 임시 복사본의 파일 바이트만 확인한다. 설치된 플러그인, 원격 CI, Figma 연결, 그 밖의 startup 실행 경로는 보장하지 않는다. 제품 수정은 별도 commit이며 해당 변경의 제품 및 배포 근거도 별도 기록해야 한다.
