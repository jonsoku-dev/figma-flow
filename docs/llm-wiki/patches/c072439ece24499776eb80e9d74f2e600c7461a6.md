# feat: keep each native read fresh without a session snapshot

## 문제와 계기

기준 bf65601803dc933fe0001235237c423ac9bf2636는 `native read keeps no session snapshot`이 없어 `native read must not serve a stored snapshot`으로 실패했다. 원격 편집, 비동기 페이지 로드, 변수 변경을 이 런타임에서 확인하지 않았다.

## 결과 동작

nativeReadSessionSnapshot은 null만 반환한다. readNativeSemantics는 그 값이 null이 아니면 `native read must not serve a stored snapshot`으로 거절한다. 현재는 항상 null이므로 full과 summary가 page.loadAsync부터 다시 읽는다. width를 21로 바꾸면 다음 full과 summary의 rect.width는 21이고, 이전 결과 객체와 다르다. clientStorage는 쓰지 않는다.

## 변경 파일과 인터페이스

figma-bridge/native_semantic_read.js에 nativeReadSessionSnapshot을 추가하고 module.exports에 넣었다. tests/rd06_fresh_read.cjs blob은 기준과 같다. docs/development-roadmap/RD-06-native-read/tasks.md의 결정은 기준 커밋에 있다.

## 설계 이유와 출처

RD-06-REQ-04는 변경 신호가 불확실하면 full로 돌아간다. 공식 documentchange의 범위를 이 런타임에서 확인하지 못했으므로 cache를 만들지 않는다. TTL은 coverage가 아니다.

## 호환성·이관·복구

기존 호출의 인자 없는 full과 summary profile은 유지한다. 저장 snapshot의 이관은 없다. 플러그인 버전은 0.26.3이다.

## 검증과 미검증

종료 게이트는 `node tests/rd06_fresh_read.cjs`를 기준 bf65601803dc933fe0001235237c423ac9bf2636에서 종료 코드 1, 대상 c072439ece24499776eb80e9d74f2e600c7461a6에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 assertion은 `native read must not serve a stored snapshot`이다. 조건은 RD-06-REQ-04다. 같은 구현에서 summary, partial 거절, getter ledger 검사도 종료 코드 0이었다. 실제 Figma documentchange는 관찰하지 않았다.

## 한계와 후속 개선

무효화는 cache가 없으므로 측정하지 않는다. 같은 fixture의 getter 이름과 UTF-8 JSON 크기 대조는 다음 단위다. wall-clock 개선율은 통과로 기록하지 않는다.
