# feat: release validated Figma Flow 0.27

## 문제와 계기
0.27.0은 컴포넌트 재사용·의미 계층·선택 동기화·자산 근거·native 읽기·작업 수명주기를 실제 제작 흐름에 연결하고, 독립 예약 앱으로 패키지·운영 경계를 확인하는 통합 릴리스다. 0.26.3의 계측과 스펙만으로는 공유 main의 실제 TEXT 속성, Group 조상 좌표, 선택된 graph 값의 원자 적용, 화면 생성에 실제 입력된 이미지/CSS 출처를 확인할 수 없었다. 통합 인수에서는 이 경계들을 Figma getter·고정 oracle·브라우저·서버 검사로 구분했다. 패치 대상은 이 커밋의 첫 부모 `7b5ae4091641430d891e0c110c8efdb9a845a6ce` 대비 347개 경로다.
## 결과 동작
반복 컴포넌트는 반환된 TEXT property key로 instance 문구를 편집하고, 구조와 의미가 같은 데 지원된 root 너비만 다른 사용처는 main을 공유한다. 기존 variant 안에 선언된 축만 연결하며 임의 조합·미선언 usage·swap target을 만들지 않는다. 텍스트 높이의 정수 올림은 원본이 겹치지 않고 위치와 한 줄 할당이 정확히 일치할 때만 판별하며, 원시 측정과 실제 충돌 거절을 유지한다. Group·Frame·Auto Layout 계층과 clipped Frame의 스크롤 축을 선언대로 작성하고 실제 overflow getter로 확인한다. 실제 배치와 충돌하는 flow, 크기·padding, 지원하지 않는 FILL 부모는 쓰기 전에 거절한다. 기존 node/main/comment/prototype 연결을 보존한다.

작업 dependency는 정확한 revision 및 artifact hash로 연결해 current/stale/retired/unknown을 나누고, 서버 실행 상태와 로컬 관측을 별도로 표시한다. 선택 동기화는 고정 manifest와 protocol에 따라 alias 및 공유 consumer 묶음만 적용하며 선택 밖 값·binding·기존 partial marker를 보존한다. 부분 적용은 전체 pairing 완료가 아니다. 입력 자산 inventory는 종류, 모든 CSS 출처, 부재와 외부 확인 불가를 구별하고 inventory와 승인된 브라우저 요청 관찰도 구별한다. native 작성 중 container 검사는 한 번의 fresh full read를 공유하되 마지막 검증은 다시 fresh full read다. 로컬 transport는 origin·route·payload·timeout을 제한하고 React 패널의 진단 export에서 URL 자격 정보·token·개인 홈 경로를 제거한다. 같은 scope에서 canonical outer payload SHA(내부 readback 문자열의 바이트 포함)가 같으면 terminal result 전달은 기존 ACK를 반환한다. 같은 task bundle/revision/artifact의 재사용과는 별도 계약이다. 실패 cleanup은 manifest가 바뀌지 않은 경우에만 수행한다.

별도 `apps/little-hands/` Django/PostgreSQL 앱은 인증·예약·대기·취소·회차 변경·운영·감사를 별도 서버 트랜잭션으로 처리하고 Docker 배포 파일을 제공한다. 그 Figma prototype은 정적 화면이다. prototype 링크 조작은 실제 앱의 업무 POST나 거래 실행으로 기록하지 않는다.

## 설계 이유와 출처
구현은 저장소 내 RD feature/design 및 AC의 지원 범위를 따른다. 같은 의미·구조에서 너비만 다른 구성은 main 재사용을 허용하되 구조·자식 배치가 다르면 별도 main/layout을 유지한다. 선언이 없는 축·swap을 추측하지 않고, 실제 graph 및 Figma getter가 제공하는 key·좌표·overflow를 근거로 삼는다. 선택 sync는 alias와 공유 consumer를 분리 적용하면 일시적으로 전체 일관성이 깨질 수 있어 선택 manifest 단위로 원자 적용한다. terminal result는 동일 scope와 canonical outer payload SHA(내부 readback 문자열 바이트 포함)를 비교해 같은 값의 재전달에 ACK를 재사용하며, 이는 task bundle/revision/artifact reuse와 별개다. transport 진단은 복사·공유될 수 있으므로 민감 URL 성분과 로컬 홈 경로를 제거한다.

Little Hands는 플러그인의 backend로 취급하지 않고 Django/PostgreSQL의 독립 제품·운영 경계로 만들었다. Figma 원본 캡처와 화면 계약은 `apps/little-hands/design/` 아래 있고, 실행 근거 요약은 [디자인 검증 기록](../../../apps/little-hands/design/VERIFICATION.md), 조건별 추적은 [최종 인수 행렬](../../development-roadmap/FINAL_ACCEPTANCE.md)이다. 동봉된 캡처와 private raw dump 대신 이 portable 요약과 공개 테스트/소스만 공유 기록에 사용한다.
## 호환성·이관·복구
기존 그래프, 노드 ID, component main, instance, annotation, prototype 연결 및 선택되지 않은 variable binding을 보존하는 방향으로 구현했다. 동일 요청·동일 산출물 재전달은 기존 receipt를 반환한다. 미확정 write를 자동 재실행하지 않으며, 실패 cleanup은 manifest 지문이 바뀌지 않은 경우에만 수행한다. workspace 상태는 현재 revision과 과거·은퇴·확인 불가 상태를 구별하고 stale 산출물을 현재 결과처럼 쓰지 않는다. 입력 inventory의 누락·외부 확인 불가는 추정값으로 치환하지 않는다.

Django schema 변경은 `apps/little-hands/booking/migrations/`에 순서대로 추가된다. 운영·백업·권한 복구 절차는 앱 `README.md`, `ARCHITECTURE.md`, `deploy/`에 있다. 캡처와 prototype은 디자인 검토 자료이며 운영 데이터 이관 수단이 아니다. 이번 기록은 실제 원격 공개 운영에 데이터를 옮기거나 TLS endpoint를 만들었다고 주장하지 않는다. 검증된 복원 범위는 별도 PostgreSQL 데이터베이스에서 확인한 21개 테이블의 행 일치다.
## 검증과 미검증
주 세션이 확정한 clean Git archive `P841aa58` 검사는 root Python 1,107개 중 1,105개 통과·2개 skip·0개 실패(247.025초), PostgreSQL backend 58개, packaging 4개, design 16개, finalize Python 74개, native demo 2개 통과를 기록한다. Node는 299개 중 298개 통과, 1개 skip, 0개 실패다. 14개 local 실행 명령은 모두 exit 0이었다. React build 및 typed runtime 배포 bytes는 원본과 byte-identical이었다. 독립 frozen improvement gate는 base `7b5ae4091641430d891e0c110c8efdb9a845a6ce`에서 target `841aa58a7f0f5fabe68aaaa7bdee1cd3ba64c988`까지 정확히 347개 변경 경로를 재생했다. 같은 diagnostic privacy oracle의 baseline AssertionError 재현을 확인하고 target diagnostic privacy, 실제 Group Python, partial consumer Node 조건이 통과했으며 checkout 원본은 그대로였다. 격리 staging HTTP 관찰은 signup 후 `staff=false`, `superuser=false`, group 0, 회원 예약 화면 200, 운영 경로 403, logout 302 및 보호 경로 302다. 이는 브라우저 암호 입력이나 공개 서비스 검증이 아니다. 화면 캡처는 22개 상태의 desktop/mobile 각 1장(44개)이며, 주 세션은 47개 이미지의 시각 검토를 보고했다. 이 문서 작성자가 그 전체 이미지를 새로 검사한 것은 아니다.

실제 Figma R8 getter 범위는 44 screens, 4,820 nodes, 두 Group, 24 mains, 두 component sets, 494 instances, 69 variables, 기존 Frame clip 550개 및 nonempty reaction node 314개(312 product + 2 palette)의 semantic target 보존이다. Group 통합 뒤 leaf geometry 3,171개의 절대 bbox 차이는 0이었다. 실제 정적 prototype은 desktop/mobile을 포함한 14개 GUI 조작 단계를 확인했다. 이것은 312개 prototype 링크 전체 실행이 아니고, 인증·예약 업무 요청도 수행하지 않는다. 앱의 캡처·브라우저 검토와 Figma prototype 조작은 서로 다른 경로다.

최종 인수 문서는 **45 AC의 bounded pass를 45 REQ의 전체 양성 구현으로 승격하지 않는다.** RD-01 optional label/icon용 BOOLEAN 및 INSTANCE_SWAP 생성은 미구현이고, NF-01 제안 범위다. 앱의 영속 Graph SSOT는 없으며 임시 복사본·Django CSS consumer round trip은 제한된 후 제거 실험이다(NF-04는 제안). 실기기, 사람의 창작/production 승인, 공개 DNS/TLS·상용 배포, 기존 61개 회귀 전체, 독립 원격 API 기반 cloud save 인수는 확인되지 않았다. 원격 CI, release 및 설치 결과는 별도 확인 전까지 pending이며 이 patch page에서 성공으로 선반영하지 않는다.
## 한계와 후속 개선
R8의 수치와 검사 결과는 해당 원본/복사본·manifest·fixture 및 실행 시점 범위에만 유효하다. Figma getter가 검사한 prototype target 수가 링크를 모두 UI에서 조작했다는 뜻은 아니며, Figma 정적 화면은 실제 업무 backend가 아니다. 45개 AC pass도 45개 REQ의 모든 긍정 기능을 구현했다는 뜻이 아니다. BOOLEAN·INSTANCE_SWAP 양성 생성, 영속 앱 SSOT, 실제 기기, 사용자 창작 승인, 공개 TLS 운영은 별도 범위로 남는다. backend test와 package check만으로 인터넷 공개 운영, 보안 침투, 고가용성 또는 사용자 수용을 추론할 수 없다.

앞선 안정 후보 검사 수치는 최종 Group 통합/clean package 결과가 아니며 최종 전체 검사로 재사용하지 않는다. 위에 기록한 final local checks와 frozen gate는 통과했지만 원격 release, CI 영수증 또는 plugin 설치를 뜻하지 않는다. 원격 게시·설치 결과는 별도 확인 전까지 pending이다. 후속 기능은 `docs/next-roadmap/README.md`의 PROPOSED 상태를 유지하며, 새 인수 주장은 해당 소스에서 다시 관찰한 근거와 연결해야 한다.
