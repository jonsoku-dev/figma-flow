# feat: keep observed conflict values with the original plan hash

## 문제와 계기

기준 0b46cdbd575cfe17d901d33925fd03c45c643782는 충돌 상세 조회가 없어 `conflict detail must keep the observed value and plan hash`로 실패했다.

## 결과 동작

conflict_detail은 native edit receipt의 plan_sha256과 operation의 before, after, observed를 rollback 이유와 연결한다. observed 20은 after 18로 바뀌지 않는다. 후속 동작은 save-evidence와 read-scope뿐이다. plan hash가 없거나 충돌 target이 operation과 맞지 않으면 거절한다. native edit 충돌 기록은 planned before, after, observed, plan hash를 포함한다. 외부 변경은 덮어쓰지 않는다.

## 변경 파일과 인터페이스

tools/figma_control.py에 conflict_detail을 추가했다. figma-bridge/native_edit.js의 nativeEditConflict가 충돌 항목에 before, after, observed, plan hash를 넣는다. docs/development-roadmap/RD-08-operation-lifecycle/tasks.md에 범위를 적었다. tests/test_rd08_conflict_detail.py blob은 기준과 같다. 재실행 버튼은 추가하지 않았다.

## 설계 이유와 출처

RD-08은 충돌 상세를 원래 plan hash에 연결하고, 안전한 후속을 근거 저장과 현재 scope 읽기로 한정한다. 관측 값을 계획 값으로 자동 복구하지 않는다.

## 호환성·이관·복구

기존 rollback 이유 문자열과 외부 변경을 유지하는 분기는 남긴다. recovery_read는 rollback_conflicts가 있으면 여전히 복구하지 않는다. 원본 receipt의 observed는 조회가 바꾸지 않는다.

## 검증과 미검증

종료 게이트가 기준 0b46cdbd575cfe17d901d33925fd03c45c643782의 종료 코드 1과 대상 b91d26553b3343a61f8094a1ac041e3043506787의 종료 코드 0을 다시 실행했다. 같은 구현에서 제어 검사와 native edit, graph panel 검사도 통과했다. 실제 Figma 충돌 표, 서버 재시작, 플러그인 재실행은 관찰하지 않았다.

## 한계와 후속 개선

화면의 충돌 표는 아직 별도로 관찰하지 않았다. 서버와 플러그인 재시작, 결과 전달 실패의 실제 경로는 다음 단위다. AC의 화면 표시는 통과로 기록하지 않는다.
