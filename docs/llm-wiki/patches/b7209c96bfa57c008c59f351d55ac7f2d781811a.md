# test: verify review full-read boundary behavior

## 문제와 계기

full native read를 공통 helper로 추출한 뒤 direction_review 소스의 requireFullNativeRead 호출 문자열 수가 2회에서 1회로 바뀌어 기존 Node 검사가 실패했다. 호출 문자열 개수는 partial evidence가 full 경계로 들어가는지의 행동과 같지 않다.

## 결과 동작

검사는 실제 review context의 indexDeclaredContainerRead에 summary를 넣으면 partial native read cannot be stored as full evidence 오류가 나고, full read를 넣으면 byId의 rect width=12를 보존하는지 확인한다. 제품 소스 변경은 없다.

## 변경 파일과 인터페이스

[rd06_reject_partial.cjs](../../../tests/rd06_reject_partial.cjs)의 source-count assertion을 행동 assertion 두 개로 교체했다. [normal-build helper](../../../tests/helpers/finalize_native_build_reads.cjs)의 host(packet()).context → indexDeclaredContainerRead(summary/full) → 거절 또는 byId index가 대상 실행 경로다.

## 설계 이유와 출처

helper 추출의 형태가 아니라 소비자가 full evidence로 저장할 수 있는 입력의 경계를 검사한다. summary가 거절되고 full의 실제 geometry 값이 index에 도달해야 하므로 partial guard를 없애거나 단순히 호출 횟수 기대를 낮추는 수정과 다르다.

## 호환성·이관·복구

native_edit와 graph discovery의 full-read 경계 및 summary handler가 full 증거를 주장하지 않는 기존 검사들은 그대로 유지한다. schema·reader API·제품 실행 경로는 이 커밋에서 바꾸지 않으며 source-count에만 결합된 기준을 교체한다.

## 검증과 미검증

Git diff에서 문자열 횟수 검사 제거와 summary reject/full width 보존 assertion을 확인했다. 상위 세션이 보고한 원래 full Node 검사 1개 실패는 helper 추출 후 호출 개수 1 대 기대 2의 불일치였다. 이번 기록 작업은 정적 대조만 했으며 수정된 기준의 실행 통과를 새로 주장하지 않는다.

## 한계와 후속 개선

API-shaped host에서 실제 index 경계를 확인하는 기준이며 live Figma의 full getter 가용성·페이지 로딩·전체 앱 import 인수를 증명하지 않는다. 제품 수정과 현재 실행 영수증, 실제 native 재검증은 따로 연결해야 한다.
