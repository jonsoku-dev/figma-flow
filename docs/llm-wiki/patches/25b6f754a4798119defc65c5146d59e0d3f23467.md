# CLI 패키지 불변성과 운영 앱 CI 문법 수정

## 문제와 계기

0.27.0 원격 앱 workflow는 job을 만들기 전에 실패했다. 독립 조사에서 `--only-binary=:all: -r`의 콜론·공백이 YAML plain scalar의 mapping indicator로 읽히는 것을 38행 71열 ScannerError로 재현했다. 별도로 설치된 startup을 일반 Python으로 실행하면 local 모듈 import가 패키지 내부 bytecode를 갱신해 `source-changed-before-update`가 발생했다. 캐시를 검증된 기존 원본으로 복원한 뒤 `-B` 재시도로 0.27.0 업데이트가 성공했지만, 명령 자체가 검증 대상 바이트를 바꾸는 원인을 해결해야 했다.

## 결과 동작

startup CLI 직접 실행은 local 모듈 import 전에 bytecode 쓰기를 끈다. 일반 Python의 `--help`를 반복해도 파일 목록과 모든 바이트가 유지된다. 라이브러리 import에서는 interpreter 설정을 바꾸지 않는다. 기존 source authority, 정확한 파일 바이트, 버전, 복구 사본, 설치 결과 검사는 그대로 유지한다. 생성 파일을 비교에서 제외하거나 변경된 사용자 소스를 덮어쓰는 우회는 추가하지 않았다. 앱 CI는 같은 locked pip 명령을 YAML block scalar로 표현한다.

## 변경 파일과 인터페이스

첫 부모 `23b44e3b3004639e088467bd91d808de24df38d7` 대비 7개 파일이다. [startup 진입부](../../../tools/plugin_startup.py)는 `__main__`일 때만 `sys.dont_write_bytecode`를 설정한다. [앱 workflow](../../../.github/workflows/little-hands.yml)는 설치 명령을 block으로 옮긴다. [일반 manifest](../../../plugin.json)와 [Codex manifest](../../../.codex-plugin/plugin.json)는 0.27.1이며 [README](../../../README.md)·[다국어 통합 가이드](../../guide.md)의 설치 대상과 [CHANGELOG](../../../CHANGELOG.md)를 맞췄다. 서버·workspace·Figma 렌더러·Django 업무 API는 변경하지 않았다.

## 설계 이유와 출처

검증기가 자신의 입력을 변경하지 않게 하는 것이 정확한 파일 검사를 완화하는 것보다 좁은 해결이다. 설정은 표준 Python interpreter 기능을 사용하며 외부 패키지를 추가하지 않는다. YAML 수정은 argv를 바꾸지 않고 구문만 명확히 한다. 실제 [실패 run](https://github.com/jonsoku-dev/figma-flow/actions/runs/43327579170)은 `jobs: []`였고 check suite에도 check run이 없었다. 서비스 이미지·DB 접속 오류로 추정하지 않는다. 로컬 YAML parser의 원본 실패와 수정 후 동일 설치 명령을 대조했다.

## 호환성·이관·복구

기존 workspace 등록·task·서버·native 데이터는 그대로다. 자동 업데이트는 여전히 확인한 원본 authority의 태그를 사용하고, 변경·출처 불명·복구 불가이면 거절한다. 기존 0.27.0 이하의 CLI로 다음 버전을 받을 때는 통합 가이드의 `-B` 명령을 사용해 예전 진입부의 bytecode 변경을 피한다. 이미 생긴 cache 차이를 무시하거나 일괄 삭제하지 말고 검증된 이전 배포 파일과 대조한다. 0.27.0 태그와 ZIP은 다시 쓰지 않고 프리릴리스 기록으로 보존한다.

## 검증과 미검증

고정 [CLI 검사](../../../tests/finalize_startup_self_cache.py)는 동일 파일로 수정 전 assertion 실패와 수정 후 성공을 확인한다. `python3 -B tests/finalize_startup_self_cache.py`, startup unittest 27개와 진단 버전/runtime Node 6개가 통과했다. YAML parser는 block 수정본과 정확한 pip 명령을 확인했다. 독립 정적 검수는 지정 diff에서 P1/P2를 찾지 못했으며 별도 실행 검수로 확대하지 않는다. 이전 0.27.0 clean source의 전체 local suite와 실제 R8·Django 업무 검증은 해당 소스와 변경 없는 범위의 근거다. 0.27.1의 원격 CI·태그·ZIP·설치·fresh native 관찰은 [현재 릴리스 기록](../releases.md#v0.27.1)에서 실제 영수증으로 구분한다.

## 한계와 후속 개선

`--help` 반복 검사는 네트워크 업데이트 전체 성공을 보장하지 않는다. source-byte 검사를 통과해도 반환된 설치 경로·두 manifest·배포 ZIP의 실제 바이트와 현재 Figma runtime을 따로 확인해야 한다. Python 라이브러리 호출이나 다른 CLI의 cache 정책을 새로 변경하지 않았고 임의 패키지 변경을 승인하지 않는다. 전체 앱 영속 SSOT·BOOLEAN/INSTANCE_SWAP 양성 작성·실기기·공개 TLS 운영·사람의 창작 승인은 이전부터 남아 있던 별도 범위다.
