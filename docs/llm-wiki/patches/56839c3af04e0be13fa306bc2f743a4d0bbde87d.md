# feat: record the asset list apart from the files Chrome loads

## 문제와 계기

기준 a069898acd764f726494c713c2b742cb834fcd0b는 contrast_css_browser_loading이 없어 `css asset list and browser loading must stay separate`로 실패했다.

## 결과 동작

contrast_css_browser_loading은 html_channel 목록과 headless Chrome이 요청한 상대 경로를 따로 돌려준다. photos/mark.png와 fonts/body.woff2는 목록에서 present이고 브라우저가 요청한다. fonts/spare.woff2는 @font-face에만 있어 목록에서는 present이고 요청에는 없다. separate는 true다. 목록을 만드는 코드는 그 파일을 대신 받지 않는다.

## 변경 파일과 인터페이스

tools/input_effect.py에 contrast_css_browser_loading과 _chrome_requested_paths를 추가했다. 로컬 서버로 index.html을 열고 Chrome 원격 디버깅의 Network 이벤트를 읽는다. docs/development-roadmap/RD-05-asset-inventory/tasks.md에 범위를 적었다. tests/test_rd05_browser_contrast.py blob은 기준과 같다.

## 설계 이유와 출처

RD-05는 목록의 present를 브라우저 렌더 성공으로 쓰지 않는다. 쓰이지 않은 글꼴은 준비 상태와 실제 요청이 다르다. 두 결과를 한 필드로 합치지 않는다.

## 호환성·이관·복구

html_channel, freshness, 목록 필터는 그대로다. 이 함수는 호출될 때만 서버와 Chrome을 열고 finally에서 둘 다 닫는다. Chrome이 없으면 대조를 만들지 않는다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd05_browser_contrast`를 기준 a069898acd764f726494c713c2b742cb834fcd0b에서 종료 코드 1, 대상 56839c3af04e0be13fa306bc2f743a4d0bbde87d에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 마지막 assertion은 `css asset list and browser loading must stay separate`다. 조건은 RD-05-REQ-05다. 대상 실행은 headless Chrome이 photos/mark.png와 fonts/body.woff2를 요청하고 fonts/spare.woff2는 요청하지 않음을 다시 확인했다. 사람이 보는 브라우저 창과 Figma 렌더는 관찰하지 않았다.

## 한계와 후속 개선

요청 목록은 headless Chrome 한 번의 네트워크 이벤트다. 글꼴이 화면에 어떻게 그려졌는지는 보지 않았다. 네이티브 읽기 요약은 RD-06이다.
