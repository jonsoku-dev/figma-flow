# feat(control): add read-only exact-scope history-detail projection

## 문제와 계기

기존 작업 이력 조회는 요약 행만 제공해, 특정 실행(`operation_id`)이 어떤 직전 아티팩트·선후 관계에서 유발됐는지와 필드 단위 인과 diff를 읽기 전용으로 안전하게 열람할 수 없었다.

## 결과 동작

커밋 `3e7b44cc9903b3bfc753b77797e96c2c831dcd5b`는 `tools/operation_detail.py`(`figma-flow-operation-detail-v1`)와 `tools/figma_control.py`에 `history_detail`(`build_operation_detail` 위임)과 `/control/history-detail` 라우트를 추가했다. 범위 안에서 찾을 수 없는 실행은 `404`, 거부된 요청은 `409`로 응답하며 정본 요청·영수증을 쓰지 않는다. 인증 누락 응답은 이후 실기 프로브에서 `403`으로 확인했다. 로드된 구현 해시(`LOADED_IMPLEMENTATION`)에 `tools/operation_detail.py`도 포함된다.

## 변경 파일과 인터페이스

`tools/operation_detail.py`(신규)와 `tools/figma_control.py`(`history_detail` 핸들러)를 추가·수정했다.

## 설계 이유와 출처

[NF-03 설계서](../../next-roadmap/NF-03-causal-history.md)와 [역량 검토](../../next-roadmap/capability-review.md#p1-causal-history)에 따라 원문 사용자 텍스트·개인 경로·내부 Figma ID·토큰이 응답에 유출되지 않도록 정규화된 타깃 키·필드 diff DTO를 설계했다.

## 호환성·이관·복구

기존 `/control/history` 요약 응답 스키마와 쓰기 경로(`apply`/`read`)는 변경하지 않는다.

## 검증과 미검증

실제 P1 Figma 제어 환경에서 동일 태스크 2개 리비전(`borderRadius` `0->8->16`) 조회 시 `history_detail`이 `1,226`개 정본 요청·영수증 파일의 바이트를 전혀 변경하지 않음을 확인했고, `e6f4fd8` 라이브 HTTP 프로브에서도 `history_status=200`(16행 제한), 긍정 상세 `200`, leak/DTO 오류 `0`건, `403`/`404`/`409` 음수 경로를 재확인했다.

## 한계와 후속 개선

브리지 릴레이·패널 UI·포터블 동기화 diff 보강은 후속 커밋(`ce1bc7d2`, `e7b1efbd`, `016a777e`)에서 완성된다.
