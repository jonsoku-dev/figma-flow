# 릴리스 근거 검증과 Figma 선택 한도의 단일 원본

## 문제와 계기

Design에서 선택한 레이어를 Codex로 읽는 한도와 뷰어 안내가 여러 위치에서 관리됐고 배포 설정과 기능 명세의 소유권을 검토하는 실행 근거가 필요했다.

## 결과 동작

`bb486531acd4c7635b12cbd0962f3d261f96b311`에서 선택 개수는 하나의 그래프 입력에서 가져오고, 워크플로와 마켓플레이스 투영 및 명세 검토 근거를 현재 배포 소스에 연결한다.

## 변경 파일과 인터페이스

`library/figma-profile/read-limits.json`이 선택 개수를 소유한다. `library/delivery/graph.json`과 워크플로 템플릿을 `tools/delivery_config.py`로 검증한다. `release/reviews/`의 검토는 후보에서 실행한다.

## 설계 이유와 출처

단일 문서 절의 소유권을 검증하며 코드 블록, 주석, 모호한 제목을 걸러낸다. 검토할 영역의 기능 그래프 목록은 배포되는 명세 색인에서 읽는다.

## 호환성·이관·복구

기본 선택 한도는 20개다. 기존 서명된 작업·식별자와 일반 배포 방식을 유지한다. 부분 읽기는 언어별 근거와 오류 상태를 제공한다.

## 검증과 미검증

격리 트리에서 한도를 2로 바꾸고 Codex/네이티브 승인·거절, 변경 감시의 생략 수와 세 언어 문구를 검사했다. 브라우저에서 실제 컴파일한 패널과 합성 호스트 메시지를 확인했다. 배포·명세 결과 및 남은 조건은 버전 대조에 기록했다.

## 한계와 후속 개선

명세의 연결과 테스트 실행은 해당 규칙의 검토 근거다. 다른 영역과 유료 Dev Mode 세션은 별도 실증을 요구한다.
