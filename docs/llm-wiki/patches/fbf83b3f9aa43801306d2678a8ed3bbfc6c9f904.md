# test: retain history within the requested scope

## 문제와 계기

전체 요청에서 최근 80개를 먼저 자르면 다른 파일/페이지의 활동이 조용한 현재 scope의 기록을 밀어낼 수 있다. 선택 검사도 실제 host manifest 상수명을 따라야 했다.

## 결과 동작

새 회귀는 다른 scope 요청 81개를 추가한 뒤 현재 scope의 원래 operation이 journalHistory에 남고 결과는 80개 이하일 것을 요구한다. 선택 소스 검사는 GRAPH_SELECTION_MANIFEST 상수명을 사용한다.

## 변경 파일과 인터페이스

새 test_finalize_history_scope.py는 FinalizeLifecycle의 실제 private HTTP fixture를 상속하고 요청 JSON을 임시 workspace에 쓴다. 두 RD04 테스트의 manifest 문자열만 함께 정정했다.

변경 경로: [tests/test_finalize_history_scope.py](../../../tests/test_finalize_history_scope.py), [tests/test_rd04_component_fields.py](../../../tests/test_rd04_component_fields.py), [tests/test_rd04_selective_apply.py](../../../tests/test_rd04_selective_apply.py).

## 설계 이유와 출처

scope 필터와 limit의 순서가 사용자 기록 보존의 핵심이다. 전체 활동량이 현재 페이지의 operation을 숨기지 않는 관찰 가능한 결과를 고정하고, 기준의 잘못된 문자열로 정상 소스를 거절하지 않도록 한다.

## 호환성·이관·복구

최대 history 80개 제한은 유지한다. 제품 history 구현이나 journal schema를 바꾸지 않으며 다른 scope 데이터 노출을 허용하지 않는다. 테스트 자료는 임시 폴더에서 생성한다.

## 검증과 미검증

Git 원문에서 원래 request ID 포함과 len(rows)≤80 assertion을 확인했다. 기준 커밋 자체의 제품 성공으로 기록하지 않으며 제품 필터 순서의 수정·실행 증거는 별도로 필요하다.

## 한계와 후속 개선

81개 cross-scope fixture는 동시 쓰기·장기 보관 정책 전체를 증명하지 않는다. native telemetry와 실제 GUI history 표시는 별도 인수 범위다.
