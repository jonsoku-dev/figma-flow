# fix: preserve authored graph edits across capture regeneration

## 문제와 계기

캡처를 다시 읽어 `graph.json`을 생성하면 이전에 검토한 사람이 수정한 node/edge 필드를 새 proposal이 덮을 수 있었다. 또한 graph가 검토·생성 중 바뀌는 경우와 입력 원본이 없어졌을 때 안전한 결과가 정의되지 않았다. 이 커밋은 이전 proposal을 기준으로 삼는 three-way merge, stale SHA guard와 파일 잠금을 추가한다.

## 결과 동작

`reconcile(current, proposal, baseline)`은 node `id`와 edge `(from,to,type)`로 행을 맞춘다. baseline 이후 source만 바뀌면 proposal을 반영하고 authored 값만 바뀌면 보존한다. 같은 scalar를 양쪽에서 다르게 바꾸면 `Graph edit conflicts`로 중단한다. baseline 없는 첫 실행은 기존값을 우선하며 그 차이는 `retained_legacy_edits`에 기록한다. source에서 사라진 기존 행은 `retained_without_source`로 보존한다. 출력 relationship의 양 끝 노드도 다시 검사한다.

`build()`는 `.figma-flow/last-source-proposal.json` 또는 `--base-graph`로 merge base를 선택한다. `--proposal-out`은 design root 밖 새 경로에만 저장하며, `--expected-sha256`는 이전 graph bytes와 다르면 조기에 거부한다. `graph.json.lock` 아래 임시 출력으로 생성하고, commit 직전 graph SHA를 다시 확인한 뒤 각 출력물을 교체한다.

## 변경 파일과 인터페이스

첫 부모 `35c6d3e3e798dee10c51335719d6ef9cd0539fb8` 대비 `apps/little-hands/design/source.py`, `apps/little-hands/design/README.md`, `apps/little-hands/.gitignore`가 바뀌었다. CLI에 `--base-graph`, `--proposal-out`, `--expected-sha256` 옵션이 추가되고 `build(base_graph=None, proposal_out=None, expected_sha256=None)`로 전달된다. lock file은 ignore 목록에 들어간다.

## 설계 이유와 출처

생성 제안과 현재 canonical graph를 이전 proposal이라는 세 번째 값과 비교해야 source update와 사용자 편집을 구분할 수 있다. 행별 identity merge는 배열 order 변화가 아니라 ID와 edge key를 기준으로 판단한다. stale hash는 사람이 승인한 바이트와 generator가 실제 읽은 graph가 다른 상태에서 publish하는 일을 막는다. 사용자 지침과 옵션, 재실행 복구 설명은 design README에 기록했다.

## 호환성·이관·복구

기존 `graph.json`은 자동으로 초기 baseline이 있다고 가정하지 않는다. baseline file이 없는 기존 graph는 legacy path로 처리하고 기존값을 보존해 review report에 남긴다. 다음 실행의 three-way 비교를 위해 `.figma-flow/last-source-proposal.json`을 관리하며, 다른 clone으로 옮길 때는 이전 proposal을 `--proposal-out`으로 내보내고 `--base-graph`로 지정한다. 새 lock file은 ignore된다. 생성 중단 후에는 같은 입력으로 다시 실행하고 graph/spec/layout hashes를 확인한다.

## 검증과 미검증

후속 acceptance `python3 -B -m unittest discover -s apps/little-hands/design -p test_regeneration.py`는 현재 checkout에서 2 tests pass했다. 이 검사는 conflict 및 stale SHA 거부, 반복 생성에서 canonical edits와 specifications hash 보존, 실패 때 기존 출력 보존을 검사한다. generated output을 file-by-file 교체하므로 프로세스가 여러 교체 중 죽는 모든 중단 지점에서 전체 output set이 원자적으로 바뀐다는 보장은 없다. 실제 Figma native readback은 이 commit의 검증 범위가 아니다.

## 한계와 후속 개선

알려진 baseline 없는 과거 graph의 edit와 generated proposal을 완전히 구별할 수 없으므로 기존 값을 보존하고 `retained_legacy_edits`에 남겨 수동 검토를 요구한다. Source-removed rows는 자동 삭제하지 않는다. Multi-file publish는 graph lock과 per-file replace를 쓰지만 전체 directory snapshot transaction은 아니다.
