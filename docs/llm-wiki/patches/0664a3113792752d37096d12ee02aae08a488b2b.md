# test: require explicit native-started from the claimed runtime

## 문제와 계기

claim만으로 native-started를 기록하면 실제 실행 시작과 timeout을 구분할 수 없다. 이 커밋 0664a3113792752d37096d12ee02aae08a488b2b의 검사는 note_native_started가 없어 `native-started must be an explicit authenticated runtime event`로 실패한다.

## 결과 동작

tests/test_rd08_native_started.py는 함수가 없으면 위 문구로 끝난다. 함수가 있으면 claim 직후 단계는 queued와 claimed뿐이고, 다른 runtime·claim·client operation ID는 거절된다. 일치하는 runtime 전달만 native-started를 한 번 더하고 상태는 claimed로 남는다. 그 뒤 정상 result는 result-received를 덧붙인다. lifecycle이 없는 요청은 단계를 만들지 않는다.

## 변경 파일과 인터페이스

tests/test_rd08_native_started.py만 추가했다. tools/figma_control.py와 figma-bridge/workspace_control.js는 이 커밋에서 바꾸지 않았다. 검사는 python3 -B -m unittest tests.test_rd08_native_started로 실행한다.

## 설계 이유와 출처

RD-08 작업 3은 claim과 runtime 검사를 포함한 명시적 native-started 전달이다. 이 사건은 성공이나 완료 증거가 아니다.

## 호환성·이관·복구

이 커밋은 검사를 고정할 뿐 요청 스키마를 바꾸지 않는다. 기존 poll과 result 경로는 그대로다.

## 검증과 미검증

로컬 unittest는 종료 코드 1이고 stderr의 마지막 assertion은 `native-started must be an explicit authenticated runtime event`다. 실제 Figma 실행은 관찰하지 않았다.

## 한계와 후속 개선

실패 기준은 합성 plugin 응답이다. 구현은 별도 커밋 24730598c912ef01c3da487193fa44e011981e7d에서 검사 blob을 유지한 채 추가한다. 화면 단계 표시는 통과로 기록하지 않는다.
