# feat: confirm the html channel as the input record route

## 문제와 계기

기준 e4f974ffeed2f9509c948141bce42de13027d157는 confirm_input_record_route가 없어 `input record route must stay on the html channel`로 실패했다.

## 결과 동작

confirm_input_record_route는 HTML 자산이 input_effect.project의 html_channel에서 freshness와 write_record를 거쳐 figma_workspace.prepare의 private task artifact로만 간다고 반환한다. ImportPanel은 소비자가 아니고 cli_flag는 없다. 설계서에 같은 문장을 적었다. project는 지금도 html 입력이 있을 때 html_channel을 호출한다. prepare의 인자 목록은 이 커밋에서 늘리지 않았다.

## 변경 파일과 인터페이스

tools/input_effect.py에 confirm_input_record_route를 추가했다. docs/development-roadmap/RD-05-asset-inventory/design.md에 확정 경로를 적고 tasks.md에 작업 1의 범위를 적었다. tests/test_rd05_input_route.py blob은 기준과 같다.

## 설계 이유와 출처

RD-05는 목록의 원본을 input-effect record 하나로 둔다. UI가 HTML을 다시 파싱하거나 ImportPanel의 선택 파일 목록을 재사용하면 상태 의미가 달라진다. 새 CLI flag는 경로를 확인한 뒤에만 정한다.

## 호환성·이관·복구

기존 project, freshness, write_record, prepare 호출 인자는 그대로다. record가 없는 task는 이 함수가 목록을 만들어 주지 않는다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd05_input_route`를 기준 e4f974ffeed2f9509c948141bce42de13027d157에서 종료 코드 1, 대상 389964b782c69b05fc305c094640132a8aea7a44에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 마지막 assertion은 `input record route must stay on the html channel`이다. 조건은 RD-05-REQ-01이다. 같은 구현에서 input effect CSS 검사도 종료 코드 0이었다. prepare가 record를 복사하는 동작과 브라우저 로딩은 관찰하지 않았다.

## 한계와 후속 개선

이 커밋은 경로를 고정할 뿐 record를 task artifact로 복사하지 않는다. hash-pinned input record는 다음 단위다. AC의 화면 표시는 통과로 기록하지 않는다.
