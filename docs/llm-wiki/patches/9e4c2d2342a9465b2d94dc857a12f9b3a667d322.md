# 공개 아카이브 검증기의 실행 환경 교정

소스 커밋 `9e4c2d2342a9465b2d94dc857a12f9b3a667d322`

## 문제와 계기

GitHub Ubuntu의 아카이브 검사가 실제 Codex OS sandbox를 쓰는 두 사례와 워크숍 재생성의 실행 제한에서 막혔다.

## 결과 동작

아카이브 검사가 macOS의 네이티브 sandbox와 실행 전용 MySQL 8.4를 사용한다.

## 변경 파일과 인터페이스

`library/delivery/reference-guard.yml.in`, `.github/workflows/reference-guard.yml`, `library/delivery/graph.json`과 `tests/test_delivery_review.py`를 갱신했다.

## 설계 이유와 출처

실제 격리 검사를 생략하지 않고 성공하는 플랫폼에서 실행한다. Codex CLI 공급 지문을 설치 전에 검증한다.

## 호환성·이관·복구

Linux의 기존 앱 CI와 제품의 배포 이미지 설정은 이어진다. Mac DB와 ZIP은 해당 GitHub 실행에서 정리한다.

## 검증과 미검증

로컬에서 정상·손상 CLI 아카이브에 대한 설치 단언과 10개 배포 관련 테스트가 통과했다. 원격의 새 실행과 최종 결과는 태그 검증에 연결한다.

## 한계와 후속 개선

릴리스 검증은 macOS 러너의 실제 아카이브를 기준으로 확인한다. 기존 Figma 워크스페이스의 권한은 제품 계약에서 관리한다.
