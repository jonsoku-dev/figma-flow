# test: pin real import axes and pure observation behavior

## 문제와 계기

단순 import/문자열 검사만으로는 CSS 대비 함수가 프로세스를 실행하지 않는지, independent variant axes가 실제 importer에서 빠짐없이 작성되는지 확인할 수 없었다.

## 결과 동작

CSS 대비 호출 중 subprocess.Popen을 실패시키고 제공 관찰 []를 그대로 소비하는지 확인한다. 새 Node 검사는 실제 compile_design 결과와 code.js의 importer loop를 실행해 모든 선언 variant가 정확히 한 번 작성되고 미선언 조합은 생기지 않도록 요구한다.

## 변경 파일과 인터페이스

finalize_input_audit.py의 AST 검사를 행동 검사로 바꾸고 rd01_import_axes_acceptance.cjs를 추가했다. design.json/axes.json → compile_design → 실제 importer loop → component set/TEXT property reference가 실행 경로다.

변경 경로: [tests/finalize_input_audit.py](../../../tests/finalize_input_audit.py), [tests/rd01_import_axes_acceptance.cjs](../../../tests/rd01_import_axes_acceptance.cjs).

## 설계 이유와 출처

함수 이름이나 금지 문자열의 부재보다 경계에서 관찰되는 동작이 중요하다. importer 함수 자체를 대체하지 않되 무관한 token styling만 fixture로 두어 축 작성과 label property 연결을 좁게 검사한다.

## 호환성·이관·복구

제품 API나 component 정의는 바꾸지 않는다. Python 표준 라이브러리 mock과 Node VM을 사용하는 기준 파일이며 Figma API 부분은 모형이다.

## 검증과 미검증

Git 원문에서 field/Variant=default와 field/state=disabled, 전체 variant 개수, 쉼표 조합 부재, TEXT definition assertion을 확인했다. 이 페이지 작성 중 역사 테스트는 실행하지 않았다.

## 한계와 후속 개선

VM의 variant 작성 통과는 실제 Figma 라이브러리 import·컴포넌트 사용성 인수가 아니다. CSS 관찰을 제공한 사실도 브라우저 네트워크 관찰의 진위를 보증하지 않는다.
