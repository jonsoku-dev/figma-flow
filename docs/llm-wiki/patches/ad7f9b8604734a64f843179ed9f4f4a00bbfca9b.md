# ad7f9b8 · 업로드 전 과대 요청 거절 테스트 수정

이 기록은 원본 커밋 `ad7f9b8604734a64f843179ed9f4f4a00bbfca9b`의 실제 diff와 파일 경로를 기준으로 작성했다.

## 문제와 계기

요청 크기 초과 상황에서 서버가 연결을 먼저 닫고 클라이언트 테스트가 큰 본문을 보내면서 macOS CI에서 전송 경쟁이 생길 수 있었다.

## 결과 동작

tests/test_serve_design_routes.py는 큰 본문을 보내는 대신 Content-Length만 제한 초과로 전달한다. route_design.route가 호출되지 않는지 확인해 본문 처리 전 413 거절을 단언한다. CHANGELOG/README/plugin metadata가 0.20.1로 갱신된다.

## 변경 파일과 인터페이스

경계는 POST /plan의 Content-Length 검사이며 응답 계약은 413과 JSON 오류, 정확한 Content-Length 헤더다. 테스트는 patch.object로 route 호출 여부를 확인한다.

## 설계 이유와 출처

서버 동작 제한을 바꾸지 않고 테스트가 업로드/연결 종료 경쟁을 만들지 않게 하는 안정화다.

## 호환성·이관·복구

요청 거절 상태·오류 내용은 이전 테스트와 같은 의도다. 새 검증은 chunked/실제 대용량 본문 업로드 동작을 다루지 않는다.

## 검증과 미검증

테스트 코드가 기대 검증을 담고 있음을 확인했다. 실제 macOS CI 실행 성공은 이 커밋에 없다.

## 한계와 후속 개선

큰 본문을 실제로 업로드할 때의 네트워크·자원 제한 검증은 별도다.
