# test: keep input route independent of fact options

## 문제와 계기

일반 HTML projection이 필요한 사실 옵션을 html_channel로 전달할 수 있게 되면, 기존 테스트의 정확한 두 인자 호출 문자열은 정상 경로까지 거절한다. route 검사의 책임과 인자 표기 의존성을 분리할 필요가 있었다.

## 결과 동작

검사는 project 정의 뒤에 channels[html]의 html_channel 호출이 있다는 사실을 확인하며 path/root 두 인자에만 고정하지 않는다. freshness가 write_record보다 먼저 정의되고 argparse는 workspace CLI가 소유한다는 기존 검사는 그대로 남는다.

## 변경 파일과 인터페이스

[test_rd05_input_route.py](../../../tests/test_rd05_input_route.py)의 source.index 비교 한 줄만 변경했다. input_effect.project → html_channel 호출 순서를 확인하는 문자열에서 고정 인자 suffix를 제거했다. 제품 함수·시그니처·CLI는 바꾸지 않았다.

## 설계 이유와 출처

route 테스트가 확인해야 할 대상은 HTML 채널 생산자의 연결이며 fact 옵션의 개수나 문법은 별도의 행동 oracle이 맡는다. 새 입력 옵션이 같은 실행 경로를 사용해도 테스트가 불필요하게 깨지지 않도록 최소 수정했다.

## 호환성·이관·복구

--input-record/--input-root admission, ImportPanel 비소비자 경계, freshness/write_record 순서 등의 기존 요구는 삭제하지 않는다. 이 변경은 권한·입력 검증을 낮추는 제품 수정이 아니라 signature에 결합된 검사 문자열의 정정이다.

## 검증과 미검증

Git diff에서 html_channel 호출 prefix만 남기고 다른 assertion이 보존되었음을 확인했다. 당시 기준 통과나 입력 제품 동작을 이번 정적 검토로 새로 확정하지 않는다. 실제 모호성 처리의 결과는 finalize_normal_input 기준과 후속 제품 구현을 따로 확인해야 한다.

## 한계와 후속 개선

문자열 순서 검사는 해당 함수가 실행되거나 올바른 옵션을 전달한다는 증명이 아니다. 실제 project와 freshness를 호출하는 행동 검사 및 현재 CLI 검증이 별도로 필요하다.
