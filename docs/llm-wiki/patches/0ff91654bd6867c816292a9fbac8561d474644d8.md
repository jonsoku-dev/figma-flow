# feat: keep declared variant axes on existing definitions

## 문제와 계기

기준 008c01c64e41b255c43b7e81e4029f4368b1f797는 회귀 디자인 시스템의 size·state 축이 컴파일 결과에 없어 `declared axes must be preserved without new combinations`으로 실패했다.

## 결과 동작

axes.json의 size sm·md와 state disabled·loading·error만 button의 기존 variant에 연결된다. field의 default는 state 축에 들어가지 않는다. sm과 disabled를 곱한 조합, 입력에 없는 사용 설명, swap target은 만들어지지 않는다. 축이 없는 컴포넌트는 Variant 축으로 남는다. 입력 usage 문장이 있으면 그 문장만 description이 된다.

## 변경 파일과 인터페이스

tools/design_system.py의 attach_declared_axes와 tools/input_effect.py의 design channel이 실제 axes.json을 기록한다. figma-bridge/code.js의 componentVariantGroups는 축마다 기존 variant만 묶고, componentUsageText와 componentSwapTargets는 선언된 값만 반환한다. 검사 보조 수정은 tests/variant_axes_oracle.cjs다. tests/test_variant_axes.py blob은 기준과 같다.

## 설계 이유와 출처

독립 축의 이름을 보존하되 존재하지 않는 조합을 생성하지 않는다. RD-01 설계서의 variant_axes·usage 경계와 AC-05를 따른다. 사용 설명은 입력 문장 없이 만들지 않는다.

## 호환성·이관·복구

축 선언이 없는 패킷은 단일 Variant 이름과 component-set semantic id를 유지한다. 기존 variant 스타일, semantic key, 변수 binding을 지우지 않는다. 여러 축은 component-set:이름:축으로 나누고 서로 곱하지 않는다.

## 검증과 미검증

종료 게이트가 기준 unittest 종료 코드 1과 대상 0ff91654bd6867c816292a9fbac8561d474644d8의 종료 코드 0을 다시 실행했다. design system, 회귀 입력의 unsupported axes, variant set 반지름, 너비 공유 oracle, 가져오기 lifecycle도 통과했다. 실제 Figma variant 속성과 description 패널은 관찰하지 않았다.

## 한계와 후속 개선

이 단위는 RD-01의 마지막 작업이다. RD-02의 선언된 컨테이너 계층은 아직이다. 61개 회귀 전체, 실기기, 클라우드 저장은 완료로 세지 않는다.
