# feat: pair an existing-page booking CTA with real browser and native edits

## 문제와 계기

기존 페이지의 반복 제작은 소유 프레임을 식별해야 했다. 실제 앱과 네이티브 양쪽에서 변경한 값과 재시도·충돌 결과를 같은 그래프에 연결해야 했다.

## 결과 동작

현재 페이지의 예약 CTA 메인과 두 인스턴스를 소유 프레임에 만든다. 페이지·형제·기존 ID를 확인해 재사용하고 그래프 색을 웹과 네이티브로 투영한다. 역수입은 fresh read·dry-run·graph SHA 조건을 확인한 후 저장한다.

## 변경 파일과 인터페이스

`tools/starter_cta.py prepare`가 실제 전체 읽기와 정본을 고정한다. `tools/native_edit.py`와 `figma-bridge/native_provision.js`가 기존 작업 실행 계약으로 적용한다. `tools/graph_sync.py`의 점→슬래시 변수 이름 매핑을 추가했다. `publish_design_system.py`와 소스 생성기가 영속 결과와 명세를 작성한다.

## 설계 이유와 출처

무료 초안의 기존 페이지에서 수동 레이어와 충돌하지 않는 작업 영역을 골랐다. 지원 API에서는 dynamic-page의 비동기 main getter와 변수의 remove 메서드를 사용해야 한다. 파일별 실제 ID는 비공개 실행 계획에만 있다.

## 호환성·이관·복구

충돌과 불확실한 쓰기는 전체 읽기로 실제 상태를 재확인한다. 이름 변환이 충돌하면 적용을 중단한다. 기존 데이터·소스 캡처를 보존하고 구버전 요청에 대한 작업 이력과 게터 근거를 유지한다.

## 검증과 미검증

초기 · 정방향 · 역방향 3개의 pairing이 각각 실제 Figma getter와 브라우저 측정에 통과했다. 기존 96개 노드의 주요 getter를 대조했다. 새 7개 노드는 메인·인스턴스·텍스트를 포함하고 이후 2회 재적용에서 변경 수 0과 동일한 ID를 확인했다. 실제 캡처 44개로 재생성한 명세도 최종 SHA와 일치했다.

## 한계와 후속 개선

첫 생성 후 TEXT 검색이 실패해 실제 생성물을 재탐색했다. 동기 main getter, 이름 정규화 오류를 실제 편집기에서 찾아 수정했다. 별도 사용자 계정·정확히 3페이지인 Starter 팀 파일·실물 모바일 기기는 이번 관측 범위 밖이다. 다른 컴포넌트와 파일의 인수 조건은 후속 설계에 남긴다.
