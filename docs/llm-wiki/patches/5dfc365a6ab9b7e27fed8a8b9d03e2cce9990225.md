# test: require the journal to survive restart when result delivery fails

## 문제와 계기

결과 POST가 도착하지 않은 채 서버 메모리가 지워지면 기록된 단계와 미확정 쓰기 차단이 HTTP 경로에서 유지되는지 고정되어 있지 않았다. 이 커밋 5dfc365a6ab9b7e27fed8a8b9d03e2cce9990225의 검사는 restart_delivery_report가 없어 `restart must keep the journal when result delivery fails`로 실패한다.

## 결과 동작

tests/test_rd08_restart_delivery.py는 함수가 없으면 위 문구로 끝난다. 함수가 있으면 HTTP claim과 native-started 뒤 결과 없이 메모리의 runtime 기록을 지운다. 같은 operation은 uncertain이고 단계는 queued, claimed, native-started, uncertain이다. 같은 mutation은 다시 enqueue되지 않고 새 poll은 그 작업을 다시 넘기지 않는다. 요청 파일은 하나다.

## 변경 파일과 인터페이스

tests/test_rd08_restart_delivery.py만 추가했다. tools/figma_control.py는 이 커밋에서 바꾸지 않았다. 검사는 python3 -B -m unittest tests.test_rd08_restart_delivery로 실행한다.

## 설계 이유와 출처

RD-08 작업 6은 서버·플러그인 재시작과 결과 전달 실패를 실제 제어 경로에서 확인한다. 단계의 근거는 디스크의 요청 파일이어야 한다.

## 호환성·이관·복구

이 커밋은 검사를 고정할 뿐 요청 스키마를 바꾸지 않는다. 기존 uncertainty blocking은 그대로다.

## 검증과 미검증

로컬 unittest는 종료 코드 1이고 stderr의 마지막 assertion은 `restart must keep the journal when result delivery fails`다. Figma Desktop은 열지 않았다.

## 한계와 후속 개선

실패 기준은 로컬 HTTP 서버다. 구현은 별도 커밋 4eab91b666eaeead1fe04395f248f936cdb51b7d에서 검사 blob을 유지한 채 추가한다. Figma 안에서의 플러그인 재실행은 통과로 기록하지 않는다.
