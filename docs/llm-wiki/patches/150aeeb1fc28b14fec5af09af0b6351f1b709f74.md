# 직접 검증기 import 호환성 복구

커밋 `150aeeb1fc28b14fec5af09af0b6351f1b709f74`

## 문제와 계기

공용 격리 helper의 직접 import가 파일 실행에서는 가능하지만 tools 패키지 소비 경로에서는 실패했다.

## 결과 동작

maintenance와 patch_knowledge_check가 패키지 실행 시 상대 import, 단독 실행 시 직접 import를 사용한다.

## 변경 파일과 인터페이스

tools/maintenance.py와 tools/patch_knowledge_check.py의 private_test_config import만 수정했다.

## 설계 이유와 출처

실행 방식에 맞춰 sibling을 선택하면 호출자가 별도 PYTHONPATH를 설정하거나 전역 모듈을 설치할 필요가 없다.

## 호환성·이관·복구

검증기 함수 서명과 CLI, 테스트 프로세스의 임시 XDG 수명 및 기존 오류 판정을 보존한다.

## 검증과 미검증

새 Python의 패키지 import·단독 실행과 기존 verification retention 및 maintenance contract 검사를 통과했다.

## 한계와 후속 개선

제어 호스트 지문은 같지만 네이티브 trusted_sources는 tools 파일 바이트도 포함한다. 최종 후보에서 해당 지문과 실앱 관측을 확인한다.
