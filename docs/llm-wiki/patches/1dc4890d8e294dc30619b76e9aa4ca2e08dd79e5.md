# feat: rank remaining graph members and probe typed CSS and text operations

## 문제와 계기

API audit membership alone did not say which exact members were worth inspecting or safe to call. The early native probe also needed bounded CSS and text-range methods instead of an unrestricted method runner.

## 결과 동작

`tools/api_priority.py` ranks every exact-key audit member by declared role terms, receiver applicability, editor and permission gates, and method scenario. `tools/native_api_probe.py` and its bridge add explicit cases for CSS and text range reads while retaining exact node and property allowlists.

## 변경 파일과 인터페이스

New APIs include `build`, `queue`, optional receiver and feasibility filters, an exact-key ranked inventory, and bounded native probe cases. `docs/api-priority.md` and `docs/native-api-probe.md` explain use and limits.

## 설계 이유와 출처

Priority is an order for evidence gathering, not a runtime capability claim. Read-only methods and purpose-approved writes use separate allowlists. Unknown receiver, type-only, permission-gated, and unreviewed methods remain in the full inventory.

## 호환성·이관·복구

New CLI outputs use caller-supplied paths and refuse no existing data by default beyond their ordinary output behavior. The probe retains its scope, selection, response-size, projection, and write limits.

## 검증과 미검증

Tests cover exact member retention, receiver candidates, probe methods, graph status, and feasible queue ordering. The final integrated observation record contains 253 typed-probe calls across 50 distinct members; later commits add 19 exact typography IDs with 10 net new members. Current total and limits are in [editable-web verification](../../editable-web-verification.md#api-observations).

## 한계와 후속 개선

Ranking scores do not demonstrate method success. Audit data and type declarations are not runtime evidence. Most methods still need separate reviewed scenarios, and this commit does not prove every candidate against Figma.
