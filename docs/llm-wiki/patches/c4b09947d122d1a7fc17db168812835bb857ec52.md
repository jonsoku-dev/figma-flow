# Codex에서 관리하는 Design 중계기와 상태 뷰어

## 문제와 계기

사용자는 작업 요청·설정·승인·복구·결과 해석을 한 Codex 대화에서 진행하고 Figma에서 실제 디자인과 실행 상태를 확인하고자 했다.

## 결과 동작

`c4b09947d122d1a7fc17db168812835bb857ec52`은 등록된 Design 플러그인의 홈을 읽기 전용 뷰어로 바꾸고 Codex에 현재 선택·환경 조회와 범위를 확인한 프로필 설정 경로를 추가한다.

## 변경 파일과 인터페이스

`tools/figma_control.py`는 인증된 로컬 폴링에서 문맥과 요청을 연결한다. `figma-bridge/workspace_host.js`와 `figma-bridge/workspace_control.js`는 Figma에서 관찰하고 기기에 저장한다. `panel-ui/src/RelayViewer.jsx`는 현재 맥락을 표시한다.

## 설계 이유와 출처

플랜·좌석 선택지는 기존 기능 정책이 정의한다. 실제 권한은 Figma가 적용한다. 서명된 작업과 디자인 graph, 로컬 선호, 순간 선택을 각각의 기존 저장 범위에 둔다.

## 호환성·이관·복구

동일한 플러그인 ID와 기존 준비 작업을 유지한다. 이전 예제 네 개는 정확한 파일·페이지에 준비한 native-edit 작업으로 실행한다. 등록된 플러그인은 대상 파일에서 열어 둔다.

## 검증과 미검증

자동 검사는 맥락 갱신·만료·상충 작업, 읽기와 작성 구분, 선택 상한, 계정·파일 격리, 첫 실행 및 동일 예제 재적용, 발행 자산과 기존 릴레이 회귀를 대조한다. 실제 Figma의 검증 범위는 버전 대조표에 기록했다.

## 한계와 후속 개선

여러 창에서는 실제 대상 파일·페이지를 먼저 대조한다. 새로 준비한 세대를 실행하려면 등록한 플러그인을 다시 연다. 유료 좌석의 Dev/Inspect 및 계정 청구 내역은 이 변경에서 검증하지 않았다.
