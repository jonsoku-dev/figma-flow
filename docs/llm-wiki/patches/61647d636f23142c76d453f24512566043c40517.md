# feat: capture a live carousel through a local Chromium pipe

## 문제와 계기

web-carousel 컴파일러는 관찰 JSON이 있어야 하지만, 그 입력을 만들려면 사람이 브라우저에서 상태를 하나씩 기록해야 했다. 개발 초기의 수동 관찰 영수증에서는 드래그 직후 활성 카드 판정이 비어 있었다(activeIndex -1). 자동재생이 마지막에서 첫 카드로 스크롤되는 약 0.2초 사이에는 중간 카드 세 개가 차례로 활성으로 잡혀 상태 경계가 불안정했다.

## 결과 동작

`tools/web_carousel_capture.mjs`가 임시 프로필의 headless Chromium을 `--remote-debugging-pipe`로 실행하고, 390×844 모바일·터치 에뮬레이션으로 페이지를 연다. `--rail` 선택자에 맞는 유일한 가로 스크롤 레일을 화면 중앙 근처로 맞추고, 레일 중심에 가장 가까운 카드를 현재 상태로 본다. 자동재생 한 바퀴 동안 각 상태가 안정되면 web_design_capture.js 결과와 PNG를 저장한다. 측정 간격의 중앙값이 `--interval-ms`와 max(500 ms, 20%) 이내인지도 확인한다. 이어서 새 타이머 주기가 시작되면 터치 드래그로 시작 경계, 전체 앞으로, 끝 경계, 전체 뒤로를 차례로 실행해 수동 wrap 여부를 판정한다. 산출물은 새 디렉터리에 배타 생성(0600)으로 쓰고, media·source·web-carousel 단계를 이어 실행해 carousel-graph.json까지 만든다.

## 변경 파일과 인터페이스

변경 경로는 `tools/web_carousel_capture.mjs`이다. 전체 경로와 diff 해시는 이 페이지의 Git 기록에 있다.

## 설계 이유와 출처

브라우저 확장 프로그램이나 계정, 외부 서비스 없이 사용자의 Chromium만으로 재현할 수 있도록 pipe 방식의 CDP를 썼고, 끝나면 프로필을 지운다. 애니메이션 중 지나가는 카드를 상태로 오인하지 않도록 안정 조건(오프셋 2 px 이내, 스크롤 변화 0.25 px 이내)을 두었다. 자동재생 간선은 순서상 다음 카드로 갈 때만 인정한다. 드래그는 타이머 주기가 시작된 직후에 실행해 타이머 전환을 터치 결과로 오인하지 않는다. 제스처 시작점이 레일 안인지는 elementFromPoint로 확인한다. 경계가 비대칭이거나 드래그가 인접 카드로 가지 않으면 추정하지 않고, 명시적 graph가 필요하다는 오류를 내며 중단한다.

## 호환성·이관·복구

포크는 이 커밋과 부모의 변경 경로를 대조해 적용할 수 있다. 캐러셀 CMS나 외부 계정 연결은 필요하지 않다. 원본 화면과 사설 영수증은 로컬에 보존한다.

## 검증과 미검증

실측 영수증의 첫 두 실행은 오류로 중단되었다. 첫 실행에서는 레일 선택자가 유일한 스크롤 레일과 맞지 않았고, 두 번째에서는 제스처 시작점이 레일 밖에 있었다. 이후 실행은 로컬에서 띄운 SaaS 템플릿의 기능 카드 4개를 Chrome 157로 캡처해 상태 4개와 관찰 전이 12개를 기록했다. 전이는 자동재생 4개와 드래그 8개이고, 드래그 중 2개는 경계에서 머문 경우다. 설정값 5000 ms에 대해 측정 간격은 5001~5280 ms, 실행별 중앙값은 5014~5035 ms였다. 이 도구의 자동 테스트는 커밋에 없다. scroll-snap 레일이 아닌 구현(transform 기반 슬라이더 등)과 다른 해상도·DPR은 확인하지 않았다.

## 한계와 후속 개선

여기서 확인한 결과는 해당 입력과 검증 범위에 해당한다. 브라우저의 연속 스크롤 관성이나 물리 모바일 기기의 동작은 별도의 관찰이 필요하다.
