# fix: clip both axes of a browser scroll rail in Design

## 문제와 계기

bcf2dd6가 고정한 대로, 캡처기는 overflowX와 overflowY가 모두 hidden 또는 clip일 때만 프레임 내용을 잘랐다. CSS에서 auto와 scroll도 해당 축의 내용을 상자 밖으로 그리지 않는다. 그래서 가로 스크롤 레일을 Design으로 가져오면 화면 밖 인접 카드가 레일 프레임 밖으로 드러났다. 수정 전 Figma 첫 화면에서도 레일 왼쪽 가장자리에 인접 카드 글자가 겹쳐 보였다.

## 결과 동작

web_design_capture.js는 이제 두 축이 모두 hidden·clip·auto·scroll 중 하나일 때 clipsContent를 true로 둔다. 변경은 2줄이다. 한 축이라도 visible이면 이전처럼 자르지 않는다. 기존 graph 필드인 clipsContent의 값만 바뀌므로 스키마와 플러그인 렌더러는 바뀌지 않는다.

## 변경 파일과 인터페이스

변경 경로는 `tools/web_design_capture.js`이다. 전체 경로와 diff 해시는 이 페이지의 Git 기록에 있다.

## 설계 이유와 출처

CSS 계산 스타일에서 한 축이 visible·clip이 아닌 값이면 다른 축의 visible은 auto로 계산된다. 따라서 두 축이 모두 visible이 아닌 경우가 실제로 내용이 잘리는 경우와 맞다. Figma 프레임의 clipsContent는 축별로 지정할 수 없으므로, 두 축이 모두 자를 때만 켜서 한 축만 자르는 요소를 과하게 자르지 않게 했다.

## 호환성·이관·복구

포크는 이 커밋과 부모의 변경 경로를 대조해 적용할 수 있다. 캐러셀 CMS나 외부 계정 연결은 필요하지 않다. 원본 화면과 사설 영수증은 로컬에 보존한다.

## 검증과 미검증

독립 gate가 별도 로컬 복제에서 59dba56과 2078ea9을 실행해 개선 전 실패와 개선 후 통과(CAROUSEL-CLIP)를 기록했다. 수정 후 실측 캡처 graph에서는 네 상태의 레일 프레임 clipsContent가 모두 true였다. 수정 전 캡처에서는 모두 false였다. 수정 후 Figma 적용 화면을 스크린샷으로 비교해 레일 가장자리 겹침이 사라졌음을 확인했다. Figma 읽기 영수증은 clipsContent를 기록하지 않으므로, Figma 쪽 확인은 시각 비교뿐이다.
