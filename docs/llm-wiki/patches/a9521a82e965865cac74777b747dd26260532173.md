# a9521a8 · 시작 검사 중 복구된 네이티브 상태 보존

## 문제와 계기
Startup 검사는 불확실 네이티브 작업을 발견해 게시를 막아야 하지만, 오래된 uncertain read만 남아 있어도 mutation이 계속 차단되거나 malformed uncertainty marker를 느슨하게 읽을 수 있었다.

## 결과 동작
`tools/plugin_startup.py`는 `pending`/`claimed` 요청을 active 상태로 거부하고, uncertain request는 mutation일 때만 차단 사유로 본다. marker가 있으면 `figma_control.SCHEMA`, object shape, `operations` dictionary를 확인하고 그 내용을 기준으로 불확실성을 계산한다. marker가 없을 때는 ledger 내 uncertain mutation을 fallback 검사한다.

## 변경 파일과 인터페이스
`tools/plugin_startup.py`, `tests/test_plugin_startup.py`, `specs/startup-freshness/spec.md`, changelog. startup 결과 형식보다 active/uncertain 판정 로직이 달라졌다.

## 설계 이유와 출처
근거: 전체 커밋 `a9521a82e965865cac74777b747dd26260532173`; `HostAdapter` startup 검사, `figma_control.SCHEMA`, `tests/test_plugin_startup.py`. 읽기 작업과 mutation 위험을 나누고 malformed private state를 유효한 상태처럼 취급하지 않는다.

## 호환성·이관·복구
정상 marker는 같은 schema로 읽는다. malformed marker는 검사를 실패시키므로 상태를 수동 확인해야 한다. uncertain read만 있는 경우 mutation 차단 사유가 되지 않는다.

## 검증과 미검증
startup 테스트 40줄이 추가됐다. 테스트 실행 결과와 plugin 실제 시작 검증은 커밋에 없어 미검증이다.

## 한계와 후속 개선
marker 없는 구형 ledger와 marker가 있는 현재 경로를 함께 지원한다. startup check와 동시 state update 경합은 별도 검증이 필요하다.
