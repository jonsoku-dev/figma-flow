# chore(api): refresh static API coverage baseline for final P2 read sources

## 문제와 계기

`native_read_measurement.js`([a5e4a09](a5e4a098726872e9953e92da36065f4789f22811.md))와 `native_semantic_read.js`([3b3fa8f](3b3fa8f0d986ee3d2b8dae1d37b2a7e2f377965e.md))가 바뀌어 static API coverage baseline의 source digest가 맞지 않았다.

## 결과 동작

커밋 `9669bc53007b544dc7ca49d6760e59786dd52f1a`는 두 파일의 SHA-256을 갱신했다. member 분류와 count는 바뀌지 않았다.

## 변경 파일과 인터페이스

`library/figma-api/coverage-baseline.json` 2줄.

## 설계 이유와 출처

공식 generator만 쓴다. recipe helper는 `tools/workspace_recipes.py verify-helpers`가 verified였고 `library/figma-recipes/build.py`가 diff를 만들지 않아 바꾸지 않았다.

## 호환성·이관·복구

생성 메타데이터만 바뀌었다. 통합되지 않은 중간 갱신 후보는 이 커밋으로 대체했다.

## 검증과 미검증

`3b3fa8f`에서 `--check-baseline` 실패, `--write-baseline` 성공, `--check-baseline` 통과. 두 digest는 파일 bytes와 같다. `9962afa` 이후 reader diff는 `utf8JsonBytes` 본문뿐이다.

## 한계와 후속 개선

최종 fixture 정본화 [13551ac](13551acbd622510721c128bcfea14f5be1c78d6c.md)은 `examples/owned-production-workspace/`의 파일 4개와 검사 4개를 바꿨다. coverage baseline의 source 범위인 top-level `figma-bridge` JavaScript와 recipe는 바뀌지 않았으므로 생성물 갱신이 필요 없었다.
