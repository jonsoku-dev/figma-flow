# test: pin scoped discovery summary behavior

## 문제와 계기

실제 R7 Django/native 앱의 일반 discovery 경로에서는 summary에 도달할 수 없고, 무관한 admitted payload를 요구하는 ImportPanel에만 요약 기능이 있었다. 일반 graph discovery에서 별도 읽기 전용 summary를 요청하되 full 기본값과 변경 근거의 경계를 보존하는 기준을 고정했다.

## 결과 동작

새 frozen oracle은 native-summary action이 허용된 primary page의 width/height만 읽고 figma-flow-native-read-summary-v1의 명시적 partial coverage를 반환하도록 요구한다. 일반 read는 계속 모든 admitted page의 full discovery여야 한다. 제품 소스 구현은 이 커밋에 없다.

## 변경 파일과 인터페이스

[finalize_discovery_summary.cjs](../../../tests/finalize_discovery_summary.cjs)를 추가했다. 실제 graph_sync.discovery_bundle을 임시 폴더에 생성하고 code.js를 API-shaped VM에서 실행한다. generated session으로 ui.onmessage → readNativeSemantics → readback → audit_log.buildAuditRecord 및 Python normalize 거절까지 연결하며 React/legacy/locales 원문도 검사한다.

## 설계 이유와 출처

요약은 full을 읽고 사후 축약하는 기능이 아니어야 한다. primary와 그 rect의 nodeIds, fields=[width,height], profile=summary, complete=false를 정확히 기록하고 styles/variables/collections/rasterImages/textSegments 생략을 명시한다. fills getter는 0회, page lookup은 primary만이어야 하며 원시 node 크기는 보존한다.

## 호환성·이관·복구

잘못된 session과 mutation action은 무시하고 busy 중 중복·다른 profile 요청을 거절한다. 잘못된 file, secondary로의 전환, loadAsync 도중 scope 변경은 fail closed여야 한다. 일반 full read는 두 admitted page를 읽고 heavy getter를 실행한다. normalize는 summary를 mutation evidence로 받지 않으며 selective apply protocol:2도 유지한다.

## 검증과 미검증

상위 세션이 보존한 제품 수정 전 실행은 `node tests/finalize_discovery_summary.cjs`에서 `AssertionError: standard discovery must accept a separate native-summary action` 및 `0 !== 2`로 실패했다. 이번 작업은 Git diff만 대조했다. 기준은 diagnostic의 complete/node_ids/fields/omitted 보존, React와 legacy의 별도 action·graph-native-summary.json·partial boundary·coverage, 최신 readback 진단 반영과 ko/en/ja 문구를 요구한다. 동시 구현 중인 제품 수정의 통과는 주장하지 않는다.

## 한계와 후속 개선

API-shaped VM의 scope/busy/read 경계 검사와 소스 affordance 검사는 실제 GUI 요약 실행·접근성·렌더링 성공을 증명하지 않는다. React 요약 view 재사용과 legacy parity는 frozen 요구이며 현재 제품 완료 사실이 아니다. 실제 summary GUI 관찰과 전체 native 인수는 별도 미검증 범위로 남긴다.
