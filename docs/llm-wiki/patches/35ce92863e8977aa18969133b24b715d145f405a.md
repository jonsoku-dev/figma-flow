# Figma 직접 편집을 Codex에서 감지하고 관측한 값을 동기화

## 문제와 계기

디자이너가 Figma에서 직접 수정하면 Codex가 다음 수동 읽기 요청 전에도 변경을 감지하고 어떤 값이 달라졌는지 확인해야 했다. 기존 상자 정렬 검사에도 글자·아이콘의 실제 표시 범위를 구분할 근거가 필요했다.

## 결과 동작

`35ce92863e8977aa18969133b24b715d145f405a`에서 현재 페이지 nodechange 구독, 인증된 변경 저널, 장기 대기와 재접속, 현재 대화 알림 및 선택된 그래프 역수입을 연결했다. 브라우저 정렬에는 선택적 paint 검사를 추가했다.

## 변경 파일과 인터페이스

`figma-bridge/workspace_changes.js`는 이벤트를 수집하고 `tools/change_journal.py`는 검증된 범위의 커서를 관리한다. `tools/figma_follow.py`가 현재 속성, 로컬 관측, 알림, 충돌 판정을 연결한다. `tools/alignment_pixels.py`는 렌더링 픽셀의 변화 범위를 측정한다.

## 설계 이유와 출처

이벤트는 재조회 신호다. 직접 입력 내용과 속성 값을 알림 문장에 넣지 않는다. 최신 관측과 그래프 반영은 별도이며, 자동 반영은 실제 이벤트가 증명하는 매핑과 graph·web 해시를 대조한다.

## 호환성·이관·복구

기존 108개 준비 작업을 보존하고 현재 Design 파일과 페이지에서만 감지한다. opt-in 텍스트, 이벤트 수신 공백, 오래된 읽기, 그래프 충돌과 유휴 대화 재개 조건을 구분한다.

## 검증과 미검증

검증 사본에서 불투명도를 100%에서 92%로 바꾸고 복원했다. 변경 이벤트 두 건과 현재 값을 확인했다. 로컬 앱 서버에서 검증용 유휴 대화에 메시지를 넣어 새 턴과 응답 완료를 확인했다. 페어링된 그래프와 웹 파일의 반영·보존 조건은 실제 역수입 코드의 자동 테스트로 대조했다.

## 한계와 후속 개선

닫힌 플러그인, 감시 프로세스 종료, 일시적인 리스너 또는 모델 런타임 중단은 즉시 전달을 보장하지 않는다. 별도 유휴 대화의 모델 응답과 실행 중 대화의 큐 접수는 서로 다른 증거다. paint 경계는 지각적 균형의 판정이 아니다.
