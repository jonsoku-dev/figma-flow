# test: compare canonical historical input root

## 문제와 계기

역사 bundle 복원 검사의 임시 root 문자열이 macOS의 /var alias와 canonical 경로 차이로 달라질 수 있었다. 제품이 저장한 정규화된 input_root와 미정규화 fixture 문자열을 비교하면 기능 결함과 무관한 실패가 발생한다.

## 결과 동작

assert_exact_revival은 restored input_root를 str(self.root.resolve())와 비교한다. root가 가리키는 대상의 canonical 경로가 일치해야 하며 단순히 assertion을 삭제하거나 임의 경로를 허용하지 않는다.

## 변경 파일과 인터페이스

[finalize_historical_restore.py](../../../tests/finalize_historical_restore.py)의 root equality 한 줄만 변경했다. CLI admission → retained row 복원 → input freshness=current → canonical input_root 비교의 나머지 경로와 assertion은 그대로다.

## 설계 이유와 출처

private input root의 권한 경계는 같은 실제 디렉터리에 고정되어야 한다. Path.resolve는 플랫폼의 alias 표기를 맞추므로 기대값을 제품의 canonical root 계약과 정렬한다. 기록 복원의 authority를 약화시키는 변경이 아니다.

## 호환성·이관·복구

전체 restored row equality, exact bundle bytes, consumer edge, source freshness와 expected-revision guard는 유지한다. 제품 CLI·source hash·catalogue/retained artifact 판정은 변경하지 않으며 macOS 밖에서도 canonical root를 비교한다.

## 검증과 미검증

Git diff에서 resolve 추가 외 변경이 없음을 확인했다. 이 정정으로 테스트 경로 alias 문제와 제품 복원 실패를 구별할 수 있지만 이번 작업에서 역사 테스트를 실행하지 않았다. 해당 checker commit 자체를 제품 복원 완료로 기록하지 않는다.

## 한계와 후속 개선

canonical 문자열 비교는 모든 symlink 공격이나 동시 파일 교체를 검증하지 않는다. 파일 freshness·명시적 admission·인증된 retained row 검사는 원래 oracle에 남아 있으며 실제 native/GUI 생성은 별도 미검증 범위다.
