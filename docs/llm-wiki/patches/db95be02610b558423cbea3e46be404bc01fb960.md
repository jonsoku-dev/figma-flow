# 예약 인원 정책의 독립 기준 고정

## 문제와 계기

예약 폼, 모델 및 서비스에서 인원 한도를 별도로 해석했다.

## 결과 동작

`db95be02610b558423cbea3e46be404bc01fb960`에서 동일한 격리 앱의 한도를 2명으로 바꿔 각 경계의 동작을 관찰하는 회귀 기준을 보존했다.

## 변경 파일과 인터페이스

`tests/test_booking_group_authority.py`는 실제 Django 폼과 DB 모델의 선언, 트랜잭션 진입 지점을 사용한다.

## 설계 이유와 출처

설정 값이 존재한다는 사실과 사용자 입력을 실제로 거절하는 동작을 구분한다.

## 호환성·이관·복구

기존 앱의 DB와 사용자 데이터는 사용하지 않는다. 새로운 작업공간에 소스를 복사한다.

## 검증과 미검증

수정 전에는 3명도 폼에서 통과해 고정한 단언이 실패했다. 수정 뒤 같은 Git blob을 재실행했다.

## 한계와 후속 개선

운영 계정과 실제 서버 배포 검증은 이 단일 케이스의 범위에 포함되지 않는다.
