# 다중 파일 작업 인덱스의 용량과 관측

커밋 `d2035bc66468b51fef14f8e1c7902391cc0a41fa`

## 문제와 계기

64개 파일이 허용되지만 22자 키만으로도 writer의 포인터가 4,290바이트가 되어 4,096바이트 reader가 거절했다. 모든 슬롯이 활성인 경우에도 이전 writer는 진행 요청의 포인터를 버렸다.

## 결과 동작

지원하는 키 길이로 저장 범위를 계산한다. 포화 상태에서 새 파일을 접수할 때 잠금 안에서 먼저 자리를 확보한다. 종결 기록이 없으면 상태 조회와 대기 방법을 반환하고 요청 파일을 만들지 않는다.

## 변경 파일과 인터페이스

tools/figma_control.py에서 파일별 포인터 해석과 작업 레코드 조회를 공유한다. specs/codex-relay/spec.md와 graph.json에서 CODEX 소유 경계와 고정 검사를 연결한다.

## 설계 이유와 출처

메트릭과 세션은 동일한 비변경 관측을 이용한다. 진행 목록에서 가장 오래된 항목을 건강 상태로 선택해 완료 항목이 진행 작업을 가리지 않는다.

## 호환성·이관·복구

단일 ID 형식은 조회 시 메모리에서 원래 파일을 찾는다. 명시적 status는 기한이 지난 요청을 확정하고 영수증을 보존한다. uncertain 쓰기 보호는 포인터 회수 이후에도 남는다.

## 검증과 미검증

정상 22자·최대 128자 키 64개, 포화 거절 시 요청·영수증 보존, 종결 슬롯 회수와 레거시 직렬화가 통과했다. 독립 health 프로브에서 FileTwo는 pending으로 표시되고 저장 바이트가 같았다.

## 한계와 후속 개선

작업 포인터 수와 과거 영수증 수는 별개다. 전체 제품군·패키징·독립 리뷰는 상위 후보 검사에서 확인한다.
