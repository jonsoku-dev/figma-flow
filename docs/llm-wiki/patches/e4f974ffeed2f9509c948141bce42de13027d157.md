# test: pin the html channel as the only input record route

## 문제와 계기

HTML 자산이 작업 준비로 가는 경로가 하나로 고정되어 있지 않았다. 이 커밋 e4f974ffeed2f9509c948141bce42de13027d157의 검사는 confirm_input_record_route가 없어 `input record route must stay on the html channel`로 실패한다.

## 결과 동작

tests/test_rd05_input_route.py는 함수가 없으면 위 문구로 끝난다. 함수가 있으면 producer는 input_effect.project, channel은 html_channel, freshness와 write_record를 지나 figma_workspace.prepare의 private task artifact가 소비자다. ImportPanel은 소비자가 아니고 cli_flag는 없다.

## 변경 파일과 인터페이스

tests/test_rd05_input_route.py를 추가했다. 제품 코드와 설계서는 이 커밋에서 바꾸지 않았다. 검사는 python3 -B -m unittest tests.test_rd05_input_route로 실행한다.

## 설계 이유와 출처

RD-05 작업 1은 producer에서 task까지의 한 경로를 설계서에 확정한다. 새 CLI flag 이름은 실제 경로를 확인하기 전에 정하지 않는다.

## 호환성·이관·복구

이 커밋은 검사만 고정한다. 기존 project와 prepare 인자는 바꾸지 않는다.

## 검증과 미검증

로컬 unittest는 종료 코드 1이고 stderr의 마지막 assertion은 `input record route must stay on the html channel`이다. 브라우저 자산 로딩은 관찰하지 않았다.

## 한계와 후속 개선

실패 기준은 경로 설명이다. 구현은 별도 커밋 389964b782c69b05fc305c094640132a8aea7a44에서 검사 blob을 유지한 채 함수와 설계 문장을 추가한다. record 복사 자체는 아직 없다.
