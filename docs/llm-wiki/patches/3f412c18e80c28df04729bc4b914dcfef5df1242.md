# docs: record G1 regeneration and orphan retry acceptance

## 문제와 계기

이 커밋은 작은손 G1 재생성 변경을 미배포 항목으로 기록해 v0.34.0 기능 기록과 섞이지 않게 한다.

## 결과 동작

CHANGELOG에는 생성 원본에서 빠진 노드와 관계를 삭제 후보로 보고하고, CSS 버전 불일치 후에도 검토 근거를 확인할 수 있다는 사용자 변화를 적었다.

## 변경 파일과 인터페이스

`docs/llm-wiki/releases.md`는 이 변경을 v0.34.0 태그 이후의 main 변경으로 구분하고, 구현과 최종 인수 문서를 patch 페이지에 연결한다.

## 설계 이유와 출처

커밋은 CHANGELOG, Wiki catalog, G1 관련 다섯 patch 페이지, release index로 이루어진 문서 변경이다. 제품 코드나 테스트 파일은 수정하지 않는다.

## 호환성·이관·복구

patch 페이지는 최초 구현, 실패를 고정한 검사, 수정 전 기준, 최종 수정, 이전 소스 기록을 각각 추적해 구현과 재검증의 순서를 보인다.

## 검증과 미검증

독립 인수 기록은 요구사항 제거 후 성공, CSS epoch 차단, 유효 입력 재시도의 종료 코드를 0·1·0으로 남긴다. 세 시점에 고아 후보 13개와 그 전체 내용이 동일했다.

## 한계와 후속 개선

고아 후보 전체에는 노드 3개와 관계 10개가 포함되고, 기존 검토 메모와 연결 근거가 보존됐다. 이 수치는 작은손 G1 재생성 시나리오에 한정된다.

## 관련 기록

이 문서 커밋은 G1 제품 릴리스 태그를 만들지 않는다. 후속 제품 릴리스에서 버전과 설치본 인수를 별도로 기록해야 한다. [G1 인수](../releases.md#g1-source-regeneration).
