# 기존 MySQL에서 동시 예약과 권한 인수

소스 커밋 `1c930384e7a8be27a505619c967bcdfd5ea850ba`

## 문제와 계기

실제 MySQL에서 fixture 연결 옵션과 MySQL의 DELETE 기반 flush가 불변 트리거와 충돌했다.

## 결과 동작

검증 전용 스키마에서는 테스트 사이에 테이블을 초기화할 수 있다. 바이너리 로깅을 쓰는 기존 서버에서도 스키마 소유자를 실행 계정으로 지정해 트리거를 설치한다.

## 변경 파일과 인터페이스

`tests/test_booking_database_release.py`, `apps/little-hands/booking/tests/test_booking.py`, `apps/little-hands/booking/migrations/0002_immutable_records.py`를 갱신했다.

## 설계 이유와 출처

테스트 DB 이름이 정확히 일치할 때만 초기화한다. 일반 DB에서 트리거와 권한 검증은 그대로 실행하고 전역 설정을 바꿀 필요가 없다.

## 호환성·이관·복구

검증과 권한 역할 확인에 실행 소유 스키마와 계정을 사용한다. 기존 스키마와 데이터의 이관은 별도다.

## 검증과 미검증

기존 MySQL 8.4.13에서 61개 사례가 통과했다. 웹 계정으로 동시에 마지막 좌석을 요청해 한 건 확정·한 건 대기를 관측했고 보호 접근 네 건이 거절됐다.

## 한계와 후속 개선

이 실행은 별도 Figma 계정 또는 Dev Mode에서의 실기를 다루지 않는다.
