# feat: serialize stable change identities apart from selection order

## 문제와 계기

기준 cc53d88e91da49ac33c54c720b1be228b78c93bd는 serialize_selection이 없어 `stable change identity must serialize with its selection bundle`로 실패했다.

## 결과 동작

serialize_selection은 token kind와 key를 canonical JSON으로 해시한 64자리 identity를 만든다. alias 묶음 type/body·type/size는 같은 bundle id를 갖고, 독립 token의 bundle은 비어 있다. plan_sha256는 identity·kind·key·bundle만 해시하므로 선택 순서가 바뀌어도 같다. 직렬 문자열은 schema figma-flow-selection-v1 문서를 sort된 JSON으로 낸다. 묶음의 한쪽만 고르면 partial alias bundle이다. 함수는 값을 쓰지 않는다.

## 변경 파일과 인터페이스

tools/graph_sync.py에 serialize_selection을 추가했다. docs/development-roadmap/RD-04-selective-sync/tasks.md에 범위를 적었다. tests/test_rd04_selection_identity.py blob은 기준과 같다. build_plan은 이 함수를 호출하지 않는다.

## 설계 이유와 출처

RD-04는 표시 index를 identity로 쓰지 않는다. 선택 묶음과 plan hash를 함께 직렬화해야 이후 UI와 실행기가 같은 범위를 본다.

## 호환성·이관·복구

기존 plan token 필드와 protocol v1은 그대로다. 이 함수는 fixture를 읽어 JSON을 돌려줄 뿐 native 값을 바꾸지 않는다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd04_selection_identity`를 기준 cc53d88e91da49ac33c54c720b1be228b78c93bd에서 종료 코드 1, 대상 0ce837ccf732354cf2a0f94cbb42042c9ca6fda2에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 마지막 assertion은 `stable change identity must serialize with its selection bundle`이다. 조건은 RD-04-REQ-01이다. 같은 구현에서 selective fixture 검사와 graph sync 검사도 종료 코드 0이었다. Figma 패널 선택은 관찰하지 않았다.

## 한계와 후속 개선

UI의 선택 수와 영향 target 행은 아직이다. 실제 variable id가 붙은 plan 직렬화와 Figma 적용은 통과로 기록하지 않는다.
