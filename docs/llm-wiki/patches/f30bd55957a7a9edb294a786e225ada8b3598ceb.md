# build: pin the Design-only bundle and qualified API source references

## 문제와 계기

Design-only recipe set, native fixture와 value-path source가 바뀐 뒤 compiled bundle과 API static coverage baseline을 다시 source에 맞춰야 했다. Standalone static reference는 런타임 acceptance를 증명하지 않는다.
## 결과 동작

고정 TypeScript compiler로 4개 Design menu recipe와 1개 graph-scoped Design recipe를 다시 빌드한다. Coverage baseline은 API catalog의 qualified references와 unresolved receiver-name references를 갱신한다.
## 변경 파일과 인터페이스

`library/figma-recipes/bundle.json`은 Design menu recipe와 `design-type-review` graph recipe의 source/compiled hash를 고정한다. `library/figma-api/coverage-baseline.json`은 새 native fixture, probe, value path source를 포함해 AST reference baseline을 갱신한다.
## 설계 이유와 출처

Pinned TypeScript 5.9.3 compiler가 bundle contents를 재현한다. Static API scan은 qualified API member path와 unresolved receiver name을 구분하고, 두 상태 모두 implementation/runtime verification과 다르게 기록한다.
## 호환성·이관·복구

`library/figma-recipes/manifest.json`의 Design/default 레시피만 bundle에 들어간다. Official API catalog의 다른 편집기 declaration은 denominator와 audit history로 보존된다.
## 검증과 미검증

`library/figma-recipes/build.py`가 pinned TypeScript 5.9.3으로 번들을 재생성한다. `coverage-baseline.json`의 qualified reference 수는 source analysis이며, Figma API 호출 성공 수가 아니다.
## 한계와 후속 개선

Static reference baseline은 실제 plugin loading, scope permission, getter return value, visual rendering을 판정하지 않는다. 그 사실은 해당 fixture의 runtime receipt와 브라우저·Figma 캡처에서 확인한다.
