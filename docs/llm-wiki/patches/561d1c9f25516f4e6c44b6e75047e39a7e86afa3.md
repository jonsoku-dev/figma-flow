# feat: inspect carousel states and open Present from the plugin

## 문제와 계기

carousel 프로토타입을 적용해도 플러그인 작업 화면에서는 어떤 상태와 전이가 Figma에 실제로 남았는지 볼 수 없었다. 재생하려면 사용자가 시작 프레임을 직접 찾아 Present를 열어야 했다. 작업 이력에는 실행 상태만 남아, 이후 편집으로 반응이 바뀌었는지도 구분되지 않았다.

## 결과 동작

workspace_host는 적용·읽기 결과에 carousel이 있으면 실제 화면 범위 읽기 결과에서 요약(`figma-flow-carousel-summary-v1`)을 만든다. 요약에는 상태별 프레임과 상태, 반응·hotspot·경계(NO_NAVIGATION) 간선이 들어가고, 상태 2~16개와 간선 최대 80개로 제한된다. 요약은 해당 실행 이력에 저장된다. 작업 화면에는 파일 단위 캐러셀 목록, 실행 흐름 안의 상태·전이 목록, `시작 프레임 선택`과 `Present` 버튼이 생긴다. 시작 프레임 선택은 먼저 현재 파일·페이지·작업 revision·실행 ID, 시작 프레임의 플러그인 데이터와 graph 해시, flow start 등록을 모두 다시 확인한다. 그다음 프레임을 선택하고 화면에 맞춘다. Present 버튼은 검증된 파일 키와 노드 ID로만 만든 프로토타입 URL을 openExternal로 연다. ko·en·ja 문구도 추가했다.

## 변경 파일과 인터페이스

변경 경로는 `figma-bridge/assets/panels.css`, `figma-bridge/assets/panels.js`, `figma-bridge/locales/workspace.json`, `figma-bridge/workspace_control.js`, `figma-bridge/workspace_host.js`, `panel-ui/src/Workspace.jsx`, `panel-ui/src/WorkspaceActivity.jsx`이다. 전체 경로와 diff 해시는 이 페이지의 Git 기록에 있다.

## 설계 이유와 출처

패널은 저장된 요약을 그대로 믿지 않고 형식을 다시 걸러 잘못된 간선을 버린다. 요약이 `current`가 아니거나 다른 파일·페이지·작업의 것이면 native read를 다시 하라고 안내하므로, 오래된 이력으로 엉뚱한 프레임을 선택하지 않는다. 플러그인 안에서 Figma 플레이어를 직접 제어하지 않고, 검증한 시작 프레임의 프로토타입 URL을 여는 방식으로 재생 진입점을 제공한다. URL 구성 요소는 정규식으로 제한했다. 재생 자체는 Figma 플레이어가 담당한다는 경계를 화면 문구로 표시한다.

## 호환성·이관·복구

포크는 이 커밋과 부모의 변경 경로를 대조해 적용할 수 있다. 캐러셀 CMS나 외부 계정 연결은 필요하지 않다. 원본 화면과 사설 영수증은 로컬에 보존한다.

## 검증과 미검증

커밋의 workspace host 테스트는 요약의 크기 제한과 잘못된 간선 제거, 그리고 현재 작업의 읽기 결과와 정확한 시작 프레임이 있어야만 선택되는 조건을 확인한다. 실측 로그에서 이 테스트 23개가 통과했고 패널 빌드도 성공했다. 이 커밋을 HEAD로 둔 소스 사본에서 전체 검사(Python 1268개, Node 362개)가 통과했다. 다만 이 사본에는 문서·버전 파일의 미커밋 변경이 함께 있었다. 실제 플러그인 홈에서 시작 프레임 선택이 기대한 프레임으로 이동한 기록이 있지만, 그 실행은 이후 미커밋 패널 수정이 있는 작업 트리에서 이루어졌다. Figma에 로드된 플러그인 런타임이 이 커밋의 파일과 같은지는 `loaded: unverified`로 남았다. Present 버튼이 연 URL에서 재생했다는 직접 기록도 없다. 커밋 코드에는 남은 문제가 세 가지 있다. next/previous 컨트롤 간선이 요약에 들어가지 않는다(읽기 결과의 컨트롤 항목에 reactions 배열이 없음). 실행 흐름 영역의 알림이 `presented`를 번역하지 않고 그대로 표시한다. Present URL 경로에는 파일 이름 `SaaS`가 고정되어 있다.

## 한계와 후속 개선

여기서 확인한 결과는 해당 입력과 검증 범위에 해당한다. 브라우저의 연속 스크롤 관성이나 물리 모바일 기기의 동작은 별도의 관찰이 필요하다.
