# fix(components): handle duplicate/auto-renamed native property keys and remove only top-level created rollback roots

## 문제와 계기

Figma `addComponentProperty`는 중복 표시명이나 정규화 시 `name#suffix` 형식의 실제 키를 돌려주는데, 기존 구현은 표시명 접두로 키를 추정해 중복 표시명 속성을 고유하게 보존하지 못했다. 또한 롤백이 보호된 자손 삭제 거부에 걸려 실패할 수 있었다.

## 결과 동작

커밋 `974b5de74bc99d645926afd5595f21f155356203`는 `figma-bridge/code.js`에 `hasValidPropertyKey`, `resolveCollisionSafePropertyName`, `addDeclaredPropertySafely`를 추가하고, 반환된 실제 키를 `actual-key-missing`, `actual-key-unsuffixed`, `duplicate-actual-key`, `definition-missing`, `definition-type-mismatch`, `definition-default-mismatch` 상태로 검증한다. readback은 계약의 `name`과 `actual_key`가 일치할 때만 통과한다. `figma-bridge/semantic_components.js`는 `usedActualKeys`로 실제 키 중복을 막고, 롤백 시 새로 만든 최상위 root만 제거한다.

## 변경 파일과 인터페이스

`figma-bridge/code.js`, `figma-bridge/semantic_components.js`를 수정했다. 선언 메타데이터에 실제 키 계약이 기록되며 레시피 helper 목록은 `a7378b82`에서 동기화됐다.

## 설계 이유와 출처

논리 속성 ID 계약은 유지하고 Figma가 돌려준 실제 키를 정본으로 기록해야 중복 표시명과 자동 정규화가 모두 안전하다. 최상위만 제거해 기존 사용자 컴포넌트와 보호된 자손을 건드리지 않는다.

**공개 재현 대응.** 비공개 개선 gate(`437aa0485e85dd2e2dcef621f570847317759b63` → `3e3f4e42b884cb64cc32c9d9f5d9173ec8bbb550`, `NODE-REPAIR-RC` 12/12 + Python adapter를 거친 `PY-REPAIR-RC` 1/1)의 base/target ref는 비공개 작업 이력에만 있어 공개 clone에서 바로 checkout할 수 없다. 공개 재현은 대응 공개 커밋 `578ffc3c51ae6e9664f03c6f71ae3d1c18a922ec` → `974b5de74bc99d645926afd5595f21f155356203`으로 한다. `figma-bridge/code.js`(`11aee85cbcc03ad58bbf6c6ba34066d9ec9b5567` → `1d581e9a7c26f96102a8b8d5c830924605b9ed8e`), `figma-bridge/semantic_components.js`(`d3aaedc0c90895abf9df2c6081a25ee75f37b311` → `0e6309f7d034d547d90555479e9354fbe336dcfe`), `tests/test_property_repair_regression.cjs`(base·target 모두 고정 blob `70d47f890d8865a8bce9d2713d91533a990e00f0`)가 각각 비공개 base/target 파일과 byte 동일함을 root가 검증했으며, 파일별 전체 blob 대응표는 저장소 밖 비공개 증거(`repair-public-equivalence.json`)에 보존한다. 공개 재현 명령은 각 공개 ref에서 `node --test tests/test_property_repair_regression.cjs`이다. 이는 공개 Node 회귀 재현이며, Python adapter를 포함한 비공개 gate 실행 자체와 구별한다. 이 기록 커밋에서는 공개 ref 위 Node 재실행을 따로 수행하지 않았고, 근거는 byte 동일성 검증과 비공개 gate 결과다.

## 호환성·이관·복구

고유 표시명 속성은 이전과 같은 키를 받는다. 실패 시 롤백 범위가 최상위 생성 노드로 좁아져 기존 `MAIN` 컴포넌트를 보존한다.

## 검증과 미검증

고정 회귀 검사 `tests/test_property_repair_regression.cjs`(blob `70d47f890d8865a8bce9d2713d91533a990e00f0`)가 이 커밋에서 통과하며, 최종 실기 Figma에서 `6`세트·`19`변형·`8`인스턴스(`108`노드)의 고유 `#suffix` 키와 편집 보존을 확인했다. 공개 Node 재현 명령은 `node --test tests/test_property_repair_regression.cjs`이다.

## 한계와 후속 개선

Python `compare_declared_component_properties`는 여전히 표시명 접두 개수를 요구해 이 키를 거절했으며 `e6f4fd84`에서 맞췄다. NF-01 6패밀리 워크벤치 밖의 legacy `metadata`와 별도 3패밀리 helper 경로는 범위 밖이다.
