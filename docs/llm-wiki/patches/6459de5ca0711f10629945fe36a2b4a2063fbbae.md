# test: reject partial native mutation evidence

## 문제와 계기

summary가 partial임을 reader에서 표시해도 mutation·import·recovery 소비자가 그 값을 full evidence처럼 쓰면 경계가 무너진다. 실제 소비 입구에서 partial 거절과 이후 정상 recovery를 함께 확인할 추가 기준이 필요했다.

## 결과 동작

새 JS2개/Python2개 사례는 summary 자체를 apply plan으로 쓰면 API 접근 전에 거절하고, plan의 extra evidence/readback에 summary를 넣어도 실제 scalar getter 및 stale-before 거절을 우회하지 못하도록 요구한다. import는 canonical 파일을 보존하고 recovery는 uncertainty를 유지해야 한다.

## 변경 파일과 인터페이스

[JS partial consumers](../../../tests/finalize_partial_consumers.cjs)는 실제 reader가 만든 width/height summary를 graphTokenSync에 전달한다. [Python consumers](../../../tests/finalize_partial_consumers.py)는 같은 summary를 import_values와 control.recovery_read/result로 전달한다. 제품 source 변경은 없다.

## 설계 이유와 출처

필드가 적다는 설명만으로는 소비 경계를 증명하지 못한다. apply-plan 거절은 Figma API0회, 위조 extra evidence 사례는 native getter reads>0/writes=0을 요구한다. import는 variables 누락 KeyError가 publication 전에 발생하고 output 자체가 생기지 않아야 한다.

## 호환성·이관·복구

partial recovery receipt를 받아도 기존 uncertain operation은 남고 새 mutation은 막아야 한다. 나중의 fresh same-scope full discovery만 reconcile하며 원래 receipt와 graph/native source 바이트는 계속 보존한다. 거절만 검사해 정상 recovery까지 영구 차단하는 구현을 허용하지 않는다.

## 검증과 미검증

Git diff에서4개 실제 소비 경로 사례, canonical graph/web/pairing 불변, partial 뒤 uncertainty 유지와 full 뒤 reconcile을 확인했다. 이번 작업은 정적 대조만 했다. import의 현재 예외가 KeyError:variables라는 사실을 기록하며 명확한 제품 오류 메시지로 바꾸었다고 주장하지 않는다.

## 한계와 후속 개선

API-shaped fixture의 synthetic summary는 실제 Figma origin을 증명하지 않는다. 정상 full read 관측·GUI 표시·native mutation의 실제 실행은 별도 근거다. source fix가 미커밋인 현재 상태와 frozen coverage-only 커밋을 분리한다.
