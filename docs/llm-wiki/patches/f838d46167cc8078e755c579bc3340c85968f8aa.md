# test: keep the width-reuse oracle stable after archived keys

## 문제와 계기

변환이 원본 semantic key를 archive 접두로 바꾸면, 구현 후 렌더 너비 조회가 실패 이유가 아니라 조회 오류가 된다.

## 결과 동작

oracle은 변환 전에 `use.narrow` 같은 key를 객체에 보관한다. 제품 코드는 그대로라 세 너비는 아직 별도 main이고 `supported width uses must share one main`으로 실패한다.

## 변경 파일과 인터페이스

바뀐 파일은 tests/semantic_component_reuse_oracle.cjs 하나다. 부모는 15f29963c1f4e7685a7deb6b851a1d360fcbad6b다.

## 설계 이유와 출처

검사 기준은 구현 diff에서 blob이 같아야 한다. 조회 키를 구현 전에 고정해 이후 semantic_components.js만 바뀌게 했다.

## 호환성·이관·복구

제품 동작과 기존 검사는 바꾸지 않는다. archive key 규칙은 그대로다.

## 검증과 미검증

이 커밋만 실행하면 oracle 종료 코드 1이다. 최종 게이트 기준은 다음 하네스 커밋이다. 실제 Figma는 관찰하지 않았다.

## 한계와 후속 개선

추가된 Layout variant의 variantProperties가 비면 재실행 검사가 다른 오류가 된다. 그 설정은 76a2d2b73a1d71631abe6f717073d15068c08155에서 고정한다.
