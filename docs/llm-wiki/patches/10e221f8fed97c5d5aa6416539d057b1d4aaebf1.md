# feat(discovery): add opt-in fresh-read measurement tasks

## 문제와 계기

기준선 측정에는 같은 full 읽기의 reader·discovery 시간과 별도 진단 counts가 필요했다. 기본 discovery 경로와 reader를 바꾸지 않아야 했다.

## 결과 동작

커밋 `10e221f8fed97c5d5aa6416539d057b1d4aaebf1`는 `graph_sync discover --read-measure timing|getter-counts`를 추가했다. 이 flag는 `figma-bridge/native_read_measurement.js`를 별도 benchmark task에 붙인다. `timing`은 같은 full `readNativeSemantics` 호출을 감싸 페이지별 reader·discovery 경과를 기록한다. `getter-counts`는 진단 회차에서 native 노드와 API 호출을 Proxy로 센다. summary 요청은 그대로 통과한다. flag가 없으면 생성 bundle과 reader 파일은 기준과 같다. `tools/figma_workspace.py`는 discover task에 이 flag를 허용한다.

## 변경 파일과 인터페이스

새 `figma-bridge/native_read_measurement.js`, `tests/p2_native_read_measurement.cjs`. `tools/graph_sync.py`(선택 flag 처리), `tools/figma_workspace.py`(허용 목록 한 줄).

## 설계 이유와 출처

[P2 1차 실행 계약](../../next-roadmap/p2-wave1-acceptance.md)의 파일 소유·계측 조건(기본 경로 불변, 선택 flag 계측, 동결 검사 blob 불변)을 따른다.

## 호환성·이관·복구

flag 없는 호출은 기존과 같다. 계측을 끄려면 flag를 주지 않는다.

## 검증과 미검증

`node --test tests/p2_native_read_measurement.cjs`가 기본 bundle의 계측 코드 부재, 시간 계측 범위, getter-counts가 읽기 결과를 바꾸지 않음, 측정 결과와 원래 reader 결과·bytes 동일, 알 수 없는 mode 거절을 검사한다. 독립 검토는 flag 없는 discovery bundle이 기준과 같은 크기·내용임을 확인했다. root는 통합 전 같은 내용의 후보를 깨끗한 아카이브에서 검사해 Node·Python 검사 통과와 static API coverage baseline 불일치를 확인했다. 그 불일치는 [954f198](954f1985531a0b73c80db76ecff393b73ca658eb.md)이 갱신했다.

## 한계와 후속 개선

이 커밋의 Proxy는 실기에서 읽기 전용 속성의 get 불변식을 깨뜨렸다. [a5e4a09](a5e4a098726872e9953e92da36065f4789f22811.md)이 고쳤다.
