# test: pin indirect CSS freshness acceptance

## 문제와 계기

HTML 입력 freshness 검사는 HTML이 직접 가리키는 자산만 확인했다. HTML의 `<link>`에서 CSS를 거쳐 `@import`, `url()`, 웹 글꼴과 사진으로 이어지는 간접 파일이 바뀌어도 투영 결과가 최신으로 보일 수 있었다. 제품 수정을 먼저 넣어 실패 기준을 바꾸지 않도록, 이 커밋은 실제 누락을 재현하는 oracle만 추가했다. 근거는 첫 부모 `25b17f9cc0cd13f73f4545403fbef0f9d6ba1a6c` 대비 테스트 파일의 diff다.
## 결과 동작

새 테스트는 임시 fixture에서 HTML→직접 CSS→가져온 CSS→폰트·이미지 연결을 만들고, 각 간접 파일을 독립적으로 바꿀 때 freshness가 `stale`이며 해당 경로를 `changed`에 포함해야 한다고 고정한다. 수정 전 구현에서는 이 기대가 실패한다. 이 커밋은 의도적으로 실패하는 기준선을 보존하며, 그 자체로 CSS 추적 기능을 제공하지 않는다.
## 변경 파일과 인터페이스

`tests/test_input_effect_css.py`에 `CssDependencyFreshnessTests.test_css_import_font_and_image_changes_make_html_projection_stale` 하나를 추가했다. `input_effect.project()`로 만든 기록을 `input_effect.freshness(record, root)`에 넣어 관찰 가능한 `status`와 `changed`를 검사한다. 제품 코드, 공개 함수 서명, fixture, 설정은 이 커밋에서 변경하지 않았다.
## 설계 이유와 출처

같은 기준 파일을 유지한 채 구현 전후를 비교할 수 있도록 오라클을 분리했다. 테스트는 폰트와 이미지 바이트를 각각 수정하고 원본을 복구하며, CSS import 자체가 변하는 경우도 확인한다. 당시 독립 실행 게이트는 기준 커밋의 실패를 실제로 관찰하고, 동일한 테스트 blob·모드로 구현 target의 조건을 재실행했다. 테스트는 수정 코드와 같은 커밋에서 약화되지 않는다.
## 호환성·이관·복구

이 커밋은 테스트만 추가하므로 기존 사용자 기록이나 플러그인 동작을 변경하지 않는다. 기존 실행에 포함되지 않던 CSS 자산은 아직 freshness 소스가 아니며, 기준 실패를 수정하려면 뒤따르는 구현 커밋이 필요하다. 이 테스트의 blob이나 실행 의미를 바꾸면 과거 baseline 비교 근거로 사용할 수 없다.
## 검증과 미검증

검토된 개선 게이트에서 개선 전 기준은 예상 AssertionError로 종료 코드 1을 냈고, 구현 target은 변경 없이 유지된 oracle로 두 조건을 통과했다. 이 문서의 독립 근거는 커밋 diff 및 게이트 실행 기록이다. 이 커밋만 단독으로 실행하면 red가 예상 결과이며, 전체 테스트 스위트·원격 CI·브라우저·Figma 인수 통과를 뜻하지 않는다.
## 한계와 후속 개선

이 oracle은 단일 재현 경로에서 간접 import, 폰트와 이미지의 바이트 변경만 고정한다. HTML·CSS 문법 전반의 정확성, 외부 URL, cascade 전체, 순환·인코딩·안전한 경로 처리까지 이 파일 하나가 검증하지 않는다. 실제 구현 범위와 후속 검증은 [CSS 자산 추적 수정](f3ec102c6dbe436495ff15391f599cddfd86a449.md)에 기록한다.
