# test: pin asset admission and live freshness

## 문제와 계기

입력 record API가 있어도 실제 prepare CLI에서 record/root 및 dependency를 받을 수 없거나 replay가 근거를 잃으면 자산 목록과 task 실행 사이의 계약이 끊긴다.

## 결과 동작

새 oracle은 CLI prepare의 --input-record/--input-root/--depends-on admission, 읽기 전용 task_input_freshness, replay 후 record 보존을 요구한다. 원본이 바뀌면 stale로 표시하고 replay를 쓰기 없이 막으며 명시적 교체 후 current가 된다.

## 변경 파일과 인터페이스

tests/finalize_asset_admission.py를 추가했다. 임시 POSIX private workspace에서 실제 CLI subprocess와 workspace API를 사용한다. sources의 sha256 → task record → public metadata → replay의 흐름을 검사한다.

변경 경로: [tests/finalize_asset_admission.py](../../../tests/finalize_asset_admission.py).

## 설계 이유와 출처

저장된 record 상태를 믿는 대신 원본 바이트를 재확인하고, snapshot 비교로 freshness와 실패 경로가 workspace를 바꾸지 않는지 확인한다. consumer의 기존 pinned dependency edge도 교체 뒤 그대로 남아야 한다.

## 호환성·이관·복구

명시적 root 없는 기존 API record는 거절하거나 current로 승격하지 않고 unverified가 되어야 한다는 기준이다. public metadata에 private root를 포함하지 않는 assertion을 둔다. 제품 구현은 이 커밋에 없다.

## 검증과 미검증

Git 원문에서 current→stale→교체 후 current, stale replay 실패 및 파일 snapshot 불변성, legacy unverified 기대를 확인했다. 이 기준의 역사적 통과 결과는 별도로 확정하지 않았다.

## 한계와 후속 개선

POSIX 외 환경은 skip 대상이다. fixture 자산과 로컬 CLI admission은 실제 브라우저 자산 로딩·라이브 Figma 반영을 증명하지 않는다.
