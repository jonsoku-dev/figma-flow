# test: bound native build getter work

## 문제와 계기

정상 다중 화면 makeDraft에서 각 화면이나 각 주석마다 페이지 전체 native getter를 반복 호출하면 getter 작업량이 화면/노트 수에 따라 불필요하게 커진다. 성능 개선이 최종 fresh read나 실패 rollback을 약화시키지 않도록 독립 기준이 필요했다.

## 결과 동작

새 oracle은 실제 normal makeDraft를 2/6 상태와 desktop/mobile로 실행하여 main-component getter와 text-segment getter 호출 수에 선형 예산을 둔다. 일반 및 readable-spec 주석 배치도 semanticKey 조회를 페이지 인덱싱과 노트당 상수 작업 이내로 제한한다. wall-clock 성능 결과를 주장하지 않는다.

## 변경 파일과 인터페이스

[finalize_native_build_reads.cjs](../../../tests/finalize_native_build_reads.cjs)와 [API-shaped helper](../../../tests/helpers/finalize_native_build_reads.cjs)를 추가했다. helper는 semantic_tokens/native_annotations/native_semantic_read/foundation_palette/design_note_board/direction_review 원문을 VM에 적재하며 normal makeDraft를 대체하지 않는다. API node의 getMainComponentAsync/getStyledTextSegments/getPluginData가 호출 횟수를 기록한다.

## 설계 이유와 출처

mainReads≤2×instances+4, segmentReads≤2×texts로 전체 snapshot 두 번 수준을 허용하되 화면별 전체 읽기는 드러나게 한다. annotation은 일반 2×nodes+notes, readable-spec은 2×nodes+8×notes 예산을 둔다. 원인은 getter 작업량이며 하드웨어·네트워크에 좌우되는 시간 대신 그 직접 비용을 검사한다.

## 호환성·이관·복구

완료 후 별도 readDraft는 바뀐 characters/x/mainComponent/overflow getter를 새로 읽고 앞선 snapshot은 독립된 값으로 보존해야 한다. build 중 parent/type/clip/axis/누락 axis drift는 거절하고 소유한 새 page만 제거하며 기존 currentPage와 unrelated data를 복구해야 한다. 제품 코드나 공개 schema 변경은 없다.

## 검증과 미검증

Git diff에서 completed reservation/페이지 소유, 위 getter 예산, 24개 annotation batch, 두 차례 독립 fresh read, 다섯 drift rollback 검사를 확인했다. 기준은 실제 entrypoint와 reader를 API-shaped host에서 구동하지만, 이 문서 작업에서는 실행하지 않았다. frozen baseline의 의도한 실패와 후속 미커밋 제품 최적화 결과는 별개다.

## 한계와 후속 개선

이 예산은 실제 Figma의 지연·메모리·장치별 성능 측정이 아니다. helper의 폰트·변수·node API 모형은 native 생성 성공을 보증하지 않으며 현재 실제 native create 인수는 남아 있다. 장기 cache로 fresh read를 건너뛰어 예산만 만족시키는 해석은 허용하지 않는다.
