# feat: apply only the validated selection and limit the baseline

## 문제와 계기

기준 5caacfd96b70a03abd80d331a5a8b5317a38e2bf는 commit_selective_apply가 없어 `selective apply must keep skipped values and limit the baseline`로 실패했다.

## 결과 동작

commit_selective_apply는 직렬화된 선택을 검증한 뒤 고른 독립 token만 after로 바꾼다. space/gap은 readback에 before 8로 남고 baseline에는 적용한 두 값만 있다. full_apply는 건너뛴 행이 있으면 false다. 관측값이 before와 다르면 stale before value로 거절하고 입력은 그대로다. 빈 선택과 alias 반쪽 선택은 쓰기 전에 거절한다. commitGraphSelection은 같은 결과를 내고, selection이 있는 플러그인 메시지는 graphSyncPlanForMessage로 그 token만 남긴 뒤 graphTokenSync에 넘긴다. selection이 없는 메시지는 전체 plan을 유지한다.

## 변경 파일과 인터페이스

tools/graph_sync.py에 commit_selective_apply를 추가했다. figma-bridge/graph_token_sync.js에 commitGraphSelection과 graphSyncPlanForMessage를 추가하고 apply 메시지가 이를 거친다. docs/development-roadmap/RD-04-selective-sync/tasks.md에 범위를 적었다. tests/test_rd04_selective_apply.py blob은 기준과 같다.

## 설계 이유와 출처

RD-04는 미선택 항목을 적용하지 않고 applied와 skipped를 구분한다. 부분 성공을 전체 baseline으로 기록하지 않는다. stale before는 transaction을 시작하기 전에 거절한다.

## 호환성·이관·복구

기존 apply 메시지에는 selection이 없으므로 전체 적용과 rollback이 유지된다. 선택이 있으면 검증에 실패한 메시지는 graphTokenSync 쓰기 전에 거절된다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd04_selective_apply`를 기준 5caacfd96b70a03abd80d331a5a8b5317a38e2bf에서 종료 코드 1, 대상 95c8714f29ec1af8094e88896f14b114c4afa63c에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 마지막 assertion은 `selective apply must keep skipped values and limit the baseline`이다. 조건은 RD-04-REQ-04다. 같은 구현에서 graph sync 검사와 graph token sync·graph panel 노드 검사도 종료 코드 0이었다. Figma에서 두 값만 바뀌는 적용은 관찰하지 않았다. 플러그인 런타임에는 Node crypto가 없어, 화면이 selection을 보내기 전에는 이 경로가 실행되지 않는다.

## 한계와 후속 개선

현재 패널은 selection payload를 보내지 않는다. component field 선택은 아직이다. AC의 Figma 관찰은 통과로 기록하지 않는다.
