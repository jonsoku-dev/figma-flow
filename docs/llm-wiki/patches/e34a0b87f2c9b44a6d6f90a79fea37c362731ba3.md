# 메트릭스 설정과 작업공간 등록의 대상별 잠금

커밋 `e34a0b87f2c9b44a6d6f90a79fea37c362731ba3`

## 문제와 계기

원자적 파일 교체는 개별 파일을 완전하게 쓰지만, 그 전에 두 프로세스가 같은 값을 읽으면 먼저 저장한 변경이 사라진다.

## 결과 동작

설정 파일마다 고정된 잠금 파일을 연다. 메트릭스 변경은 init의 존재 확인부터 저장까지, 등록은 목록 읽기부터 병합·교체까지 같은 잠금을 유지한다.

## 변경 파일과 인터페이스

tools/private_io.py가 locked_update를 제공한다. tools/metrics/cli.py와 tools/workspace_registry.py가 실제 대상 경로로 이를 공유한다.

## 설계 이유와 출처

교체되는 데이터 inode와 잠금 inode를 분리해 다른 프로세스도 같은 잠금을 기다리도록 했다. 읽기 전용 명령은 기존 경로를 사용한다.

## 호환성·이관·복구

기본 비활성, 파일별 병렬 처리, 기존 원자적 교체와 0600, 등록의 실패 반환을 보존한다. finally에서 파일 기술자를 닫아 예외 때에도 잠금을 놓는다.

## 검증과 미검증

격리된 교차 프로세스 테스트에서 두 소스가 남았고 강제 초기화 순서와 다른 파일의 동시 수정도 확인했다. 독립 프로브에서 두 등록이 모두 true였고 저장 레코드는 두 개였다.

## 한계와 후속 개선

잠금은 이 경로를 사용하는 협력 프로세스의 쓰기를 직렬화한다. 설정 파일을 별도 편집기로 덮어쓰는 경우는 이 근거의 범위 밖이다.
