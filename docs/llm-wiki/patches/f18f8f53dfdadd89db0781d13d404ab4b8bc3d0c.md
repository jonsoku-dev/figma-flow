# f18f8f5 · macOS 네이티브 CLI로 격리 검사

이 기록은 원본 커밋 `f18f8f53dfdadd89db0781d13d404ab4b8bc3d0c`의 실제 diff와 파일 경로를 기준으로 작성했다.

## 문제와 계기

npm 패키지를 통해 제공한 Codex CLI 호출로는 macOS에서 필요한 실제 OS 격리를 확인하기 어려웠다.

## 결과 동작

CI runner를 ubuntu-latest에서 macos-15로 바꾸고 공식 릴리스 tarball을 CPU 아키텍처별로 받아 SHA-256을 확인한 뒤 codex sandbox 읽기 전용 검사를 수행하도록 변경했다. CONTRIBUTING.md에 Ubuntu hosted runner의 bubblewrap 루프백 문제와 선택 배경을 기록했다.

## 변경 파일과 인터페이스

워크플로 다운로드 단계는 arm64/aarch64-apple-darwin과 x86_64-apple-darwin 해시를 분기한다. 검증 후 PATH에 임시 설치 디렉터리를 등록하고 codex sandbox를 실행한다.

## 설계 이유와 출처

네이티브 플랫폼에서 실제 격리 경로를 검증하고 바이너리 무결성을 고정 해시로 확인하려는 CI 변경이다.

## 호환성·이관·복구

제품 호출 계약과 사용자 데이터에는 영향이 없다. CI 플랫폼·비용·실행시간이 Ubuntu에서 macOS로 바뀐다.

## 검증과 미검증

정적 workflow diff와 해시 값만 확인했다. 실제 다운로드·해시 검증·sandbox 성공은 미검증이다.

## 한계와 후속 개선

macOS hosted runner 및 아키텍처 선택이 지원 환경과 맞는지 CI 실행 결과가 필요하다.
