# docs: publish 0.26.1 patch knowledge

## 문제와 계기

앞선 `e3bb050`에서 시작한 fork용 패치 Wiki의 최초 발행 뒤, 당시 canonical 목록에 발행 커밋 자신이 빠져 있었다. 0.26.1 릴리스에 상세 기록·전체 커밋 대조표·기록 계약을 묶고, 새 발행 커밋까지 정식 계보에 포함할 필요가 있었다. 근거는 이 커밋의 첫 부모 `e3bb0505b011f77a656e096b821c7d0d01f2990c`와 실제 문서 diff다.
## 결과 동작

Wiki 인덱스가 canonical 기록을 44개 커밋으로 다시 집계하고, `v0.26.1`을 이 발행 커밋 `25b17f9`에 연결한다. CHANGELOG의 짧은 변경과 전체 SHA별 설명, 버전·태그 대조가 이어진다. 이 커밋은 문서 발행이며 플러그인 동작이나 입력 결과 형식을 바꾸지 않는다.
## 변경 파일과 인터페이스

`docs/llm-wiki/catalog.json`에 이 커밋의 생성 메타데이터와 기록 페이지 경로를 추가했다. `docs/llm-wiki/README.md`는 canonical 수를 44로 갱신하고, `docs/llm-wiki/releases.md`는 0.26.1에 `0bd8177` 코드 변경과 `e3bb050` 기록 시스템을 연결한다. 새 상세 기록은 `docs/llm-wiki/patches/e3bb0505b011f77a656e096b821c7d0d01f2990c.md`다. 외부 API나 사용자 데이터 인터페이스는 없다.
## 설계 이유와 출처

전체 커밋 SHA를 식별자로 삼아 버전 문자열과 실제 Git 계보를 혼동하지 않게 한다. CHANGELOG는 간단한 사용자 변화에, Wiki는 변경 경로와 검증 한계에 사용한다. 이 방향과 기록 원칙은 이전 [기록 시스템 도입](e3bb0505b011f77a656e096b821c7d0d01f2990c.md) 및 [Wiki 계약](../README.md)을 따른다. 근거는 첫 부모 대비 네 파일의 실제 diff와 커밋 메타데이터다.
## 호환성·이관·복구

제품 코드, plugin ID, 입력 스키마, 사용자 프로젝트 자료는 바뀌지 않는다. 기존 Wiki 본문을 보존하면서 발행 커밋만 추가했다. 포크는 전체 Git clone에서 `python3 tools/patch_knowledge.py inventory --ref HEAD`와 `verify --ref HEAD`로 자신의 도달 가능한 계보를 확인할 수 있다. 태그 대상과 카탈로그가 어긋나면 실제 Git diff를 확인하고 기록을 다시 동기화한다.
## 검증과 미검증

이 커밋 자체의 diff는 문서·카탈로그·버전 대조만 수정한다. 0.26.1 릴리스의 CI, 공개 산출물, 설치 파일과 기존 네이티브 보존 검증은 별도 릴리스 실행에서 확인되었으며, 그 실행 결과가 이 문서 diff에서 수행된 검사를 뜻하지는 않는다. 이 커밋에서 플러그인의 실제 Figma 동작을 새로 실행했다는 근거는 없다.
## 한계와 후속 개선

카탈로그와 기록 검사는 Git 기록과 문서 구조를 대조할 뿐 설명의 진실성, 다음 실행의 지속, Figma 품질을 보증하지 않는다. 포크의 원격·브랜치 보호·태그 권한은 자동 변경되지 않는다. CSS 간접 의존성 추적은 이 릴리스 발행에 포함되지 않았고 이후 별도 커밋으로 다뤄졌다.
