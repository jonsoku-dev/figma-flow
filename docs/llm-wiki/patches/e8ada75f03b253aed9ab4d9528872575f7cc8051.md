# test: pin native fractional linebox boundaries

## 문제와 계기

실제 native 관찰에서 단일 줄 leading 23.390625의 text node height가 24로 양자화되고, 원본 text 바닥에 정확히 붙은 control이 겹침으로 분류되는 사례가 있었다. 이 좁은 ceil 차이와 실제 충돌·좌표 drift를 구분하는 고정 기준이 필요했다.

## 결과 동작

새 frozen oracle의 정상 사례는 h=leading=23.390625, max_lines=1, native height=24이며 control y=153+23.390625를 그대로 둔다. JS/Python native 검사는 이 경우를 허용하고 원시 geometry를 바꾸지 않아야 한다. 이 커밋은 테스트만 추가하며 runtime 수정은 포함하지 않는다.

## 변경 파일과 인터페이스

[JS oracle](../../../tests/finalize_linebox_rounding.cjs)는 실제 direction_review의 validateDraftGeometry를 API-shaped desktop/mobile fixture에서 호출한다. [Python oracle](../../../tests/finalize_linebox_rounding.py)은 figma_draft.native_screen_findings와 authored design_quality.evaluate를 호출한다. 공개 fixture는 최소 geometry와 합성 semantic key만 사용한다.

## 설계 이유와 출처

전역 1px tolerance로 충돌을 숨기지 않고 source의 단일 줄 할당과 native ceil만 좁게 구분하려는 기준이다. control 상하 0.25 이동, source 자체 0.25 겹침, 두 줄 높이, h와 leading 불일치, text width/x/y의 0.25 drift, ceil이 아닌 높이, max_lines=2 또는 부재의 11개 반례는 계속 control-text-overlap으로 거절해야 한다.

## 호환성·이관·복구

원본 text/control 좌표와 native raw evidence는 clamp하거나 재작성하지 않는다. Python authored-quality 경로는 접한 정상 source를 허용하되 실제 source overlap을 계속 차단한다. 제품 schema·폰트 정의·native getter 계약은 이 테스트 커밋에서 변경하지 않는다.

## 검증과 미검증

Git 원문에서 정상 native ceil 허용과 raw 불변성, 양 언어의 11개 negative guards, authored-quality source overlap 거절을 확인했다. 상위 세션의 초기 정상 사례 실행은 의도한 red였으며 후속 runtime 수정은 아직 미커밋이다. 현재 알려진 native 실패 191건 전체가 false positive인 것은 아니고 그중 30건만 양자화 유형으로 분류되었다는 관찰 범위를 유지한다.

## 한계와 후속 개선

이 고정 geometry fixture는 모든 폰트의 line metrics·wrap·실제 겹침을 설명하지 않는다. 다른 폰트 사례는 별도 calibration 중이며 실제 Figma replay와 native 생성 인수는 남아 있다. 이 baseline이나 후속 로컬 통과만으로 GUI 성공·제품 승인·전체 실패 해소를 주장하지 않는다.
