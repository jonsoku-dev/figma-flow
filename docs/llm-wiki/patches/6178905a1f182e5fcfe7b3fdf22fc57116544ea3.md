# ci: match the app PostgreSQL environment

## 문제와 계기

앱 CI workflow는 `DATABASE_URL`을 설정했지만 실제 `config/settings.py`는 `LH_DB_HOST`, `LH_DB_PORT`, `LH_DB_NAME`, `LH_DB_USER`, `LH_DB_PASSWORD`를 읽는다. 따라서 CI의 URL은 사용되지 않고 앱 기본 포트 55439로 접속을 시도해 PostgreSQL 연결이 실패했다. 이 커밋은 앱과 workflow가 같은 설정 변수를 쓰도록 맞춘다.

## 결과 동작

workflow 환경에 `LH_DB_*` 다섯 설정을 넣어 disposable PostgreSQL 서비스의 주소·포트·DB·사용자·암호를 명시한다. CI 앱이 실제로 읽는 값을 전달하므로 로컬 개발 기본값에 의존하지 않는다. 제품의 데이터베이스 설정 동작은 바꾸지 않는다.

## 변경 파일과 인터페이스

첫 부모 `e75d60b7b95fc48144368f7d659ad0d0918fddce` 대비 `.github/workflows/little-hands.yml`과 `CHANGELOG.md` 두 파일만 바뀌었다. workflow에서 미사용 `DATABASE_URL` 하나를 `LH_DB_*` 변수로 대체했고 CHANGELOG에 수정 내용을 덧붙였다. 애플리케이션 API와 데이터베이스 스키마는 변경하지 않았다. 실제 변경은 `git show 6178905a1f182e5fcfe7b3fdf22fc57116544ea3`로 대조했다.

## 설계 이유와 출처

연결 설정은 애플리케이션이 이미 사용하는 환경변수 계약을 그대로 따라야 한다. 원격 실패 trace의 선택 포트와 저장소의 실제 Django 설정을 대조해 원인을 확인했으며, 민감값은 기록하지 않는다. 재현 확인은 pinned PostgreSQL 17 컨테이너를 로컬 `127.0.0.1:5432`에 띄우고 같은 workflow 환경값을 적용해 수행했다.

## 호환성·이관·복구

변경은 GitHub Actions job 환경에만 적용된다. 서비스용 secret, 사용자 데이터, Django 마이그레이션에는 영향이 없다. workflow를 되돌리면 이전의 미사용 URL과 잘못된 기본 포트 동작으로 돌아가므로, 롤백 시 앱 설정과 CI 환경변수를 함께 대조해야 한다. 로컬 컨테이너는 검증 후 제거했다.

## 검증과 미검증

원격 앱 CI 실패 run `43339869591`의 접속 오류와 앱 설정의 실제 `LH_DB_*` 소비를 대조했다. 새 환경변수로 PostgreSQL 17에 연결해 `check`, migration dry-run, PostgreSQL 테스트 58개, packaging 테스트 4개를 실행했고 네 명령 모두 exit 0이었다. 이 실행은 Apple Silicon Mac에서 한 로컬 확인이다. 원격 GitHub Actions는 Ubuntu AMD64 환경이며 이 로컬 실행이 원격 CI 성공을 대신하지 않는다. 후속 원격 workflow와 tag/ZIP/install/native 재읽기의 최종 결과는 별도 확인이 필요하다.

## 한계와 후속 개선

이 수정은 CI 연결 설정 불일치만 해결한다. 원격 runner의 서비스 시작·연결과 모든 앱 테스트의 성공은 실제 workflow 결과로 확인해야 한다. workflow 설정이 바뀌면 Django 설정에서 읽는 변수와 job이 제공하는 변수를 다시 대조한다.
