# feat: create editable carousel frames with verified drag and timer reactions

## 문제와 계기

컴파일된 carousel graph가 있어도 Figma 플러그인 렌더러는 각 상태를 정적 프레임으로만 만들었다. Present에서 드래그로 넘기거나 시간이 지나 다음 카드로 가는 동작, 첫·마지막 카드의 경계 동작을 Design 파일에 편집 가능한 형태로 남길 경로가 없었다. 개발 중 실제 적용 영수증에는 경계 상태가 자기 자신을 가리키는 NAVIGATE 반응을 Figma가 거부한 기록이 있다. Figma의 NAVIGATE 목적지는 같은 페이지의 다른 최상위 프레임이어야 하고, 이 거부로 연결 단계 전체가 실패했다.

## 결과 동작

figma-bridge/web_design.js가 carousel 계약을 Python과 같은 규칙으로 다시 검증한다. 새로 만든 상태 프레임마다 레일을 좌우 절반으로 나눈 투명 hotspot 프레임 두 개를 만든다. 여기에 ON_DRAG, PUSH, 0.3초 EASE_OUT, LEFT/RIGHT 반응을 쓰고, 프레임 자체에는 간격을 초로 바꾼 AFTER_TIMEOUT 반응을 setReactionsAsync로 쓴다. 캡처된 next/previous 컨트롤이 있으면 그 요소에 ON_CLICK을 붙이고, 물리 경계에서 머무는 간선에는 반응을 쓰지 않는다. 초기 상태 프레임은 페이지 flow starting point로 등록한다. 적용 뒤 실제 reactions, hotspot 위치·크기·불투명도, flow start를 다시 읽어 `current`가 아니면 실패로 처리한다. 적용 영수증과 읽기 결과에는 carousel 상태를 넣고, 장면 지문에서는 hotspot을 뺀다.

## 변경 파일과 인터페이스

변경 경로는 `figma-bridge/web_design.js`, `tests/test_web_design.cjs`이다. 전체 경로와 diff 해시는 이 페이지의 Git 기록에 있다.

## 설계 이유와 출처

Figma가 자기 자신으로 가는 NAVIGATE를 받지 않으므로 경계에서 머무는 동작은 반응이 없는 상태로 표현했다. 이미 있는 프레임을 재사용할 때는 반응을 다시 쓰지 않는다. 읽은 상태가 계획과 다르면 사용자가 편집한 프레임을 보존하고 중단해 수정 사항을 덮어쓰지 않는다. 편집기가 레거시 별칭과 기본값을 덧붙이므로, 비교는 직접 작성한 필드만 정규화해서 한다. hotspot을 장면 지문에서 빼 프로토타입 배선이 화면 내용 변경으로 오인되지 않게 했다. 실패 메시지에는 단계 이름을 붙여 Figma가 어느 상태와 입력에서 거부했는지 영수증에 남긴다.

## 호환성·이관·복구

포크는 이 커밋과 부모의 변경 경로를 대조해 적용할 수 있다. 캐러셀 CMS나 외부 계정 연결은 필요하지 않다. 원본 화면과 사설 영수증은 로컬에 보존한다.

## 검증과 미검증

커밋의 Node 테스트는 2개 상태 carousel에서 좌우 hotspot 좌표(x 64/195, 각 131×120), 경계 hotspot에 반응이 없음, ON_DRAG PUSH LEFT, AFTER_TIMEOUT 3.2초, flow start 등록을 확인한다. 재적용 때 자식 수가 변하지 않고 `current`로 다시 판정되는지도 확인한다. 실측 렌더러 테스트 26개가 통과했다. 실제 Figma 파일에 4개 상태를 적용·재사용·다시 읽은 영수증 세 개 모두 carousel과 flow start가 `current`였다. 모든 상태에 AFTER_TIMEOUT 5초가 있었고, 경계(반응 없음)는 첫 상태 swipe_right와 마지막 상태 swipe_left뿐이었다. Present에서 손을 떼면 약 4.95초와 10.01초에 다음 상태로 넘어가 마지막에서 첫 상태로 돌아왔다. 마지막 상태에서 앞으로 드래그하면 1.5초 넘게 머물렀다. 한계도 있다. 첫 드래그가 넘어가지 않고 재시도에서 넘어간 사례가 두 번 있어, 드래그 시작 위치와 속도에 민감하다. ON_DRAG는 실제 드래그 방향을 구분하지 않고, 시작한 hotspot 절반으로 방향을 근사한다.

## 한계와 후속 개선

여기서 확인한 결과는 해당 입력과 검증 범위에 해당한다. 브라우저의 연속 스크롤 관성이나 물리 모바일 기기의 동작은 별도의 관찰이 필요하다.
