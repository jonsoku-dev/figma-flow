# fix: bound raster readbacks and interrupted reviews

## 문제와 계기

앞서 고정한 두 오라클은 표시된 동일 사진의 바이트가 행마다 복제되는 문제와, 중간 생성된 검토 페이지를 무시해 재시도 때 중복 페이지가 생기는 문제를 재현했다. 사진 테이블 전송과 보수적인 부분 작업 재사용/복구가 필요했다. 이 커밋은 manifest를 0.26.2 후보로 올렸지만 공개 릴리스나 전역 설치를 완료한 기록은 아니다. 근거는 첫 부모 `ce10c8591bda9ad100c5de7a0f5323f20f5827c9` 대비 14개 경로의 실제 diff다.
## 결과 동작

표시된 IMAGE 노드마다 `imageHash` 참조를 두고 페이지에서 실제 raster 바이트는 해시별 1회 읽어 최상위 테이블로 전달한다. 중복 해시의 바이트가 다르면 읽기를 거부하며, Python readback 검증기는 base64·단일 IMAGE paint·참조·테이블·선택적 옛 inline 바이트를 맞춰 검사한 뒤 입력을 변형하지 않는 복사본에서 기존 이미지 검증에 전달한다. 부분 검토는 packet/layout/file identity를 예약해 렌더러 업그레이드 뒤에도 같은 작업의 새 중복 페이지를 막고, 생성 중인 페이지를 실패 경로에서 되돌린다. 완료로 재사용할 페이지에는 늦게 기록되는 명세·노트 보드·팔레트·텍스트 스타일·범위와 flow metadata가 모두 있어야 한다. 일치하는 불완전 상태나 손상된 예약은 쓰기 전에 거부하고, 무관한 페이지는 무시한다.
## 변경 파일과 인터페이스

`figma-bridge/native_semantic_read.js`와 `code.js`가 `rasterImages`/`rasterImageRef`를 읽고 여러 페이지 결과를 합친다. `tools/figma_draft.py`의 `_native_readback_nodes()`가 table과 기존 inline 형식 모두를 검증·정규화한다. `figma-bridge/direction_review.js`가 검토 예약, 완료 메타데이터 검증과 실패 시 되돌리기를 관리한다. `tools/graph_sync.py`는 이 커밋에서는 변경되지 않았다. 두 manifest, README, 통합 가이드 한국어·영어·일본어, CHANGELOG 및 Python/Node 검사가 연결된다.
## 설계 이유와 출처

이미지 해시는 같은 실제 이미지 바이트를 공유할 테이블 키이며, 행 참조는 IMAGE paint의 `imageHash`와 일치해야 한다. 옛 inline bytes만 있는 readback도 계속 받되, table과 inline 양쪽이 있으면 디코딩 바이트까지 동일해야 한다. 전송은 기존 cap 아래로 유지한다. 부분 상태는 자동 정리하지 않고 기존 페이지 ID와 수동 복구 안내를 노출해 사용자 작업을 보존한다. 준비 중 예약은 instance hash만이 아니라 같은 논리 packet identity를 보며 업그레이드 후 중복 재실행을 막는다. 설계 경계는 [예약과 완료 메타데이터 결정](../decisions.md)에서 “재사용”과 “정상 네이티브 검증”을 별도로 둔다.
## 호환성·이관·복구

기존 인라인 `rasterImageBytes` readback은 계속 허용되고 새 테이블은 그 형식과 함께 올 수 있다. 새 참조는 해당 행의 단일 IMAGE paint 및 테이블의 같은 hash/bytes가 필수다. 기존 Figma 페이지와 사용자 수정은 지우지 않으며, 중단 상태를 성공으로 바꾸는 자동 복구도 하지 않는다. 기존 사용자 페이지는 실제 상태를 읽고 ID·사진 바이트를 확인한 뒤 지원되는 명세 edit 경로에서 정확한 누락 명세·주석만 고쳐야 한다. 완료 소유 마커만 남고 늦은 필수 metadata가 없는 같은 패킷은 재사용하지 않는다. 버전 문자열 0.26.2는 릴리스 게시·설치 보증이 아니며, 당시 전역 설치는 계속 0.26.1이었다.
## 검증과 미검증

이 변경에서 Python·Node 단위 및 전체 검사 기록은 통과했지만 후속 실제 생성 그래프 탐색에서 raster table이 빠지는 결함이 발견됐다. 따라서 이 커밋 단독으로 여러 경로의 기능 완료를 선언할 수 없다. 0.26.2 후보를 사용한 실제 작업에서 사진 4·24·56개가 있는 페이지 3개(노드 75·95·127개)와 각 8개 주석, desktop/mobile 정상 handoff를 읽고 기존 네이티브 값(전송 wire format 제외)이 보존된 후속 실행 근거가 있다. 14개 원본 작성은 약 100초라는 비직렬 비교 수치로 성능 향상을 주장할 수 없다. 실제 개선 gate는 이 커밋까지의 경로만으로 완성된 기준이 아니며, 최신 전체 검사와 생성 탐색 고정은 e179 후속 기록을 본다.
## 한계와 후속 개선

2,000,000바이트 전송 cap은 유지되며 본 변경이 외부 파일의 모든 소비 경로를 자동 변환하지 않는다. 입력 검증은 raster table의 구조·base64·실제 pinned asset hash를 검사하지만 네이티브 상태 전체의 품질 승인이나 화면 시각 승인은 아니다. 검토 완료 가드는 commit-marker 안전성과 필수 완료 metadata를 확인하는 방어선이며 전체 current wrappers/board의 정확성을 대신하지 않는다. 정상 재사용에는 정상 verifier가 계속 필요하다. 부분 복구가 기존 영수증이나 최종 ownership/flow completion metadata를 대신 복원하지 않으며 자동 재개·cleanup·delete도 하지 않는다. 생성 discovery 전파 누락은 별도 기준·수정으로 남았다.
