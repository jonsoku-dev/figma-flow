# feat: extend local Figma tooling and preserve native component properties

## 문제와 계기

기능을 찾았을 때 어떤 로컬 도구로 실행할지 알기 어려웠고, 기존 가져오기는 숨김·교체 속성을 연결한 자식 레이어의 참조를 전체 읽기에서 잃었다.

## 결과 동작

기능 검색은 편집기·제품 경로와 필요한 권한을 반환한다. 기존 Design 페이지의 네 예제는 독립 컨테이너에 추가한다. 일반 가져오기와 HTML/SVG 미리보기에서 선언된 BOOLEAN 및 INSTANCE_SWAP 기본값과 오버라이드를 처리한다.

## 변경 파일과 인터페이스

`tools/figma_feature.py route`, `tools/figma_api_inventory.py`, `tools/figma_rest_inventory.py`가 검색과 조회를 담당한다. SDK·위젯 생성기는 새 프로젝트를 작성한다. `figma-bridge/code.js`, `native_semantic_read.js`, `tools/design_system.py`에서 작성·실제 읽기·미리보기를 연결했다.

## 설계 이유와 출처

공식 Plugin API·REST·Widget 선언의 원본, 커밋, 라이선스를 library 하위에 보존했다. 같은 이름을 가진 멤버의 정적 참조는 실제 호출 증거와 분리한다. 예제는 검토한 고정 번들만 실행한다.

## 호환성·이관·복구

기존 등록 ID와 작업 홈을 사용한다. 출처가 바뀌면 번들을 재생성하고 기존 개발 플러그인을 다시 연다. 구버전 태그와 이전 작업의 근거를 보존한다.

## 검증과 미검증

getter 누락을 잡는 고정 Node 검사는 dc72dd8에서 실패하고 이 커밋에서 통과했다. 실제 Figma에서 컴포넌트 속성 검사 PASS, 그리드 셀, Boolean 결과, 마스크와 모션 클릭 왕복을 확인했다. 깨끗한 이 커밋의 Python 전체 검사 1,162건은 2건을 건너뛰고 통과했다.

## 한계와 후속 개선

공개 선언의 수와 개별 기능 구현률은 다르다. FigJam·Slides·Dev 및 Widget의 컴파일, 자동 fixture와 실제 편집기 인수 범위를 구분해야 한다. REST 요청 생성은 실제 인증 API 실행 전 단계다.
