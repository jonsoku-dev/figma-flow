# test: initialize the private workspace in clean value-probe checkouts

## 문제와 계기

value-path CLI test는 `ROOT/.figma-flow`를 temporary parent로 지정했지만 clean checkout에서는 그 디렉터리가 없었다. 따라서 검사는 다른 local state가 이미 생성한 환경에서만 시작할 수 있었다.
## 결과 동작

테스트가 owner-only `.figma-flow` root를 만든 뒤 그 안에서 private temporary bundle을 준비한다. 새로운 checkout에서도 같은 scope·manifest·file mode assertion을 수행한다.
## 변경 파일과 인터페이스

`tests/test_native_value_paths.py::test_private_runner_reuses_exact_scope_without_printing_it`가 실행 전에 private root를 생성한다. Product CLI와 plugin 코드는 바꾸지 않는다.
## 설계 이유와 출처

TemporaryDirectory에는 이미 존재하는 parent가 필요하다. Test가 `.figma-flow` 생성 책임을 가지면 사용자 작업 디렉터리를 preflight가 준비했는지에 의존하지 않는다.
## 호환성·이관·복구

생성된 root는 owner-only mode `0700`이고, 테스트용 output은 그 안에서 정리된다. 기존 source, plugin task와 Figma 자료는 건드리지 않는다.
## 검증과 미검증

Regression은 private runner가 file/page/plugin ID를 보존하고, generated code와 manifest를 owner-only로 만들며, network를 비활성화하는지 확인한다. 이 변경은 fixture admission test만 고친다.
## 한계와 후속 개선

검사는 repository-root directory creation과 private mode를 다룬다. Actual value getter 결과는 0.32 value receipt의 별도 범위다.
