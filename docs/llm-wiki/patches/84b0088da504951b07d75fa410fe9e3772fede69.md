# Little Hands 예제의 MySQL 8.4 전환

소스 커밋 `84b0088da504951b07d75fa410fe9e3772fede69`

## 문제와 계기

사용자는 플러그인과 독립된 예약 예제를 PostgreSQL에서 MySQL 8로 바꾸기로 했다.

## 결과 동작

예제의 Django, Compose, CI와 배포 SQL이 고정한 MySQL 8.4 LTS를 사용한다.

## 변경 파일과 인터페이스

`apps/little-hands/config/deployment.json`, `apps/little-hands/booking/migrations/0002_immutable_records.py`와 `tests/test_booking_database_release.py`를 바꿨다.

## 설계 이유와 출처

InnoDB 잠금과 트리거로 회차 구간을 직렬화하고, 활성 예약은 생성 열의 고유 키로 보호한다. 스키마 계정과 웹 계정 권한을 구분한다.

## 호환성·이관·복구

새 MySQL 스키마를 초기화한다. 운영 중인 다른 엔진의 데이터는 승인된 환경으로 별도 이관해야 한다.

## 검증과 미검증

DB를 띄우지 않고 Compose·CI 투영, Django 앱 검사와 마이그레이션 상태, 저장소 그래프의 관계를 대조했다. 동시 예약과 DB 권한은 실제 MySQL 검증이 남았다.

## 한계와 후속 개선

사용 중인 클러스터의 재사용과 새 클러스터 생성은 이번 작업 범위에서 제외했다. 이전 스크린샷과 Design 인수는 당시 증거에 연결된다.
