# feat: keep one font asset when two stylesheets import it

## 문제와 계기

기준 dbd4c0eb275a75dd5519e924c3c209716aa0578d는 자산에 sources가 없어 `duplicate font ingress must stay one asset and a byte change must go stale`로 실패했다.

## 결과 동작

html_channel은 각 참조에 유입 문서의 상대 경로를 붙이고, ref·path·status가 같은 자산은 하나로 합친다. fonts/body.woff2의 sources는 css/a.css와 css/b.css다. freshness는 record에 적힌 sha256과 현재 파일이 같으면 current, 바이트가 다르면 stale이고 changed에 그 상대 경로를 남긴다.

## 변경 파일과 인터페이스

tools/input_effect.py에 _ingress와 _merge_ingress를 추가하고 html_channel이 이를 사용한다. docs/development-roadmap/RD-05-asset-inventory/tasks.md에 범위를 적었다. tests/test_rd05_asset_freshness.py blob은 기준과 같다. freshness의 반환 필드는 그대로다.

## 설계 이유와 출처

RD-05-AC-01은 중첩된 두 출처의 같은 글꼴을 한 자산과 두 출처로 보여 준다. RD-05-AC-04는 바이트 변경 뒤 과거 목록을 최신으로 두지 않는다. 이 커밋은 그 두 사실을 로컬 파일로 고정한다.

## 호환성·이관·복구

기존 자산의 ref, path, status는 유지한다. sources가 없던 항목은 유입 경로 목록을 추가로 가진다. record schema와 freshness 계산은 이전과 같다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd05_asset_freshness`를 기준 dbd4c0eb275a75dd5519e924c3c209716aa0578d에서 종료 코드 1, 대상 29198999ebfe2aa9975576dc5792939315fbc850에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 마지막 assertion은 `duplicate font ingress must stay one asset and a byte change must go stale`이다. 조건은 RD-05-AC-01이다. 같은 구현에서 경로 검사와 input effect CSS 검사도 종료 코드 0이었다. 브라우저에서 글꼴이 로드되는지는 관찰하지 않았다.

## 한계와 후속 개선

요약 행은 아직 sources 목록 전체를 한 줄로 펼치지 않는다. 실제 CSS 간접 사진과 브라우저 로딩 대조는 다음 단위다. AC의 브라우저 관찰은 통과로 기록하지 않는다.
