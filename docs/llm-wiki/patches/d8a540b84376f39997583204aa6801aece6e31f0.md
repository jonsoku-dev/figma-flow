# test: pin declared layout token bindings

## 문제와 계기

실제 정상 makeDraft 출력에서 선언 Auto Layout의 gap=12에 필요한 variable binding 22개가 빠져 있었다. 숫자가 보이는 것만으로 token binding과 fresh readback 계약을 충족하지 않으므로 실제 생성 경로의 기준을 고정했다.

## 결과 동작

2상태×2 viewport의 gap-row에서 itemSpacing=12와 padding=4/8의 실제 FLOAT variable binding을 요구한다. normal readDraft가 같은 binding을 보고하고 geometry·paint·기존 control binding 및 무관한 node/variable을 보존해야 한다. 제품 수정은 포함하지 않는다.

## 변경 파일과 인터페이스

[finalize_declared_layout_bindings.cjs](../../../tests/finalize_declared_layout_bindings.cjs)를 추가했다. declaredPacket → normal makeDraft → 실제 variable store/resolveForConsumer → fresh readDraft가 경로다. negative gap, Infinity, pinned geometry와 모순되는 flow는 page/node 생성 전에 거절한다.

## 설계 이유와 출처

값 직기입만 확인하지 않고 boundVariables alias, store의 실제 variable, consumer에 대한 FLOAT12 해석을 검사한다. frame [12,236,68,28], AUTO leaf 위치, paint, control padding binding도 확인하여 binding 추가가 레이아웃을 깨뜨리지 않게 한다.

## 호환성·이관·복구

무관한 기존 variable=99와 node는 보존한다. 뒤의 readDraft는 바뀐 control x를 새로 읽고 이전 snapshot은 유지해야 한다. 제품 schema/API는 바꾸지 않는다. raw valuesByMode에 literal12가 직접 있어야 한다는 초기 assertion은 후속 fcace53이 실제 alias chain에 맞춰 정정한다.

## 검증과 미검증

Git diff에서 makeDraft의 4개 frame, FLOAT 해석, fresh binding ID 일치, geometry/기존 binding 보존과 생성 전 거절을 확인했다. 상위 세션 최초 실행은 missing binding의 의도한 red였다. 미커밋 제품 수정의 결과를 이 기준의 역사적 성공으로 바꾸지 않는다. 이번 작업은 정적 기록만 했다.

## 한계와 후속 개선

host는 실제 native reflow를 모사하지 않는다. getter·variable store가 있는 API fixture 통과와 Figma binding 관찰은 별개다. R6 뒤 남은 22개 결함과 새 R7 결과를 혼동하지 않으며 R7 native 전체 성공은 미확정이다.
