# feat: route the full API backlog by Design applicability and verify owned native receivers

## 문제와 계기

기존 priority inventory는 Plugin API 선언·역할 점수·관측 여부를 정렬했지만, Design 전용 작업에서 다른 편집기 전용 receiver가 실행 후보로 보일 수 있었다. 페이지·문서와 추가 scene node 종류에 대한 실제 receiver 관측 근거도 제한돼 있었다.
## 결과 동작

API priority rows에 Design 범위 분류를 연결하고 `--design-only` queue가 `design-node`, `shared-node`, `design-api`만 반환한다. Design typography graph도 이 필터를 사용한다. 새 private fixture generator는 등록된 개발 플러그인으로 표본 scene을 만들고, 선택한 정확한 node ID·type에서 정적 allowlist의 property와 method만 probe한다. 결과는 해시와 안전한 값 요약을 담은 그래프로 보존한다.
## 변경 파일과 인터페이스

`tools/api_priority.py`는 편집기 scope를 구분하고 Design queue를 filter한다. `tools/design_type_review_graph.py`는 Design-only queue 위치로 graph를 만든다. `tools/native_api_fixture_project.py`와 `figma-bridge/native_api_fixture.js`가 owned Design lab을 생성하고, `tools/native_api_probe.py`와 `figma-bridge/native_api_probe.js`가 노드별로 허용된 관측을 수행한다. 회귀 테스트와 sanitized scene evidence는 `tests/`와 `specs/design-inspection/scene-observations.json`에 있다.
## 설계 이유와 출처

공식 Plugin API audit·원문·다른 편집기의 분류를 지우지 않는다. 그 멤버들은 전체 조사 분모와 설명에는 남지만 Design queue에서는 제외한다. 런타임 관측은 exact `member:<hash>`와 exact receiver type을 사용하며, method 호출도 개별 static branch를 통해서만 수행한다. 표본은 이 플러그인의 marker가 있는 node로 한정한다.
## 호환성·이관·복구

fixture는 해당 private lab의 새 소유 페이지/레이어에만 쓴다. 재실행은 marker로 기존 표본을 재사용하고 원래 페이지와 selection을 복원한다. 읽기 그래프는 node ID, 이름, text, variable ID, raw vector path와 이미지 바이트를 싣지 않는다. 이전 API audit와 overlay는 역사적 출처로 보존한다.
## 검증과 미검증

검사 범위는 API inventory, priority queue, fixture generator와 bounded probe 회귀에 연결된다. 실제 관측 그래프는 timestamp와 receipt hash를 동반한 exact member edge를 사용한다. 지원 표면과 관측 값은 [Design API 관측 안내](../../native-api-probe.md), [priority 정책](../../api-priority.md), [scene evidence graph](../../../specs/design-inspection/scene-observations.json)에서 확인한다.
## 한계와 후속 개선

분류는 현재 pinned Plugin API catalog와 관측 그래프에 한정된다. 성공한 선택 receiver를 전체 Figma Design API의 런타임 지원으로 확대하지 않는다. 0.32 overlay의 최종 unique-key 합계는 최종 service/value graph가 고정된 뒤 release index에서 확인한다.
