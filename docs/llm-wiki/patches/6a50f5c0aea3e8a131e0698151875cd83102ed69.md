# fix: record each failed execution once

## 문제와 계기

독립 검수가 실행 이력의 두 실제 코드 문제를 찾았다. native error가 관측된 뒤 handler가 throw하면 failed가 두 번 기록됐고, remote handler가 정상 readback을 주지 않아 domain validation이 실패하면 history가 requested에 남았다. 두 조건을 기준 fce49da의 실제 코드에서 재현했다.

## 결과 동작

직접 UI catch는 이미 관측한 failed를 다시 추가하지 않는다. 자동 control의 검증·실행 실패는 executionId를 정리하기 전에 마지막 실패 한 건을 저장한다. 검토 수신기 verification 실패도 같은 outcome으로 보존해 이중 기록을 막는다. 현재 상태 차트는 요청됨이 아니라 실제 실패 관측을 집계한다.

## 변경 파일과 인터페이스

`figma-bridge/workspace_host.js`의 예외 기록과 `figma-bridge/workspace_control.js`의 domain catch·verification catch만 수정했다. 바뀐 경로는 두 개다. tests/workspace_history_failure_oracle.cjs와 host/control/activity 검사는 기준 커밋과 같은 blob·mode를 유지했다. wire 권한, native transaction, Python uncertainty와 payload 한도는 바꾸지 않았다.

## 설계 이유와 출처

실패를 UI 집계기에서 추정하지 않고 실제 실패가 발생한 실행 경계에서 기록한다. 이미 관측한 실패는 중복 제거하고, 검증에서 새로 확인한 실패는 보존한다. 기준을 낮추는 대안이나 성공 receipt 재작성은 사용하지 않았다. 근거는 부모 대비7줄 추가·2줄 제거 diff와 고정 oracle다.

## 호환성·이관·복구

선택적 executionId와80건 제한, legacy 이력, task/revision scope를 유지한다. 기존 저장 파일을 migration하거나 삭제하지 않는다. 원래 실패 결과와 private readback을 남긴다. 이 수정은 애매한 native 쓰기를 자동으로 재실행하거나 uncertainty를 해제하지 않는다.

## 검증과 미검증

고정 oracle의 실제 Git archive 기준 실행은 AssertionError 종료1, 대상은 종료0이다. host/control/activity의29개 검사는 통과했다. 후속 전체 Node 검사는229개 중228통과·1skip, 데모2개 통과다. 실제 Figma에서0.26.3 runtime의 read 한 번을 요청·진행·읽기 완료3단계로 관찰했고127개 node·변수·collection·3 raster entry가 직전 설치본 읽기와 같았다. 강제 native 실패의 UI 조작은 실제 Figma에서 수행하지 않았다. Python 전체 결과는 별도 verification 기록을 따른다.

## 한계와 후속 개선

실행 ID는 UI 연관 정보이며 서버 claim이나 권한 증거가 아니다. 이 테스트는 해당 두 실패 기록 조건과 scope를 검증하며 모든 비동기 실패의 부재를 증명하지 않는다. 원래61개 회귀·실기기·클라우드 저장·실제200%확대·글꼴 binary 동일성의 미검증 범위는 유지한다.
