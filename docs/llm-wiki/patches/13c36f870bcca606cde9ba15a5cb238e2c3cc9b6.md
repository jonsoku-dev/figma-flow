# feat(little-hands): add opt-in DOM-to-semantic family target mapping

## 문제와 계기

`apps/little-hands/design`의 DOM-to-Design 내보내기에는 화면 요소를 NF-01 정본 컴포넌트 패밀리 대상과 연결하는 명시적 매핑이 없었다. 기존 내보내기를 바꾸지 않고 선택적으로 켤 수 있는 opt-in 매핑 계층이 필요했다.

## 결과 동작

커밋 `13c36f870bcca606cde9ba15a5cb238e2c3cc9b6`는 `apps/little-hands/design/family-targets.json`(스키마 `little-hands-family-targets-v1`)을 추가하고, `apps/little-hands/design/source.py`의 `load_family_targets`가 허용된 패밀리·대상 종류·상태만 받아들이며 잘못된 항목은 `ValueError`로 거부하는 opt-in 매핑을 구현했다. 기본 DOM 내보내기 동작은 그대로 유지된다.

## 변경 파일과 인터페이스

`apps/little-hands/design/family-targets.json`(신규), `apps/little-hands/design/source.py`, `apps/little-hands/design/test_source.py`, `apps/little-hands/design/README.md`를 추가·갱신했다.

## 설계 이유와 출처

[NF-01 설계서](../../next-roadmap/NF-01-component-families.md)의 app-mapping 단계와 [역량 검토](../../next-roadmap/capability-review.md#p1-component-families)에 근거해 기존 `apps/little-hands/design` 출력 호환성을 깨지 않는 opt-in 선택지로 설계했다.

## 호환성·이관·복구

opt-in 매핑을 지정하지 않은 기존 내보내기는 P0 이전 출력과 동일하다. 후속 커밋 `b40278221d8c023249462cd628edbdc51c0b041f`와 `baac57eb1582698d4cdfef2cbf63b2c34d3ba9fd`가 `nf01-contract` 정렬과 그래프 소유 예제를 이어서 확장한다.

## 검증과 미검증

`apps/little-hands/design` 단위 테스트(`test_source.py`)는 이후 최종 제품 소스 `e6f4fd8` 및 CI Run `43599181267`까지 `28/28 OK`로 통과했다. 이 커밋 단독으로는 실제 Figma 컴포넌트 세트 생성이나 브라우저 렌더를 수행하지 않았다.

## 한계와 후속 개선

초기 매핑 스키마는 `nf01-contract` 정규화 전 단계여서 후속 커밋(`ad26c908`, `b4027822`, `baac57eb`)에서 정본 계약 및 자체 예제와 결합된다.
