# feat(benchmark): record pinned fresh-read baselines with strict evidence boundaries

## 문제와 계기

측정 task를 반복 실행해 샘플·보고서·공개 요약을 남기는 러너가 필요했다. 독립 검토는 이전 러너 후보에서 coverage 객체가 없는 full 읽기를 complete로 추정하는 문제, 작업 트리가 dirty한 소스를 허용하는 문제, 요청한 file·page와 readback을 대조하지 않는 문제를 찾았다.

## 결과 동작

커밋 `5d068b010d5fb53147a15913efbd458737eb8281`는 `tools/native_read_benchmark.py`를 추가했다. 기본·timed·진단 task를 받아 샘플(`figma-flow-native-read-benchmark-sample-v1`), 비공개 보고서(`…-report-v1`), 공개 요약(`…-public-v1`)을 쓴다. `--repeats`는 최소 5회다. 실패는 재시도하거나 지우지 않고 센다. content drift, dirty 또는 알 수 없는 소스 상태, 다른 file·page의 readback, 측정 전후 runtime이 `current-self-reported`가 아닌 경우에는 verdict가 `inconclusive`이고 종료 코드는 2다. full discovery coverage는 complete로 추정하지 않는다. 공개 요약은 원시 file·page ID를 숨긴다. NF-02 부록을 이 동작에 맞췄다.

## 변경 파일과 인터페이스

새 `tools/native_read_benchmark.py`, `tests/test_native_read_benchmark.py`, `tests/test_native_read_benchmark_boundaries.py`. `docs/next-roadmap/NF-02-incremental-native-read.md`.

## 설계 이유와 출처

[P2 1차 실행 계약](../../next-roadmap/p2-wave1-acceptance.md)의 B1–B5(모든 시도 보존, drift·범위 불일치 시 통계 없음, coverage `null`, 진단 분리)를 코드 검사로 고정했다.

## 호환성·이관·복구

새 도구다. 제품 경로를 바꾸지 않는다. 보고서는 새 비공개 디렉터리에만 쓴다.

## 검증과 미검증

`python3 -B -m unittest tests.test_native_read_benchmark tests.test_native_read_benchmark_boundaries`가 workload 교차 실행과 진단 분리, 실패 집계, drift 차단, 휘발 필드만 뺀 content hash, runtime 변경 시 판정 불가, 공개 요약의 ID 숨김, 5회 미만 거절, workspace 허용, coverage 비추정, dirty·미상 소스 거절, 다른 file·page readback 거절, 부록의 캐시 절감 상한 비주장을 검사한다.
