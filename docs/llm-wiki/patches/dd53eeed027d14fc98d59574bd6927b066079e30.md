# fix: hit-test the same visible tab list and keep repeated clicks once

## 문제와 계기

독립 검수에서 같은 클릭을 반복한 A→B→A→B 관찰이 결합 단계에서 거절되는 문제와, 숨겨진 형제 요소가 hit test 순번을 밀 수 있는 문제를 찾았다.

## 결과 동작

스크롤과 가려진 탭 검사는 읽을 때와 같은 유일한 보이는 목록과 보이는 컨트롤을 쓴다. 같은 출발·컨트롤·목적지의 반복 클릭은 `inputs.json`에 모두 남기고 전이에는 한 번만 넣는다. 입력 형식 문서는 이 동작과 `Initial state` 라벨을 설명한다.

## 변경 파일과 인터페이스

`tools/web_tabs_capture.mjs`(`readTabs`의 `probe` 인자)와 `docs/web-tabs-input.md`를 바꿨다.

## 설계 이유와 출처

같은 관찰을 다시 확인한 클릭은 새 사실이 아니므로 그래프에 중복 간선으로 넣지 않는다. 다른 목적지로 가는 같은 컨트롤은 여전히 컴파일러가 거절한다.

## 호환성·이관·복구

출력 파일 이름과 관찰 JSON 형식은 그대로다.

## 검증과 미검증

실제 Devtool 홈에서 A→B→A→B를 다시 캡처해 클릭 세 번의 hit test가 모두 참이고 그래프에 전이 두 개가 생성됨을 확인했다.

## 한계와 후속 개선

숨겨진 형제 요소가 있는 페이지는 실제로 시험하지 않았다. 처음 상태가 다시 클릭되지 않으면 라벨은 `Initial state`로 남는다.
