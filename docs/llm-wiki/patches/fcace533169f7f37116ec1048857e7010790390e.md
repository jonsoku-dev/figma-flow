# test: resolve observed layout variable aliases

## 문제와 계기

선언 gap binding의 초기 raw assertion은 semantic variable의 valuesByMode에 literal12가 직접 있다고 가정했다. 실제 binding은 review/space/12→primitive12→FLOAT12 alias chain을 보존하므로 이 검사만 정상 alias를 거절했다.

## 결과 동작

fresh raw의 binding 대상에서 각 collection의 defaultModeId 값을 읽고 VARIABLE_ALIAS이면 실제 target을 따라 최종 FLOAT12에 일치하도록 요구한다. alias를 flatten하는 제품 변경은 하지 않는다.

## 변경 파일과 인터페이스

[finalize_declared_layout_bindings.cjs](../../../tests/finalize_declared_layout_bindings.cjs)의 literal 배열 포함 검사를 raw alias traversal로 바꿨다. 각 단계에서 cycle, FLOAT형, collection 존재, alias target 존재를 assert하고 마지막 value=12를 확인한다.

## 설계 이유와 출처

consumer 값만이 아니라 fresh evidence의 실제 variable·collection을 따라 semantic/primitive 계층을 보존하면서 올바른 gap 해석을 증명한다. 직접 literal이라는 가정은 바로잡되 누락 target이나 순환을 허용하지 않는다.

## 호환성·이관·복구

normal makeDraft, binding ID, resolveForConsumer, padding·geometry·unrelated binding 보존, fresh read 독립성, 잘못된 선언의 생성 전 거절은 유지한다. 제품 schema나 variable store를 flatten하거나 검사를 약화하는 커밋이 아니다.

## 검증과 미검증

Git diff에서 raw.variables/raw.collections의 default-mode chain과 seen 집합의 cycle 거절, 최종12 일치를 확인했다. 이번에는 실행하지 않았다. 초기 oracle의 잘못된 literal 가정 보정과 그 뒤 제품 binding 수정의 통과는 구분한다.

## 한계와 후속 개선

이 fixture는 default mode의 FLOAT alias chain을 대상으로 하며 모든 mode/variable형의 일반 해석기가 아니다. 실제 Figma의 22개 gap binding 해소와 새 R7 전체 통과는 별도 관측이 필요하다.
