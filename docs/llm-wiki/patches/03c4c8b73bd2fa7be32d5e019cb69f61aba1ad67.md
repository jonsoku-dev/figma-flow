# test: keep localization and input admission checks current

## 문제와 계기

의존성 상태 UI가 번역 키를 사용하고 입력 record의 실제 CLI 경로가 명시되면서, 한국어 리터럴과 문자열 부재를 요구하던 검사 기준이 구현 계약과 어긋났다.

## 결과 동작

검사는 DependencyText의 tr 호출과 ko/en/ja의 stale·retired·orphan 번역값을 함께 확인한다. input_effect는 argparse를 소유하지 않고 workspace CLI가 입력 admission을 소유한다는 경계를 고정한다. 제품 코드 변경은 없다.

## 변경 파일과 인터페이스

두 Python 테스트만 변경했다. DependencyText 소스 → workspace locale JSON, input_effect 소스 → figma_workspace의 --input-record 경로를 정적으로 대조한다.

변경 경로: [tests/test_rd03_dependency_freshness.py](../../../tests/test_rd03_dependency_freshness.py), [tests/test_rd05_input_route.py](../../../tests/test_rd05_input_route.py).

## 설계 이유와 출처

문구 리터럴보다 번역키와 각 언어의 실제 값이 사용자 계약이다. --input-record가 설명 문자열에 있다는 이유로 실패시키는 대신 argparse 소유 여부를 검사하여 CLI 책임을 확인한다.

## 호환성·이관·복구

CLI 플래그·번역 API를 새로 만들지 않는다. 이전 검사의 문자열 기대만 교체하며, sendMessage/workspace-open 부재 검사와 workspace CLI 플래그 존재 검사는 유지한다.

## 검증과 미검증

git show 원문에서 번역 세 언어 확인과 argparse 부재 assertion을 확인했다. 이 기준 커밋만으로 번역된 화면이나 입력 admission이 제품에서 통과했다고 주장하지 않는다.

## 한계와 후속 개선

소스 문자열 검사는 런타임 언어 전환·사용성의 증명이 아니다. 실제 UI와 CLI의 실행 증거는 별도 제품 변경 및 검증에 연결해야 한다.
