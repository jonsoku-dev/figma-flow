# test: pin actual Figma group coordinates

## 문제와 계기

실제 Group 자식 getter의 x/y를 Group 원점에 또 더해 title을(-330,-648)로 계산했지만 native absoluteBoundingBox는(-165,-324)였다. 기존 mock이 자식 좌표를 Group-relative로 잘못 모델링하여 제품과 검사가 같은 오류를 공유했다.

## 결과 동작

새 JS/Python oracle과 sanitized getter fixture는 Group/Boolean Operation을 좌표 누적에서 투명하게 취급하고 실제 containing Frame 원점만 더하도록 요구한다. translated Frame·nested Group·readback·placement·rollback·post-authoring geometry를 검사한다. 제품 코드는 이 커밋에 없다.

## 변경 파일과 인터페이스

[JS Group oracle](../../../tests/finalize_group_coordinates.cjs), [Python oracle](../../../tests/finalize_group_coordinates.py), [sanitized fixture](../../../tests/fixtures/rd02/native-group-coordinates.json)를 추가했다. 기존 [native layout](../../../tests/finalize_native_layout.cjs), [placement](../../../tests/rd02_container_placement_oracle.cjs), [readback](../../../tests/rd02_container_readback_oracle.cjs), [sizing](../../../tests/rd02_container_sizing_oracle.cjs)의4개 mock도 실제 Group getter와 맞췄다.

## 설계 이유와 출처

공식 계약은 Group/Boolean Operation의 직계 부모 대신 containing parent 기준으로 좌표를 해석하고 절대 위치 누적에서 두 종류를 건너뛰라고 설명한다. [Figma relativeTransform](https://developers.figma.com/docs/plugins/api/properties/nodes-relativetransform/). grouping은 같은 절대 위치를 보존하며 appendChild는 상대 위치를 보존한다. [Figma group](https://developers.figma.com/docs/plugins/api/properties/figma-group/). fixture는 실제 숫자 getter와 독립 absoluteBoundingBox를 보존하고 ID는 합성 값으로 바꿨다.

## 호환성·이관·복구

실제 Group은 자식 bounds에서 x/y/width/height가 파생되며 Group 이동은 자식 위치에 delta를 준다. 보정한 mock은 이 동작을 반영한다. placement는 annotation/reaction identity와 무관한 leaf를 보존하고 실패 시 원래 raw 좌표·부모·순서를 복구해야 한다. missing/cyclic ancestry와 실제 geometry drift는 계속 거절한다.

## 검증과 미검증

상위 세션의 수정 전 기준은 Node6개 실패와 Python2개 subtest 실패였고 rollback negative는 통과했다. 이후 미커밋 제품의4개 조건부 수정 뒤 Node7개/Python2개 및 관련 검사가 통과했다는 별도 결과가 있다. 원래 R7의6개 JS와 packet/code attestation 보존 archive는 비공개 근거이며 이 커밋의 실제 native 성공으로 소급하지 않는다. 이번 기록은 diff와 공식 문서를 대조했다.

## 한계와 후속 개선

captured getter와 달리 translated Frame/nested 사례는 합성이다. 단순 x/y 모델은 임의 rotation/skew의 일반 transform 해석을 검증하지 않는다. R8의44 screen+2 footer Group 정상 생성은 진행 중이므로900초 허용 실행의 성공·최종 native positive를 주장하지 않는다. 실제 ID/file key/원시 packet/개인 경로는 공유 페이지에 싣지 않는다.
