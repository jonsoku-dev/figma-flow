# test: prove runtime extraction and task isolation

## 문제와 계기

RD07의 transport 추출 동등성, trusted source pin, task closure 격리를 문서나 문자열 존재만으로 완료할 수 없었다. 당시 source 본문을 동결하고 실제 publisher 출력과 claim 경계를 실행하는 coverage-only 기준이 필요했다.

## 결과 동작

새3개 테스트는 과거 추출 전후 함수 본문·transport trace 동등성, transport만 변경한 implementation digest의 옛 mutation claim 거절과 현재 identity의 정상 claim, 실제로 게시한 두 native-edit closure의 UI/readback 격리를 검사한다. 제품 변경은 없다.

## 변경 파일과 인터페이스

[runtime contract matrix](../../../tests/finalize_runtime_contract_matrix.py)와 [extraction baseline](../../../tests/fixtures/rd07/extraction-baseline.json)을 추가했다. fixture는 2db4fdafa3e8e337c68cdb4d4dd53f9d1f30a797→199683f8c221fcac718991dd91ad96b6a50ab144 원문의 Git blob/SHA256 및 publisher assembly를 보존한다. 테스트는 Git refs 없이 내장 원문 hash를 재계산한다.

## 설계 이유와 출처

controlRequest 추출 body와 남은 control body의 정확한 일치, transport-before-control 조립 순서와 poll/native-started/result/reject의4개 trace를 비교한다. 동등성 범위는 당시 추출뿐이며 뒤의 protocol2·용량 변경은 포함하지 않는다. copied installation의 transport 한 파일만 수정해 digest 경계를 직접 검사한다.

## 호환성·이관·복구

옛 implementation은 pending mutation을 claim하지 못하고 readiness=unverified여야 한다. 같은 요청은 정확한 current identity로 claim 가능해야 하므로 모든 claim을 막는 잘못된 구현도 걸린다. 두 task의 nonce·workspace envelope·lexical constants는 각각 격리되고 stale/foreign 메시지는 무시해야 한다.

## 검증과 미검증

Git diff에서 publisher가 만든 두 정상 task의 동일 lexical 이름을 VM에서 함께 로드하고 각 UI/config와 file/page readback만 관측하는 검사를 확인했다. 이는 runtime 격리의 fixture 근거이며 실제 Figma 접속이 아니다. 이번 기록 작업은 정적 대조만 했고 별도의 실행 통과나 제품 인수를 새로 주장하지 않는다.

## 한계와 후속 개선

과거 fixture는 이후 모든 transport 버전이 동일하다는 증명이 아니다. copied source digest 및 VM은 서버·브라우저·live Figma가 없으며 실제 host 설치나 native task 실행을 대체하지 않는다. private 원본 workspace나 실제 ID는 기록하지 않는다.
