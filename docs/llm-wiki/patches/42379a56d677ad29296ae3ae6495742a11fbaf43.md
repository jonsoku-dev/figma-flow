# docs: record clean CI environment repairs

## 문제와 계기

0.27.1 후보의 두 clean CI 실패는 각각 DB workflow 환경변수 불일치와 WOFF2 변환 의존성 누락이었다. 선행 수정 `6178905a1f182e5fcfe7b3fdf22fc57116544ea3`와 `aa8b7191405b160d1119c403510152a12e0ae801` 뒤, 상세 원인과 당시 검증을 릴리스 기록에 연결할 필요가 있었다. 이 커밋은 제품 코드를 수정하지 않고 해당 변경을 기록한다.

## 결과 동작

Wiki는 DB 설정 수정, WOFF 지원 extra 선언, 그 이전의 CI 실패와 0.27.1 결과를 상세 페이지로 연결한다. `releases.md`에는 제품 소스 변경과 문서 발행의 관계가 남는다. 기록 추가만으로 CI·설치·Figma 검증을 새로 수행하거나 성공으로 승격하지 않는다.

## 변경 파일과 인터페이스

첫 부모 `aa8b7191405b160d1119c403510152a12e0ae801` 대비 변경은 `docs/llm-wiki/catalog.json`, 세 페이지 `6178905a1f182e5fcfe7b3fdf22fc57116544ea3.md`, `aa8b7191405b160d1119c403510152a12e0ae801.md`, `e75d60b7b95fc48144368f7d659ad0d0918fddce.md`, 그리고 `docs/llm-wiki/releases.md`다. 공개 제품 인터페이스와 설정은 변하지 않는다.

## 설계 이유와 출처

전체 Git SHA별 본문은 두 수정의 근거를 해당 제품 커밋과 분리해 보존한다. 새 문서는 원격 PostgreSQL workflow 실패, Brotli 누락, 후속 clean 환경 검사 결과를 별도로 설명한다. 관련 근거는 위 세 페이지와 [0.27.1 릴리스 기록](../releases.md#v0.27.1)이며, 이 커밋은 그 내용을 색인하고 서로 연결한다.

## 호환성·이관·복구

문서와 catalog만 바뀌므로 플러그인 동작, 설치 데이터, 앱 데이터에는 이관이 없다. 문서 발행을 되돌리면 근거 페이지와 catalog 연결이 사라진다. 제품 수정의 복구 여부는 각 제품 패치의 설명을 따른다.

## 검증과 미검증

변경 범위는 Wiki 기록 파일뿐이며, 제품 테스트를 추가하거나 실행하지 않았다. 본문에 인용된 테스트와 원격 CI 영수증은 각각 그 실행 시점의 근거다. 문서 커밋 자체는 새 CI, 패키지, 설치 또는 native 실행을 증명하지 않는다.

## 한계와 후속 개선

기록은 실제 명령 출력의 진실성이나 모든 환경에서의 성공을 보증하지 않는다. 이후의 원격 CI와 0.27.1 tag·ZIP·설치·Figma 영수증은 후속 커밋 `068eb35374c2ec5f6f86efad6cefe7c316fa0740`의 릴리스 기록에서 별도로 다룬다.
