# perf: publish one signed workspace generation per native plugin upgrade

## 문제와 계기

Design host가 stale task 80개를 갱신할 때 `workspace.replay`가 task마다 전체 signed plugin generation을 발행했다. 각 generation은 그 시점의 모든 task 코드를 다시 묶으므로 같은 workspace를 반복 직렬화했다.
## 결과 동작

`HostAdapter.native`는 한 번의 batch replay에서 stale generator task를 재생성하고, 모든 row를 검증한 뒤 workspace manifest를 가리키는 새 generation을 한 번 발행한다. generator source fingerprint가 바뀌었지만 task revision이 같으면 artifact를 다시 교체하지 않고 generator fingerprint만 보정한다.
## 변경 파일과 인터페이스

`tools/figma_workspace.py`에 `replay_batch`와 source fingerprint를 고정하는 선택적 `publish` 인수를 추가했다. `tools/plugin_startup.py`의 native update 경로가 batch 결과 하나를 사용한다. `tests/test_plugin_startup.py`는 3개 task, 단일 발행, dependency pin, backup 보존, 중간 실패를 검증한다.
## 설계 이유와 출처

batch는 기존 admission·artifact 검증, exact file/page destination, request hash, argument/input hash, source-input pin, dependency graph 검증을 재사용한다. signed catalogue generation/signature와 trusted source fingerprint를 비교해 snapshot을 고정한다. dependency edge의 key·revision·artifact hash는 자동으로 새 dependency에 맞추지 않는다. 기존 per-task `replay` API는 그대로 둔다.
## 호환성·이관·복구

기존 `.tasks` artifact와 `.generations` backup은 수정하거나 삭제하지 않는다. 실패 전에는 임시 batch에서만 작업한다. manifest commit marker가 그대로이면 새 staging artifact를 임시 위치로 되돌리고 이전 catalogue sidecar를 복구한다. Figma 문서나 control request를 변경하지 않는다.
## 검증과 미검증

`python3 -m unittest tests.test_plugin_startup`은 30개 테스트를 통과했다. `python3 -m unittest tests.test_workspace_replay tests.test_plugin_startup`은 35개 테스트를 통과했다. 새 3-task regression은 generator 3회·publish 1회, old artifact/generation 보존, dependency edge의 기존 revision 보존을 확인한다. 중간 두 번째 generator 실패는 catalogue·artifact tree를 바꾸지 않는다. 동일 최신 workspace의 재실행은 publish 없이 `files-current`를 반환한다.
## 한계와 후속 개선

batch가 기존 external input 또는 dependency revision과 맞지 않으면 재실행을 거절하고 fresh admission을 요구한다. 성공적인 파일 발행만으로 등록된 plugin의 실제 로드 완료를 주장하지 않는다. 작업을 마친 뒤 같은 등록 Figma Flow를 다시 열어야 한다.
