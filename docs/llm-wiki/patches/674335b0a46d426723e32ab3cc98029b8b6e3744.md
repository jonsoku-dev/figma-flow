# test: pin scroll-aware authored quality admission

## 문제와 계기

선언한 스크롤 영역을 native 경로가 허용해도 일반 quality/prepare-native-review 입구가 같은 정상 authored overflow를 off-canvas로 거절하면 작업은 여전히 막힌다.

## 결과 동작

새 frozen oracle은 두 authored-native schema의 정상 수평·수직·양축 overflow와 텍스트를 design_quality.run 파일 입구에서 허용하도록 요구한다. root clip·일반 clip·잘못된 축·미소유 leaf는 계속 차단한다.

## 변경 파일과 인터페이스

tests/finalize_scroll_quality.py 하나를 추가했다. 임시 native-layout.json → design_quality.run → errors/passed를 읽고 파일 바이트와 원본 객체가 변하지 않는지 검사한다. 제품 소스는 변경하지 않았다.

변경 경로: [tests/finalize_scroll_quality.py](../../../tests/finalize_scroll_quality.py).

## 설계 이유와 출처

quality 내부 helper만 우회해 통과시키지 않고 일반 파일 입구를 사용한다. nested clip은 조상 순서로 판정해야 하며 스크롤 허용은 text-overlap·tiny-text·contrast·control-size·control-text-overlap 검사를 면제하지 않는다.

## 호환성·이관·복구

원시 x/y를 viewport에 맞춰 clamp하면 안 된다. 새 schema나 변경된 사용자 CLI를 도입하는 커밋이 아니라 현재 계약의 독립 기준을 고정하는 커밋이다.

## 검증과 미검증

상위 세션이 제공한 기준 실행 요약은 이 커밋의 quality oracle에서 5개 테스트, 8개 subtest 실패라는 의도한 red였다. 이번 작업은 Git 원문만 대조했다. 이후 미커밋 제품 수정의 통과를 이 기준 커밋의 통과로 소급하지 않는다.

## 한계와 후속 개선

authored admission은 native getter·Figma 스크롤 상호작용의 증명이 아니다. 후속 제품 수정과 현재 실행 영수증을 별도로 연결해야 한다. 전체 앱 Figma import는 미완료다.
