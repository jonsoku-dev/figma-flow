# feat: move control transport out of the domain checks

## 문제와 계기

기준 2db4fdafa3e8e337c68cdb4d4dd53f9d1f30a797는 controlRequest가 workspace_transport.js에 없어 `pure transport must leave domain checks in place`로 실패했다. 전송과 도메인 검사가 한 파일에 있었다.

## 결과 동작

figma-bridge/workspace_transport.js의 controlRequest는 POST와 Bearer로 poll, native-started, result를 보낸다. figma-bridge/workspace_control.js는 그 함수를 정의하지 않고 호출만 한다. controlExecute와 controlAllowed는 그 파일에 남는다. tools/figma_workspace.py 발행은 workspace_transport.js를 workspace_control.js 앞에 붙인다. mock fetch는 http://localhost:9/control/poll과 Bearer private를 본다.

## 변경 파일과 인터페이스

figma-bridge/workspace_transport.js를 추가했다. figma-bridge/workspace_control.js에서 함수 본문만 뺐다. tools/figma_workspace.py의 발행 문자열과 tests/test_native_runtime_version.cjs의 로드 순서, docs/development-roadmap/RD-07-runtime-boundaries/tasks.md의 문장을 맞췄다. tests/rd07_transport_move.cjs blob은 기준과 같다.

## 설계 이유와 출처

RD-07 작업 2는 순수 전송만 옮긴다. kind, operation, scope, revision 검사는 workspace_control.js에 남긴다. 전송 파일은 eval이나 controlExecute를 포함하지 않는다.

## 호환성·이관·복구

wire format과 허용 operation은 그대로다. 발행 bundle이 전송 함수를 포함하므로 호출이 비지 않는다. 플러그인 버전은 0.26.3이다.

## 검증과 미검증

종료 게이트는 `node tests/rd07_transport_move.cjs`를 기준 2db4fdafa3e8e337c68cdb4d4dd53f9d1f30a797에서 종료 코드 1, 대상 199683f8c221fcac718991dd91ad96b6a50ab144에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 assertion은 `pure transport must leave domain checks in place`다. 조건은 RD-07-REQ-02다. 같은 구현에서 runtime version, workspace control, history oracle, trace, native-started 검사는 종료 코드 0이었다. 실제 Figma 플러그인 재로드는 하지 않았다.

## 한계와 후속 개선

publisher 모듈 목록과 trusted_sources의 단일 선언은 아직이다. 생성된 bundle의 모든 task kind 실행도 아직이다.
