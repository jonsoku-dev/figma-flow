# test: require actual diagnostic build version

## 문제와 계기

graph 진단이 실제 build manifest 대신 legacy 하드코딩 0.26.3을 내보내거나 생성 config에 버전이 없을 수 있었다. 현재 진단의 버전 출처와 과거 fixture의 버전 보존을 구분하는 독립 기준이 필요했다.

## 결과 동작

새 Node 테스트 4개는 graph_panel 생성 config가 canonical plugin.json 버전을 공급하고 React/legacy 진단이 같은 metadata를 소비하도록 요구한다. legacy config의 현재 버전과 임의 버전은 그대로 사용하고 버전 부재는 fallback 없이 null 및 plugin-version 미관측으로 기록해야 한다. 제품 변경은 이 커밋에 없다.

## 변경 파일과 인터페이스

[finalize_diagnostic_version.cjs](../../../tests/finalize_diagnostic_version.cjs)를 추가하고 [rd09_audit_log.cjs](../../../tests/rd09_audit_log.cjs)의 binder 소스 기대를 0.26.3 literal에서 config.plugin_version으로 정정했다. 실제 Python graph_panel → graph-panel-config → legacy audit binder VM → renderAuditExport 경로를 실행하고 React DiagnosticExport의 model 소비를 정적으로 검사한다.

## 설계 이유와 출처

제품이 실제 제공한 version과 관측하지 못한 version을 구분해야 한다. synthetic 88.77.66도 전달된 그대로 나와야 하므로 현재 manifest만 무조건 대입하는 구현으로는 기준을 만족할 수 없다. visible Markdown의 fenced JSON과 진단 record가 같고 fetch/postMessage/Figma 접근이 0회인지도 확인한다.

## 호환성·이관·복구

기존 0.26.3 역사 입력 fixture와 그 export 기대는 유효하게 유지한다. 변경 대상은 현재 binder가 소스에 0.26.3을 포함해야 한다는 잘못된 oracle이다. 진단은 읽기 전용이며 새 버전 배포나 global release를 수행·승인하는 커밋이 아니다.

## 검증과 미검증

상위 세션이 보존한 제품 수정 전 실행에서는 새 테스트 4개가 config undefined 또는 legacy 0.26.3 때문에 예상대로 실패했다. 이후 제품 수정은 canonical manifest version과 legacy config를 사용하도록 진행되었지만 이 기준 커밋의 역사적 통과로 소급하지 않는다. 현재 native 진단 버전 0.27 관측은 별도 비공개 근거이며 이번 작업은 Git diff 정적 대조만 했다.

## 한계와 후속 개선

legacy VM 행동 검사와 React 소스 검사는 실제 진단 GUI·파일 다운로드·설치된 모든 runtime 버전의 일치를 보증하지 않는다. 전체 suite는 안정된 소스에서 재실행 중이므로 현재 full pass나 global release 완료는 주장하지 않는다. 실제 ID·원시 진단·개인 경로는 싣지 않는다.
