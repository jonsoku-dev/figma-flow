# test: require a stable change identity for a serialized selection bundle

## 문제와 계기

같은 token을 다른 순서로 골라도 같은 identity와 plan hash가 되는 직렬화가 고정되어 있지 않았다. 이 커밋 cc53d88e91da49ac33c54c720b1be228b78c93bd의 검사는 serialize_selection이 없어 `stable change identity must serialize with its selection bundle`로 실패한다.

## 결과 동작

tests/test_rd04_selection_identity.py는 함수가 없으면 위 문구로 끝난다. 함수가 있으면 color/action과 color/quiet의 순서를 바꿔도 직렬 문자열이 같고, space/gap은 선택되지 않으며 type/body와 type/size는 같은 bundle id를 가진다. plan_sha256는 선택 플래그를 빼서 계산한다. type/body만 고르면 partial alias bundle이다.

## 변경 파일과 인터페이스

tests/test_rd04_selection_identity.py를 추가했다. tools/graph_sync.py는 이 커밋에서 바꾸지 않았다. 검사는 python3 -B -m unittest tests.test_rd04_selection_identity로 실행한다.

## 설계 이유와 출처

RD-04 작업 2는 표시 index가 아니라 kind와 key의 stable identity와 선택 묶음을 직렬화한다.

## 호환성·이관·복구

이 커밋은 검사만 고정한다. 기존 전체 적용 경로는 바꾸지 않는다.

## 검증과 미검증

로컬 unittest는 종료 코드 1이고 stderr의 마지막 assertion은 `stable change identity must serialize with its selection bundle`이다. Figma 패널 선택은 관찰하지 않았다.

## 한계와 후속 개선

실패 기준은 합성 fixture다. 구현은 별도 커밋 0ce837ccf732354cf2a0f94cbb42042c9ca6fda2에서 검사 blob을 유지한 채 직렬화를 추가한다. UI 선택 행은 아직 없다.
