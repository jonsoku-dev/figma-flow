# feat: support multi-tab concurrent work and improve setup/panel UX

커밋 `06976347ca2b75b089c99c50d40b30b153d709ff`

## 문제와 계기

기존 `tools/figma_control.py`와 브리지 상태 저장소는 단일 전역 `active`·`RELAY_STATE` 구조 위주여서 여러 Figma Design 탭을 동시에 열어 작업할 때 한 탭의 요청·컨텍스트·완료 결과가 다른 탭의 상태와 섞이거나 덮어쓸 위험이 있었다. 또한 플러그인 초기 등록·1회 설정·세션 연결 흐름이 문서에 분산·중복되어 있었고, Figma 패널 오프라인 시 원인(설정 누락, `fileKey` 미확인, 구버전 런타임, 서버 미응답)을 사용자가 구분하기 어려웠다.

## 결과 동작

1. **멀티탭 동시 연결·제어**: `tools/figma_control.py`가 활성 네이티브 세션을 `NATIVE_SESSIONS`와 파일별 `active.json`(`by_file`/`active_for_file`/`active_operations`, `uncertainties_for_file`) 및 `RELAY_STATES`(`sessions`/`active_by_session`)로 분리해 관리한다. `sessions` 부명령과 `context`·`profile`·`status`의 `--file-key`·`--session-id` 옵션으로 특정 탭을 조회·타기팅할 수 있고, `setup-status`는 `connected_session_count`와 `connected_sessions`를 반환하며 `_peek_active_operations`는 상태를 바꾸지 않는 읽기 전용 조회를 보장한다.
2. **패널 오프라인 원인 진단 UX**: `figma-bridge/workspace_control.js`와 `workspace_host.js`가 `missing-control-config`, `file-key-unavailable`, `stale-runtime`, `server-unreachable` 상태를 판별하고 `workspaceRelayDiagnostics()`로 전달한다. `panel-ui/src/RelayViewer.jsx`와 `useRelaySnapshot.js`는 원인별 한국어·영어·일본어 안내(`figma-bridge/locales/relay.json`)와 `<details>` 접기 영역의 `플러그인 ID · 제어 포트 · 세대` 메타데이터를 표시한다. `workspace_control.js`는 `workspaceProfileManager` 전역이 없는 샌드박스 환경도 안전하게 가드하고 `controlRunSession` 식별자를 강화했다.
3. **설정·가이드 통합**: `docs/guide.md`에 `#quickstart-lifecycle`(1회 설정 · 세션 사용 · 멀티탭 동시작업) 절을 신설하고 중복 패널 찾기 절을 통합했으며, `skills/figma-plugin-setup/SKILL.md`, `specs/codex-relay/spec.md`, `README.md`를 동일 계약으로 갱신했다.

## 변경 파일과 인터페이스

- `tools/figma_control.py`: `NATIVE_SESSIONS`, `_record_native_session`, `_native_client`, `_peek_active_operations`, `sessions` 서브커맨드, `--file-key`/`--session-id` CLI 인자, 파일·세션 스코프 `result()`/`note_native_started()` 및 `setup_status` 확장.
- `figma-bridge/workspace_control.js`, `figma-bridge/workspace_host.js`: `workspaceRelayDiagReason`, `workspaceRelayRuntimeStatus`, `workspaceRelayDiagnostics()`, `workspaceProfileManager` 존재 가드.
- `figma-bridge/locales/relay.json`, `panel-ui/src/RelayViewer.jsx`, `panel-ui/src/useRelaySnapshot.js`, `figma-bridge/assets/panels.js`: 진단 문구·세부 정보 UI 반영 및 패널 번들 재빌드.
- `docs/guide.md`, `skills/figma-plugin-setup/SKILL.md`, `specs/codex-relay/spec.md`, `README.md`: 설정·멀티탭 가이드 및 중계 스펙 갱신.
- `tests/test_multi_tab_control.py`, `tests/test_workspace_control.cjs`, `tests/helpers/relay_viewer.mjs`: 멀티탭 제어·진단 상태·Chromium 렌더링 회귀 테스트 추가.

## 설계 이유와 출처

전역 단일 키로 상태를 덮어쓰는 방식 대신 `fileKey`와 `controlRunSession` 이중 키로 릴레이 컨텍스트·활성 작업·결과를 격리해야 멀티탭 동시 요청과 읽기/쓰기 확인이 충돌하지 않는다. 패널 상단은 최소 텍스트 정책을 지키기 위해 진단 메타데이터를 `<details>` 접기 영역 내부에 배치하고 Graph 거버넌스 9단계 검사를 통과하도록 맞췄다.

## 호환성·이관·복구

기존 단일 파일 작업자는 `--file-key`/`--session-id` 없이 기존처럼 가장 최근 또는 유일한 활성 세션을 자동으로 사용할 수 있어 CLI 호환성을 유지한다. `active.json`과 `RELAY_STATES`가 없을 때는 빈 맵에서 초기화되므로 별도 마이그레이션 없이 적용된다.

## 한계와 후속 개선

`--file-key`/`--session-id`를 생략했을 때 다수 탭이 연결된 모호한 쓰기 작업은 명시적 대상 지정을 요구하도록 유도하며, 실사용 환경에서의 멀티탭 시나리오는 후속 실기 검수에서 추가로 확인할 수 있다.
