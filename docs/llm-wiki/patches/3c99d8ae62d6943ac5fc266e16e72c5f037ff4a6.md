# feat: realize observed tab clicks as instant Figma click hotspots

## 문제와 계기

브리지가 tabs 계약을 Figma 프레임과 프로토타입 반응으로 만들 경로가 없었다. 캐러셀 읽기·적용 코드는 캐러셀 전용이었다.

## 결과 동작

읽기·적용을 하나의 관찰 상태 그래프 경로로 바꾸고 carousel과 tabs의 경로 생성기를 둔다. 탭 전이는 누른 탭 상자 위의 투명한 최상위 frame `Click · 목적지`와 즉시 `NAVIGATE`하는 `ON_CLICK` 반응이 된다. 첫 상태는 흐름 시작점이다. 편집된 반응은 덮어쓰지 않고 거절한다.

## 변경 파일과 인터페이스

`figma-bridge/web_design.js`에 `webTabsValidate`, `webTabsRoutes`, `WEB_INTERACTIONS`, `webInteraction`, `webInteractionRead`, `webInteractionApply`, `webInteractionReceipt`를 추가하고 캐러셀 전용 함수를 대체했다. `tools/web_design.py`는 누른 frame이 화면 안에 있어야 한다. `tests/test_web_design.cjs`에 hotspot·멱등 재적용·편집 보존·거절 사례를 추가했다.

## 설계 이유와 출처

처음에는 반응을 탭 레이어에 직접 넣었다. Figma Desktop은 실제 장면에서 `setReactionsAsync`를 "Unable to establish connection to Figma after 10 seconds"로 두 번 거절했고 새 노드는 롤백됐다. 작은 합성 장면에서는 같은 방식이 성공했다. 별도 그래프 ID의 진단 작업에서 같은 장면의 최상위 hotspot은 성공했다. 그래서 캐러셀 드래그와 같은 최상위 hotspot을 쓴다. Figma 내부 원인은 확인하지 않았다.

## 호환성·이관·복구

0.33 프레임이 쓰는 플러그인 데이터 키(`figmaFlowCarouselKey`, `figmaFlowCarouselState`, `figma-flow-carousel-hotspot`, `figma-flow-carousel-side`)는 그대로다. 오류 문구의 Carousel은 Prototype으로 바뀌었다.

## 검증과 미검증

Node 테스트 31개가 통과했다. 실제 Figma 파일에서 적용과 별도 읽기가 모두 `current`였고, Figma 프레젠테이션에서 A→B→A와 미연결 탭의 머묾을 확인했다.

## 한계와 후속 개선

hotspot은 탭 레이어를 옮겨도 따라가지 않는다. 진단용 프레임 4개가 검증 페이지에 남아 있다.
