# 검증기의 패키지·단독 실행 회귀 기준

커밋 `a24adcc9b6a7930702e82eb4d7d439f84f601aa3`

## 문제와 계기

RC2에서 성공하던 두 tools 모듈의 패키지 import가 별도의 Python에서 test_env를 찾지 못했다.

## 결과 동작

각 모듈을 새 인터프리터로 불러와 패키지의 sibling helper와 동일성을 확인하고 스크립트·모듈 CLI의 help 본문과 종료 코드를 대조한다.

## 변경 파일과 인터페이스

tests/test_verifier_imports.py가 별도 PYTHONPATH 없이 기존 진입점을 실제 실행한다.

## 설계 이유와 출처

argparse가 출력하는 실행 파일 이름은 실행 방식에 따라 달라질 수 있어 명령별 help 본문과 실제 기능 계약을 검사한다.

## 호환성·이관·복구

각 프로세스는 격리된 XDG만 상속한다. 사용자 전역 설정이나 Python 검색 경로를 넓히지 않는다.

## 검증과 미검증

수정 전 독립 패키지 import가 두 모듈 모두에서 실패했다. 단독 명령 실행은 그대로 가능했다.

## 한계와 후속 개선

기존에 패키지 소비를 지원한 두 모듈만 검사하며 다른 내부 도구의 API 계약은 확대하지 않는다.
