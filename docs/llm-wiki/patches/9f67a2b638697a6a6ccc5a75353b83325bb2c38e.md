# 9f67a2b · 선택한 디자인 승격과 네이티브 웹 동기화 확인

## 문제와 계기
선택된 디자인 후보를 단순 검토 결과로 남기지 않고 승인된 산출물로 승격하며 Figma native 결과와 웹 연결을 확인할 경로가 필요했다.

## 결과 동작
`tools/design_directions.py`, `figma_draft.py`, `design_quality.py`가 후보 선택과 품질검사를 확장한다. `tools/native_edit.py` 및 `figma-bridge/native_edit.js`가 선택된 후보의 네이티브 편집을 처리한다. Review panel에서 흐름을 다루고 tests가 selection/production/edit 경계를 추가 검증한다.

## 변경 파일과 인터페이스
42개 파일: 위 Python 도구와 bridge, locales, Review panel, skills/docs, Python/CJS tests. 선택 후보용 native edit packet/readback 계약이 확대됐다.

## 설계 이유와 출처
근거: 전체 커밋 `9f67a2b638697a6a6ccc5a75353b83325bb2c38e`; `native_edit.py`, `design_directions.py`, `design_quality.py`, selected production 및 native edit 테스트. exploratory draft와 선택 이후 production을 구분하는 경계다.

## 호환성·이관·복구
새 생산 경로는 선택 pin과 scope 검증에 의존한다. 기존 초안이 선택 근거 없이 자동 승격된다고 볼 수 없다. 네이티브 변경의 실패 복구는 native edit 구현 계약을 따라야 한다.

## 검증과 미검증
선택·품질·native edit 관련 테스트가 여러 개 추가됐다. CI 실행 기록이나 실 Figma round-trip 증거는 커밋에 없어 미검증이다.

## 한계와 후속 개선
테스트 코드가 제품 acceptance나 사람의 선택을 입증하지 않는다. 실제 문서 mutation 결과는 별도 확인해야 한다.
