# feat: expose shared import labels as text properties

## 문제와 계기

같은 컴포넌트를 여러 화면에 둘 때 문구가 하위 TEXT에만 써져 속성 패널에서 한 정의로 고칠 수 없었다. 기준 7260d2995764d65d736aed031ddc63323ecf4e0c의 세 문구 검사가 `TEXT property reference missing`으로 실패했다.

## 결과 동작

일반 가져오기는 component set 또는 단독 main에 TEXT 속성 `문구`를 만들고, Figma가 반환한 key를 `label_property_key`에 보관한 뒤 `instance.setProperties`로 화면 문구를 넣는다. 세 문구는 한 main을 공유하고 main의 기본 문구는 바뀌지 않는다. 같은 source를 다시 가져오면 page·set·main·instance ID와 사용자가 바꾼 문구·글자 크기·opacity가 남는다. 속성 API가 없으면 글자를 직접 쓴다.

## 변경 파일과 인터페이스

`figma-bridge/code.js`의 `bindOwnedLabelProperty`와 instance 작성만 바꿨다. 안내 문장은 `docs/guide.md`, 현재 상태는 `docs/development-roadmap/CURRENT_STATE.md`, RD-01 기능서·작업서다. 부모 대비 5개 파일, 58줄 추가·7줄 제거다. 검사 파일 blob은 기준 커밋과 같다. 방향 검토와 semantic component 경로는 그대로다.

## 설계 이유와 출처

방향 검토의 `addComponentProperty`·`setProperties` 패턴을 일반 가져오기 한 경로에 둔다. key는 API 반환값만 쓰고 표시 이름 `문구`와 같으면 거절한다. 기존 참조가 충돌하면 자동으로 이름을 바꾸지 않고 진단한다. 공식 component properties 설명은 RD-01 설계서의 2026-11-12 조사에 있다.

## 호환성·이관·복구

기존 패킷과 재가져오기 분기를 유지한다. 새 페이지의 main에만 속성을 더하고, 같은 패킷의 재실행은 기존 페이지를 다시 쓰지 않는다. 사용자 instance를 detach하지 않는다. 속성 API가 없는 환경은 이전의 직접 쓰기를 유지한다.

## 검증과 미검증

종료 게이트가 임시 Git 아카이브에서 기준 커밋의 `tests.test_figma_bridge`를 다시 실행해 AssertionError `TEXT property reference missing`, 종료 코드 1을 확인했다. 대상 1f80e5d9896e85afb865919aad7dad3572be932e는 같은 25개 검사가 종료 코드 0이었다. 로컬 결과 해시는 `.figma-flow/improvement-result.json`에만 둔다.

Figma Desktop에서 기존 회귀 파일을 본 뒤 새 파일 선택 화면까지 열었다. Design 버튼의 접근성 동작과 화면 클릭은 빈 캔버스를 열지 못했고, 컴파일한 개발 플러그인을 불러 속성 패널의 `문구`를 읽지 못했다. 기존 회귀 페이지의 내용은 수정하지 않았다. 창 크기는 캡처 후 원래 크기로 되돌렸다.

## 한계와 후속 개선

실제 Figma getter와 속성 패널, main 수정이 여러 instance에 반영되는 것, resize는 미검증이다. 지원된 너비만 다른 재사용과 variant 축은 RD-01의 다음 단위다. 61개 회귀 전체, 실기기, 클라우드 저장, 글꼴 바이너리 동일성은 이 변경의 완료 범위가 아니다.
