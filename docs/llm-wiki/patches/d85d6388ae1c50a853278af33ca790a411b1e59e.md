# feat: show the selection count, select-all, and affected targets

## 문제와 계기

기준 88398e9b2186fb6dac1512eecda2c9e8d8e74af3는 graphSelection이 없어 `selection rows must show the count and affected targets`로 실패했다.

## 결과 동작

graphSelection은 identity·name·key로 행을 만들고, 넘긴 선택만 selected로 센다. 선택이 null이면 전부 선택이다. target이 없으면 그 행의 name을 영향 대상으로 쓴다. 그래프 패널의 변경 행은 체크와 영향 대상을 보여주고, 전체 선택은 다시 모두 고른다. 변경이 있는데 count가 0이면 applyBlocked로 적용을 시작하지 않는다. 변경 목록이 비어 있으면 기존 적용 메시지를 그대로 보낸다.

## 변경 파일과 인터페이스

panel-ui/src/graphSelection.mjs에 graphSelection을 추가했다. panel-ui/src/GraphPanel.jsx와 figma-bridge/graph-panel.html이 선택 수, 전체 선택, 영향 대상을 기존 행에 붙인다. figma-bridge/locales/graph.json에 선택 문구를 추가했다. figma-bridge/assets/panels.js는 React 패널의 생성 번들이다. docs/development-roadmap/RD-04-selective-sync/tasks.md에 범위를 적었다. tests/test_rd04_selection_rows.py blob은 기준과 같다.

## 설계 이유와 출처

RD-04는 기존 변경 행 안에서 선택 범위를 보여야 한다. 빈 변경 목록의 전체 적용은 protocol v1로 남기고, 행이 있을 때만 빈 선택을 막는다.

## 호환성·이관·복구

기본 선택은 모든 행이다. 변경 카드의 앞쪽 자식 구조는 그대로라 기존 값 미리보기가 유지된다. 빈 선택은 적용 메시지를 보내지 않는다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd04_selection_rows`를 기준 88398e9b2186fb6dac1512eecda2c9e8d8e74af3에서 종료 코드 1, 대상 d85d6388ae1c50a853278af33ca790a411b1e59e에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 마지막 assertion은 `selection rows must show the count and affected targets`다. 조건은 RD-04-AC-05다. 같은 구현에서 graph panel 노드 검사도 종료 코드 0이었다. Figma에서 고른 두 값만 바뀌는 적용은 관찰하지 않았다.

## 한계와 후속 개선

서버가 같은 선택을 검증하고 transaction으로 쓰는 단계는 아직이다. AC의 Figma 관찰은 통과로 기록하지 않는다.
