# feat: compile observed tab clicks into a pinned Design graph

## 문제와 계기

NF-09의 1순위인 Devtool 탭 A→B→A를 정본 그래프로 표현할 계약이 없었다. 캐러셀 계약은 순서·경계·자동재생을 가정해 클릭으로 패널을 바꾸는 탭을 담을 수 없었다.

## 결과 동작

정본 그래프에 `tabs` 키를 추가했다. 상태는 화면, 라벨, 패널 글자 해시, 스크린샷 고정을 갖고, 전이는 관찰한 `click`, 출발 화면의 frame 요소 ID와 근거 스크린샷을 갖는다. `native_edit.py web-tabs`가 관찰 JSON을 결합하고, plan은 tabs를 정본과 정확히 같게 고정한다. 미관찰·자기 반복·frame이 아닌 대상·한 컨트롤의 두 목적지·도달하지 않는 상태는 거절한다.

## 변경 파일과 인터페이스

`tools/web_design.py`에 `validate_capture_source`, `validate_tabs`, `join_tab_observations`, `_read_join_inputs`, `_write_joined_graph`를 추가하고 `validate_carousel_evidence`를 `validate_interaction_evidence`로 바꿨다. `tools/native_edit.py`는 plan의 `tabs` 고정과 `web-tabs` 명령을 갖는다. `tests/test_web_design.py`에 결합·plan 고정·거절 사례를 추가했다.

## 설계 이유와 출처

NF-09은 이벤트 이름이나 CSS 클래스로 도착 상태를 추측하지 말라고 요구한다. 따라서 상태 정체성은 보이는 패널 글자, 전이 출발점은 실제로 누른 요소로 정했다. 실제 캡처에서 같은 탭 버튼의 요소 ID가 상태마다 달라(`el-37`과 `el-54`) 전이마다 출발 화면의 ID를 기록한다.

## 호환성·이관·복구

캐러셀 그래프 형식은 그대로다. 증거 검사 함수 이름과 오류 문구만 일반화됐다. 한 그래프는 carousel과 tabs 중 하나만 가질 수 있다.

## 검증과 미검증

`python3 -B -m unittest tests.test_web_design`이 통과했다. 일곱 가지 거절 사례가 각각 의도한 오류 문구로 실패함을 별도로 출력해 확인했다.

## 한계와 후속 개선

탭 수가 많을 때 관찰하지 않은 조합은 연결하지 않는다. 키보드 포커스와 스크린리더 의미는 계약에 없다.
