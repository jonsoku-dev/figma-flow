# 0bd8177 · 연결 자산의 신선도와 실제 네이티브 사진 확인

## 문제와 계기

출처는 `0bd817701f3df66673e314007f768a6de404fd78`, 부모는 `90f9195600dd54131c80a817bebdd88fd63fe52a`이다. HTML 본문이 같아도 연결한 CSS·JS·사진·글꼴의 바이트나 존재 상태는 바뀔 수 있었다. 이전 근거는 이를 모두 고정하지 않았다. 저장된 자산 키 역시 실제 Figma 사진의 내용과 동일하다는 증거가 아니었다.

## 결과 동작

HTML의 직접 로컬 참조를 URL 경로로 해석해 쿼리·프래그먼트를 제외한 파일 바이트와 부재 상태를 입력 해시에 넣는다. 사진 준비에는 유효한 PNG·JPEG·GIF와 한 변4,096px 이하를 요구한다. 가져온 뒤 실제 Figma 이미지 바이트·IMAGE 페인트·scale mode·불투명도·부모 프레임을 원본과 대조한다. 실제 사진·Hahmlet 회귀 예제와 바이너리 MIME을 제공한다.

## 변경 파일과 인터페이스

`tools/input_effect.py`의 결과 스키마는 `figma-flow-input-effect-result-v2`다. `sources`에 직접 연결 파일의 상대 경로·해시를 넣고 부재는 `sha256: null`이다. `locate(..., require_file=False)`는 부재를 확인한다. `tools/figma_draft.py`의 `_check_native_raster()`와 `_native_authored_image_findings()`가 준비·실제 재읽기를 검사한다. Pillow가 없으면 준비를 거절한다. `figma-bridge/native_semantic_read.js`는 `rasterImageBytes`, `reactions`, `clipsContent`를 읽고 실패를 `unavailable_fields`로 남긴다. `examples/regression-program/html/positive-assets/`의 사진·서체·CSS·JS, `sources.json`·OFL, `examples/regression-program/server/serve.py`, `tests/test_native_raster_assets.py`·`.cjs`와 입력 회귀 검사가 함께 바뀐다.

## 설계 이유와 출처

부재까지 고정해야 HTML이 그대로인 자산 교체도 오래된 근거로 거절할 수 있다. 자산 식별자는 실제 바이트의 증거가 아니므로 `getImageByHash().getBytesAsync()`를 사용한다. 이는 실제 diff에서 확인한 구현 이유이며 당시 전체 논의·대안의 근거는 미상이다. 파일 원문은 `git show 0bd817701f3df66673e314007f768a6de404fd78:<경로>`로 확인한다. 사진·글꼴의 출처·변환·라이선스는 당시 `sources.json`·OFL이 기준이다.

## 호환성·이관·복구

결과 v1로 현재 입력 완료를 주장하지 않고 v2로 다시 준비·검증한다. 손상·미지원·초과 크기 사진은 원본을 보존해 교정한 뒤 패킷을 다시 만든다. 이 거절은 원본 삭제나 Figma 자동 복구를 수행하지 않는다. 실제 이미지 getter를 사용할 수 없는 실행은 네이티브 검증 미완료다.

## 검증과 미검증

추가된 회귀 코드는 자산 변경·부재·쿼리 참조와 이미지 손상·크기·실제 바이트 변조를 다룬다. 코드 존재를 당시 실행 통과로 세지 않는다. 커밋 메시지는 데스크톱·모바일 브라우저·Figma에서 사진 해시·글꼴·왕복·기존 자료 보존을 검증했다고 보고하지만, 원시 실행 자료가 이 보완에 포함되지 않아 독립 재현 통과로 계산하지 않는다. 출처 없는 인계 수치는 성공 근거로 옮기지 않는다.

## 한계와 후속 개선

직접 HTML 참조만 추적한다. CSS url()/@import의 재귀 의존성·외부 주소·동적 참조의 완전한 추적, 임의 HTML importer, 브라우저 글꼴 바이너리의 Figma 업로드는 추가하지 않았다. 실제 기기·사용자 첨부 검증은 미확인이다. 후보0.26.1의 별도 검증표 정리도61개 전체 케이스를 통과로 바꾸지 않는다.
