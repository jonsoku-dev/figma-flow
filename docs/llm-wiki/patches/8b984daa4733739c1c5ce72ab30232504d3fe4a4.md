# test: pin final integration acceptance boundaries

## 문제와 계기

RD 통합 종료 전에 부분 동기화, native 계층, 의존성 게시, operation history, 개인정보 및 transport 경계의 실제 연결을 확인하는 독립 기준이 필요했다.

## 결과 동작

새 oracle들은 실제 export bundle의 panel→sandbox 선택 적용, private HTTP journal→게시 host→Workspace 렌더링, source 교체/retire→dependency freshness, native preflight/배치/rollback을 요구한다. 잘못된 입력은 쓰기·자격 전송 전에 막아야 한다.

## 변경 파일과 인터페이스

14개 테스트 경로를 변경했다. finalize_selective_sync.py가 graph/receipt/bundle을 만들고 CJS가 실제 checkbox 송신과 handler를 구동한다. lifecycle Python은 authenticated HTTP service를 쓰며 runtime helper가 게시 host와 실제 React UI를 검사한다. rd07 helper를 helpers로 옮기고 호출자도 갱신했다.

## 설계 이유와 출처

선택값이나 관찰을 UI에서 신뢰하지 않고 host manifest와 실제 before 값에 고정한다. unchecked token·alias·binding·marker의 보존, indivisible group, v1 선택 거절, 오류 뒤 busy 해제를 요구한다. native 계층은 기존 node identity·metadata·순서와 실패 rollback을 확인한다.

## 호환성·이관·복구

legacy 선택 생략은 full apply, legacy history는 unknown 분류로 보존한다. journal은 telemetry와 분리하고 scope별 최대 80개와 안전 필드만 노출한다. retired source의 pinned artifact와 consumer edge는 보존해야 한다. 제품 구현 변경은 없다.

## 검증과 미검증

Git diff에서 URL userinfo/query redaction, loopback/route allowlist, UTF-8 payload cap, AbortController 없는 timeout, 잘못된 edge의 쓰기 전 ValueError 기대를 확인했다. graph panel 하네스는 JSON script를 제외한 모든 실행 script를 순서대로 읽고 multipage snippet은 async로 실행한다. 이 커밋을 제품 인수 통과로 기록하지 않는다.

## 한계와 후속 개선

API-shaped native fixtures·정적 렌더링·로컬 HTTP는 실제 Figma resize, 디자인 품질 또는 장치 검증을 대신하지 않는다. 후속 harness 수정 및 미커밋 제품 수정과 분리해서 재현해야 한다.
