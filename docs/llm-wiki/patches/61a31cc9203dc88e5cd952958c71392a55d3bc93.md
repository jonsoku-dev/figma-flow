# 제어 CLI 거절의 고정 재현

커밋 `61a31cc9203dc88e5cd952958c71392a55d3bc93`

## 문제와 계기

실제 graph 왕복 작업에서 후속 read가 종료 코드 2와 포괄적인 오류 한 줄을 반환했다. 1.1.0의 파일별 작업 슬롯에서도 같은 현상이 발생하는지 확인할 기준이 필요했다.

## 결과 동작

테스트가 임시 개인 작업공간과 실제 루프백 서버를 만들고 CLI 하위 프로세스의 stdout, stderr, 종료 코드와 거절 전후 파일 바이트를 검사한다.

## 변경 파일과 인터페이스

tests/test_control_cli_rejections.py가 busy, stale revision, uncertain write, 비공개 오류의 네 경우를 검사한다.

## 설계 이유와 출처

첫 요청을 --no-wait로 접수하면 Figma 없이도 같은 파일의 두 번째 요청이 실제 직렬화 검사에 도달한다. 기대값은 사용자에게 필요한 복구 행동이다.

## 호환성·이관·복구

제품 동작은 기준 커밋에서 그대로다. 기존 control 테스트의 서버와 서명된 작업 준비 도우미를 재사용한다.

## 검증과 미검증

기준 후보에서 busy·stale·uncertain 세 진단 assertion이 실패했고 비공개 경로 가림 검사는 통과했다. 첫 요청의 JSON은 pending이었다.

## 한계와 후속 개선

루프백 픽스처는 Desktop 렌더를 검수하지 않는다. 후보 패널과 실제 Figma 선택은 후속 구현 기록에 따로 남겼다.
