# docs(roadmap): mark P0 reference safety and API queue verified with public receipts

## 문제와 계기

`976a966c1b497890aae12dd1a63b1dd6b05ee763` 배포 가드, `b9495234cdbc4547f083f5ee21cbd623c67a381f` Linux CI 브랜치 수정, `d98860037b4082b744a3ecd9fd7aae9ae2d729bf` 자체 공개 기준 입력이 `main`에 통합된 뒤, `docs/next-roadmap/backlog.graph.json`의 P0 노드 상태를 실제 공개 인수 근거와 연결해 갱신할 필요가 있었다.

## 결과 동작

공개 인수 영수증 `docs/next-roadmap/p0-reference-acceptance.md`를 신설하고 `backlog.graph.json`의 `p0-reference-safety`(`status=verified`, `evidence_status=verified-with-public-receipt-and-local-full-guard`)와 `p0-api-queue-validation`(`status=verified`, `evidence_status=verified-with-post-p0-reproduction`)를 갱신했다. `p0-api-queue-validation`은 P0 이후 재실행에서도 동일 SHA-256(`4e5480245bf3779a7d39668698be65fd5d0974bee71b5ce9316eea0918c551a5`)과 `1,382`/`825`/`12`(`8 design-api` + `4 design-node`)를 재현하며 신규 API 런타임 관측(`new_api_observations=0`)이나 기능 지원 주장이 아님을 명시한다.

## 변경 파일과 인터페이스

`docs/next-roadmap/p0-reference-acceptance.md`(신규), `docs/next-roadmap/backlog.graph.json`, `docs/next-roadmap/capability-review.md`, `docs/next-roadmap/README.md`, `tests/test_next_roadmap_backlog.py`를 갱신했다. `tests/test_next_roadmap_backlog.py`는 `EXPECTED_P0_PROOF_REFS`에 `p0-reference-acceptance.md`, `.github/workflows/reference-guard.yml`, `examples/owned-design-baseline/graph.json`, `manifest.json`, `tests/test_owned_design_baseline.py`를 추가하고 4개 로드맵 문서의 링크·앵커·금지 문자열을 검사한다.

## 설계 이유와 출처

비공개 원본 레이블, 개인 경로, Figma 파일/노드 ID, 과거 rewritten 이전 SHA를 공개 이력에 남기지 않으면서도 4개 참고 아카이브 무결성, 독립 브라우저 캡처, 실제 Figma 플러그인 읽기·재생, API 후보 분류 경계를 추적 가능한 공개 영수증으로 고정하기 위함이다.

## 호환성·이관·복구

기존 `v0.35.0` FAQ·G1 기록과 `NF-01`~`NF-09` 설계 문서를 보존한다. P0 두 노드가 `verified`로 전환됨에 따라 `backlog.graph.json`의 `next-ready` 규칙으로 P1 후속 작업이 착수 가능 후보가 되며, 이는 P1 구현 완료를 뜻하지 않는다.

## 검증과 미검증

이 커밋 체크아웃(`6c9c6e454d826347971d4f7e612abcd43b8a306b`)에서 `tests.test_design_specialization`·`tests.test_owned_design_baseline`·`tests.test_reference_distribution_guard`·`tests.test_next_roadmap_backlog`·`tests.test_api_priority` 합산 33개 테스트 통과, `tools/reference_distribution_guard.py --ref HEAD --format text` `paths_only_clear`(1,682개 파일), `graph.py validate examples/owned-design-baseline/graph.json --strict-local` 통과, `api_priority.py` 1,382/825/12 재현을 직접 확인했다. 통합 보고된 P0 인수 근거에는 4개 참고 아카이브·보존 사본 SHA-256 일치(변동 0), 로컬 4개 아카이브·67개 가드 규칙 검증, 독립 Chromium 1440×900 7클릭·3상태·6전이·10/10 PNG 바이트 일치, 설치된 자체 플러그인 Figma Desktop `85/103/103` 편집 가능 노드(초안 `86/104/104` 폐기 후 재실행)·`6/6` `ON_CLICK`·`6/6` Figma Present 재생 및 반복 적용 프레임 ID 유지가 포함된다. 공식 Figma MCP 미사용·클라우드 동기화 미보장 경계와 P1/P2 미구현 상태는 그대로 유지된다.
