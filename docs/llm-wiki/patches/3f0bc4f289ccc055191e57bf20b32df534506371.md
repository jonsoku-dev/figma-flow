# chore(api): refresh static API coverage baseline for P1 bridge and importer

## 문제와 계기

P1 브리지(`cfc7fbd1`, `3e7b44cc`, `ce1bc7d2`) 및 제어 코드 변경 후 `library/figma-api/coverage-baseline.json`의 정적 AST 참조 집계와 해시가 최신 소스와 불일치해 API 감사 체크가 깨질 수 있었다.

## 결과 동작

커밋 `3f0bc4f289ccc055191e57bf20b32df534506371`은 `library/figma-api/coverage-baseline.json`을 재생성해 `no-static-reference` `680->670`, `qualified-static-reference` `62->70`, `unresolved-receiver-name-reference` `640->642`(총 `1,382` 멤버)와 대상 파일 SHA-256 해시를 갱신했다.

## 변경 파일과 인터페이스

`library/figma-api/coverage-baseline.json`만 갱신했으며 제품 런타임 코드는 건드리지 않았다.

## 설계 이유와 출처

P0 API 큐 규칙과 동일하게 정적 AST 출현 변화만 baseline에 동기화하되, `implementation`·`runtime_acceptance` 상태를 임의로 `verified`로 승격하지 않기 위함이다.

## 호환성·이관·복구

후속 시맨틱 패밀리 런타임과 수리 패치(`22995b1f`, `a7378b82`)에서 동일한 방식으로 baseline이 두 차례 더 최신화됐다.

## 검증과 미검증

`tools/figma_api_inventory.py coverage --check-baseline`과 `tools/figma_api_audit.py verify` 통과 대상이나, 정적 AST 출현 횟수 변경은 런타임 지원 증명이 아님을 분명히 유지한다.

## 한계와 후속 개선

`709f1104`·`974b5de7` 추가 이후의 최종 숫자는 `a7378b82` 기준(`664/70/648`)으로 승계됐다.
