# 누락된 RC1 요청의 인수 검사

커밋 `8006a765c56bdd1be3adf8ac6eb4a0bc7990e93f`

## 문제와 계기

RC1이 65개 파일의 요청을 접수한 후 원래 64개 키만 포인터에 남겼다. 첫 RC2는 빠진 파일을 idle로 보고 중복 요청을 허용했다.

## 결과 동작

기존 요청 ID와 claim을 보존한 상태에서 파일별 상태 조회, 자리 회수, 실제 poll 및 결과 확인을 검사한다.

## 변경 파일과 인터페이스

tests/test_legacy_slot_recovery.py가 기존 큐 진입점으로 원본 요청과 claim을 만들고 RC1의 64개 포인터 모양을 재현한다.

## 설계 이유와 출처

과거 요청 수와 현재 포인터 항목 수를 별도로 센다. 확인되지 않은 쓰기를 새 요청으로 재실행하지 않는지 검사한다.

## 호환성·이관·복구

65개가 모두 진행 중인 경우에는 원래 작업을 상태에서 찾고 중복 접수를 보류한다. 빈자리가 생기면 기존 ID로 계속한다.

## 검증과 미검증

수정 전 네 개 테스트가 실패했다. 원본 pending ID 부재 및 기한이 지난 누락 쓰기의 uncertain 누락이 확인됐다.

## 한계와 후속 개선

별도의 일회성 검수에서는 실제 RC1의 공개 enqueue로 만든 65개 요청 디렉터리를 RC2가 인계했다.
