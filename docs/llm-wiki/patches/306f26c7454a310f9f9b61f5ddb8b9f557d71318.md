# feat: list input assets by status without loading them

## 문제와 계기

기준 325e122cb48aebe61663333db337e093bc6a1429는 assetInventory가 없어 `asset inventory must filter status and show the relative source`로 실패했다.

## 결과 동작

assetInventory는 404, rejected, external-unverified를 present보다 앞에 둔다. 상태 필터를 해도 source는 상대 경로로 남는다. 종류별 count를 세고, 행이 없으면 empty이며 ready는 아니다. 문제 행이 없으면 ready다. public_task_metadata는 안전한 요약만 복사하고 input_record와 /Users 경로는 공개하지 않는다. workspaceAssetSummary가 그 요약을 작업 목록 payload에 싣고, AssetDisclosure가 상태 선택과 텍스트 목록을 그린다. 그 함수는 fetch를 호출하지 않는다.

## 변경 파일과 인터페이스

panel-ui/src/assetInventory.mjs에 assetInventory를 추가했다. panel-ui/src/Workspace.jsx가 작업 행에서 그 목록을 연다. figma-bridge/assets/panels.js는 생성 번들이다. figma-bridge/workspace_host.js가 input_summary를 거르고, tools/figma_workspace.py의 public_task_metadata가 공개 작업에 요약을 싣는다. docs/development-roadmap/RD-05-asset-inventory/tasks.md에 범위를 적었다. tests/test_rd05_asset_inventory.py blob은 기준과 같다.

## 설계 이유와 출처

RD-05는 목록 count를 파일 준비 상태로 두고 렌더 성공률로 쓰지 않는다. 경로와 파일명은 텍스트다. 빈 목록은 모든 파일이 정상이라는 뜻이 아니다.

## 호환성·이관·복구

input_summary가 없는 task metadata와 작업 목록 payload는 필드를 추가하지 않는다. 의존성 보기와 기존 열기 동작은 그대로다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd05_asset_inventory`를 기준 325e122cb48aebe61663333db337e093bc6a1429에서 종료 코드 1, 대상 306f26c7454a310f9f9b61f5ddb8b9f557d71318에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 마지막 assertion은 `asset inventory must filter status and show the relative source`다. 조건은 RD-05-AC-05다. 같은 구현에서 dependency 검사와 workspace host 검사도 종료 코드 0이었다. 브라우저에서 사진과 서체가 로드되는지는 관찰하지 않았다.

## 한계와 후속 개선

freshness가 바뀐 목록과 같은 파일의 여러 출처는 아직이다. AC의 브라우저 관찰은 통과로 기록하지 않는다.
