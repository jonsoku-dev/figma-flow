# test: pin normal HTML asset projection boundaries

## 문제와 계기

일반 HTML 자산 목록을 준비할 때 서로 다른 selector의 gap:12px와 gap:24px를 하나의 surface-gap 값으로 요구하면, 레이아웃 scalar를 요청하지 않은 정상 입력까지 막힐 수 있다. 자산 조사와 사실 선택의 경계를 독립 기준으로 고정했다.

## 결과 동작

새 oracle은 surface-gap을 요청하지 않은 project에서 status=projected를 유지하고 두 값은 unresolved_facts에 남기도록 요구한다. consumption에는 그 scalar를 넣지 않으며 실제 stylesheet·image·font 목록과 source freshness는 유지해야 한다. 제품 구현 변경은 없다.

## 변경 파일과 인터페이스

[finalize_normal_input.py](../../../tests/finalize_normal_input.py)를 추가했다. 임시 brief/facts/authority와 HTML/CSS/SVG/font fixture → input_effect.project → html facts/assets/consumption → freshness 경로를 검사한다. 관찰 대비는 contrast_css_browser_loading에 requested_paths를 명시해 호출한다.

## 설계 이유와 출처

서로 무관한 CSS gap을 임의의 단일 값으로 택하지 않으면서 정상 asset inventory를 보존하는 것이 목적이다. surface-gap이 명시적으로 HTML 권한에 선택되거나 legacy html_channel 직접 호출이면 여전히 one gap fact 오류를 요구한다. gap이 하나가 되면 그 정확한 값을 생산해야 한다.

## 호환성·이관·복구

기존 직접 scalar 읽기의 모호성 거절은 완화하지 않는다. 입력 record schema나 CLI를 바꾸는 커밋이 아니며, 비요청 fact만 자산 준비 실패의 원인에서 분리하는 검사 기준이다. CSS 원본 변경 후 freshness=current가 stale로 바뀌는 assertion도 유지한다.

## 검증과 미검증

실제 Git diff에서 projected, unresolved 두 값, consumption 부재, 세 자산의 present/kind, render=unverified 및 CSS 변경 후 stale 기대를 확인했다. 이 커밋은 제품 수정을 담지 않은 frozen baseline이며 당시 제품 통과로 기록하지 않는다. 이번 기록 작업은 정적 Git 대조만 수행했다.

## 한계와 후속 개선

font fixture 바이트는 유효한 production 폰트임을 증명하지 않는다. provided-observation은 브라우저 실행 결과가 아니라 호출자가 제공한 관찰이며 실제 렌더링·자산 사용·native Figma 생성은 별도 인수다.
