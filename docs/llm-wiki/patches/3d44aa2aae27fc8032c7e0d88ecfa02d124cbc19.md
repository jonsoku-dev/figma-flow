# 3d44aa2 · 오래된 discovery 거부와 control server 사전 확인

## 문제와 계기
오래된 discovery 결과나 호환되지 않는 control server로 graph를 적용하면 잘못된 범위로 작업할 수 있었다.

## 결과 동작
`tools/figma_control.py`가 `/control/readiness`를 제공해 protocol/schema, loaded plugin version, implementation hash와 operation capability를 돌려준다. `require_ready()`는 CLI가 queue 전에 이를 검증한다. `tools/graph_sync.py`는 stale discovery import를 거부하고 대상 범위를 검사한다.

## 변경 파일과 인터페이스
`figma_control.py`, `graph_sync.py`, guide/examples, `tests/test_figma_control.py`, `tests/test_graph_sync.py`. control readiness endpoint가 추가됐고 기존 명령은 준비 상태 확인을 거친다.

## 설계 이유와 출처
근거: 전체 커밋 `3d44aa2aae27fc8032c7e0d88ecfa02d124cbc19`; `readiness()`, `require_ready()`, handler readiness route, discovery import와 관련 tests. 현재 CLI와 서버 구현/기능이 맞는지 먼저 확인한다.

## 호환성·이관·복구
호환 서버가 실행 중이어야 control operation을 queue할 수 있다. 서버가 없거나 version/hash/capability가 다르면 안내된 경로로 현재 설치를 확인한 후 재시도한다. 오래된 discovery는 새 자료를 수집해야 한다.

## 검증과 미검증
두 테스트 파일에 제어·동기화 경계 사례가 추가됐다. 실행 로그와 실제 native server 상태는 미검증이다.

## 한계와 후속 개선
preflight 이후 상태가 바뀌는 race는 남을 수 있다. 실 Figma 서버와 workspace의 동작은 커밋만으로 증명되지 않는다.
