# fix: validate the complete priority export against the canonical graph contract

## 문제와 계기

API priority graph export produced nodes with status and type values that did not satisfy the repository’s canonical graph contract. Its local tests checked IDs and endpoints but not the structural validator result.

## 결과 동작

Graph export now uses canonical node types and statuses, attaches official source URLs to declared API members, and runs the graph validator before it returns. The exported graph includes a machine-readable structural validation result; invalid graphs raise an error.

## 변경 파일과 인터페이스

The commit updates `tools/api_priority.py` and `tests/test_api_priority.py`. The test imports the canonical validator and checks zero errors and the exact validation summary.

## 설계 이유와 출처

Unobserved member evidence and feasibility are represented as planned work. Only a validated observation edge can produce observed evidence. This prevents type declarations or queue ranking from being emitted as runtime results.

## 호환성·이관·복구

JSON inventory and row-queue behavior remain unchanged. Graph export is the only affected format. Existing audit keys and overlay receipts keep their exact join rules.

## 검증과 미검증

The focused graph test calls `validate_graph` and asserts no errors. In the final release, eight before-and-after API graph audit tests passed. The stable-clone Python suite passed 1215 tests with zero skips.

## 한계와 후속 개선

The validator confirms structure and canonical statuses; it does not prove the member observations or receiver claims. Twelve relationship-completeness warnings remain on the capability worklist and are recorded as warnings, not errors.
