# test: pin exact terminal result redelivery

## 문제와 계기

정상 terminal result를 서버가 이미 저장했지만 전달 확인이 유실되어 같은 payload를 다시 보내면, 종전의 무조건 duplicate 거절은 안전한 재전달도 실패시켰다. 정확한 재전달과 충돌을 나누는 기준이 필요했다.

## 결과 동작

새 7개 테스트는 이미 수락한 success/error의 동일 payload에 원래 receipt를 반환하고 저장 바이트·mtime·native client 상태를 바꾸지 않도록 요구한다. transition 기대도 exact duplicate=accepted, conflicting duplicate=rejected로 강화했다. 제품 구현은 이 커밋에 없다.

## 변경 파일과 인터페이스

[finalize_terminal_result.py](../../../tests/finalize_terminal_result.py)를 추가하고 [operation transitions](../../../tests/test_rd08_operation_transitions.py)를 수정했다. 실제 private workspace의 claim→control.result→terminal 저장→재전달을 검사하며 raw readback UTF-8 바이트와 전체 파일/mtime, NATIVE_CLIENTS snapshot을 비교한다.

## 설계 이유와 출처

JSON object key 순서는 달라도 payload 값과 readback 문자열 바이트가 같으면 재전달이어야 한다. 반대로 whitespace가 다른 readback, status/error, claim/session/file/page/revision, extra field, null은 충돌로 거절한다. readback 부재와 null도 구별해 중복 판정을 넓히지 않는다.

## 호환성·이관·복구

과거 receipt 재전달은 다른 expired active claim을 만지거나 나중 uncertainty를 reconcile하지 못한다. 서버가 만든 terminal/legacy 상태는 재전달 권위로 쓰지 않으며 잘못된 operation ID는 path lookup 전 거절한다. 무조건 거절을 없애는 대신 exact-match·부작용 금지 조건을 고정한다.

## 검증과 미검증

상위 세션의 제품 수정 전 frozen 실행은 assertion 실패5개였다. 후속 실제 새 서버의 native JSON 재전달은 HTTP200, 충돌은409였고 source 파일은 보존되었다는 별도 관측이 있다. 그 관측을 이 테스트 커밋의 제품 구현이나 전체 native 성공으로 소급하지 않는다. 이번 작업은 diff 정적 대조만 했다.

## 한계와 후속 개선

합성 plugin payload와 private storage 검사는 live Figma 생성 성공을 증명하지 않는다. 실제 재전달 관측도 해당 claim 범위의 결과이며 모든 retry·동시성·장치 인수를 포괄하지 않는다. 현재 제품 소스 수정은 미커밋이고 R8 생성 결과는 미확정이다.
