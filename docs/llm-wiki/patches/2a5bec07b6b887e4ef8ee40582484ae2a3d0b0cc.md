# fix: bind scoped screen readbacks to the signed task's exact graph and selection

## 문제와 계기

screen-scope readback이 추가된 뒤에도 컨트롤 패널은 기대한 scope와 다른 응답을 generic page readback처럼 받아들일 수 있었다. 요청한 화면과 실제 읽은 화면의 연결을 확정해야 했다.

## 결과 동작

준비된 task는 graph SHA와 선택된 screen ID 순서를 signed scope에 담는다. 컨트롤은 screen-discovery schema, `readback_scope`, 바깥·안쪽 graph hash, screen ID 목록과 순서를 비교한 뒤에만 응답을 승인한다. 일반 네이티브 페이지 읽기는 기존 schema 검사를 유지한다.

## 변경 파일과 인터페이스

`tools/native_edit.py`는 task를 준비할 때 `web_screen_receipt`를 구성하고, `tools/graph_sync.py`가 이를 패널 설정으로 전달한다. `figma-bridge/workspace_control.js`는 실제 읽기 응답을 그 서명 범위와 대조한다.

## 설계 이유와 출처

화면 선택과 graph는 계획 단계에서 이미 정해져 있으므로 런타임의 현재 선택이나 읽기 편의를 근거로 범위를 넓히지 않는다. graph hash와 화면 순서를 함께 비교해 같은 집합의 다른 순서도 일치로 취급하지 않는다.

## 호환성·이관·복구

기존 full-page 요청은 계속 generic discovery schema를 사용한다. screen-scope를 고른 task만 추가 receipt metadata를 받는다. 거부된 응답은 실제 getter 증거로 저장되지 않는다.

## 검증과 미검증

고정 HEAD에서 `tests.test_native_edit` 및 관련 Python 묶음과 `tests/test_workspace_control.cjs` 9개가 통과했다. 실제 screen readback 36개 모두 signed graph hash와 순서가 있는 screen ID 목록에 일치했다.

## 한계와 후속 개선

이 검사는 반환된 native readback이 signed task 범위에 맞는지 확인한다. 외부 서비스의 저장 성공, 모든 화면의 시각적 충실도 또는 다른 scope의 사용자 데이터 상태를 증명하지 않는다.
