# 영구 workspace 등록 의도와 테스트 환경 분리

커밋 `a49dd1d1b5794a295aa7e71a3983c5777adc5dc5`

## 문제와 계기

init, enable, refresh, serve가 PC 등록을 수행했고 경로 이름만으로 테스트 여부를 추정했다. 여러 유효 후보 중 기본값이 없어도 첫 행을 선택했다.

## 결과 동작

일반 작업은 지정 경로만 사용한다. remember가 PC 등록과 메타데이터 갱신을 담당하고 --default가 명시된 경우에 기본값을 선택한다. 여러 후보 중 선택이 필요하면 setup-status가 사용 가능한 경로와 다음 명령을 안내한다.

## 변경 파일과 인터페이스

tools/workspace_registry.py는 등록 잠금 안에서 유효한 기존 문서만 갱신한다. tools/figma_workspace.py와 figma_control.py가 조작·관측을 분리한다. tools/test_env.py는 각 테스트 명령의 임시 XDG를 제공하며 CI 템플릿과 생성물에 연결된다.

## 설계 이유와 출처

설치된 PC 상태와 실행 중인 작업공간의 실제 설정은 별개다. 조회 시 작업공간에서 포트와 플러그인 ID를 읽으므로 서비스를 띄울 때 기본값을 다시 쓸 필요가 없다.

## 호환성·이관·복구

기존 정상 레지스트리와 기본값은 그대로 읽힌다. 동일한 remember의 재실행은 이미 맞는 설정을 다시 쓰지 않는다. 기존 파일의 바이트나 권한을 확인할 수 없으면 명시적 등록은 실패한다.

## 검증과 미검증

OS로 개인 설정 접근을 차단한 재현에서 RC2는 가짜 PC에 새 행을 남겼고 수정 후에는 원래 바이트와 디렉터리 상태가 보존됐다. 실제 CLI remember, 동시 등록, 기존 기본값 및 선택이 필요한 조회를 검사했다.

## 한계와 후속 개선

테스트 실행기는 XDG 설정 격리 경계다. macOS의 실제 사용자 설정 접근 거부는 이번 검수에서 별도 OS 보호 환경으로 확인했다.
