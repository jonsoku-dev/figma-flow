# feat: project one product graph into native reviews and trace real inputs

## 문제와 계기

직군별 도구에 요구사항과 화면을 반복 입력하면 버전·관계가 달라진다. SSR의 실제 앱별 자산과 편집기별 공개 API가 어떻게 동작하는지도 네 템플릿에서 확인해야 했다.

## 결과 동작

정본에서 선택한 노드·관계를 Design의 카드·FigJam 표·Slides 덱으로 투영한다. 관측 결과를 API 멤버에 연결한다. SSR의 캡처 경로와 응답·로컬 바이트 SHA를 정상 input record 최신성 검사에 넣었다.

## 변경 파일과 인터페이스

`tools/review_graph.py`, `tools/review_api_coverage.py`, `tools/native_api_probe.py`, `tools/input_effect.py`, `figma-bridge/native_graph_review.js`, `library/figma-recipes/manifest.json`과 두 에디터 recipe, 도구별 인수 검사를 변경했다. 기능 계약은 specs/graph-review/graph.json에 있다.

## 설계 이유와 출처

안정적인 graph ID, 원본 SHA와 선택 SHA를 서로 구분한다. 같은 출처의 서로 다른 쿼리는 별도 입력이다. 메뉴와 기능 라우팅 및 빌드의 중복된 레시피 등록을 통합했다. 실제 투영 비용을 측정한 뒤 기존 JSON 정본과 메모리 인덱스를 유지했다.

## 호환성·이관·복구

구 input v3는 source freshness 검사를 유지하며 새 기록은 v4를 쓴다. 구버전 source-only FigJam·Slides 산출물은 정확한 소유 노드, 텍스트, 순서, 관계를 확인한 경우에만 새 식별자로 이관한다. Slides는 현재 Canvas Grid API로 구 경로를 대체했다.

## 검증과 미검증

실제 네 앱에서 SSR 입력 4개와 URL 45개를 추적했다. 20개 노드·16개 관계의 동일 graph로 Design 보드·FigJam 123개 노드·Slides 7행 21장을 확인했다. Figma가 숫자 이름을 부여하는 과거 덱은 중복 생성과 안전 거절을 재현한 뒤 71개 노드 그대로 이관·재실행했다. Design 9개 노드의 141개 조합이 성공했으며 고유 멤버 37개다.

## 한계와 후속 개선

실제 관측을 새로 증명한 49개를 포함해 127/1,382개 멤버가 개별 실행 근거를 갖는다. 나머지 1,255개는 구현 여부·편집기·계정 조건에 따라 추가 검증이 필요하다. 보드·덱은 그래프의 시각화이며 웹 전체를 편집 가능한 화면으로 자동 변환하는 기능은 별도다.
