# test: use fictional home paths in distributable redaction fixtures

## 문제와 계기

공개 ZIP 검사에서 기존 두 검사의 fixture에 실제 개발자 홈 디렉터리 문자열이 있음을 발견했다. 실행에서 수집된 입력이나 인증정보는 아니었지만 배포할 검사 자료에 실제 사용자 이름을 계속 포함할 필요가 없었다.

## 결과 동작

입력 자료 예제와 그에 대응하는 부정·긍정 assertion의 홈 디렉터리를 허구의 계정명으로 통일한다. 실제 절대 경로가 요약에서 제거되고 원본 기록에는 남는 검사 동작을 그대로 확인한다.

## 변경 파일과 인터페이스

`tests/test_rd05_html_input_record.py`와 `tests/test_rd05_asset_inventory.py`에 쓰인 fixture 문자열과 기대값을 같은 허구 경로로 교체했다.

## 설계 이유와 출처

포크 사용자는 자신의 설치 경로와 무관하게 같은 검사를 반복할 수 있어야 한다. 개인 경로를 하나도 포함하지 않는지 전체 Git 배포 파일과 ZIP 바이트를 조사했다.

## 호환성·이관·복구

기존 설치본 경로나 runtime 동작, 개인정보 필터 규칙은 바뀌지 않는다. 이전 검사의 변환은 동일한 절대 경로 형식으로 재현한다.

## 검증과 미검증

실제 배포 ZIP 사전 점검에서 해당 fixture가 발견되는 실패를 보존했다. 두 독립 회귀 검사를 실행해 통과했고, 새 아카이브의 전체 파일을 대조해 이 개인 홈 문자열이 없음을 확인했다.

## 한계와 후속 개선

검사는 현재 공유 패치와 설치본의 파일 바이트를 대상으로 한다. 이미 배포된 과거 Git 이력·태그를 다시 쓰지 않는다.
