# fix: reconcile interrupted imports with a read of the same signed screen plan

## 문제와 계기

Screen-scoped imports can be interrupted after a write, leaving a mutation uncertain. A retry must not apply the same signed plan again until the current Figma state has been reconciled, and it must not accept a read from a different plan or changed screen.

## 결과 동작

Recovery permits only a readback from the same native-edit task, matching the original file/page, plan input pin, graph hash and `screens` scope. Each selected screen must report `current` or `missing`; changed, mismatched or partial evidence leaves the original operation uncertain.

## 변경 파일과 인터페이스

`tools/figma_control.py` adds the screen-scoped branch in `recovery_read`. `tests/test_figma_control.py` exercises same-plan recovery, changed revision, changed screen status, missing frames and plan-hash mismatch.

## 설계 이유와 출처

Recovery is an observational step over the original signed plan. It checks the same selection and only reconciles whether each expected frame exists unchanged or is missing; it never converts a changed frame into a successful retry.

## 호환성·이관·복구

Existing generic page discovery and mutation recovery rules remain unchanged. No new task revision, frame replacement or data migration settles the original uncertain operation.

## 검증과 미검증

On the frozen 0.31 candidate, the scoped Python test set passed 67 tests, including recovery coverage; web-design Node 19 tests and workspace-control Node 9 tests passed.

## 한계와 후속 개선

A recovery read can establish current/missing state under the signed plan. It does not prove the full design is visually faithful or authorize a retry when a frame changed.
