# feat: link responsive screens to routes and scope native receipts to their graph

## 문제와 계기

반응형 캡처는 같은 URL 경로를 여러 뷰포트에서 담지만 graph에는 화면끼리의 경로 관계가 없었다. 기본 네이티브 읽기는 전체 페이지를 반환해 가져온 화면 밖의 노드가 함께 들어올 수 있었다.

## 결과 동작

선택한 화면들을 출처의 origin·pathname으로 묶고 각 관측 viewport를 route 상태에 연결한다. 가져오기 계획은 전체 페이지 읽기 또는 graph가 소유한 화면만 읽기를 선택할 수 있고, screen 범위 응답에는 graph hash와 화면 노드가 포함된다.

## 변경 파일과 인터페이스

`tools/web_route_graph.py`가 캡처 출처를 검증하고 route·viewport 관계를 만든다. `tools/web_design_source.py --responsive`가 그 관계를 저장하며, `tools/web_design.py`는 최대 256개 원본 화면을 검증하고 한 계획에서 최대 16개를 허용한다. `tools/native_edit.py --readback-scope screens`와 `figma-bridge/native_edit.js`가 선택 graph의 최상위 소유 프레임만 읽는다.

## 설계 이유와 출처

route identity는 캡처 증거의 실제 URL과 pathname에서 가져온다. 같은 경로·같은 viewport의 중복 관측은 거부한다. 네이티브 읽기는 현재 페이지의 모든 노드가 아니라 `WEB_DESIGN_KEY`가 현재 graph와 선택 화면을 가리키는 프레임만 순회한다.

## 호환성·이관·복구

기존 full-page 읽기는 기본값으로 남아 이전 가져오기 호출이 바뀌지 않는다. 응답 범위를 선택할 때는 `screens`를 지정한다. source graph는 최대 256개 화면까지 보유할 수 있지만 한 번에 선택하는 수는 기존 한도인 16개다.

## 검증과 미검증

고정 HEAD에서 관련 Python 검사 11개와 native-control Node 검사 9개가 통과했다. 실제 플러그인 screen-scope readback 36개는 요청 graph hash와 정렬된 화면 ID가 모두 일치했고, 총 120개 선택 화면 관측을 기록했다. 처음 거절된 일부 effect 적용 시도는 성공 receipt로 세지 않았다.

## 한계와 후속 개선

screen 범위 읽기가 증명하는 것은 선택 graph에 속한 네이티브 프레임의 제한된 getter 결과다. 모든 CSS 변환, 전체 페이지 상태나 픽셀 동일성을 보증하지 않는다. 실패한 effect payload 적용은 별도 네이티브 쓰기 검증이 필요하다.
