# feat: pin the current runtime transport trace

## 문제와 계기

기준 56034e24e922a9ff9b5e4b45e3a5cab00001a248는 load_runtime_boundary_trace가 없어 `runtime boundary trace must pin transport and source pins`로 실패했다. poll, native-started, result와 source pin 범위가 한 fixture에 없었다.

## 결과 동작

load_runtime_boundary_trace는 tests/fixtures/rd07/protocol-trace.json을 읽는다. schema는 figma-flow-runtime-boundary-v1이다. 전송 경로는 poll, native-started, result이고 method는 POST, authorization은 Bearer다. 허용 operation은 review create, import read·import·sync, discover read, sync read·apply, native-edit read·apply다. source pin 폴더는 figma-bridge, library, tools이고 접미사는 .css, .html, .js, .json, .py다. workspace_control.js의 호출은 옮기지 않는다.

## 변경 파일과 인터페이스

tools/figma_workspace.py에 load_runtime_boundary_trace를 trusted_sources 옆에 추가했다. tests/fixtures/rd07/protocol-trace.json을 추가했다. tests/test_rd07_runtime_boundary.py blob은 기준과 같다.

## 설계 이유와 출처

RD-07 작업 1은 현재 trace를 고정하고 모듈 책임을 표로 남긴다. workspace_transport는 아직 분리하지 않는다. 도메인 검사는 workspace_control에 남긴다. publisher 조립과 trusted_sources는 이 단위에서 옮기지 않는다.

## 호환성·이관·복구

전송 코드와 발행 조립은 그대로다. 새 operation 권한은 없다. 플러그인 버전은 0.26.3이다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd07_runtime_boundary`를 기준 56034e24e922a9ff9b5e4b45e3a5cab00001a248에서 종료 코드 1, 대상 b170f11568364a8c1e4494613f717ad87519ec83에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 assertion은 `runtime boundary trace must pin transport and source pins`다. 조건은 RD-07-REQ-01다. 생성된 bundle 실행과 실제 Figma 플러그인 재로드는 하지 않았다.

## 한계와 후속 개선

이 단위는 fixture다. 순수 전송 함수의 이동, publisher 조립, 모든 task kind 실행, 구 경로 삭제는 다음 단위다.
