# feat: apply shared component fields without a new main component

## 문제와 계기

기준 80742c55590c46e85ca8289298abc0a58371a9a8는 commit_component_fields가 없어 `component field selection must keep the main component`로 실패했다.

## 결과 동작

commit_component_fields는 같은 token을 쓰는 필드를 한 closure로 본다. paddingLeft만 고르면 partial component closure다. 둘을 함께 고르면 12가 되고 fontSize는 14로 readback에 남는다. baseline에는 padding 두 필드만 있다. node_id와 main_component_id는 main-1이다. before와 다른 관측값은 stale before value로 거절되고 입력은 바뀌지 않는다. commitComponentFields는 같은 결과를 내고, component_fields가 있는 메시지는 graphSyncPlanForMessage가 그 baseline과 기존 id를 plan에 붙인다. 그 필드가 없는 메시지는 전체 plan을 유지한다.

## 변경 파일과 인터페이스

tools/graph_sync.py에 commit_component_fields를 추가했다. figma-bridge/graph_token_sync.js에 commitComponentFields를 추가하고 graphSyncPlanForMessage가 message.component_fields를 넘긴다. docs/development-roadmap/RD-04-selective-sync/tasks.md에 범위를 적었다. tests/test_rd04_component_fields.py와 tests/fixtures/rd04/component-fields.json blob은 기준과 같다.

## 설계 이유와 출처

RD-04는 component field를 token root와 같은 선택 identity로 다루되, 공유 consumer closure는 쪼개지 않는다. 필드 적용이 새 main component나 인스턴스 variant를 만들면 기존 node ID가 바뀐다.

## 호환성·이관·복구

component_fields가 없는 apply는 이전과 같다. 토큰 선택 함수의 반환 필드는 유지한다. 실패한 closure 검사는 관측값을 쓰지 않는다.

## 검증과 미검증

종료 게이트는 `python3 -B -m unittest tests.test_rd04_component_fields`를 기준 80742c55590c46e85ca8289298abc0a58371a9a8에서 종료 코드 1, 대상 f5e853a2056798c94b5cf5419484255998f6bd85에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 마지막 assertion은 `component field selection must keep the main component`다. 조건은 RD-04-REQ-01이다. 같은 구현에서 선택 적용 검사와 graph token sync·graph panel 노드 검사도 종료 코드 0이었다. Figma에서 padding만 바뀌고 main component가 유지되는 적용은 관찰하지 않았다.

## 한계와 후속 개선

이 필드 선택은 합성 값이다. 화면은 component_fields payload를 아직 보내지 않는다. AC의 Figma 관찰은 통과로 기록하지 않는다.
