# feat: connect the complete API backlog to ranked receiver-specific graph nodes

## 문제와 계기

The first priority queue ordered remaining API rows, but it did not yet provide a complete connected graph of candidates, use cases, receiver facts and evidence status for every audit member.

## 결과 동작

Queue graph export now includes the exact complete member set, ranked candidates, feasible scenarios, receiver references and current evidence. It keeps observed status attached to exact validated links rather than loose node labels.

## 변경 파일과 인터페이스

`tools/api_priority.py queue --format graph` and `tests/test_api_priority.py` define and check the graph shape. The command still supports the row-based JSON queue.

## 설계 이유와 출처

Graph export makes the relationships reviewable without turning score or queue membership into evidence. Exact audit member keys remain the join boundary.

## 호환성·이관·복구

The new output is additive. Existing JSON inventory and queue formats remain available. The data is regenerated from pinned audit, receiver catalog and observation graphs.

## 검증과 미검증

The commit adds graph export and test cases for all-member coverage, exact status, and source links. The final release connects the graph to 150 observed members and 1232 unobserved members out of 1382; [API priority guide](../../../docs/api-priority.md) has current commands.

## 한계와 후속 개선

Graph structure validates supplied relationships but does not prove the source readback, call success, or support of unobserved API members.
