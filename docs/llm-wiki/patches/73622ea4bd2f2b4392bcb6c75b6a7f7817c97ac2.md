# feat: export a redacted diagnostic record from the graph panel

## 문제와 계기

기준 015f440ee635d817f033dddabb504acaea69895f는 buildAuditRecord가 없어 `audit export must keep the diagnostic record`로 실패했다. 버전, 파일, 작업, 페어링, 오류, 입력 요약, 읽기 범위가 한 진단 기록에 없었다.

## 결과 동작

figma-bridge/audit_log.js의 buildAuditRecord와 renderAuditExport는 schema figma-flow-audit-log-v1 기록을 만든다. bearer, 동기화 토큰, 채팅 토큰, 홈 경로, 자격 증명 쿼리를 가린다. 노드 ID, 리비전, 오류 문장, 작업 식별자는 남긴다. figma-bridge/graph-panel.html의 진단 기록 섹션은 복사, 마크다운 저장, JSON 저장만 한다. bindAuditExport는 적용 메시지를 보내지 않는다.

## 변경 파일과 인터페이스

figma-bridge/audit_log.js와 figma-bridge/graph-panel.html을 추가하거나 고쳤다. tests/rd09_audit_log.cjs blob은 기준과 같다. 이 기록 발행은 그 제품 커밋의 페이지다.

## 설계 이유와 출처

RD-09는 그래프 패널에서 읽기 전용으로 진단 기록을 내보낸다. 문서를 바꾸거나 네이티브 쓰기를 보내거나 페어링을 바꾸지 않는다.

## 호환성·이관·복구

기존 그래프 적용 경로는 진단 버튼과 분리된다. 플러그인 버전은 0.26.3이다. 입력 객체와 pairing plan은 바꾸지 않는다.

## 검증과 미검증

종료 게이트는 `node tests/rd09_audit_log.cjs`를 기준 015f440ee635d817f033dddabb504acaea69895f에서 종료 코드 1, 대상 73622ea4bd2f2b4392bcb6c75b6a7f7817c97ac2에서 종료 코드 0으로 다시 실행했다. 기준 stderr의 assertion은 `audit export must keep the diagnostic record`다. 조건은 RD-09-AC-01이다. 같은 구현에서 test_graph_sync와 test_panel_components 35개는 종료 코드 0이었다. 실제 Figma 패널의 복사와 저장은 보지 않았다.

## 한계와 후속 개선

로컬 Node 검사와 패널 소스 확인은 실제 Figma 패널 관찰을 대신하지 않는다. 라이브 패널 인수 조건은 통과로 적지 않는다.
