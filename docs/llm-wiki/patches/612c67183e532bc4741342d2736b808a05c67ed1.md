# 느린 러너에서 준비와 전송 시간 제한을 구분

소스 커밋 `612c67183e532bc4741342d2736b808a05c67ed1`

## 문제와 계기

호스팅된 러너에서 검증 작업공간 생성부터 요청 후 정리까지 묶은 30초 제한이 만료됐고 정지 단계가 출력되지 않았다.

## 결과 동작

외부 fixture 준비·정리 한도를 요청의 제한과 따로 두고 경과 단계와 스택을 남긴다.

## 변경 파일과 인터페이스

`tests/test_control_transport_authority.py`와 그 사례를 참조하는 네 증거의 해시를 갱신했다.

## 설계 이유와 출처

실제 인증된 HTTP 요청의 5초 소켓·15초 프로세스 한도와 정상·거절 단언을 유지한다.

## 호환성·이관·복구

제어 서버의 시간 제한, 토큰과 데이터 예산은 변경하지 않는다.

## 검증과 미검증

같은 이름의 실제 루프백 테스트를 로컬에서 다시 실행했으며 종료 0을 확인했다.

## 한계와 후속 개선

호스팅된 워크플로에서 시간 제한이 반복되면 어느 단계인지 새 증거에 출력된다.
