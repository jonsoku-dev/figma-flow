# test: pin real-capture graph regeneration before preserving authored edits

## 문제와 계기

`source.py`가 캡처를 다시 생성할 때 기존 `graph.json`의 사람이 고친 필드·관계와 새로운 source proposal을 어떻게 합칠지 정해진 기준이 없었다. 구현을 바꾸기 전 기대 동작을 고정하기 위해 real-capture fixture를 임시 복사하고 반복 생성, 충돌, 삭제된 source 항목과 stale hash를 확인하는 테스트를 추가했다.

## 결과 동작

이 커밋의 test는 노드 ID와 관계 identity를 따라 authored edit 보존, source와 양쪽에서 바뀐 필드의 충돌, source에서 빠진 기존 항목 유지, 신규 requirement 추가와 기존 order 변형, stale expected SHA 거부를 요구한다. test가 실제 canonical graph를 덮어쓰지 않도록 design directory를 temporary root에 복사해 실행한다.

## 변경 파일과 인터페이스

첫 부모 `dc72dd8e23461164e24f7a11e5863a91bdf00332` 대비 `apps/little-hands/design/test_regeneration.py`만 추가됐다. 제품 CLI나 generator는 이 commit에서 바뀌지 않았다. 테스트는 다음 구현의 `source.reconcile(...)`와 `source.build(...)` 계약을 사용한다.

## 설계 이유와 출처

Capture generator는 기존 graph를 덮어쓸 수 있으므로 검사는 작은 독립 merge case와 실제 `source.py` 반복 실행을 함께 다룬다. 생성된 `specifications.json` source graph SHA도 canonical graph bytes와 같아야 하고, 충돌이나 stale SHA일 때 graph/layout/specification 출력은 유지돼야 한다.

## 호환성·이관·복구

테스트만 추가되므로 사용 데이터와 generator 동작은 변경하지 않는다. 이 commit 단독으로는 `source.reconcile` API를 아직 제공하지 않아 구현과 결합해 실행해야 한다. 후속 구현 `4621d47b6deb866d913e4430f44fb7f7635827a8`가 해당 계약을 채운다.

## 검증과 미검증

이 테스트는 구현 전 acceptance 기준을 먼저 기록한 commit이다. 35c6d3e 자체의 `source.py`에는 `reconcile`가 없으므로 이 commit만 checkout하면 해당 suite는 완전 통과하지 않는다. 후속 4621d47 구현이 있는 현재 checkout에서는 `python3 -B -m unittest discover -s apps/little-hands/design -p test_regeneration.py`가 2 tests pass했다. 테스트는 real Figma canvas acceptance를 주장하지 않는다.

## 한계와 후속 개선

복제된 checkout에서 fixture inputs와 generator를 검증하며, production graph를 실제 filesystem race로 동시에 수정하는 운영 상황 전체를 증명하지는 않는다. 새 generator 변경은 temp copy에서 재실행하고 concurrent writer/CAS 경계를 별도로 확인해야 한다.
