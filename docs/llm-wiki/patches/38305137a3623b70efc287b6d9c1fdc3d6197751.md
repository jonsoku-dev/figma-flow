# 작업을 거절한 파일별 원인과 복구 안내

커밋 `38305137a3623b70efc287b6d9c1fdc3d6197751`

## 문제와 계기

같은 파일의 작업 슬롯이 사용 중이어도 제어 CLI가 revision 오류와 동일한 포괄 문구를 출력했다. 사용자는 기다려야 하는지 작업을 다시 준비해야 하는지 판별할 수 없었다.

## 결과 동작

진행 중이면 해당 파일의 status 명령을 안내한다. stale 또는 알 수 없는 작업에는 list와 현재 revision 확인을, 결과가 불확실한 쓰기에는 상태 확인과 해당 파일·페이지의 실제 읽기를 안내한다.

## 변경 파일과 인터페이스

tools/figma_control.py의 task와 enqueue가 기존 거절 조건에서 ControlDiagnostic을 발생시킨다. main이 허용된 진단만 stderr에 출력한다. specs/codex-relay/graph.json은 새 검사를 CODEX 구현과 연결한다.

## 설계 이유와 출처

판정은 서명된 작업 확인과 파일별 잠금 안에 그대로 둔다. 예외 문자열을 분류하거나 상태를 두 번째로 추측할 필요가 없다.

## 호환성·이관·복구

기존 ValueError와 ReadinessError 호출 계약, 성공 JSON, 거절 종료 코드 2, 비공개 오류의 포괄 처리 및 쓰기 차단을 유지한다.

## 검증과 미검증

영향 단위 검사 56개와 maintenance check가 통과했다. 실제 RC 패널에서 읽기 중 중복 요청의 stdout은 비었고 정상 읽기는 노드 20,425개를 반환했다. 이후 selection-info가 같은 파일·페이지의 텍스트 노드 하나를 반환했다.

## 한계와 후속 개선

실기동은 별도 루프백 포트와 이미 등록된 시험용 개발 매니페스트에서 확인했다. 시험 후 매니페스트·공유 설정 해시를 대조했다. 전체 제품군과 패키지 검수는 상위 릴리스 절차에서 수행한다.
