# test: pin canonical asset identity and admission contract

## 문제와 계기

같은 font가 서로 다른 CSS 상대 표기에서 유입될 때 summary가 한 파일을 중복 집계하지 않는지, 실제 workspace CLI admission을 테스트가 인정하는지 고정할 필요가 있었다.

## 결과 동작

두 번째 CSS가 ../fonts/./body.woff2를 참조하도록 바꾸고 font row가 정확히 하나인지 확인한다. record 경로 설명의 cli_flag는 --input-record이며 workspace의 --input-root도 요구한다.

## 변경 파일과 인터페이스

finalize_input_audit.py의 생산자 fixture/summary assertion과 test_rd05_input_route.py의 CLI·문서 경계 검사를 수정했다. input_effect.project→html_channel→freshness/write_record→workspace.prepare가 대상 경로다.

변경 경로: [tests/finalize_input_audit.py](../../../tests/finalize_input_audit.py), [tests/test_rd05_input_route.py](../../../tests/test_rd05_input_route.py).

## 설계 이유와 출처

정규화된 로컬 파일 identity는 모든 CSS ingress를 한 항목에 보존해야 한다. CLI admission은 workspace가 소유하고 ImportPanel은 이 목록의 소비자가 아니라는 책임을 유지한다.

## 호환성·이관·복구

제품에 플래그를 구현하는 커밋이 아니다. 새 CLI 계약을 테스트에 고정하고 긴 문서 문장 전체 일치 대신 핵심 경로와 플래그를 검사한다. 후속 03c4c8b가 input_effect의 문자열 부재 검사를 argparse 경계로 정정한다.

## 검증과 미검증

Git diff에서 동일 파일의 ./ 표기와 font 개수 1 assertion, 두 플래그 존재 검사를 확인했다. 제품 구현이 이 baseline에서 이미 통과했다는 주장은 하지 않는다.

## 한계와 후속 개선

정규화 fixture는 symlink·모든 URL 동일성이나 실제 폰트 사용을 보증하지 않는다. 실제 CLI admission과 source freshness는 별도 oracle 및 후속 제품 수정으로 검증한다.
