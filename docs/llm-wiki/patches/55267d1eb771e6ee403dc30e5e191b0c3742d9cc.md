# feat: capture SaaS FAQ disclosure open, close, and sibling switch clicks

## 문제와 계기

이 커밋은 로컬 Chromium에서 disclosure 트리거를 차례로 클릭하고 상태와 증거를 수집하는 `tools/web_disclosure_capture.mjs`를 추가한다.

## 결과 동작

캡처기는 accordion, item, trigger, content selector를 입력받아 단일 열린 항목의 라벨, 답변 문자열, 트리거 좌표, 상태, 화면 크기를 읽는다.

## 변경 파일과 인터페이스

각 클릭 전에 목표 트리거가 보이고 실제 hit-test가 그 트리거를 가리키는지 확인한다. 클릭 후 DOM 상태가 바뀌면 스크린샷과 상태 해시를 저장한다. 관련 변경: `tools/web_design_capture.js`, `tools/web_disclosure_capture.mjs`.

## 설계 이유와 출처

실행은 닫힘에서 열기, 다시 닫기, 열려 있는 형제 항목으로 전환하기 같은 사용자가 지정한 클릭 순서를 관측한다. 관측하지 않은 간선은 만들지 않는다.

## 호환성·이관·복구

스크립트는 screenshots, WEB 화면 입력, click receipts, `observations.json`, `inputs.json`, 결합 그래프를 지정한 새 출력 디렉터리에 작성한다.

## 검증과 미검증

반복 클릭도 입력 로그에는 남기지만 상태 전이가 중복되면 관측 그래프의 전이는 한 번만 기록한다. 화면이 바뀌지 않거나 selector가 모호하면 실행을 중단한다.

## 한계와 후속 개선

실제 FAQ 보고서에는 질문 다섯 개가 있었고 두 질문의 열기·닫기·상호 전환만 실행해 세 상태와 여섯 전이를 얻었다. 나머지 세 질문의 열림 동작은 관측되지 않았다.

## 관련 기록

캡처는 로컬 브라우저의 단일 viewport와 선택한 selector 및 클릭 경로만 증명한다. 여러 기기, 모든 화면, 로그인 이후 상태의 정확성을 자동으로 보장하지 않는다. [FAQ 인수와 한계](../../../specs/interactive-web/disclosure.md) · [관측 입력](../../web-disclosure-input.md) · [0.35.0 기록](../releases.md#v0.35.0).
