# fix: distinguish partial native seeding from empty return paths in diagnostics

## 문제와 계기

typed value route의 일부 seed assignment가 실패한 뒤에도 getter가 표본 값을 돌려주면, scenario 상태가 `seed-error`로 남아 partially seeded 상태를 구분하지 못했다.
## 결과 동작

collector는 assignment 실패 후 readback object를 관측하면 scenario를 `partial`로 표시한다. 값이 전혀 생성되지 않은 경로는 `seed-error` 또는 unavailable로 유지한다.
## 변경 파일과 인터페이스

`library/figma-recipes/inspection/values.js`의 `setScenario` 조건을 조정하고 `tests/test_native_value_paths.cjs`에 failure와 readback 조합 회귀를 추가했다.
## 설계 이유와 출처

getter 결과는 seed가 완전했는지와 분리해 기록해야 한다. assignment status와 실제 readback object가 서로 다른 정보를 제공하므로 collector는 둘 다 유지한다.
## 호환성·이관·복구

변경은 진단 receipt에만 적용된다. 기존 value path route와 API member identity는 바뀌지 않는다.
## 검증과 미검증

Node regression은 assignment failure 뒤에 readback이 나타나는 case를 `partial`로, 값 반환 없이 끝나는 case를 `seed-error`로 구분한다. 이 테스트는 Figma runtime에서 다시 실행하지 않는다.
## 한계와 후속 개선

Partial 결과는 데이터 형상의 실제 getter 지원을 뜻하지 않는다. 각 field status와 scenario status를 따로 검토한다.
