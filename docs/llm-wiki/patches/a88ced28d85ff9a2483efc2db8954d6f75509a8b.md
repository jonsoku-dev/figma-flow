# Codex의 웹·Figma 정렬 검사와 뷰어 여백 수정

## 문제와 계기

사용자가 대상 화면을 지정하면 공통 기준에서 얼마나 벗어났는지 측정하고 수정 전후를 비교할 수 있어야 했다.

## 결과 동작

`a88ced28d85ff9a2483efc2db8954d6f75509a8b`은 브라우저의 기준선·편차·이미지 비교와 명시한 Design 노드의 절대 바운딩 박스 비교를 추가했다. 등록 뷰어는 한 컨테이너 여백 값을 사용한다.

## 변경 파일과 인터페이스

`tools/alignment_audit.mjs`, `tools/alignment_compare.py`, `tools/relay_alignment.py`가 웹 증거를 생성한다. `tools/figma_alignment.py`는 서명된 작업이 생성한 기하 읽기 결과를 오프라인에서 비교한다.

## 설계 이유와 출처

목표 간격과 허용 오차를 구분하고, 누락된 기준이나 대상이 있으면 미확인으로 반환한다. 다른 컴포넌트의 부모 좌표를 혼합하지 않는다.

## 호환성·이관·복구

명시한 노드 ID를 별도 옵션으로 전달한다. 기존 선택 기반 조회를 보존하고 기하 조회가 현재 선택을 바꾸지 않도록 했다.

## 검증과 미검증

같은 배포용 빌드와 브라우저 조건의 전후 검사에서 기존 1px·2px 편차가 각각 0px가 됐다. 다른 그래프 기반 로컬 화면과 실제 Design 예약 버튼 3개의 왼쪽 가장자리를 추가로 검사했다.

## 한계와 후속 개선

좌표는 CSS 상자 또는 Design 페이지의 축 정렬 절대 상자 기준이다. 완전히 다른 화면 상태, 글자의 잉크 윤곽, 미리 정하지 않은 정렬 의도는 별도 시각 검토가 필요하다.
