# Plugin API evidence priority

The ranked graph connects each audited API member to its exact owner, compatible receivers, user roles, feasibility and evidence. The default command joins the pinned audit and the 0.29, 0.30 and responsive-web observations. A property can be readable even when the SDK also allows writes. Only explicitly mapped methods enter the read-only or owned-write queues. Methods needing a scenario, declaration-only types, unresolved receivers and editor or permission gates retain distinct classifications.

The score is a work-order hint, not evidence that a method or getter works. Graph status is copied only from a validated `observed member` edge to the exact `member:<hash>` audit key. An unlinked graph node with status `observed` contributes nothing. The builder never converts audit references, declarations, or queue membership into successful runtime observations.

```sh
python3 tools/api_priority.py build --out .figma-flow/api-priority.json
python3 tools/api_priority.py queue --inventory .figma-flow/api-priority.json --format graph > .figma-flow/ranked-graph.json
python3 tools/api_priority.py queue --inventory .figma-flow/api-priority.json --receiver TEXT --limit 30 --feasible-only
python3 tools/api_priority.py build --baseline-only --out .figma-flow/api-priority-029.json
python3 tools/api_priority.py build --observations specs/graph-review/api-observations.json \
  --overlay .figma-flow/new-sanitized-api-observations.json --out .figma-flow/api-priority-updated.json
```

The CLI defaults to joining `specs/editable-web/api-observations.json` and `specs/responsive-web/api-observations.json` as receipt-validated overlays. The 0.30 baseline has 150 observed keys and 1,232 unobserved rows. Four responsive-web reads added 39 distinct keys, bringing the total to 189 and the remaining queue to 1,193. They made 488 bounded getter calls: 473 succeeded, 10 returned unavailable values, and 5 properties were absent on their concrete receiver. The first batch alone had little net effect because it overlapped 0.30 evidence. Later batches use the exact-key overlay to skip already observed members. Pass `--baseline-only` to reproduce the earlier 0.29 queue with 1,255 unobserved rows. Direct `build()` library calls retain the baseline-only behavior for existing callers. The full queue includes receiver-unknown, type-only, and editor or permission limited rows so their blockers stay visible. `--feasible-only` filters to readable properties, explicitly approved read-only methods, and purpose-approved owned-write methods.

Every row includes role term matches, a short reason for its feasibility rank, catalogued node receiver types, editor and permission requirements, and any validated evidence links. Observation graphs count only when a test evidence node connects to the exact official member node with an `observed member` edge. Graph structure, unique IDs, and all edge endpoints are checked. Each `--overlay` must also carry a timezone-aware non-future `observed_at`, a SHA-256 receipt reference, and at least one successful getter call. Repeat `--overlay` to join more sanitized graphs. This checks the supplied graph record; it does not verify the receipt hash against a raw receipt file or prove that the overlay was produced by the plugin.

The native probe sorts eligible candidates by the same queue score used here, attaches each item's role matches and feasibility reason, and excludes keys already linked to successful observations. It requires exact node IDs and types from a saved native readback, then runs bounded getter batches against those receivers. Its allowlist includes scalar layout, grid, appearance and text-style properties plus an explicit static read-only text range font-weight call. Opaque style identities become assigned/unassigned state; collection values become bounded counts or small enum summaries. Values pass through type-specific safe projections. Raw vector paths, vector networks, text contents, names, style identities, nested variable maps and arbitrary method invocation stay outside the probe. The sanitized responsive-web overlay retains timestamps, aggregate getter counts and receipt hashes, but omits file/page/node IDs and raw readbacks.

For an installed-version regression check, a private API probe selection can add `recheck_member_ids` with 1–16 exact audit member keys already linked to evidence. Use offset zero and select actual nodes that support those members. The read still uses the same static receiver and output allowlists. Omitting this field continues exploration of the unobserved queue.
