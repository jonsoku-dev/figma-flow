# 캠페인 아이덴티티

## 입력과 경로

동봉된 디자인 지침을 사용할 때는 [의존성 계약](../figma-flow/references/skill-dependencies.md)에 따라 실제 설치본을 검증하고 필요한 원문·참조만 읽는다.

참조 사이트나 로컬 미리보기를 브라우저로 열면 [허용 대상 등록과 적용 확인](../figma-flow/references/browser-access.md)을 먼저 수행한다. 새 작업 대상도 같은 목록에 추가한 뒤 계속한다.

현재 프롬프트와 이전에 합의한 게임명·언어·용도·제약으로 `tools/route_design.py`를 실행한다. 들어갈 매체와 크기를 먼저 정한다. 24px 내비게이션 심볼, 첫 화면의 워드마크, 인쇄용 항구 도장은 서로 다른 결과물이다. 시네마틱 키비주얼·그래픽 레터링·수집품 일러스트가 한 기획에 함께 필요하면 해당 표면에 각각 배정한다.

## 로고와 이미지 시안

1. 세계관에서 알아볼 수 있는 단서를 고른다. 게임명을 직접 조판한 비교안과 전용 글자형·심볼을 결합한 비교안을 검토한다.
2. 이미지 생성 요청이면 내장 `imagegen`으로 독립 래스터 시안을 만든다. 정확한 게임명·구도·매체·배경·금지 요소를 지정하고 산출물을 실제 크기로 연다. 생성물의 글자가 틀리거나 축소 시 형태가 사라지면 그대로 출고하지 않는다.
3. 선택한 글자형과 심볼은 편집 가능한 패스로 정리한다. 워드마크, 심볼 단독, 단색 양·음각, 소형 간략형을 만들고 배경 대비와 최소 여백을 확인한다. 브랜드 식별용 심볼과 조작 아이콘을 구분한다. 다른 로고를 참고했으면 사례에서 가져온 원리만 기록한다.
4. Figma가 SSOT인 작업에서는 최종 로고·에셋·스타일을 **실제 네이티브 문서**에 배치하고 읽어낸 다음 앱에 연결한다. 의뢰받은 출력이 래스터인 배경·캐릭터는 원본 해시, 크롭, 표시 위치를 기록한다.

## 아이콘과 인장

조작용은 격자·획 굵기·모서리·광학 중심을 공유한다. 수집용은 각 기항지·캐릭터의 차이를 단색 실루엣에서도 보이게 한다. 16·24·48px는 현지 테스트 크기의 예이며 프로젝트의 실제 최소 표시 크기도 확인한다. 아이콘이 16px이어도 사용자가 누르는 영역과 접근 가능한 이름은 별도로 확인한다. 섬세한 인장이 16px에 맞지 않으면 별도 소형 심볼로 교체한다.

## 활자

- 전용 로고 레터링, 라틴 제목, KO/JA 제목과 UI 문구, 숫자·일련번호의 역할을 지정한다.
- 언어별 Figma TEXT에서 실제 사용 패밀리·스타일·크기·행간과 줄바꿈을 기록한다. 한자 공유 코드포인트도 지역별 자형이 다를 수 있으므로 각 언어에서 읽는다.
- 배포 시 실제 서체에 동봉된 라이선스를 확인한다. 로컬 배포·서브셋을 택하면 한국어·일본어 본문, 동적 상태, 이미지 저장에 필요한 글리프를 검사한다.
- Figma의 디자인을 그대로 옮기라는 요청에서는 원본의 벡터·좌표·서체 출력물을 사용한다. 저장 이미지에 번호처럼 바뀌는 글자가 있다면 같은 데이터로 만든 네이티브 출력과 실제 다운로드를 비교한다.

## 인계

프롬프트 → 선택 경로 → 실제 원문 → 제작한 로고/폰트/아이콘 → Figma 노드 → 웹 사용처 → 작은 크기·모바일 다운로드 테스트를 연결한다. 스킬이나 지침을 읽었다는 사실은 디자인이 통과했다는 증거가 아니다. [출처와 자동 라우팅](../figma-flow/references/design-routing.md)
