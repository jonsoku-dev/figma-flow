# 동봉된 외부 스킬과 첫 실행 검증

Figma Flow의 디자인 지침은 플러그인 안의 고정된 원문에서 읽는다. 사용자 전역 스킬 폴더를 준비하거나 다른 PC의 설치 경로를 복사할 필요가 없다. 원본 파일·참조·스크립트와 라이선스는 `vendor/skills/`에 함께 배포하며, [의존성 목록](../../../vendor/skills/manifest.json)에 원본 저장소·커밋과 파일별 해시를 기록한다.

## 첫 실행

설치 결과의 실제 `installedPath`를 플러그인 루트로 확인하고 그 안의 `tools/skill_dependencies.py --check`를 실행한다. 원본·참조·라이선스의 현재 바이트와 안전한 경로를 검사하고 `ready`가 된 다음 해당 디자인 작업을 시작한다. 재실행은 설치 폴더를 수정하지 않는다. 필수 파일이 없거나 바뀌었으면 그 디자인 단계만 차단하고 해당 버전의 정상 플러그인 묶음으로 복구한다. 전역 스킬이나 인터넷의 최신 파일로 조용히 대체하지 않는다.

검증은 동봉된 원문과 검토 기록을 연결하기 위한 검사다. 원문의 지시를 따랐다는 사실, 저자의 신원, 미적 완성도나 도구 실행을 인증하지 않는다. 관련 없는 기술·열람 작업을 새 디자인 제작으로 바꾸지 않는다.

## 원문과 적용 범위

| 원문 | Figma Flow에서의 적용 |
| --- | --- |
| [Impeccable](../../../vendor/skills/impeccable/SKILL.md) | 요청한 표면에 해당하는 제작·비평 playbook과 참조를 읽는다. 공식 4.0.2 원문이며 개발자 PC의 전역 수정본을 복사하지 않는다. |
| [design-taste-frontend](../../../vendor/skills/design-taste-frontend/SKILL.md) | 랜딩·포트폴리오 등 원문 적용 범위를 따른다. 고밀도 제품 UI에는 해당 제외·제한을 유지한다. |
| [Unslop 원문](../../../vendor/skills/unslop/SKILL.md) | 원문 전체를 출처 자료로 보존한다. 실제 Figma Flow 작업은 별도 [각색 절차](unslop.md)를 따른다. 원문의 수치·스타일·승인·실행 규칙을 프로젝트 계약 위에 놓지 않는다. |

음악·영상 장르 스킬인 정확한 ID `taste`는 사용하지 않는다. `design-taste-frontend`는 별개의 디자인 스킬이다.

처음 검증할 때 모든 의존성의 무결성을 확인하되, 작업 중에는 필요한 원문·참조만 읽는다. 원문에 포함된 에이전트·후크·브라우저·생성 스크립트를 동봉했다는 이유로 등록·설치·실행하지 않는다. 실행에는 현재 작업 범위와 호스트의 실제 도구·접근 권한을 적용한다. Figma·이미지 생성·Playwright 같은 도구 연결은 해당 설치·검수 단계에서 따로 확인한다.

## 검토 기록과 업데이트

새 디자인 검토 기록의 스킬 원문은 플러그인 기준 경로와 실제 원문 해시로 기록한다. 현재 동봉된 원문과 일치해야 하며, 임의 전역 경로나 다른 원문을 같은 스킬이라고 제출하지 않는다. 원본 위치가 달라진 과거 영수증은 보존하고 새 버전의 실제 작업에 필요한 검토 기록을 새로 만든다. 과거 증거의 경로나 해시를 덮어써 통과시키지 않는다.

업데이트는 명시적으로 고른 원본 커밋·라이선스·필요 파일 범위를 검토한 후 플러그인 릴리스로 수행한다. 원본 파일을 각색할 때는 별도 Figma Flow 문서에 변경 사실을 남겨 원본과 구분한다. [패키지 출처·업데이트 규칙](../../../vendor/skills/README.md)을 따른다. 개인 설정과 쓰기 가능한 캐시는 프로젝트의 비공개 위치에 두며, 원문 묶음은 실행 중 수정하지 않는다.
