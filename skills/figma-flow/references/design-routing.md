# 프롬프트로 디자인 작업 배정하기

플러그인 루트에서 현재 요청을 입력한다. 이어지는 채팅에서는 앞서 지정된 디자인 원본·언어·매체·금지 조건을 `--context`로 함께 넘긴다. 파일 입력은 `--prompt-file`·`--context-file`로 받는다.

```sh
python3 tools/route_design.py --prompt '일본 모바일 게임 캠페인용 시네마틱 키아트, 전용 로고, 항구 인장과 수집용 승선증을 만들어줘' --context '한국어·일본어 지원. Figma 디자인 원본 그대로 구현. Figma MCP 없이 로컬.'
python3 tools/route_design.py --prompt '기존 이미지를 재사용하고 폰트는 유지해줘. 모션만 검토해줘'
python3 tools/route_design.py --prompt '로고·아이콘 제작 스킬의 원출처를 조사만 해줘'
```

UI 제작·리디자인 경로는 [실행 가능한 시안 선택 단계](direction-selection.md)에서 시작한다. 폰트와 주석·제안 팔레트를 갖춘 실제 후보들을 사용자에게 보여주고 선택을 검증한다. 이어서 [폰트 우선 제작·실제 검토](design-review.md)를 실행한다. Impeccable과 적용 가능한 웹 tasteskill 원문을 읽고, 필요한 게임 역할은 실제 이미지 생성 후 제작한다. 같은 행동의 폭별 재사용과 서로 다른 행동/섹션의 고유한 그림 목적을 구분한다. 생성된 제목/버튼은 실제 문구가 늘면 감싸는 프레임과 다음 내용도 흘러가야 한다. 라우팅은 실제 실행의 허가/증거를 대체하지 않는다.

Figma 경로가 선택되면 시안 생성 명령에 `--review-destination figma`를 전달한다. 선택 요청 전에 `figma_direction_review`에서 실제 후보 페이지의 주석, 팔레트, 변수, 프로토타입 전환 및 복귀를 검증한다. 선택 후의 `native_semantic_handoff`는 `SSOT` 문구나 로컬/MCP 전송 방식과 무관하게 필수다. 일반 번들과 맞춤 제작 모두 [필수 네이티브 캡처·기대 계약·bindings 선언·검사 명령](local-design-audit.md#필수-네이티브-전달-검사-0130)을 수행하고 생성된 화면 명세와 영수증을 전달한다. 순수 로컬 경로에는 이 Figma 게이트를 적용하지 않는다.

`--out`에 새 디렉터리를 지정하면 라우팅 결과와 요청에 맞는 카테고리별 캠페인 검사 계획을 보존한다. CLI는 문구 단서를 해석해 작업 순서·참고 자료·검사를 선택한다. 에이전트는 현재 기획의 의미와 사용 가능한 스킬을 대조한 뒤 선택 경로를 실행한다. 조사만 요청한 경우에는 추천 자료를 반환한다.

| 요청 | 적용 방식 |
| --- | --- |
| 시네마틱한 게임 소개 | 키아트 크롭과 제목의 대비, 첫 화면의 행동을 결정한다. |
| 강한 로고·심볼 | 전용 글자형과 작은 단색 심볼을 설계한다. 선택 후 고정한 같은 게임 콘셉트로 실제 이미지 생성 원본을 만들고, 출처와 실제 사용 크기를 확인한다. |
| 조작용 아이콘 | 직접 생성한 래스터 원본, 역할별 사용처·크기·터치 영역을 확인한다. 수작업 SVG·트레이스·아이콘 폰트는 생성 근거가 될 수 없다. |
| 수집형 인장·승선증 | 소재가 다른 인장을 만들고 선택 조합과 실제 출력물을 대조한다. |
| KO/JA 타이포그래피 | 제목·UI·인쇄 숫자를 나누고 실제 지역별 자형과 줄바꿈을 측정한다. |
| 모든 Figma 디자인 | 실제 화면·조작의 네이티브 주석, 사용 중인 컴포넌트 인스턴스와 변수 바인딩을 재읽고 기대 계약으로 검증해야 완료한다. `SSOT` 문구와 로컬/MCP 방식에 관계없이 적용한다. |
| Figma 그대로 구현 | 해당 문서의 실제 네이티브 노드와 내보내기를 읽은 뒤 웹 작업을 시작한다. |

근거 목록은 [design-routes.json](../../../library/design-routes.json)에 있다. 제작자 공개 스킬, 공식 플랫폼·디자인 지침, 실제 사례의 종류와 한계가 각각 기록돼 있다. 다운로드·이미지 생성, 로고와 UI 아이콘, 유지·변경의 차이가 요청에 있으면 그대로 유지한다. 여러 방향이 맞으면 한 페이지 전체를 섞지 않고 각 표면에 필요한 방향을 배정한다.

## 입력을 브라우저에서 비교하기

플러그인 루트에서 `python3 tools/serve_design_routes.py`를 실행하고 출력된 로컬 주소를 연다. 같은 입력으로 CLI와 같은 라우터를 호출한다. 이 페이지는 배정 결과를 확인하는 화면이며 실제 제작은 Codex의 `$figma-flow` 요청에서 선택된 경로로 진행한다. `--port`로 원하는 로컬 포트를 정할 수 있다.


## 캠페인 형태를 각각 또는 함께 선택하기

```sh
python3 tools/campaign_forms.py
python3 tools/route_design.py --prompt '1,2,3 모두' --context '게임 웹 캠페인 제작: 1 기념·행사형, 2 출시·공개형, 3 참여·프로모션형'
python3 tools/route_design.py --prompt '출시·공개형만 만들어줘'
```

세 형식은 정보 구조와 목표 행동의 선택이다. A/B/C 디자인 방향 선택은 별도로 기다린다. `campaign_forms`의 세 행은 각각 섹션 순서, 콘텐츠, 자산 범위, 주요 CTA와 실제 검사를 제공한다. 기념·행사형은 히어로→프로그램/음악/갤러리→행사 행동, 출시·공개형은 세계/캐릭터→진짜 티저→사전등록/설치, 참여·프로모션형은 혜택·보상/규칙을 먼저 보여준 뒤 참여→획득 결과→공유/저장으로 만든다. 요청한 형태를 모두 유지하고 각 형태의 목적·자산·행동을 독립적으로 검증한다. 정적 재생 그림을 진짜 티저라고 하거나 모든 형태를 작은 게임 하나로 줄이지 않는다.
