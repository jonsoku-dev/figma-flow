# 제품에 맞춘 Unslop 비평

이 문서는 Damir Sokolovsky의 [unslop](https://github.com/heydamir/unslop/tree/97daa3eb365670ea3f87ed85356cbfcee18105a5/skills/unslop)을 Figma Flow의 시안 선택·검토에 맞게 각색했다. 원문의 방향 다섯 항목, 결함 정도에 따른 수정 범위, 아홉 단계 비평을 사용한다. 격자·서체·색·아이콘·모션과 승인 절차는 아래 프로젝트 기준으로 변경했다. 이 문서는 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)으로 제공하며, 복사·각색할 때 Damir Sokolovsky와 원본 링크, 변경 사실을 유지한다.

[동봉한 원문 전체](../../../vendor/skills/unslop/SKILL.md)와 이 각색 문서는 별개다. 원문의 참조 이미지·스크립트·라이선스도 고정된 커밋으로 보존하며 [의존성 검사](skill-dependencies.md)로 확인한다. 원본 패키지 보존이 원본 도구의 실행이나 현재 작업에 대한 적용 승인을 뜻하지 않는다.

## 적용 범위와 우선순위

새 UI·캠페인의 후보를 작성할 때, 기존 화면을 리디자인할 때, 완성 화면을 검토할 때 읽는다. 단순 기술 수정·소스 대조에는 디자인 변경을 추가하지 않는다. 기존 Impeccable·적용 가능한 design-taste-frontend와 [디자인 검토](design-review.md)를 함께 사용한다.

사용자의 요청·선택한 시안·지정한 디자인 시스템·프로젝트의 접근성 및 자산 계약을 우선한다. 원문의 예시 수치를 새 디자인 토큰으로 일괄 덮어쓰지 않는다.

- 격자는 기존 프로젝트 토큰과 [시안 시각 품질 요구사항](visual-quality.md)을 따른다. 캠페인의 8px 격자를 원문의 4px 기본값으로 바꾸지 않는다.
- 서체는 실제 대상 언어의 제목·본문·조작 표본으로 선택한다. 라틴 서체 추천이 한국어·일본어 표본을 대체하지 않는다.
- 단일 강조색·중립 배경·가벼운 글자 굵기를 모든 제품에 강제하지 않는다. 게임·브랜드의 의미 있는 색, 굵은 제목, 그라디언트와 모션은 선택한 방향에 맞게 유지하고 가독성·초점을 확인한다.
- 아이콘·로고는 현재 사용자가 지정한 생성 원본·기존 자산 조건을 따른다. 원문의 라이브러리 아이콘 권장은 그 조건을 변경하지 않는다.
- 지정한 시스템이 있을 때 시안 간 차이는 그 시스템이 허용하는 구성·동선·위계에서 만든다. 색과 서체를 임의로 바꿔 차이를 만들지 않는다.

## 1. 방향을 다섯 항목으로 기록하기

브리프·기존 브랜드·분석 자료를 읽고 후보별 계획 또는 `research.md`에 기록한다. 새 승인 문서나 별도 점수를 만들지 않는다.

| 항목 | 기록할 내용 |
| --- | --- |
| 제품 | 누구의 어떤 행동을 돕는 화면인지 한 문장 |
| 성격 | 제품에 맞는 구체적 성질 2–3개와 근거 |
| 세계관 | 색·재료·이미지가 제품과 연결되는 장소나 맥락 |
| 강조할 장면 | 주목해야 하는 콘텐츠 1–2곳과 그 이유 |
| 고유 디테일 | 해당 제품에 속하는 작은 표현 한 가지와 실제 사용 위치 |

시안 단계에서는 이 방향으로 비교 후보를 만들고 기존 사용자 선택을 기다린다. 본제작에서는 선택한 방향을 유지한다. 원문의 방향 확인을 이유로 같은 선택을 다시 요구하지 않는다. 승인 후 방향 자체를 바꾸는 제안은 현재 선택을 조용히 덮어쓰지 않고 변경 범위로 제시한다.

## 2. 실제 화면으로 수정 범위 정하기

먼저 데스크톱·모바일과 필요한 상태를 실제로 본다. 브라우저를 사용하면 [접근 등록](browser-access.md)을 먼저 마친다. Figma 납품에서는 실제 Figma 내보내기와 네이티브 읽기 결과도 확인한다. HTML 캡처가 Figma 확인을 대체하지 않는다.

발견한 문제마다 실제 요소·노드, 관찰값과 사용자에게 생기는 영향을 적는다. 문제가 여러 영역에 걸치면 전체 비평을 수행한다. 일부만 문제이면 그 부분만 수정한다. 결함이 없으면 구체적인 관찰과 최종 캡처를 남기고 현재 디자인을 보존한다. 비평 기록을 채우기 위한 가짜 결함이나 불필요한 리디자인은 만들지 않는다.

## 3. 아홉 항목 순서로 비평·수정하기

각 항목을 화면 전체에서 확인한 뒤 다음 항목으로 넘어간다. 실제 변경이 없는 항목은 관찰·유지 이유를 남긴다.

| 순서 | 확인할 것 |
| --- | --- |
| 간격 | 프로젝트 격자, 그룹 안팎의 간격, 같은 역할의 크기, 정렬 |
| 색 | 콘텐츠와 조작의 위계, 의미 있는 강조, 대비, 장식의 경쟁 |
| 아이콘 | 실제 의미, 일관된 표현, 자산 원본과 최종 사용 위치 |
| 문구 | 사용자의 행동·결과가 읽히는지, 검증되지 않은 주장, 불필요한 감탄·배지 |
| 서체 | 대상 문자 로딩, 역할별 위계, 실제 줄바꿈·획 밀도·숫자 정렬 |
| 구성 | 읽기·조작 순서, 시각적 중심, 제품에 맞는 밀도와 모바일 재배치 |
| 디테일 | 모서리·패딩 관계, 입력·오류·선택·포커스 상태, 클릭 영역 |
| 이미지 | 제품·세계관과 연결되는 내용, 실제 크롭·가독성, 의미 없는 채움 여부 |
| 모션 | 행동·상태를 설명하는지, 주의 분산, reduced-motion 대응 |

표현을 제거한 뒤 화면이 어떤 제품에나 맞는 템플릿처럼 보이는지도 확인한다. 제품명·내용·동작을 임의로 바꾸거나 새로운 기능·주장·데이터를 만들어 해결하지 않는다.

## 4. 기존 검토에 연결하기

선택 전에는 기존 미리보기 → `design_quality.py` → 수정 루프와 후보별 검토 메모에 연결한다. 선택 후에는 기존 `critique.findings` 또는 실제 기준별 `critique.checks`에 요소 위치·관찰·수정값·전후 캡처를 남긴다. 실제로 하지 않은 검사를 `pass`로 채우지 않는다.

수정 후 현재 산출물의 데스크톱·모바일과 영향받은 상태를 다시 확인하고 기존 `prepare_design_review.py`·`check_project.py`를 실행한다. 문서·해시·체크리스트는 미적 완성도나 사용자 인수를 인증하지 않는다. 내장 참조는 외부 설치 스킬로 위장해 receipt의 `skills` 목록에 넣지 않는다.

원문의 `snapshot.mjs`·`story.mjs`는 원본 패키지 안에 보존하지만 Figma Flow 기본 경로에서 실행하지 않는다. 실제 브라우저 검수는 허용 목록을 적용한 호스트 도구를 사용한다. 설명 영상이 요청되면 별도 범위에서 도구·접근 권한과 결과를 확인한다.
